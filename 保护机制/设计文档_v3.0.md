## 一、v3.0 核心变更

### 1.1 架构升级

```
v2.2：/保护 命令 → 直接读API、持仓账本、知识库 → 角色分析 → 结论
v3.0：build_protection_snapshot.py → 保护快照.json → /保护 命令 → 角色分析 → 结论
                                         ↑ 只读快照层 ↑
```

**关键变化**：主系统负责生成只读快照，保护机制只读取快照和自身目录文件。二者联动但不互相污染。

### 1.2 设计目标

1. 保护机制在盘前、盘中、盘后基于最新数据提醒用户降温
2. 不污染评分、交易、数据主链路
3. 所有结论先给腰子结论，再给证据
4. 结论枚举固定：`可 / 等 / 否 / 强制冷却`
5. 数据不新鲜/冲突时默认输出"等/否"，不给冲动交易找理由

## 二、系统边界

```
硬隔离边界：
  读：代码文件/（只读，通过 build_protection_snapshot.py 读取主系统数据）
  写：保护机制/保护快照.json（唯一写入目标）
  禁：保护机制不引用 pipeline_engine
  禁：保护机制不修改 代码文件/、模拟交易/、每日荐股/、重点股票/
```

### 2.1 数据流方向

```
主系统（每日荐股、重点股票、模拟交易、信号引擎）
  ↓ 只读
build_protection_snapshot.py
  ↓ 写入
保护机制/保护快照.json
  ↓ 只读
/保护 命令（盘前/刹车/复盘）
  ↓ 写入
保护机制/盘前简报/、刹车记录/、复盘记录/
```

### 2.2 联动但不污染

- 主系统可以新增 `build_protection_snapshot.py`（属于 代码文件/tools/）
- 快照生成器可以只读主系统数据
- 但只能写入 `保护机制/保护快照.json`
- `/保护` 命令不得调用 pipeline_engine

## 六、命令入口（v3.0 更新）

| 命令 | 触发方式 | 前置步骤 | 流程 |
|:-----|:--------|:--------|:-----|
| `/保护 盘前` | Cron 8:53 + 9:23 / 手动 | 先读 `保护快照.json`，检查 stale_seconds ≤ 600 | 山猫→信鸽→玉夜→流金→青山→腰子 |
| `/保护 刹车 <标的> <方向> <价格> [金额] [理由] [止损依据]` | 手动 | 先读 `保护快照.json`，检查 stale_seconds ≤ 600 | 信鸽→流金→青山→腰子（压缩+四层判定） |
| `/保护 复盘` | 手动/自动 | 先读 `保护快照.json` + 当日刹车记录 | 腰子主导偏差分析 |

### 6.1 `/保护 刹车` 新格式

```
保留兼容：/保护 刹车 <标的> <买入/卖出> <价格>
新增推荐：/保护 刹车 <标的> <买入/卖出> <价格> <金额或股数> <操作理由> <止损依据>

缺少"金额/理由/止损依据" → 最多给"等"，不得给"可"
```

### 6.2 盘中刹车前检查

```
1. 读 保护快照.json
2. 检查 stale_seconds > 600？
    是 → 尝试重建快照；重建失败→默认"等"
3. 按四层判定：
    硬阻断 → "否"/"强制冷却"
    软警告 → "等"
    盈亏比检查
    行为模式匹配
```

### 6.3 刹车判定规则

**硬阻断（任一命中→"否"或"强制冷却"）：**

1. 当前处于冷却期
2. 数据状态为 missing / conflict
3. 买入发生在 9:30-10:00 且为追涨
4. 无事件催化且涨幅超过 3%
5. 已持有且浮亏时继续买入
6. 单票仓位将超过上限
7. 总仓位将超过上限
8. 当日亏损超过阈值
9. 有低胜率信号(<50%)仍作为主要买入理由
10. 止损口径冲突且用户仍要求买入

**软警告（命中→默认"等"）：**

1. 数据 stale
2. 信号胜率偏低
3. 报告结论为 wait/neutral
4. 当前价接近压力位
5. 目标收益/止损风险比 < 2:1

## 八、流程设计

### 8.1 盘前流程

```
8:53  build_protection_snapshot.py 生成 保护快照.json
        ↓ 失败 → 发降级简报，腰子默认"今日少动或不动"
8:57  /保护 盘前 只读快照，输出纪律卡片
9:23  build_protection_snapshot.py 重新生成快照
9:25  /保护 盘前 只读新快照，输出竞价校准
```

### 8.2 盘中刹车流程

```
用户触发 /保护 刹车
  → 检查 保护快照.json 是否超过 10 分钟
    ├── 未过期 → 直接判定
    └── 过期 → 尝试重建快照
          ├── 成功 → 用新快照判定
          └── 失败 → 默认"等"
  → 按硬阻断→软警告→盈亏比→行为模式四层判定
  → 写入 保护机制/刹车记录/YYYY-MM-DD.md（追加模式）
```

### 8.3 盘后复盘流程

```
触发（手动或 Cron 19:37）
  → 检查当日是否有真实交易或刹车记录
    └── 无 → 静默跳过
  → 对比盘前纪律、刹车结论、用户实际操作
  → 生成纪律评分（1-10）
  → 发现新行为模式 → 追加到 行为模式.md
  → 写入 保护机制/复盘记录/YYYY-MM-DD.md
```
