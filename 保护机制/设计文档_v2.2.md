## 四、飞书消息体设计

### 格式规范

```
1. 结论先行 — 腰子结论放在消息最前面
2. 角色分块 — 每个角色独立段落，之间空一行
3. 列表换行 — 多个条目用换行+缩进，不用逗号挤在一起
4. 警告突出 — 风控警告独占一段，不与其他内容合并
5. 尾部固定 — 所有消息以"——"分隔 + 免责声明结尾
6. 总长度 — 盘前 ≤ 30 行，刹车 ≤ 20 行，复盘 ≤ 25 行
```

## 五、输出灵活性原则

| | 固定（框架） | 灵活（内容） |
|:--|:-----------|:-----------|
| 山猫 | 必须报：外盘/A50/汇率/情绪/3指标 | 每天数字不同，情绪不同，指标不同 |
| 信鸽 | 必须报：12h新事件 + 今日关注 | 有事件详说，无事件 3 个字"无新事件" |
| 玉夜 | 必须报：双源状态 + 财务时效 | 正常时报"正常"，异常时才展开 |
| 流金 | 必须报：持仓摘要 + 止损线 + 禁止模式 | 持仓变就变，禁止模式根据行为模式库动态调整 |
| 青山 | 必须报：每只持仓信号 + 区间 + 位置 | 信号方向随市场变，区间随价格变 |
| 腰子 | 必须报：一句话纪律 | 每天主题不同，根据当天实际情况决定 |

**原则**：角色必须到场发言，但说什么取决于当天实际情况。没问题就说没问题，有情况就说清楚。

## 六、调度配置

| 任务ID | Cron | 动作 | durable | 节假日 |
|:-------|:-----|:-----|:--------|:------|
| `shield-pre-850` | `57 8 * * 1-5` | 执行 8:50 盘前简报 | true | 跳过 |
| `shield-pre-925` | `23 9 * * 1-5` | 执行 9:23 竞价校准 | true | 跳过 |

**节假日过滤**：Cron 触发 → 读 `holidays_2026.csv` → 命中节假日 → 写日志"YYYY-MM-DD 节假日跳过" → 退出。

**无持仓过滤**：持仓账本 positions 为空 → 输出"无持仓数据，跳过盘前简报" → 退出。

### 9.2 运行审计（每两周）

> 执行者：旧影。产出 `保护机制/运行审计/YYYY-MM-DD.md`。

```
S1 — 简报产出率
  方法：统计最近 10 个交易日，盘前简报文件存在几个
  标准：≥ 90%（允许最多 1 天缺失）

S2 — 简报质量抽查
  方法：随机抽取 3 份简报，检查角色齐全 + 格式合规 + 免责声明
  标准：3/3 全部合格

S3 — 刹车响应时效
  方法：若有刹车记录，检查消息时间戳差值
  标准：≥ 80% 在 180 秒内完成

S4 — 复盘纪律
  方法：对比持仓 history 有交易的日期 vs 复盘记录文件
  标准：有交易日 = 必含复盘

S5 — 系统隔离
  方法：git diff 检查保护机制是否修改了非保护机制/路径
  标准：零修改

S6 — 知识库活性
  方法：检查行为模式.md 近 30 天是否随复盘更新
  标准：有新行为模式 → 必须已记录；无新行为模式 → 正常

S7 — 飞书送达率
  方法：对比本地简报文件数 vs 飞书实际收到消息数（用户确认）
  标准：≥ 90%

S8 — Cron 存活性
  方法：CronList 确认两个任务
  标准：shield-pre-850 和 shield-pre-925 均在，cron 表达式未变
```

### 9.3 效能回顾（每月）

> 执行者：旧影。

```
Q1 — 拦截成功率
  统计刹车记录中"否/等"判断 vs 用户实际操作
  刹车说"否"且用户未操作 → 拦截成功
  刹车说"否"但用户操作且亏损 → 拦截失败

Q2 — 纪律评分趋势
  近一月复盘中的纪律评分趋势（上升/持平/下降）

Q3 — 保护机制退化检测
  对比本月简报 vs 首月简报，字数/深度是否下降
  若字数缩水 ≥ 30% 或角色输出变空洞 → 标记退化预警

Q4 — 飞书稳定性
  近一月飞书消息送达率，失败次数及原因
```

### 9.4 漂移熔断

```
触发条件：连续 2 次运行审计出现同一条 FAIL
熔断动作：
  1. 旧影 CronDelete 两个定时任务
  2. 旧影发送飞书通知用户 + 腰子，附 FAIL 项详情
  3. 用户确认修复后，旧影重新执行部署闸门 G1-G6
  4. 全部 PASS → 解冻，恢复 Cron
```
