# 04 后评估与自我迭代

> **本文档说明青山如何从后评估中学习，以及如何通过六库演进核心知识。**
> 版本：v1.0 | 更新日期：2026-06-10

---

## 1. 核心原则

### 1.1 青山从后评估中学习的方式

青山通过后评估获取判断偏差的事实反馈，但**不直接将单次后评估结果改写为核心知识**。

学习路径：
```
后评估结果 → 写入六库 → 积累多次一致证据 → 青山评估 → 知识更新候选
                                                                 ↓
                                                   腰子审批 → 旧影审计 → 更新核心知识
```

### 1.2 六库是学习账本

六库（信号胜率库、后评估库、反例库、参数库）记录的是：
- 判断对错的事实反馈
- 失败模式的归因分析
- 可调整的参数候选
- 可更新的信号胜率新数据

青山通过六库学习，但**不能绕过六库直接改写核心知识**。

## 2. 青山如何判断自己哪里错

### 2.1 偏差归因分类

青山在后评估中识别到偏差时，按以下维度归因：

| 偏差类型 | 描述 | 典型例子 |
|---------|------|---------|
| 信号评估偏差 | 对信号有效性的判断与事实不符 | MACD金叉判断有效但实际胜率低于预期 |
| 参数偏差 | 参数设置不在有效窗口内 | 超卖阈值25不合适，实际应调为20 |
| 环境匹配偏差 | 没有识别市场环境变化 | 震荡市用了趋势策略参数 |
| 来源等级偏差 | 高估了知识来源的可靠性 | 把外部参考值当项目实值使用 |
| 逻辑偏差 | 分析逻辑存在跳跃或假设错误 | 看到A现象直接推断C结论漏了B中介 |
| 表达偏差 | 结论强度大于证据支撑力度 | L5-seed信号写出"确定性机会" |
| 外部归因 | 偏差由不可控外部因素导致 | 政策突变、黑天鹅事件 |

**来源**：role_consensus（参考六库/后评估库归因体系）
**等级**：L4 | 状态：reference

### 2.2 偏差记录流程

当青山发现自己的判断与后评估结果不符时：

1. **确认偏差存在**：对比判断与事实结果
2. **归因分析**：按以上分类确定偏差类型
3. **写入后评估库**：记录偏差详情、归因结果
4. **判断是否需要提出候选**：
   - 单次偏差 → 仅记录到后评估库和反例库
   - 同类偏差≥3次 → 核心知识或规则调整候选
   - 参数偏移→ 参数候选
5. **不直接修改**：青山知识库内容不因单次偏差而自动修改

## 3. 青山如何提出更新候选

### 3.1 反例候选

**触发条件**：同一类型偏差出现 ≥3 次，且每次偏差均可归因。

**流程**：
```
偏差记录 → 同类偏差≥3次 → 整理反例候选
                                   ↓
          写入错误反例库 → 青山评估 → 腰子确认 → 青山知识更新
```

**来源**：role_consensus（参考 `00_项目地基/07_知识进化/` 反例库索引）
**等级**：L4 | 状态：reference

### 3.2 参数候选

**触发条件**：观察到参数阈值在当前市场环境下持续表现不佳（连续≥5次偏差）。

**流程**：
```
参数偏差记录 → 连续≥5次偏差 → 提出新参数值候选
                                      ↓
          写入参数库 → 回测验证 → 腰子审批 → 更新参数
```

**来源**：role_consensus（参考 `00_项目地基/07_知识进化/parameters/` 参数库索引）
**等级**：L4 | 状态：reference

**示例**：
- MACD 金叉在缩量震荡中多次失效 → 提出限制适用条件的候选 → 写入信号胜率库更新 → 进入反例库 → 青山修改适用条件候选

### 3.3 信号胜率更新候选

**触发条件**：某个信号的项目内累计样本达到门槛（≥20条项目真实后评估/eval_hooks结果）。

**流程**：
```
信号触发 N 次 → 收集后评估结果 → 统计项目内胜率
                                       ↓
          对比种子胜率 → 若差异显著 → 提出胜率更新候选
                                           ↓
       腰子审批 → 旧影审计 → 更新信号胜率库 → L5-seed → L2 升级候选
```

**来源**：role_consensus
**等级**：L4 | 状态：reference

### 3.4 核心知识候选

**触发条件**：六库中积累的多条一致证据表明现有核心知识需要更新。

**流程**：
```
六库积累 ≥N 条一致证据 → 青山评估评估 → 形成知识更新候选
                                              ↓
           跨角色共识（如涉及）→ 腰子终审 → 旧影审计
                                                  ↓
       更新角色知识库 + registry.json 更新 + migration_report.md 记录
```

**来源**：role_consensus（参考 `00_项目地基/07_知识进化/L2_INDEX_知识进化总账_v1.0.md`）
**等级**：L4 | 状态：reference

### 3.5 废弃候选

**触发条件**：某个知识条目持续产生反例、已验证不再适用、来源被更可靠的知识取代。

**流程**：
```
反例积累或来源替代 → 青山评估 → 提出废弃候选
                                         ↓
           腰子确认 → 旧影审计 → registry.json 状态改为 deprecated
                                         ↓
           旧文件引用归档（deprecated_refs.md 更新）
```

**来源**：role_consensus
**等级**：L4 | 状态：reference

## 4. 实践示例

### 4.1 技术修复后没有延续

观察：某股票MACD金叉且RSI超卖给出买入信号，但价格在修复后没有延续上涨。

**后评估结果**：技术信号部分命中（价格先涨后跌）或失败（完全未涨）

**青山动作**：
```
1. 归因：环境匹配偏差（震荡市而非趋势市）
2. 写入后评估库：记录偏差详情
3. 写入反例库（如同类案例≥3个）：震荡市MACD金叉失效模式
4. 参数候选：修改MACD金叉的适用条件，标注"仅限趋势市"
5. 多次验证（≥3次）→ 青山知识更新候选 → 腰子审批 → 更新02_策略方法论/适用条件
```

### 4.2 MACD 金叉在缩量震荡中多次失效

观察：连续3次以上MACD金叉信号后后评估显示在缩量震荡中失效

**青山动作**：
```
1. 归因：环境匹配偏差（缩量震荡环境）
2. 更新信号胜率库：为MACD金叉添加"震荡市/缩量"环境下的胜率记录
3. 写入反例库：震荡市MACD金叉失效案例
4. 青山评估：确认适用条件需要修改
5. 修改03_信号与因子当前知识.md（适用条件部分）→ 经腰子审批
6. registry.json 更新适用条件
```

### 4.3 单次失败

观察：某次信号判断在正常适用条件下仍然失败

**青山动作**：
```
1. 归因：外部归因（偶发事件冲击）
2. 写入反例库：单次反例，不直接修改核心规则
3. 标注"单次偶发"类型
4. 继续观察，积累到≥3次同类失败后再评估
```
