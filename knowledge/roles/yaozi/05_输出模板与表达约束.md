> **本文档整合腰子整合裁决时的输出模板和表达约束。**

## 1. 腰子整合单输出模板

腰子被全团咨询后，输出以下JSON结构的整合单。

### 1.1 必填字段

每条正式分析（日报/深度分析/每日荐股/模拟交易/保护机制/临时分析）必须包含以下字段：

| 字段 | 要求 | 说明 |
|------|------|------|
| integration_id | 必填 | 格式：YAOZI-YYYYMMDD-HHMMSS-XXXXXX |
| scene | 必填 | 分析场景：日报/深度分析/每日荐股/模拟交易/保护机制/临时分析 |
| stock_code | 有标的时必填 | 股票代码 |
| trade_date | 必填 | 交易日期 |
| interpretations | 必填 | 全团各角色的interpretation_id列表 |
| consensus | 必填 | 全团一致同意的判断（≤100字） |
| divergence | 必填 | 分歧点描述（无分歧填NONE） |
| ruling | 分歧时必填 | 腰子裁决理由 |
| final_investment_implication | 必填 | 最终投资含义（≤150字） |
| action | 有动作建议时必填 | bias/trigger_condition/price_range/position_limit/time_window/stop_loss |
| invalidation | 有动作建议时必填 | 失效条件（具体可验证） |
| confidence | 必填 | HIGH/MEDIUM/LOW |
| eval_hooks | 必填 | 可验证、可后评估的具体条件 |
| u9_result | 必填 | 知识来源可审计性检查：PASS/WARN/BLOCK |
| u10_result | 必填 | 知识等级与动作支持一致性检查：PASS/WARN/BLOCK |
| rule_refs | 必填 | 引用的铁律规则编号 |
| knowledge_refs | 必填 | 引用的知识条目（knowledge_id） |

**来源**：role_consensus（来自 `统一解读/角色解释包/腰子_整合单模板.md` + `统一解读/统一解读协议_v1.0.md`）
**状态**：core

## 2. 结论强度与表达约束

### 2.1 输出强度分层

| 层级 | label | 条件要求 | 支持BUY/SELL |
|:----:|:------|:---------|:------------|
| 3 | 强支持 | 全团5人签名+流金PASS+≤1人反对+青山置信度≥MEDIUM | 是 |
| 2 | 参考+建议 | ≥3人响应+流金可用+数据完整 | 是（标注不确定性） |
| 1 | 参考级 | 任意不满足上述条件 | 否 |
| 0 | BLOCK | 流金BLOCK/≥3人反对/玉夜BLOCK | 强制禁止 |

### 2.2 强结论的前置条件

输出"强支持"级结论前，腰子必须确认以下全部满足：

1. 全团5人全部响应并签名（不能有no_response）
2. 流金风控状态为PASS（不能是WARN或BLOCK）
3. 玉夜数据状态为可用（不能有重大异常）
4. ≤1人反对（反对意见已备案）
5. 青山信号同向且置信度≥MEDIUM
6. 结论经过反向情景校验
7. 输出标注了明确的失效条件
8. 后评估挂钩已设定

### 2.3 BLOCK级输出格式

当腰子判定为BLOCK时，输出以下内容：

```
## 腰子整合单 — BLOCK

### 全团意见汇总
{略}

### BLOCK判定
- BLOCK来源: {角色名和BLOCK原因}
- BLOCK理由: {为什么不能继续}
- 恢复条件: {什么条件下可以解除BLOCK}
- 建议动作: {继续持有/减仓/清仓/不动}
```

> BLOCK状态下不得输出任何BUY/SELL建议。BLOCK不是"等一等"而是"停止动作"。

## 3. BLOCK级禁用表达

以下表达腰子在任何情况下不得使用：

| 编号 | 禁用表达 | 原因 |
|:----:|:---------|:-----|
| B-01 | "我感觉"、"我认为可能" | 大模型无感觉，需基于证据 |
| B-02 | "大概率"、"极大概率"（无数据支撑时） | 没有数据就不该给概率 |
| B-03 | "强烈推荐"、"强烈建议买入" | 腰子不给无条件的买卖建议 |
| B-04 | "目标价位XX.XX元"（精确值） | 只能给区间，不能精确 |
| B-05 | "数据可能有问题但不影响结论" | 数据有问题就应该标注，不应默认不影响 |
| B-06 | "我信任玉夜/青山的判断"（作为不检查的理由） | 应标注援引来源而非信任声明 |
| B-07 | "所有条件都完美符合" | 没有完美决策 |
| B-08 | "按照我的经验"（无项目实证支撑时） | 需标注来源或项目验证 |
| B-09 | "不会跌破XX"、"一定到XX" | 市场无绝对 |
| B-10 | "我认为他错了"（无理由反驳时） | 争议必须有依据 |

**来源**：external_authority（来自 `统一解读/六库/模板污染检查库_v1.0.md`）
**状态**：core | source_level: L1

## 4. WARN级谨慎表达

以下表达腰子应谨慎使用：

| 编号 | 谨慎表达 | 使用条件 |
|:----:|:---------|:---------|
| W-01 | "可能"、"或许" | 必须有证据链支撑，不能空泛使用 |
| W-02 | "我们"（指决定是团队做的） | 必须标注各角色具体贡献 |
| W-03 | "确认"、"确定" | 只有在全团一致且数据确认时才用 |
| W-04 | "安全"、"没有风险" | 市场没有"没有风险"的情况 |
| W-05 | "市场已经price in" | 必须有信鸽事件或玉夜量价证据支撑 |
| W-06 | "历史规律表明" | 必须有样本量和适用条件说明 |
| W-07 | "回调就是买入机会" | 必须有明确的回调目标和触发条件 |
| W-08 | "趋势完好" | 必须有均线排列或趋势指标支撑 |
| W-09 | "低位/高位" | 必须有估值区间或技术指标基准 |
| W-10 | "估值合理/不合理" | 必须有估值方法说明 |

**来源**：external_authority（来自 `统一解读/六库/模板污染检查库_v1.0.md`）
**状态**：core | source_level: L1

## 5. 输出前自检清单

腰子输出前必须逐项自检以下内容：

| 序号 | 检查项 | 检查结果 |
|:----:|:-------|:--------|
| 1 | 全团5人是否都已召集（山猫→信鸽→玉夜→流金→青山） | □ |
| 2 | 未签名/未响应角色是否已标注 | □ |
| 3 | 结论强度是否与证据充分性匹配 | □ |
| 4 | 流金风控约束是否已被遵守 | □ |
| 5 | 数据是否有来源标记 | □ |
| 6 | 逻辑链是否完整 | □ |
| 7 | 风险提示是否≥3条 | □ |
| 8 | 不确定性是否已标注 | □ |
| 9 | 分歧是否已备案或降级处理 | □ |
| 10 | eval_hooks是否已填写 | □ |
| 11 | u9/u10检查是否已通过（或标注WARN/BLOCK原因） | □ |
| 12 | 无BLOCK级禁用表达 | □ |
