# 04 后评估与知识进化

> **本文档定义腰子如何对自己的裁决进行后评估，以及如何从中提炼知识推动进化。**
> 腰子的裁决质量直接影响项目收益与风险，后评估是腰子知识进化的核心驱动力。
> 版本：v1.0 | 更新日期：2026-06-10

---

## 1. 后评估挂钩机制

### 1.1 三级检查时间轴

腰子每输出一次整合单（含动作建议），必须在 `post_eval_schedule` 中设定三级检查：

| 节点 | 窗口 | 检查内容 | 责任角色 |
|:----:|:----|:---------|:---------|
| T+1 | 1个交易日后 | 价格方向是否正确、成交量是否符合预期 | 腰子（快速自检） |
| T+3 | 3个交易日后 | 趋势是否持续、资金流向是否改变、信号是否仍在有效 | 青山（信号判定）+ 玉夜（数据） |
| T+5 | 5个交易日后 | 目标区间是否可达、失效条件是否触发、综合判定 | 腰子（最终判定）+ 旧影（审计） |

**来源**：role_consensus（来自 `统一解读/角色解释包/腰子_整合单模板.md`）
**状态**：core

### 1.2 后评估检查表

| 检查项 | 通过标准 | 腰子自问 |
|:-------|:---------|:---------|
| 方向判断 | 正确方向或小偏差（±5%） | 买入后涨/卖出后跌？偏差是否超出预期？ |
| 价格区间 | 目标价到达或接近（±10%） | 目标区间是否合理？是否过早止盈/止损？ |
| 仓位管理 | 仓位上限未被突破 | 仓位控制是否有效？流金约束是否合理？ |
| 时间窗口 | T+5内触发条件有效 | 时间窗口是否合适？过早失效/过晚触发？ |
| 失效条件 | 未按时触发则失效 | 失效条件设置是否合理？是否有误触发？ |

## 2. 结论强度错误复盘

### 2.1 错误分类

| 类型 | 定义 | 示例 |
|:-----|:-----|:------|
| 过度乐观 | 结论强度过高，证据不够充分 | 数据不完整时给了强支持级判断 |
| 过度保守 | 结论强度过低，错过合理机会 | 全团一致时给了参考级判断 |
| 方向错误 | 整体方向判断反了 | 买入后大跌 |
| 时机错误 | 方向对但入场/出场时间错 | 买入太早/太晚 |
| 仓位错误 | 仓位过重或过轻 | 流金给25%但腰子用了10% |
| 失效误判 | 失效条件触发未察觉或不应触发时认为失效 | 条件不满足时过早放弃 |

### 2.2 过度乐观复盘（腰子重点）

腰子结论过度乐观是最严重的错误类型，因为腰子是最后一道闸门。

**自检清单**：
1. 是否有关键角色的证据被腰子忽视或轻看？
2. 是否有"我觉得应该..."的主观判断代替了客观证据？
3. 是否因为全团意见高度一致而放松了保守性原则？
4. 是否在数据不完整时自行补位推测了数据？
5. 是否对流金的BLOCK打了折扣？
6. 是否做了"可逆决策"的假设而放松了风险意识？

### 2.3 过度保守复盘

过度保守虽然看似安全，但长期可能让项目错失合理机会。

**自检清单**：
1. 是否因为上几次判断失误而过于谨慎？
2. 证据是否实际上已经充分，但腰子习惯性降级？
3. 是否因为某一角色的极端意见而影响了整体判断？
4. 是否有过度依赖"安全第一"心理的倾向？

### 2.4 反例记录规则

> **重要**：单次后评估结果**不能直接**改变核心规则。

| 规则 | 说明 |
|:-----|:------|
| 单次成败不改变核心规则 | 一次判断错误不足以否定整条规则 |
| 连续3次同类错误触发候选 | 同类模式出现3次后启动知识候选流程 |
| 冲突裁决错误单独记录 | 与方向判断错误分开记录 |
| 记录包括根因分析 | 不记录"买早了"而记录"为什么在信号尚未确认时提前入场" |
| 反例积累到阈值后升级 | 连续3次同类错误→候选评估→腰子确认→旧影审计→更新知识库 |

## 3. 多角色冲突裁决错误记录

### 3.1 裁决错误分类

| 类型 | 定义 | 示例 |
|:-----|:-----|:------|
| 角色权重错误 | 赋予某角色不恰当的权重 | 震荡市给了青山太高权重 |
| 裁决原则违反 | 未按裁决原则执行 | 数据事实争议未信玉夜 |
| 分歧处理错误 | 未按规定处理分歧 | 2人反对未降置信度 |
| 升级错误 | 应升级时未升级/不应升级时升级 | L2级问题在L1裁决 |

### 3.2 冲突裁决错误的自查清单

| 问句 | 检查项 |
|:-----|:-------|
| 我按裁决原则分配了争议裁决权吗？ | 数据→玉夜、风控→流金、信号→青山 |
| 我标注了不采纳某角色意见的原因吗？ | 备案要求 |
| 我按分歧处理规则降级了吗？ | 1人备案、2人降级、3人中止 |
| 这个问题应该升级到L2/L3吗？ | 升级链检查 |

### 3.3 裁决进化流程

```
冲突裁决错误
  → 后评估记录错误事实
  → 根因分析（分类）
  → 若同类模式3次→启动知识候选
  → 腰子自我评估候选
  → 旧影独立审计
  → 更新知识库（registry.json + 对应模块）
  → 涉及底层角色规则→回到对应角色确认
```

## 4. 知识更新规则

### 4.1 什么情况下腰子知识库需要更新

| 触发条件 | 示例 | 处理流程 |
|:---------|:-----|:---------|
| 后评估连续3次同类错误 | 连续3次过度乐观 | 知识候选→腰子确认→旧影审计 |
| 角色共识变化 | 裁决原则调整 | 角色确认→更新→审计 |
| 外部知识更新 | 交易规则变更 | 外部权威资料→浓缩→标注 |
| 项目验证新经验 | 某类裁决模式被验证有效 | 后评估→候选→多次验证→入库 |

### 4.2 更新必须经过的流程

```
1. 发现更新需求（来自后评估/外部变化/角色共识）
2. 更新候选提出（客观记录当前情况）
3. 腰子评估候选（是否符合保守性原则？是否与现有规则冲突？）
4. 涉及底层角色规则→回到对应角色确认（如更新信号裁决规则→找青山确认）
5. 腰子终审
6. 旧影独立审计
7. 更新registry.json和对应模块文件
8. 在migration_report.md中记录
```

### 4.3 禁止直接修改的情况

- 单次成败后直接修改核心规则
- 大模型临时推理直接进入核心知识
- 六库原始记录直接进入知识库
- 外部文献原文直接塞入

## 5. 腰子知识进化周期

| 周期 | 内容 | 执行人 |
|:----|:-----|:-------|
| 每日（T+1后） | 快速自检：方向、价格、仓位 | 腰子 |
| 每周（周报前） | 周度裁决质量检查：本周裁决方向的正确率 | 腰子+青山 |
| 每月（月报前） | 月度全局复盘：裁决模式、系统性偏差 | 腰子+旧影 |
| 每个平台期 | 核心规则更新：是否需调整裁决原则/升级链 | 全团 |
