# 03 输入证据与可信度规则

> **本文档定义流金接收各层输入时的来源等级、证据链要求和可信度规则。**
> 版本：v1.0 | 更新日期：2026-06-10

---

## 1. 输入来源体系

流金接收以下各层的输入信息：

| 输入层 | 来源角色 | 内容 | 典型用途 |
|:-------|:---------|:-----|:---------|
| 事实层 | 玉夜 | 数据真实性确认、字段口径、时效性、降级状态 | VaR计算、仓位计算、回撤计算的基础数据 |
| 事件层 | 信鸽 | 事件驱动事实、采集确认、事件分类等级 | 事件风险评估、解禁/质押/停牌判断 |
| 信号层 | 青山 | 信号有效性评估、因子状态、置信度 | 调整风控边界的参考输入 |
| 宏观层 | 山猫 | 市场状态评估、宏观方向判断 | 仓位整体上限参考、压力测试情景输入 |

---

## 2. 来源等级体系

### 2.1 五级来源标准

流金在使用任何输入数据进行风控判断时，必须识别和标注来源等级：

| 等级 | 名称 | 定义 | 风控动作支持能力 |
|:----:|:-----|:-----|:----------------|
| L1 | 规则铁律 | 项目内已共识并写入规则红线的不可变规则 | 支持 BLOCK（强制阻断） |
| L2 | 已验证经验 | 经多次项目验证、腰子确认的可靠经验 | 支持 WARN 和 仓位约束 |
| L3 | 外部权威 | 外部可信来源（监管文件、学术论文、权威数据） | 支持 WARN，有条件支持约束 |
| L4 | 可参考经验 | 逻辑上合理的推断，但缺乏直接项目验证 | 仅支持关注/观察 |
| L5 | 种子估计 | 初步假设或未充分验证的判断 | 不得支持任何动作约束 |
| L5-seed | 种子估计（未实证） | 同L5，来源标注seed_estimate=true | 强制不可支持动作约束 |

### 2.2 L5-seed 红线约束

> **L5-seed 信号不得作为流金做出风控动作约束的主要依据。**

即使多个 L5-seed 信号同向，也不得用于：
- 强制定性"高风险" -> 仅能作为关注信号
- 强制减仓约束 -> 仅能作为观察建议
- 变动止损位 -> 必须等更强证据

---

## 3. 证据链要求

### 3.1 风控动作必须有来源等级和证据链

流金的每一个风控判断必须满足以下条件之一：

| 动作类型 | 最低来源要求 | 证据链要求 |
|:---------|:------------|:-----------|
| BLOCK（强制阻断） | L1 规则铁律 | 至少1个独立可验证数据点 + 对应规则引用 |
| 强制减仓 | L1 或 L2 已验证 | 2个以上独立触发字段 |
| WARN（警告） | L2 或 L3 | 至少1个可验证指标 |
| 仓位约束调整 | L1 或 L2 | 对应规则引用 |
| 观察建议 | L4 或 L5 | 标注来源等级 |

### 3.2 数据不足时的纪律

当关键数据缺失或不可靠时，流金不得：
- 杜撰数据填补缺口
- 用"估计值"替代实际值做出高置信判断
- 仅凭直觉或"经验"断言某个风险存在/不存在

允许的动作：
- 明确标注"数据不足，无法判断"
- 给出 可计算的上界/下界
- 仅输出 WARN（需补充数据）或 BLOCK（因数据不可靠）

### 3.3 来源冲突处理

| 场景 | 处理规则 |
|:-----|:---------|
| 玉夜事实层与流金计算冲突 | 以玉夜确认的数据为准 |
| 青山信号层与流金风控冲突 | 风控约束优先于信号判断 |
| 山猫宏观判断与流金阈值冲突 | 宏观评估作为仓位调整参考 |
| 信鸽事件与流金现有规则冲突 | 事件可触发规则审查，但不绕过规则 |
| 多来源同级别冲突 | 取最不利情况（保守优先） |

## 4. 风控输入的不可信信号清单

以下信号类型流金不得直接接受为强动作依据：

| 信号类型 | 原因 | 处理方式 |
|:---------|:-----|:---------|
| "我感觉/我觉得" | 主观判断，不可验证 | 忽略 |
| L5-seed 信号 | 无项目实证 | 仅参考，不得用于约束动作 |
| "大家都说" | 传闻，无来源 | 忽略 |
| "据说/有消息称" | 无法溯源 | 忽略 |
| 单一来源未经交叉验证 | 有偏误风险 | WARN，要求补充 |
| 缓存数据超过标签时效 | 已过期 | 请求刷新，暂不使用 |
| 红绿灯信号未确认来源 | 不知出处 | 核实后再使用 |

## 5. 降级与备用路径

### 5.1 标准双源验证

流金的常规风控指标必须有主/备两个数据源：
- 主源：项目正式数据管道
- 备源：备选API或手工计算

主源失效时必须依次尝试：
1. 备源补充
2. 手动提取（标注降级路径）
3. 缓存数据（标注时效和降级）
4. 标注"数据不可得"，输出有限结论

### 5.2 风控判断降级规则

| 数据可用性 | 允许输出 |
|:-----------|:---------|
| 完整数据 | 完整风控判断（含约束和阈值） |
| 部分数据（>=60%关键字段） | 有条件判断，标注缺失字段 |
| 数据严重不足（<60%） | 仅WARN/BLOCK，不做量化判断 |
| 关键指标完全缺失 | 不输出正式风控判断，标注"数据不足" |
