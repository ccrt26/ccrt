# 04 后评估与知识进化

> **本文档定义流金的风控失效复盘机制、止损参数候选流程和知识更新路径。**
> 版本：v1.0 | 更新日期：2026-06-10

---

## 1. 风控失效复盘

### 1.1 失效定义

流金风控失效分为以下类型：

| 失效类型 | 定义 | 严重程度 |
|:---------|:-----|:--------:|
| 漏报 | 风险事件发生，但流金未给出预警 | 致命 |
| 误报 | 流金给出预警，但实际未发生对应风险 | 轻微 |
| 阈值偏差 | 预警等级判断偏离实际风险严重度 | 中等 |
| 动作约束不足 | 给出的约束偏弱，导致风险超出控制 | 严重 |
| 约束过紧 | 给出的约束过严，不当限制了交易空间 | 轻微 |

### 1.2 单次失效处理规则

**单次漏报/阈值偏差不得直接修改风险规则。**

每次风控失效后，流金必须执行：
1. 记录到风控事件日志（按R0-R4分级）
2. 填写根因分析（直接原因 + 深层原因 + 是否可预防）
3. 提交候选分析（但不升级）

### 1.3 进入反例库的条件

| 条件 | 说明 |
|:-----|:-----|
| 同类漏报累计>=3次 | 同类型风险事件连续漏报 |
| 单一阈值偏差>=2次 | 同一阈值判断错误两次 |
| 误报率>=20%（月） | 当月风控判断中，误报比例过高 |
| 漏报导致亏损>=总资金5% | 因未预警导致单次重大损失 |

反例积累到上述阈值后，流金应：
1. 整理反例分析报告
2. 提交候选规则修改或新增
3. 经腰子终审+旧影审计后更新知识库

## 2. 止损/止盈参数候选

### 2.1 参数调整候选条件

止损/止盈参数可成为候选的条件：

| 参数 | 候选条件 | 最低观察期 |
|:-----|:---------|:----------:|
| ATR止损倍数 | 当前倍数导致>=3次异常止损 | 20个交易日 |
| 硬止损幅度 | 硬止损被ATR止损连续覆盖 | 10笔交易 |
| 移动止损倍数 | 移动止损被频繁触发（>=3次正常回撤） | 15个交易日 |
| 止盈分档阈值 | 超过R3后回吐>=50%利润 >=2次 | 10笔交易 |
| 时间止损天数 | 超过时间止损后股价反弹 >=5次 | 20个交易日 |
| 冷却期时长 | 冷却期后首笔交易即亏损 >=3次 | 10个交易日 |

### 2.2 参数候选测试阶段

一旦达到候选条件，参数调整必须经过以下阶段：

```
Phase 1: 候选提出
  流金提交参数调整候选 -> 附带观察数据和统计

Phase 2: 小舱测试
  测试周期：>=20个交易日 或 >=10笔交易
  测试仓位：正常仓位的25%
  测试规则：新参数运行，旧参数同时监控

Phase 3: 腰子终审
  流金提交测试报告
  腰子审批通过或否决

Phase 4: 知识更新
  旧影审计确认
  写入知识库registry.json
  更新参数库（六库）
```

### 2.3 单次失败防规则漂移

**单次亏损不能直接改规则** —— 这是知识进化的根本原则。

- 单次止损触发可能只是市场噪音，不是阈值错误
- 单次止盈后股价继续涨可能有幸存偏差
- 任何规则修改必须基于 累计数据，而非单次事件

## 3. 知识更新路径

### 3.1 知识更新触发条件

| 触发条件 | 说明 | 紧急程度 |
|:---------|:-----|:--------:|
| 同类型风险事件>=3次/月 | 趋势性变化 | MEDIUM |
| 阈值偏差>=2次 | 参数过时 | LOW |
| 新监管政策发布 | 更新A股风险规则 | HIGH |
| 新数据源上线 | 更新来源等级 | LOW |
| 项目外权威资料确认 | 补充知识 | LOW |
| 跨角色共识变更 | 协作规则变化 | MEDIUM |

### 3.2 更新流程

```
Step 1: 流金提出更新候选
  - 描述当前知识的内容
  - 说明更新理由+证据
  - 标注建议来源等级

Step 2: 流金确认
  - 在自身知识范围内交叉检查
  - 评估对风控判断的影响范围

Step 3: 腰子终审
  - 确认更新是否与整体策略一致
  - 审批或否决

Step 4: 旧影审计
  - 检查更新流程完整性
  - 确认未引入逻辑冲突
  - 登记到审计日志

Step 5: 写入registry.json
  - 更新知识条目状态
  - 记录升级链路
```

### 3.3 知识版本纪律

| 操作类型 | 需要谁确认 |
|:---------|:----------|
| 新增core状态知识 | 流金+腰子+旧影 |
| 修改core状态知识 | 流金+腰子+旧影 |
| 新增reference状态知识 | 流金 |
| 修改reference状态知识 | 流金 |
| 废弃知识 | 流金+腰子+旧影 |
| 跨角色知识冲突 | 腰子裁决+旧影审计 |

## 4. 知识淘汰机制

### 4.1 知识废弃条件

| 条件 | 说明 |
|:-----|:-----|
| 对应规则被项目废弃 | 规则红线删除或替换 |
| 对应金融制度变更 | A股规则更新（如ST新规） |
| 连续6个月未使用 | 知识处于休眠状态 |
| 已被更准确知识覆盖 | 新版替代旧版 |
| 来源数据源下线 | 无数据支持该知识 |

### 4.2 知识降级顺序

```
core -> reference -> deprecated -> 废弃归档
```
