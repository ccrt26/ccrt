# 04 时效性缺失异常与降级规则

> **本文档定义玉夜在数据时效性检查、缺失标注、异常值处理、多源冲突时的降级和 BLOCK 规则。**
> 版本：v1.0 | 更新日期：2026-06-10

---

## 1. 核心原则

### 1.1 时效性是数据生命线
过期数据比无数据更危险——它会误导分析结论，造成错误的金融判断。

### 1.2 事实不可确认时必须输出"不足以支撑判断"
当数据来源不明确、多源冲突无法裁决、或关键字段缺失时，玉夜必须明确输出"数据不足以支撑判断"，不得强行给出可用结论。

**来源**：role_consensus | 等级：L4 | 状态：core

### 1.3 多源冲突不能靠大模型猜测
多源数据冲突时，玉夜必须依据数据契约中的裁决规则判断，不得让大模型凭"常识"猜测哪个数据正确。若裁决规则无法覆盖，则降级或 BLOCK。

## 2. 数据新鲜度检查（Freshness）

### 2.1 各类数据的时效性 SLA

> 以下为标准SLA，详细检查规则和降级策略见 `00_项目地基/04_一致性闸门/freshness_rules.json`。

| 数据类型 | 期望时点 | BLOCK条件 | WARN条件 | 备注 |
|:---------|:---------|:-----------|:---------|:------|
| K线行情 | T日 15:30前 | ≥T+1未到 | T日 15:00未到 | T+0必须可用 |
| 四档资金 | T日 15:30前 | ≥T+1未到 | T日 16:00未到 | 盘中实时更新 |
| 融资融券 | T+1 12:00前 | ≥T+2未到 | T+1 15:00未到 | T+1更新 |
| 板块相位 | T日 15:30前 | ≥T+1未到 | T日 15:00未到 | 盘后计算 |
| Baseline | T+1 10:00前 | ≥T+2未到 | T+1 12:00未到 | 日报依赖 |
| Eval_hooks | T+1 12:00前 | ≥T+2未到 | T+1 15:00未到 | — |

**来源**：external_authority（`00_项目地基/04_一致性闸门/freshness_rules.json`）
**等级**：L1（规则引用）| 状态：core

### 2.2 Freshness 状态标注

| 状态 | 定义 | data_confidence 影响 |
|:-----|:-----|:-------------------|
| T+0 | 数据为当日最新 | 不降级 |
| T+1 | 数据为前一日 | medium → low |
| T+≥2 | 数据为2日或更早 | → none，应 BLOCK |
| stale | 数据超过SLA但可用 | → low |
| expired | 数据过期、不可用 | → none，应 BLOCK |

## 3. 数据缺失处理

### 3.1 缺失分类

| 类型 | 典型原因 | 处理方式 |
|:-----|:---------|:---------|
| 字段缺失 | API返回中无该字段 | 标注为 missing，判断是否阻断 |
| 数值缺失 | 字段存在但值为 null/0/空 | 确认是有效值0还是数据缺失 |
| 记录缺失 | 整条数据缺失 | 检查数据源是否正常、判断降级 |
| 时间窗口缺失 | 特定时间段无数据 | 检查该时段是否为非交易日 |

### 3.2 缺失标注格式

```
missing_field: 字段名
reason: 缺失原因（API未返回/源站无数据/缓存未命中/超时）
impact: 影响范围（该字段/该记录/该数据类型的全部记录）
can_proceed: true/false（无此字段是否可继续分析）
```

### 3.3 缺失阻断规则

| 场景 | 动作 | 说明 |
|:-----|:-----|:-----|
| 关键价格字段缺失 | BLOCK | 无法判断行情是否正常 |
| 资金流字段缺失 | WARN + 降级 | 可用其他资金维度替代 |
| 财务字段缺失 | WARN | 标注缺失，使用最近可用值 |
| 缓存未命中 | 降级到备源 | 尝试备源，记录降级路径 |
| 全部数据源不可用 | BLOCK | 输出"数据不足以支撑判断" |

## 4. 异常值处理

### 4.1 异常类型与处理

| 异常类型 | 示例 | 处理方式 |
|:---------|:-----|:---------|
| 离群值 | 价格突变为正常值的10倍 | 标记异常、检查数据源是否正常 |
| 零值突现 | 成交量=0但非停牌 | 标记待确认、检查数据源 |
| 逻辑矛盾 | 最高价<最低价 | BLOCK，标记为数据错误 |
| 突变异常 | 涨跌幅超过±10%且无停牌 | 标记异常、确认是否真实 |
| 口径错误 | 单位错误的数值（元 vs 万元） | 修正或 BLOCK |

### 4.2 异常值标注格式

```
abnormal_field: 字段名
observed_value: 观测值
expected_range: 正常范围
anomaly_type: 离群/零值/逻辑矛盾/突变/口径
suspected_cause: 可能原因
action: WARN/BLOCK
```

## 5. 多源冲突处理

### 5.1 冲突裁决规则

| 场景 | 裁决方式 | 说明 |
|:-----|:---------|:-----|
| 同一等级源冲突 | 以权威注册表指定的主源为准 | 主源优先级 |
| 不同等级源冲突 | 较高等级源覆盖较低等级源 | L1>L2>L3>L4>L5 |
| 权威注册表未覆盖 | 标记为冲突、输出双方数据 | 由腰子决定使用哪个 |
| 无法判断哪侧正确 | 降级输出 + 标注冲突 | 不得猜测 |

**来源**：external_authority（数据契约中的裁决规则汇总）
**等级**：L1（规则引用）| 状态：core

### 5.2 冲突标注格式

```
conflict_field: 字段名
source_a: [来源路径] = 数值A (source_level=X)
source_b: [来源路径] = 数值B (source_level=Y)
resolution: 裁决依据
outcome: 选用数值A/B / 降级 / BLOCK
```

## 6. 降级与 BLOCK 规则总表

### 6.1 降级路径

| 触发条件 | 降级动作 | data_confidence | 输出标记 |
|:---------|:---------|:---------------|:---------|
| 主源不可用，备源可用 | 使用备源 | medium | 标注降级路径 |
| 缓存命中但新鲜度T+1 | 使用缓存 | low | 标注[C]+新鲜度 |
| 数据部分缺失 | 标注缺失字段，使用其余 | medium→low | 标注missing |
| 单源数据延迟 | 等待或使用T-1数据 | low | 标注delayed |
| 多源冲突已裁决 | 使用裁决值 | medium | 标注conflict_resolved |

### 6.2 BLOCK 条件

| 触发条件 | BLOCK 原因 | 输出内容 |
|:---------|:-----------|:---------|
| 全部数据源不可用 | 无数据可提供 | "数据不足以支撑判断" |
| 关键字段冲突且无法裁决 | 不确定使用哪个值 | "字段冲突无法裁决" |
| 过期数据（≥T+2） | 数据已不可用 | "数据已过期" |
| 数据口径无法确认 | 无法确认字段含义 | "字段口径不明确" |
| 大模型推断被作为数据事实 | 来源不可追溯 | "大模型推断不能作为事实源" |

## 7. 盘前/盘中/盘后巡检框架

### 7.1 巡检时间

| 时段 | 时间 | 范围 |
|:-----|:-----|:-----|
| 盘前 | 08:00 | 全量数据源连通性检查 |
| 盘中 | 每30分钟 | 轻量温度巡检 |
| 盘后1 | 15:00 | K线/资金到齐检查 |
| 盘后2 | 18:00 | 融资融券/Baseline到齐检查 |

### 7.2 巡检内容

- 各数据源API连通性
- 缓存新鲜度状态
- 异常告警事件确认
- 降级路径是否生效

**来源**：role_consensus（参考 `.claude/agents/玉夜-知识库/05-异常检测与告警.md`）
**等级**：L4 | 状态：core
