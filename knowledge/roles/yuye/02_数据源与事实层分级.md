# 02 数据源与事实层分级

> **本文档定义数据来源可信度分级体系。**
> 版本：v1.0 | 更新日期：2026-06-10

---

## 1. 核心原则

### 1.1 数据存在 ≠ 数据可信
数据已经从API返回或缓存中获取，不代表它可以用作分析依据。必须经过来源分级、时效性检查和口径确认。

### 1.2 大模型推断不能作为事实源
大模型基于上下文推断的数值、日期、趋势等不能作为数据事实来源。玉夜输出中的任何数据点必须有可追溯的数据源。

**来源**：external_authority（来源等级标准 `统一解读/六库/知识库来源等级标准_v1.0.md`）
**等级**：L1（规则引用）| 状态：core

### 1.3 字段有值 ≠ 可支撑结论
一个字段有值，不代表这个值可以被其他角色用于做出判断。data_confidence 和 source_level 必须在字段输出时同时标注。

## 2. 数据来源可信顺序（L1-L5）

### L1 — 项目铁律/已验证 canonical

**定义**：项目内已验证、通过一致性闸门检查的权威数据。

**包含**：
- baseline_registry.json（权威基线注册表）
- D04 L1 JSON（当日权威缓存）
- D04 L2 SQLite（历史权威库）
- 通过 P0-A~P0-I 准入的 canonical 数据
- 通过 sidecar/md 一致性检查的字段

**can_support_financial_conclusion**：true — 可用于支撑分析输入

### L2 — 官方事实

**定义**：来自官方披露、交易所、监管机构、财报公告的可追溯事实。

**包含**：
- 交易所行情（上交所/深交所）
- 上市公司财报（正式公告）
- 证监会监管文件
- 交易所制度公告
- 官方披露的融资融券数据

**can_support_financial_conclusion**：true — 官方事实可作为分析输入

### L3 — 项目已验证外部数据源

**定义**：项目内长期使用、经过验证的第三方数据源，已知问题和降级路径已记录。

**包含**：
- 腾讯行情 [1]
- 新浪K线 [2]
- 东方财富财务 [3]
- 东方财富 Skills MCP [15]
- 北向资金 [8]
- 个股资金流 [9]
- 行业资金流 [10]
- 融资融券 [12]
- 板块/行业 [7]
- 必盈API [13]（注意：已标记为不稳定，需额外验证）
- baostock [14]（分红/宏观/预告/快报/复权标记为高风险）
- 本地计算指标 [5]
- 缓存数据 [C]（参见缓存策略）

**can_support_financial_conclusion**：默认 true，但已知高风险源须降级

### L4 — 临时抓取/API 返回但未验证

**定义**：非项目标准接入来源、首次使用或偶尔使用的数据。

**特征**：
- 未经过项目验证的 API 接口返回
- 未在项目数据源清单中注册的临时来源
- 无已知降级路径的兜底数据

**can_support_financial_conclusion**：false — 默认不可支撑分析输入
**处理**：须标注 source_level=L4，data_confidence=low，不得作为分析的主要依据

### L5 — 大模型推断或人工口述事实

**定义**：非来自数据源的事实断言。

**包含**：
- 大模型基于记忆或上下文的数值推断
- 人工口述的未验证数据
- 非结构化文本中提取的未确认事实

**can_support_financial_conclusion**：**强制 false**
**处理**：不得作为数据事实输出。如需引用，须标注为"未确认推测"并声明不可用于分析

## 4. Source Level 与 Data Confidence 的关系

| source_level | data_confidence 默认值 | 可支撑分析输入 |
|:------------|:----------------------|:---------------|
| L1 | high | ✅ 可 |
| L2 | high | ✅ 可 |
| L3 | medium | ✅ 可（高风险源须降级） |
| L4 | low | ❌ 默认不可 |
| L5 | none | ❌ 强制不可 |

data_confidence 可根据具体检查结果上调或下调：
- 通过所有检查 + 无已知问题 → high
- 部分检查未执行或有轻微 WARN → medium
- 有 WARN 或已知降级路径中 → low
- 有 BLOCK 或不可确认 → none

## 5. 1+2 主备架构概要

> 主源+备源1+备源2的三级降级体系。详细规则见 `.claude/agents/玉夜-知识库/04-1+2架构合规检查.md` 和数据契约。

**核心规则**：
1. 主源可用时不得使用备源
2. 备源使用时必须标注降级路径
3. 长期使用备源（超24小时）须上报为P2问题
4. 缓存数据（[C]）优先1+2架构内的缓存

**来源**：role_consensus | 等级：L4 | 状态：reference
