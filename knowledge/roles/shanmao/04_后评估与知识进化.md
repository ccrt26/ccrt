## 1. 宏观误判记录机制

### 1.1 什么构成"宏观误判"

以下情况必须记录为宏观误判：

| 类型 | 定义 | 示例 |
|:-----|:-----|:-----|
| 方向性误判 | 宏观方向判断与实际走势相反 | 判断经济复苏但PMI连续下行 |
| 幅度性误判 | 方向正确但幅度偏差大 | 预期降息25bp实际未降 |
| 时效性误判 | 方向正确但时间节点偏差大 | 预期Q1宽松实际Q3才宽松 |
| 遗漏性误判 | 重要宏观信号被忽略 | 未察觉连续多日DR007突破阈值 |
| 过度解读 | 将小事件放大为趋势信号 | 单月数据波动被判断为趋势反转 |

### 1.2 误判记录模板

每次宏观误判被发现后，山猫按以下格式记录：

```
## 宏观误判记录 #N

### 基本信息
日期：YYYY-MM-DD
类型：[方向性/幅度性/时效性/遗漏性/过度解读]
原始判断：{判断原文}
实际结果：{实际发生了什么}
偏差描述：{偏差的具体说明}

### 根因分析
- 信息来源问题：[有/无] 使用了低质量或过期信息
- 框架问题：[有/无] 判断框架存在缺陷
- 遗漏信号：[有/无] 哪些可得信号被忽略
- 逻辑错误：[有/无] 推理链条中的错误环节

### 影响评估
- 对持仓/建议的实际影响：{高/中/低}
- 影响金额/风险敞口：{如有}

### 改进措施
- 框架修正：{需要调整的判断框架}
- 新增监控指标：{哪些指标应新增为巡检项}
- 反例入库：{是否收入反例库}

### 复核
山猫确认：{签名}
腰子终审：{签名}
旧影审计：{签名+日期}
```

## 2. 政策解读偏差的反例管理

### 2.1 触发条件

以下情况必须产生政策解读反例：
- 政策实际效果与山猫评估结果相反（如评估为A级但市场无反应）
- 政策落地时间与山猫预期严重不符
- 政策后续出现了山猫未预判到的修正/补充
- 同一类政策在不同时点产生了截然不同的市场影响

### 2.2 反例入库规则

```
反例编号：CASE-POLICY-NNN
政策名称：{政策全称+文号}
山猫原始解读：{S/A/B/C分级+影响评估原文}
实际结果：{市场反应+影响范围+持续时间}
偏差分析：
  - 高估/低估了哪个维度
  - 遗漏了什么信息
  - 框架哪里需要调整
入库日期：YYYY-MM-DD
```

### 2.3 反例应用

- 反例在下次同类政策分析时自动加载
- 每月复盘已入库的反例
- 反例积累达3个月或5条以上时触发框架修正

## 3. 风格判断错误的候选管理

### 3.1 记录范围

- 市场风格（大/小盘、价值/成长）判断持续偏差超过5个交易日
- 情绪五阶段定位与实际行情持续偏差1个阶段以上
- 板块轮动方向判断错误（如判断TMT退潮但该板块继续领涨）

### 3.2 候选迭代流程

```
1. 识别错误：山猫发现或团队反馈风格判断错误
2. 记录分析：填写《风格判断偏差分析表》
3. 阈值调整：评估是否需要调整核心阈值（如成交额各档位边界值）
4. 回测验证：用最近3笔同类行情验证调整后的阈值
5. 升级确认：回测验证通过 → 山猫确认 → 腰子终审 → 旧影审计
6. 更新阈值表：在 02_核心判断框架.md 中更新
```

## 4. 外部研究观点升级规则

### 4.1 引入外部观点

山猫在分析时偶尔会引用外部研究报告（券商/经济学家观点），引入必须满足：

**引入条件**：
- 必须有独立的数据或事实支撑，不得仅依赖报告结论
- 必须是多个来源交叉验证过的观点（至少2个独立机构结论一致）
- 必须标注来源机构和发布时间

**升级条件**（外部观点→项目内部知识）：
1. 项目自行验证通过：该观点被后续至少2个宏观数据点确认
2. 至少2次独立应用成功：该观点在后续分析中连续2次验证为有效
3. 腰子审核通过：腰子判断该观点对全金融线有长期参考价值
4. 旧影审计记录：审计记录版本和验证数据

### 4.2 不会被自动升级的情况

- 单一券商的独家观点
- 未经数据验证的经济学家个人判断
- 已被后续数据证伪的观点
- 时效性过强（如对特定事件的短期评论）

## 5. 知识更新流程

### 5.1 更新审批链路

```
山猫发现知识缺陷
  ↓
山猫记录缺陷并起草修正方案
  ↓
腰子终审（确认修正对全金融线的影响）
  ↓
旧影审计（审计修正过程的完整性和可追溯性）
  ↓
更新知识库文件（更新01-05模块或registry.json）
  ↓
在migration_report.md中记录变更
```

### 5.2 自动触发更新的条件

| 触发条件 | 更新动作 | 时限 |
|:---------|:---------|:----|
| 货币政策利率变动 | 更新02_核心判断框架阈值表 | 变动后24小时内 |
| 监管规则重大修订 | 更新核心判断框架A股政策部分 | 发布后48小时内 |
| 情绪阈值需调整 | 更新阈值表+记录原因 | 确认偏差后1周内 |
| 宏观经济数据口径变化 | 更新解读框架+历史数据重标 | 下次发布前 |
| 知识库迁移新增条目 | 更新registry.json | 迁移完成后24小时内 |

### 5.3 更新记录格式

```
更新日期：YYYY-MM-DD
更新人：山猫
受影响的文件：{文件名}
更新的内容：{具体字段/章节}
更新的原因：{规则变更/误判复盘/框架修正/新增知识}
审核状态：[待腰子终审/已终审/已审计]
```

### 5.4 版本记录管理

- 每个模块文件单独维护版本号，变更时更新 "版本" 字段
- 重大变更（框架修正/阈值调整/新增模块）记录在README版本记录表中
- 变更至少保留3个月版本历史
