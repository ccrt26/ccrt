# 05 — 输出模板与表达约束

> 知识库版本: v1.0 | 2026-06-10
> 关联: 02_核心判断框架.md, 03_输入证据与可信度规则.md, 04_后评估与知识进化.md
> ⛔ 适用: 信鸽在金融分析/咨询中输出事件事实时的格式
> ⛔ 红线: 禁止把传闻写成事实。禁止直接给 BUY/SELL/HOLD。

---

## 一、输出总原则

1. **只陈述事实**：只描述"发生了什么"，不解释"这意味着什么"
2. **标注不确定性**：未证实信息必须以 WAIT/WARN/BLOCK 标注
3. **来源可追溯**：每条事件必须标明来源级别（S1-S5）和具体来源
4. **禁止深度解读**：不量化影响程度，不给出评分调整建议，不给出交易决策
5. **禁止给出交易信号**：不得出现 BUY/SELL/HOLD 或等价表述
6. **禁止编造**：无法从数据源确认的信息不得输出

---

## 二、正式输出模板

### 完整事件结构

每次被腰子或其他角色咨询时，信鸽按以下结构输出：

```json
{
  "event_name": "事件名称",
  "event_source": "具体来源名称",
  "source_level": "S1|S2|S3|S4|S5",
  "event_time": "YYYY-MM-DD HH:MM",
  "first_seen_time": "YYYY-MM-DD HH:MM",
  "confirmation_status": "confirmed|unconfirmed|disputed|planned",
  "affected_scope": {
    "stock_codes": ["600114"],
    "sector": "材料",
    "is_industry_wide": false
  },
  "uncertainty": {
    "flag": "none|WAIT|WARN|BLOCK",
    "reason": "无|待确认原因",
    "expected_resolution": "YYYY-MM-DD 或 null"
  },
  "next_router": "腰子|山猫|玉夜|流金|青山|阿黑",
  "interpretation_id": "INT-{YYYYMMDD}-{序号}",
  "role_interpretations": "信鸽知识条目引用 XG-*"
}
```

### Markdown 输出结构

当以Markdown形式在对话中输出时，使用以下结构：

```markdown
## 信鸽事件解释包 — {股票代码} — {日期}

### 1. 事件清单

| 事件ID | 事件标题 | 类型 | 等级 | 方向 | 状态 | 来源 | 窗口 |
|:-------|:---------|:-----|:-----|:-----|:-----|:-----|:-----|
| EVT-{YYYYMMDD}-{序号} | {≤40字} | {业绩/并购/股东/经营/监管/政策} | {P0/P1/P2/P3} | {利好/利空/中性/不确定} | {待兑现/已兑现/落空} | {来源+级别} | {X天} |

### 2. 事件过滤说明

过滤层级: 原始采集{X}条 → 去重→去噪→分级→输出{Y}条
已过滤项:
- 自媒体来源{X}条（已过滤）
- P3级日常事件{Y}条（已过滤，仅归档）
- 重复报道{Z}条（已合并）
- BLOCK/WARN事件{W}条（已拦截/待确认）

### 3. P0事件专项

是否存在P0事件: {是/否}
P0事件详情: {如无填"无"}
是否已紧急通知腰子: {是/否/不适用}

### 4. 事件影响矩阵

| 事件 | 等级 | 方向 | 对股价影响 | 对基本面影响 | 对资金面影响 |
|:-----|:-----|:-----|:----------|:-----------|:----------|
| {事件ID} | {等级} | {方向} | 不填(腰子判断) | 不填(腰子判断) | 不填(腰子判断) |

> ⛔ 信鸽仅标注催化方向（利好/利空/中性/不确定），不量化影响程度。量化由腰子完成。

### 5. 事件跟踪窗口

待跟踪事件:
- {事件ID}: {事件标题} — 兑现窗口 {YYYY-MM-DD}至{YYYY-MM-DD}
- ...

### 6. 事件时间映射

| 事件 | 已发生 | 下一步 | 同类周期 | 不确定性 |
|:-----|:-------|:-------|:---------|:--------|
| {事件标题} | {关键日期} | {关键信息} | {历史参考} | {当前不确定性分析} |
```

## 三、日常简短输出模板

当仅需快速回复（如日常采集摘要）时，使用以下精简模板：

```markdown
## 采集摘要 — {日期}

### 概览
- 采集覆盖: {N}只股票
- 原始采集: {X}条 → 过滤后: {Y}条入库
- L1丢弃: {N1} | L2丢弃: {N2} | L3丢弃: {N3} | L4上限: {N4}
- P0事件: {有/无}

### 入库事件概要
| 股票 | 事件 | 类型 | 等级 | 方向 | 不确定性 |
|:-----|:-----|:-----|:-----|:-----|:--------|
| {代码} | {标题} | {类型} | {P0-P3} | {方向} | {无/WAIT/WARN/BLOCK} |

### 模式识别（如有）
- 同股共振: {A1/A2/A3} → {说明}
- 板块共振: {B1/B2/B3} → {说明}
- 时间聚类: {C1/C2} → {说明}

### 异常/待处理
- 数据源异常: {有/无}
- 待确认事件: {列表}
- P0上报状态: {已上报/无需上报}
```

## 四、单事件输出条目模板

当只需输出一条事件时（如回答特定问题）：

```markdown
### 事件: {事件标题}
- **事件ID**: EVT-{YYYYMMDD}-{序号}
- **类型/等级**: {类型} / {P0-P3}
- **来源**: {来源名称} [S{1-5}]
- **时间**: {event_time}
- **方向**: {利好/利空/中性/不确定}
- **状态**: {confirmed/unconfirmed/disputed}
- **不确定性**: {无/WAIT-原因/WARN-冲突/BLOCK-原因}
- **受影响标的**: {股票代码(是否板块性)}
- **时间映射**: 已发生→下一步→同类周期→不确定性
```

## 五、统一解读协议对接

信鸽的输出必须与 `统一解读/统一解读协议_v1.0.md` 规范对接。

### 统一解读必含字段

每条正式分析输出必须包含:

| 字段 | 说明 | 信鸽填写 |
|:-----|:------|:---------|
| `interpretation_id` | 解释ID | INT-{YYYYMMDD}-{序号} |
| `role_interpretations` | 本角色解释内容 | 引用本知识库知识条目（XG-*） |
| `yaozi_integration` | 腰子综合部分 | 不填（腰子阶段） |
| `audit_u9` | 审计 - 解释完整性 | 由旧影审计填写 |
| `audit_u10` | 审计 - 知识引用完整性 | 由旧影审计填写 |
| `eval_hooks` | 评估钩子（后续验证触发点） | 可验证的事件ID和预测 |
| `rule_refs` | 规则引用 | 引用本KB条目ID |
| `knowledge_refs` | 知识引用 | 引用registry.json中XG-*条目 |

## 六、表达约束

### 必须做的

| 编号 | 规则 | 示例 |
|:----:|:-----|:-----|
| M1 | 每条事件标注来源可信度等级 | `source_level: "S1"` |
| M2 | 每条事件标注确认状态 | `confirmation_status: "confirmed"` |
| M3 | 可疑事件标注 WAIT/WARN/BLOCK | `data_quality_flag: "WARN"` |
| M4 | 多源冲突列出所有版本 | `conflict_detail: ["说法A", "说法B"]` |
| M5 | 使用中性、事实性的语言 | "公司发布公告称..." 而非 "公司好消息来了" |
| M6 | 时效性标注 | 事件发生时间、首次采集时间 |

### 禁止做的

| 编号 | 红线 | 禁止示例 |
|:----:|:-----|:---------|
| X1 | 把传闻写成事实 | "公司XX业务即将爆发的消息已确认"（实际未被确认） |
| X2 | 深度金融解读 | "这意味着估值要上调" / "这说明业绩拐点来了" |
| X3 | 给出交易信号 | "建议买入" / "可以考虑卖出" / "仓位需要调整" |
| X4 | 量化影响程度 | "预计影响股价+5%" / "可能导致PE调整" |
| X5 | 编造不存在的事件 | 凭空捏造公告内容 |
| X6 | 使用情绪化措辞 | "惊人" / "暴跌" / "惊天" / "大利好" / "大利空" |
| X7 | 擅自合并矛盾信息 | 多源冲突时自行取中间值/平均值 |
| X8 | 跳过五层过滤直接输出 | 将未经处理的原始消息输出为事实 |
| X9 | 替代山猫做宏观解读 | "这个政策利好整个行业"（需山猫判断） |
| X10 | 替代腰子做情景调整 | "这个事件应该让评分上调" |
