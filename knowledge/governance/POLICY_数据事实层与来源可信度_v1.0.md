# 数据事实层与来源可信度 v1.0

> **本政策定义数据事实层在全项目中的角色、来源可信度等级体系、以及各角色对数据事实的使用规范。**
> 核心原则：数据事实层是项目知识的基础层，保证其他角色使用的数据可追溯、可验证、可审计。
> 生效日期：2026-06-10
> 维护人：玉夜 | 审计人：旧影

---

## 1. 数据事实层的定位

### 1.1 什么是数据事实层

数据事实层是项目知识体系的基础层，负责：
- 判断数据来源的可靠性
- 确认字段口径和单位
- 检查数据时效性和新鲜度
- 识别缺失和异常
- 裁决多源冲突
- 标注数据可信度
- 给出降级或 BLOCK 决策

### 1.2 数据事实层的产出

数据事实层**输出**的是：
- 已确认的数据事实（字段值、口径、来源、时点）
- 来源等级和可信度标注
- 缺失/冲突/异常的警告
- 是否可支撑分析的结论

数据事实层**不输出**的是：
- 投资建议或交易决策
- 信号解释或因子评估
- 风险动作建议
- 最终金融结论

### 1.3 数据事实层与其他层的关系

```
数据事实层（玉夜）        ← 数据能不能用、可信等级
    ↓
策略信号层（青山）        ← 信号有没有效、因子解释
    ↓
风险边界层（流金）        ← 风险在不在边界内
    ↓
金融决策层（腰子）        ← 最终金融判断
```

下层为上层提供输入，但下层不得越界做上层的判断。

## 2. 来源可信度五级体系

### 2.1 分级定义

| 等级 | 名称 | 定义 | 示例 |
|:-----|:-----|:-----|:------|
| L1 | 项目铁律/已验证canonical | 项目内已验证、通过一致性闸门检查的权威数据 | baseline_registry, D04 L1/L2 |
| L2 | 官方事实 | 官方披露/交易所/监管机构/财报公告 | 交易所行情、财报 |
| L3 | 项目已验证外部数据源 | 项目内长期使用的第三方数据源 | 腾讯行情、东方财富、北向 |
| L4 | 临时/未验证数据 | 非标准接入、首次使用的来源 | 新API接口、临时抓取 |
| L5 | 大模型推断/人工口述 | 无数据源支持的事实断言 | LLM数值推断、未确认口述 |

### 2.2 核心规则

1. **L1-L3 可作为分析输入**，但具体使用方式由消费角色自行判断
2. **L4 默认不可支撑分析**，必须标注原因和临时性
3. **L5 强制不可支撑分析**，不得作为数据事实输出
4. **L5 若要升级为 L3**，需要经过：来源登记 → 项目验证 → 玉夜确认 → 腰子终审 → 旧影审计
5. 来源等级不自动决定 data_confidence，data_confidence 还受 freshness、冲突状态等因素影响

## 3. 各角色对数据事实的使用规范

### 3.1 青山（策略研究员）
- 消费玉夜输出的数据事实作为信号判断输入
- 不得质疑已由玉夜确认的数据事实（除非发现明显错误）
- 发现数据问题时，反馈给玉夜而非自行修正

### 3.2 腰子（金融业务负责人）
- 消费玉夜输出的数据事实包作为金融分析输入之一
- 玉夜 BLOCK 数据时不得强行使用不可靠数据

### 3.3 流金（风控官）
- 消费玉夜输出的数据事实作为风控决策输入
- 风控阈值涉及的字段口径以玉夜标注为准

### 3.4 信鸽（信息采集员）
- 事件类的事实采集结果经玉夜确认后才可作为数据事实
- 信鸽提供原始事件文本，玉夜判断结构化后的字段是否可用

### 3.5 旧影（审计官）
- 审计数据事实层的 source_level 标注是否准确
- 检查玉夜是否遵守"大模型推断不能作为事实源"规则
- 审计数据事实层与其他层的边界是否清晰

## 4. 数据事实层的变更流程

### 4.1 日常更新
- 数据源的新增/退役 → 玉夜更新 `02_数据源与事实层分级.md` + registry.json
- 数据契约条款变更 → 玉夜同步更新相关模块的引用
- 时效性SLA变更 → 玉夜更新 `04_时效性缺失异常与降级规则.md`

### 4.2 知识进化
数据事实层核心知识的变更必须走以下流程：

```
数据异常/事实复核/外部资料/后评估 → 写入六库记录
       ↓
积累多次一致证据（≥3次同类型异常/≥20个样本）
       ↓
玉夜评估 → 提出知识更新候选
       ↓
角色确认
       ↓
腰子终审（涉及金融口径时）
       ↓
旧影审计
       ↓
更新玉夜知识库 + registry.json
```

### 4.3 禁止行为
- ❌ 不得在巡检过程中直接修改玉夜核心知识库
- ❌ 不得因单次数据异常立即改写玉夜知识库规则
- ❌ 不得因外部资料原文直接塞入玉夜知识库
- ❌ 不得让大模型"总结"后直接写入玉夜知识库

## 5. 与六库的关系

六库（信号胜率库/后评估库/反例库/参数库/来源等级库/模板污染库）与数据事实层的关系：

- **来源等级库**：与数据事实层的 L1-L5 体系重合，来源等级库为项目级标准，数据事实层为其具体应用
- **后评估库**：数据质量问题的后评估记录可写入后评估库
- **反例库**：数据源故障和异常的历史记录可写入反例库

数据事实层不直接依赖六库中的其他库（信号胜率库、模板污染库与玉夜无关）。
