# 知识来源分层与权威等级 v1.0

> **本政策定义角色知识库中所有知识的来源等级体系。**
> 所有角色核心知识必须标注来源类型和权威等级，未经分层标注的知识不得进入角色知识库。
> 生效日期：2026-06-10
> 维护人：青山 | 审计人：旧影 | 终审人：腰子

---

## 1. 核心原则

### 1.1 大模型自身能力的边界

大模型在角色知识系统中承担以下角色：
- **通用理解**：解析自然语言、理解问题上下文
- **归纳与比较**：从多个来源提炼共性、识别差异
- **表达组织**：将角色知识转化为规范的输出格式
- **候选提出**：基于现有知识提出可能的更新方向

**大模型能力不可替代以下环节：**
- 外部权威资料的首次采集与核验
- 项目实证数据的获取与验证
- 角色共识的协商与确认
- 腰子的最终审批
- 旧影的独立审计

**大模型临时推理不可单独作为稳定知识来源。**
大模型输出若要进入角色知识库，必须经历：候选提出 → 来源补强 → 角色确认 → 腰子审批 → 旧影审计的完整流程。

### 1.2 四类来源的权威顺序

| 优先级 | 来源类型 | 说明 | 可单独进核心知识？ |
|--------|---------|------|-------------------|
| 1 (最高) | external_authority | 外部权威资料 | 否，需浓缩标注 |
| 2 | project_verified | 项目已验证经验 | 是，需角色确认 |
| 3 | role_consensus | 角色共识规则 | 是，需记录参与角色 |
| 4 (最低) | model_candidate | 大模型临时推理 | 否，必须转化为可验证候选 |

### 1.3 通用规则
1. 所有角色核心知识必须标注 `source_type`。
2. `model_candidate` 不得单独成为核心知识，必须先转换为可验证候选。
3. 外部文献原文不得直接塞入角色知识库，必须经过浓缩、标注来源、设定复审日期。
4. 项目验证经验必须有后评估记录、归因记录和角色确认记录作为依据。
5. 角色共识规则必须记录参与角色、确认日期、适用范围和复审日期。
6. 来源等级（L1-L5）与来源类型（source_type）是正交维度，知识条目必须同时标注两者。

## 2. 来源等级体系（L1-L5）

### 2.1 L1 — 项目铁律

**定义**：项目运作的刚性规则，违反即产生实际风险（资金损失、合规违规、流程失效）。

**来源**：
- 项目宪法（`docs/constitution.md`）
- 金融铁律（`金融铁律/金融铁律_v1.17.md`）
- 一级事件规则（`events/event_rules.yaml`）
- 红线审查规则

**特征**：
- 不可争议，不可绕过
- 属于项目层面约束，不归角色自由裁量
- 修改须经 L3 升级

**can_support_strong_action**：true（铁律本身就是动作依据）

### 2.2 L2 — 已验证项目共识

**定义**：经项目内多次实证验证、角色确认、腰子审批、旧影审计的知识。

**来源**：
- 经过完整知识进化流程（后评估 → 候选 → 多次验证 → 角色确认 → 腰子终审 → 旧影审计）的知识
- 样本量达标的信号胜率实证结果（门槛见信号胜率库标准）
- 经后评估确认3次以上且无反例的策略规则
- 经灰度测试验证的参数和阈值

**特征**：
- 可支持动作升级
- 可作为正式分析依据
- 修改须经版本记录和角色确认
- 有失效退出的触发条件

**can_support_strong_action**：true（须经项目验证，且只能支持已验证范围内的动作）

### 2.3 L3 — 外部权威资料

**定义**：来自可审计外部来源的专业知识，经角色浓缩和标注后入库。

**来源**：
- 教材、学术论文、因子研究文献
- 交易所制度文件、证监会规则
- 财务分析框架、风控方法框架
- 宏观研究框架、数据质量理论
- 已出版的行业研究方法和框架

**特征**：
- 有出处、版本、日期、适用范围标注
- 进入核心知识前必须经角色浓缩和标注
- 必须有复审日期

**can_support_strong_action**：false（默认；除非有项目验证补充，或腰子特批）

### 2.4 L4 — 角色共识规则

**定义**：由角色协作形成的阶段性共识规则，尚未经过完整项目验证。

**来源**：
- 多角色讨论后形成的一致意见
- 基于现有资料和经验的合理推断
- 角色协作中确认的行为规范和约束

**特征**：
- 必须记录参与角色、确认日期
- 必须设定复审日期
- 适用范围受参与角色覆盖范围限制
- 不可单独作为动作升级依据

**can_support_strong_action**：false

### 2.5 L5 — 经验假设 / 种子估计

**定义**：基于有限经验、外部参考、大模型推理形成的估计或假设。

**子类型 L5-seed**：种子估计，尚未经过任何形式验证的初始假设。

**来源**：
- 大模型通用知识推理（model_candidate 的默认等级）
- 外部资料中未经验证的参考值
- 未达到项目实证门槛的观察和推断
- 初始种子数据（信号胜率初始值、默认参数等）

**特征**：
- L5 默认 cannot_support_strong_action
- L5-seed 强制 cannot_support_strong_action
- 必须升级为 L2 或 L3 后才能支持动作
- 必须标注升级条件
- 不可作为正式分析的主要依据

**can_support_strong_action**：
- L5：false（默认）
- L5-seed：**强制 false**

## 3. 来源类型定义

### 3.1 external_authority（外部权威资料）

**来源范围**：
- 学术文献、教材、专著
- 监管规则、交易所制度、行业标准
- 权威机构发布的框架和方法论
- 经过同行评议的研究成果

**入库要求**：
```
source_ref: 出处（文献名/规则文号/URL）
version: 版本号或日期
scope: 适用范围（市场/行业/时间）
review_date: 复审日期
extracted_by: 提炼角色
```

**限制**：
- 原文不得直接塞入角色知识库
- 必须经过角色浓缩，标注关键结论
- 须声明适用范围和已知局限性
- 默认不得支持强动作

### 3.2 project_verified（项目已验证经验）

**来源范围**：
- 经过后评估的信号胜率实证
- 模拟交易验证的参数和策略
- 周报/日报中经过归因确认的判断规律
- 错误归因后确认的失败模式
- 经多次验证的知识进化候选

**入库要求**：
```
evidence_ref: 实证记录路径（日报/后评估/KUC ID）
sample_count: 样本量
verification_period: 验证期间
confirming_roles: 确认角色列表
confirmed_by: 角色确认人
approved_by: 腰子（如适用）
audited_by: 旧影（如适用）
```

**限制**：
- 必须有后评估记录作为依据
- 单次观测不能直接升级为核心知识
- 样本量低于门槛时只能作为参考

### 3.3 role_consensus（角色共识规则）

**来源范围**：
- 多角色讨论后形成的协作规则
- 角色间分工和边界共识
- 阶段性行为约束

**入库要求**：
```
participating_roles: [角色列表]
confirm_date: 确认日期
scope: 适用范围
review_date: 复审日期
consensus_log: 共识形成过程记录（可选）
```

**限制**：
- 适用范围限于参与角色的覆盖范围
- 超出参与角色的建议需相关角色确认
- 属阶段性内容，到期须复审

### 3.4 model_candidate（大模型临时推理）

**来源范围**：
- 大模型基于上下文提出的分析和建议
- 临时整理的未验证规律
- 表达层面的组织建议

**限制**：
- **不可单独作为核心知识**
- 若要入库，必须转化为可验证候选
- 必须补强来源（external_authority 或 project_verified）
- 补强前状态只能为 candidate，不得为 core
- 必须标注升级条件

## 4. 等级与类型的交叉规则

| source_type \ status | core | reference | candidate | deprecated |
|---------------------|------|-----------|-----------|------------|
| external_authority | 可 | 可 | 可 | 可 |
| project_verified | 可 | 可 | 不适用 | 可 |
| role_consensus | 可 | 可 | 不适用 | 可 |
| model_candidate | 禁止 | 可（标注） | 可 | 不适用 |

## 5. 升级路径

### 5.1 model_candidate → external_authority
1. 找到对应外部权威资料作为依据
2. 更新 source_type 和 source_ref
3. 角色确认
4. 设置复审日期

### 5.2 model_candidate → project_verified
1. 提出可验证假设
2. 设计验证方案（回测/后评估/模拟交易）
3. 收集实证数据
4. 样本量达标后由角色评估
5. 角色确认 → 腰子审批 → 旧影审计

### 5.3 L5-seed → L2
1. 在项目中收集实证数据
2. 样本量达到信号胜率库设定的门槛
3. 后评估确认
4. 青山提出升级候选
5. 腰子审批
6. 旧影审计
7. 更新 registry.json 中的等级和状态

### 5.4 L3 → L2
1. 在项目中验证外部知识在 A 股环境中的适用性
2. 项目验证达标
3. 角色确认
4. 更新 source_type 为 project_verified 或保留 external_authority + 补充 project_verified 记录

## 6. 审计要求（U-9 / U-10）

**U-9 知识来源可审计性检查**：
每条核心知识必须可追溯至来源记录。
若无法追溯来源，该知识自动降级为 model_candidate。

**U-10 知识等级与动作支持一致性检查**：
- L5 / L5-seed 的知识不得支持强动作
- model_candidate 的知识不得支持强动作
- external_authority 的知识若需支持强动作，必须有项目验证补强
- 检查 registry.json 中每条知识的 can_support_strong_action 与来源等级的一致性
