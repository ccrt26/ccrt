## 二、数据格式规范审计

### 2.1 JSON规范

#### 2.1.1 BOM问题

| 文件 | 编码 | BOM | 备注 |
|:-----|:-----|:---:|:-----|
| data_final.json | UTF-8 | **有** | JSON规范不推荐BOM，Python json.load()默认失败 |
| data_scored.json | UTF-8 | **有** | 同上 |
| data_full.json | UTF-8 | **有** | 同上 |
| dynamic_pool.json | UTF-8 | **有** | 同上 |
| stock_data_raw.json | UTF-8 | **有** | 同上 |

**风险**: 所有核心数据JSON文件带BOM。PowerShell `-Encoding UTF8` 自动处理BOM所以无感知，但Python `json.load()` 默认失败需指定 `utf-8-sig`。跨工具链兼容性风险。

#### 2.1.2 字段命名一致性

| 文件 | 命名风格 | 混合情况 |
|:-----|:--------|:--------|
| data_final.json | **PascalCase为主** | 6个snake_case字段: `S_News, S_Tech, S_Base, S_Fund, S_Risk, S_Money` |
| data_scored.json | **PascalCase为主** | 1个snake_case: `data_quality` |
| data_full.json | **纯PascalCase** | 无混合 |
| dynamic_pool.json | **纯PascalCase** | 无混合 |
| stock_data_raw.json | **纯PascalCase** | 无混合 |
| unified_market_data.schema.json | **纯snake_case** | 无混合 |

**结论**: data_final.json 的6个 `S_` 前缀字段是子评分维度，属于有意义的命名约定。总体来说，核心数据文件以PascalCase为主流，schema文件用snake_case。存在两种风格并存的问题，但不影响功能——因为同一文件内部是一致的一一data_final.json的混用也是内部统一的(S_前缀约定)。

### 风险2: 37个脚本硬编码绝对路径 — 严重度: 高 (D1)

| 属性 | 描述 |
|:-----|:-----|
| **现象** | 41处 `C:\Users\34269` 硬编码分布于37个脚本，包括核心调度脚本daily_workflow.ps1。 |
| **影响** | 换用户/换机器/重装系统=项目全面瘫痪。Git clone到新环境后零脚本可用。 |

### 风险3: L3事件驱动告警完全缺失 — 严重度: 中高 (D1-D2)

| 属性 | 描述 |
|:-----|:-----|
| **现象** | 无任何数据异常自动告警机制。数据源降级/缓存大规模过期/评分结果异常——均静默发生。 |
| **影响** | 数据可在两个审计周期间(最长7天)持续退化而不被发现，可能产生基于劣质数据的交易决策。 |
| **最大风险** | 非交易日(如连续假期)期间无人巡检，数据质量问题积累到交易日集中爆发。 |
| **修复建议** | Phase 1: 在关键路径(check_data_quality.ps1被调用处)对FAIL结果添加终端告警输出(红色高亮+exit非零)。Phase 2: 实现邮件/日志标记通知。 |

### 风险4: 错误知识库空洞 — 严重度: 中 (D2)

| 属性 | 描述 |
|:-----|:-----|
| **现象** | `.claude/knowledge/常见错误.md` 仅1个种子案例(PE直接用于否决)。5个已登记的缺陷台账全为代码拆分bug，无数据质量类。 |
| **影响** | 数据质量类错误(如API返回异常值未拦截、缓存静默过期导致陈旧PE用于评分)发生后不会沉淀为组织知识，同类错误必然重复。 |
| **最大风险** | 新团队成员(或新Agent上下文)无法从历史中学习，每次数据异常都像首次遇到。 |
| **修复建议** | 每次新安/旧影发现数据质量问题时，同步在常见错误.md中登记(标签:`#数据`)。每月旧影审计时检查入库率>=80%。 |

### 风险5: JSON文件BOM与跨工具兼容性 — 严重度: 中低 (D2-D3)

| 属性 | 描述 |
|:-----|:-----|
| **现象** | 所有核心数据JSON文件带UTF-8 BOM。PowerShell无感知，Python `json.load()` 默认失败。 |
| **影响** | 当任何Python工具(如后评估脚本、月度学习脚本)直接读取这些JSON时，会遇到 `JSONDecodeError: Unexpected UTF-8 BOM`。 |
| **最大风险** | 评分引擎(Python)写入评分数据时，如果上游JSON带BOM，可能导致解析链路断裂。 |
| **修复建议** | 标准化JSON输出: PowerShell使用 `-Encoding UTF8NoBOM`(PS 7+)或 `[System.Text.UTF8Encoding]::new($false)`(PS 5)。Python写入时用 `encoding='utf-8'`(默认无BOM)。 |
