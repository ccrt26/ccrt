## Phase 2：核心拆分 + 验证（1-2 周内完成）

### 2.1 评分引擎拆分

| 项 | 内容 |
|:--|:-----|
| 执行人 | 红结（编码），情墨（监督边界） |
| 输入 | Phase 1.1 依赖分析结果 |
| 产出 | `engine/` 包，8 个 .py 文件 |
| 拆分表 | |

| 文件 | 来源区块 | 等级 | 预计行数 |
|:-----|:--------|:----:|:----:|
| `__init__.py` | — | — | ~15 |
| `theme.py` | 题材三分类+PE估值 | L1 | ~250 |
| `technical.py` | 技术指标 | L0 | ~80 |
| `sector.py` | 板块相位+动量 | L1 | ~400 |
| `veto.py` | 否决体系+市场状态 | **L2** | ~300 |

**硬性要求**：
- `veto.py` 每条否决规则带红线条款编号注释（腰子+流金 要求）

- 依赖方向单向：`engine → scores → {theme, technical, sector, veto, subscores}`

### 2.3 Golden Master diff 验证

| 项 | 内容 |
|:--|:-----|
| 执行人 | 新安 |
| 方法 | 拆分后的 `engine/` 包跑同样 5 天输入，输出与 Golden Master 逐行 diff |
| 验收标准 | 评分/排序/否决标记/相位分类 **四项完全一致** |
| 不一致处理 | 打回 红结，修复后重跑，直到完全一致 |
| diff 结果 | 存入 `审计报告/golden_master/diff_results/` |

### 2.4 边界注入测试

| 项 | 内容 |
|:--|:-----|
| 执行人 | 新安 |
| 注入场景 | PE=0/负数、换手率极端值、收盘价缺失、单股票板块、全否决、零否决 |
| 验收标准 | 不崩溃、不除零、不误杀、不误放 |
| 结果 | 写入缺陷台账（如有发现） |

### 2.5 流金 风控复核

| 项 | 内容 |
|:--|:-----|
| 执行人 | 流金 |
| 对象 | `engine/veto.py`（L2） |
| 方法 | 逐条对照规则红线原文，核验代码中的阈值、判断符号、否决条件 |
| 验收标准 | 所有否决规则有红线编号注释，代码逻辑与规则原文一致 |
| 发现偏差 | 标 B1 级缺陷，暂停该模块上线，红结 修复后重检 |

### 2.6 并跑验证

| 项 | 内容 |
|:--|:-----|
| 执行人 | 新安（每日执行），阿黑（监督） |
| 方法 | 拆分完成后，原版和新版并行跑 **连续 3 个真实交易日** |
| 每日产出 | 两版输出 diff 报告 |
| 验收标准 | 连续 3 天 100% 一致 → 切换新版 |
| 不一致 | 停切，排查原因，修复后重新计数 3 天 |
