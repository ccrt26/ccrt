## 零、设计摘要

### 0.1 现有架构的核心问题

```
当前:  评估数据 → sim_trading.ps1(全自动规则) → 交易流水
                    ↑
              腰子的分析被隔离开，无法介入
```

| 问题 | 影响 |
|:-----|:-----|
| 腰子分析结果无法注入引擎 | 深度分析报告写了白写，引擎不认 |
| 团队协作(山猫→玉夜→流金→青山→腰子)与交易脱节 | 分析是分析，交易是交易，两层皮 |
| 无策略演进闭环 | 交易结果不反馈回分析逻辑优化 |
| 无决策审计 | 不知道为什么买、为什么卖、谁决定的 |
| 引擎规则僵化 | 固定P1-P5规则，无法响应市场变化 |
| GitHub Actions `git add -A` 核弹提交 | 临时文件/日志/无关变更混入交易commit |
| 引擎崩溃后继续commit/push | 损坏数据被推送到仓库 |
| 无并发锁 | scheduled+workflow_dispatch可同时触发损坏数据 |
| 两引擎独立运行无协调 | Key stock和Daily rec各自资金池，无统一视图 |
| 数据降级静默 | 评估数据缺失时用旧数据，GitHub Actions不告警 |

### 0.2 新架构六层模型

```
┌─────────────────────────────────────────────────┐
│  ⑥ 演进层: 后评估 → 知识积累 → 策略迭代          │
├─────────────────────────────────────────────────┤
│  ⑤ 展示层: 持仓仪表盘 + 交易历史 + 绩效曲线       │
├─────────────────────────────────────────────────┤
│  ④ 记录层: 交易流水 + 决策日志 + 分析快照         │
├─────────────────────────────────────────────────┤
│  ③ 执行层: sim_trading.ps1(安全网) + 腰子指令通道 │
├─────────────────────────────────────────────────┤
│  ② 分析层: 山猫→玉夜→流金→青山→腰子(综合决策)    │
├─────────────────────────────────────────────────┤
│  ① 数据层: 行情 + K线 + 财务 + 评估数据(1+2架构)  │
└─────────────────────────────────────────────────┘
```

### 0.3 核心设计决策

| 决策 | 内容 |
|:-----|:-----|
| **腰子指令 > 自动化规则** | 腰子明确指令优先执行；无指令时由自动化规则兜底 |
| **止损不可覆盖** | P1止损和P2趋势恶化是硬安全网，腰子也不能取消（只能更早卖） |
| **分析→决策强绑定** | 腰子每笔决策必须附团队分析摘要（哪个角色说了什么） |
| **两阶段执行** | 阶段1: 腰子盘前/盘后做决策(任意时间) → 阶段2: 引擎盘中执行(09:35) |
| **策略演进闭环** | 交易结果 → 归因分析 → 知识积累 → 分析逻辑优化 → 更好的决策 |

## 二、分析层 — 团队协作强制流程

### 2.1 分析触发场景

| 场景 | 触发条件 | 涉及角色 | 产出 |
|:-----|:--------|:--------|:-----|
| **每日复盘** | 每个交易日收盘后 | 全员 | 次日交易指令 |
| **开仓分析** | 选股池出现新标的 | 山猫→玉夜→流金→腰子 | 开仓决策 |
| **持仓审视** | 现有持仓需要调仓 | 流金→青山→腰子 | 调仓/清仓决策 |
| **风险事件** | 市场极端波动/黑天鹅 | 山猫→流金→腰子 | 紧急响应 |

### 2.2 强制团队流程（不可跳过）

```
腰子收到分析任务
    │
    ▼
① 山猫: 宏观/政策/情绪/事件风险判断
    │
    ▼
② 玉夜: 数据可用性确认 + 1+2合规 + 降级路径
    │
    ▼
③ 流金: 风险评估 + 红线边界 + 持仓约束
    │
    ▼
④ 青山: 策略维度 + 因子信号 + 后评估规律
    │
    ▼
⑤ 腰子: 综合四角色意见 → 输出交易决策
    │
    ▼
写入 交易指令_YYYYMMDD.json
```

## 三、执行层 — 腰子指令 + 自动化安全网

### 3.1 执行优先级（核心设计）

```
        ┌──────────────────────────────┐
        │  优先级 (高→低)               │
        ├──────────────────────────────┤
        │  P1 止损 (硬安全网,不可覆盖)   │
        │  P2 趋势恶化 (硬安全网,不可覆盖)│
        │  腰子卖出指令 (人工决策优先)    │  ← 新增
        │  腰子买入指令 (人工决策优先)    │  ← 新增
        │  P0 黑天鹅减仓                 │
        │  P3 预判转空                    │
        │  P4 全部止盈                    │
        │  P5 止盈减仓                    │
        │  自动开仓规则 (腰子无指令时兜底) │
        └──────────────────────────────┘
```

**关键规则**：
- 腰子指令在止损/趋势恶化之下（安全第一）
- 腰子指令在自动规则之上（人工判断优先于机械规则）
- 腰子不能取消止损，但可以**提前**卖出（比止损价更高的位置退出）
- 无腰子指令时，自动规则照常运行（兜底）

### 3.3 指令生命周期

```
pending → queued(引擎已读取) → executed(已执行) → verified(后评估已确认)
                                      ↘ rejected(无法执行:涨停/跌停/停牌)
                                      ↘ expired(过期:跨日未执行)
```

### 3.4 sim_trading.ps1 改造要点

| 改造点 | 当前 | 新 |
|:-----|:-----|:---|
| 数据输入 | 仅评估数据JSON | 评估数据 + 腰子指令JSON |
| 开仓逻辑 | 全自动评分→仓位 | 腰子指令优先，无指令才自动 |
| 卖出逻辑 | P1-P5固定优先级 | P1+P2硬安全网 → 腰子指令 → P3-P5 |
| 交易理由 | reason字段固定格式 | reason = 腰子原话 (或 "自动_规则名") |
| 执行标记 | 无 | 每笔标注 `manual`(腰子) / `auto`(自动) |

### 3.5 两阶段执行时序

```
【阶段1 — 盘后分析】任意时间(通常18:00-24:00)
  ① run_keystock_analysis.ps1 → 生成评估数据_YYYYMMDD.json
  ② 山猫→玉夜→流金→青山 顺序输出
  ③ 腰子综合 → 输出 交易指令_YYYYMMDD.json
  ④ git commit + push → GitHub

【阶段2 — 盘中执行】T+1 日 09:35
  ⑤ GitHub Actions 拉取最新代码(含指令)
  ⑥ sim_trading.ps1 运行:
     - 读取评估数据 + 腰子指令
     - P1/P2 安全网检查(不可跳过)
     - 执行腰子指令
     - 无指令部分走自动规则
  ⑦ 输出交易流水 + 更新持仓 + 绩效报告
  ⑧ git commit + push 结果 → 本地拉取查看
```

## 六、演进层 — 策略迭代闭环

### 6.1 闭环流程

```
交易执行 → 记录结果 → 后评估归因 → 知识积累 → 策略优化
    ↑                                                    │
    └────────────────────────────────────────────────────┘
```

### 6.2 后评估对接

| 评估维度 | 数据来源 | 分析内容 |
|:--------|:--------|:--------|
| 腰子决策准确率 | 交易指令 + transactions.csv | 手动决策的胜率 |
| 自动规则vs腰子对比 | source字段 | 人和机器的表现差异 |
| 团队分析有效性 | analysis_ref字段 | 哪个角色的判断最准 |
| 策略衰减检测 | 连续交易记录 | 策略是否需要迭代 |
| 参数优化建议 | 止盈止损触发记录 | R2/R3/止损距离调整 |

### 6.3 知识积累路径

```
交易记录
  ├── 成功的决策 → 提取模式 → 固化到分析逻辑
  ├── 失败的决策 → 归因分析 → 更新规避清单
  └── 自动规则触发 → 评估有效性 → 保留/修改/废弃
```

### 6.4 触发策略迭代的条件

| 条件 | 级别 | 动作 |
|:-----|:---:|:-----|
| 腰子决策连续3次亏损 | L1 | 审视决策流程 |
| 自动规则连续5次亏损 | L2 | 修改规则参数 |
| 人和机器同时亏损 | L2 | 审视市场环境或方法论 |
| 某角色分析被腰子连续推翻 | L1 | 审视该角色判断框架 |
| 腰子胜率<40%(≥10笔) | L3 | 全面方法论审视 |
