## 一、系统概述

### 1.1 定位

每日荐股模拟交易系统是铁律量化体系的**广谱策略验证主阵地**。

与重点股票模拟系统（深度验证）的关系：

```
每日荐股模拟（广谱验证）          重点股票模拟（深度验证）
├─ 候选池: 25-40只/日             ├─ 候选池: 6只固定
├─ 数据深度: 评分+技术指标          ├─ 数据深度: +KeyLevels+TrendHealth
├─ 交易频率: 高（日换手2-3只）      ├─ 交易频率: 低（周换手1-2只）
├─ 目标: 验证评分体系整体有效性      ├─ 目标: 验证深度分析择时能力
├─ 样本积累: 2-4周即有意义         ├─ 样本积累: 3-6个月
└─ 共享: 组合风控框架 + 归因方法论 + 绩效指标体系
```

### 1.2 目标

1. **快速验证评分体系**：以 25-40 只/日的候选池，快速积累交易样本，统计评分与实际收益的相关性
2. **因子有效性量化**：通过盈亏归因，识别哪些评分子维度真正贡献正收益
3. **策略参数寻优**：利用高周转率快速迭代止损/止盈/仓位参数
4. **为深度分析提供方向**：哪些板块/题材/评分段表现优异，指导重点股票的选池方向

### 1.3 适用股票范围

每日荐股流程输出的全部通过筛选的股票（data_scored.json 中 Recommendations 数组，通常 25-41 只），不预设固定股票池。

### 1.4 非目标

- 不接入真实交易接口
- 不做日内高频交易
- 不做融资融券模拟
- 不修改每日荐股评分体系的任何代码
- 不新增外部 API 依赖

## 二、交易规则

### 2.1 开仓条件

开仓需同时满足以下全部条件：

| 序号 | 条件 | 规则 | 数据来源 |
|:----:|:-----|:-----|:---------|
| 1 | 评分门槛 | TotalScore >= 55 | data_scored.json TotalScore |
| 2 | 多头排列 | MA5 > MA10 > MA20 | data_scored.json MA5/MA10/MA20 |
| 3 | RSI 非超买 | RSI < 75 | data_scored.json RSI |
| 4 | 未涨停 | ChangePct < 9.4%（主板）/ 19.4%（创业板/科创板） | data_scored.json ChangePct |
| 5 | 流动性 | TurnoverRate >= 1.5% | data_scored.json TurnoverRate |
| 6 | 板块过滤 | SectorPhase ≠ "衰退期" | data_scored.json SectorPhase |
| 7 | 量能正常 | VolRatio >= 0.5 | data_scored.json VolRatio |
| 8 | 未持仓 | 该股票当前无持仓 | positions_daily.json |
| 9 | 仓位上限 | 总持仓 <= MaxPositions(5只) | sim_config_daily.json |
| 10 | 止损冷却期 | 过去 CooloffPeriodDays(5日)内未触发止损 | positions_daily.json LastStopLossDate |
| 11 | 止盈冷却期 | 过去 FullTakeProfitCooldownDays(3日)内未触发 P4 止盈 | positions_daily.json LastFullTakeProfitDate |

### 2.2 多股选股优先级

当同时满足开仓条件的股票数量超过最大持仓限制(5只)时，按以下优先级依次选取：

| 优先级 | 因子 | 规则 |
|:------:|:-----|:-----|
| P1 | TotalScore | 评分高者优先 |
| P2 | SectorPhase | 高潮期 > 主升调整 > 潜伏期（衰退期已在开仓条件中过滤） |
| P3 | S_Tech | 同评分时，技术面得分高者优先 |
| P4 | 代码顺序 | 以上均相同，按代码排序取前 N 只 |

**SectorPhase 排序映射**：

| SectorPhase | 排序值（高优先） |
|:-----------|:---------------:|
| 高潮期 | 3 |
| 主升调整 | 2 |
| 潜伏期 | 1 |
| 衰退期 | 0（不予开仓） |

### 2.3 仓位管理

仓位比例根据 TotalScore 分档确定：

| TotalScore 区间 | 仓位比例（占现金%） | 说明 |
|:---------------:|:------------------:|:-----|
| >= 78 | 20% | 高分，重点配置 |
| >= 65 | 15% | 中高分，正常配置 |
| >= 55 | 10% | 及格，轻仓试探 |
| < 55 | 0% | 不参与 |

**仓位计算规则**：
- 仓位比例 = 占**当前现金**的百分比
- 买入股数向下取整到 100 股（一手）
- 单只股票买入金额不超过总资产的 SingleStockLimitPct(20%)
- 若计算所得股数不足 100 股，跳过该股开仓

### 2.4 入场价格

1. **优先使用开盘价**：腾讯行情 API 返回的当日开盘价
2. **兜底**：开盘价不可用时，使用 data_scored.json 的 Price 字段（昨日收盘价）
3. **滑点**：入场价 × (1 + SlippagePct)，默认 0.1%

**引擎运行时序**：

```
T日 15:00   市场收盘
T日 20:00   每日荐股流程完成 → data_scored.json 生成
T+1 09:25   集合竞价结束，开盘价确定
T+1 09:35   引擎运行（开盘5分钟后，确保行情API稳定）
```

- 超过 09:45 未运行 → 跳过当日开新仓，仅执行止损检查
- 节假日/周末静默跳过

### 2.5 出场规则

#### 2.5.1 出场优先级总览

| 优先级 | 出场原因 | 条件 | 操作 | 冷却期 |
|:------:|:---------|:------|:-----|:------:|
| P1 | 止损 | 现价 <= 入场价 × (1 - 8%) | 全部卖出 | 5 交易日 |
| P2 | 趋势破坏 | MA5 下穿 MA20（MA5 < MA20 且前日 MA5 >= MA20） | 全部卖出 | 5 交易日 |
| P3 | 评分恶化 | 最新日 TotalScore < 45 | 全部卖出 | 无冷却 |
| P4 | 止盈 | 现价 >= 入场价 × (1 + 12%) | 全部卖出 | 3 交易日 |
| P5 | 超买减仓 | RSI > 80 持续 2 个交易日 | 卖出 50%（向下取整到 100 股） | 无冷却 |

> **优先级设计理由**：止损(P1)永远是最高优先级——截断亏损比锁定利润更重要。趋势破坏(P2)作为技术面兜底。评分恶化(P3)捕捉基本面崩塌——Daily Scoring 中 TotalScore < 45 意味着多数维度失效。止盈(P4)达到目标后退出。超买减仓(P5)是预防性减仓，不触发冷却期。

#### 2.5.2 P2 MA 下穿确认机制

P2 需要"收盘确认"以避免盘中假突破：

- 引擎 09:35 运行时，使用**前一交易日**的 MA5/MA20 数据判断是否已发生下穿
- MA 数据来源：data_scored.json（收盘后生成，MA 值基于收盘价计算）
- 这引入了最多 1 个交易日的滞后（与 P3 预判转空类似），属于系统固有局限

#### 2.5.3 P3 评分恶化数据源

- 检查条件：在最新的 data_scored.json 中查找该股票的 TotalScore
- 若该股票已不在当日推荐列表中（TotalScore 视为 0），视为评分恶化触发
- 股票从推荐池消失本身就是一个强退出信号

#### 2.5.4 P5 超买减仓

- RSI 数据源：腾讯行情 API 实时 RSI（若有），否则使用 data_scored.json 的 RSI
- "持续 2 日"判断：前一交易日 RSI > 80 且当日 RSI > 80
- 卖出当前持仓的 50%，向下取整到 100 股；若不足 100 股则全卖
- 不触发冷却期

### 2.6 交易费用

A 股真实费率标准：

| 费用类型 | 费率 | 收取方向 | 说明 |
|:---------|:----|:---------|:-----|
| 佣金 | 万分之 2.5 | 买卖双向 | 最低 5 元/笔 |
| 印花税 | 千分之 1 | 仅卖出 | 按卖出金额计算 |

### 2.7 初始参数

| 参数 | 默认值 | 说明 |
|:-----|:------|:-----|
| 初始资金 | 1,000,000 元 | 模拟启动资金 |
| 最大持仓 | 5 只 | 总持仓数量上限 |
| 单股上限 | 20% 总资产 | 单一股票仓位上限 |
| 滑点 | 0.1% | 买卖双向均适用 |
| 止损比例 | 8% | 入场价下方止损距离 |
| 止盈比例 | 12% | 入场价上方止盈距离 |
| 止损冷却期 | 5 交易日 | P1/P2 出场后不可再入场天数 |
| 止盈冷却期 | 3 交易日 | P4 出场后不可再入场天数 |
| 开仓评分门槛 | 55 | TotalScore 最低要求 |

## 三、组合级别风控

### 3.1 四级预警体系

| 级别 | 条件 | 操作 | 恢复条件 |
|:----:|:-----|:-----|:---------|
| 黄旗 | 单日回撤 > 3% | 次日不开新仓 | 单日回撤 < 1% 连续 2 日 |
| 红旗 | 单日回撤 > 5% | 当日全部持仓减仓 50%，停开仓 3 日 | 3 日后 + 回撤 < 1% 连续 2 日 |
| 黑旗 | 累计回撤 > 10% | 暂停系统，全面审查所有规则 | 人工确认后重启 |
| 连败 | 连续亏损 >= 6 笔 | 停开仓，审视信号有效性 | 人工确认后重启 |

### 3.2 红旗减仓执行细节

- 对所有持仓执行 SELL_HALF（向下取整到 100 股）
- 减仓后 3 个交易日内维持停开仓
- 若减仓后再次触发单日回撤 > 5%，继续减 50%（总减 75%）并重置冷却期
- 减仓不触发个股冷却期

### 3.3 预警联动

触发红旗或黑旗时：
- 日志标记级别标签，便于事后检索
- 周报中单独列出预警事件
- 若黑旗触发，同步通知重点股票赛道关注

## 四、数据流

### 4.1 每日运行流程

```
步骤 0: 检测交易日（节假日/周末跳过）
步骤 1: 读取 sim_config_daily.json
步骤 2: 读取 positions_daily.json
步骤 3: 读取 data_scored.json（T-1日收盘后生成）
步骤 4: 数据质量检查
步骤 5: 调用腾讯行情API获取候选+持仓股票实时行情
步骤 6: 计算组合单日净值回撤，检查组合风控条件（§3）
步骤 7: 执行出场检查（按优先级 P1→P2→P3→P4→P5）
步骤 8: 应用出场交易（更新现金、持仓、冷却期）
步骤 9: 执行开仓检查（筛选→排序→仓位计算→开仓）
步骤 10: 写入交易流水 transactions_daily.csv
步骤 11: 更新持仓文件 positions_daily.json
步骤 12: 计算组合净值 → 每日快照 snapshot_daily_YYYYMMDD.json
步骤 13: 更新绩效汇总 perf_summary_daily.json
步骤 14: 写入运行日志 + 控制台简报
```

### 4.3 行情 API 降级

| API 状态 | 开新仓 | 止损检查 | 净值计算 |
|:---------|:------|:--------|:---------|
| 主源正常 | 正常 | 正常 | 正常 |
| 备源可用 | 正常，数据标注 [1B] | 正常 | 正常 |
| 全部不可用 | 跳过开仓 | 用保守估计价 [C] | 用昨日净值 [C] |

## 五、绩效指标

### 5.1 核心指标

| 指标 | 公式 | 说明 |
|:-----|:-----|:-----|
| 总收益率 | (当前净值 / 初始资金 - 1) × 100% | 整体盈利水平 |
| 日收益率 | (当日净值 / 前日净值 - 1) × 100% | 每日波动 |
| 最大回撤 | min(当日净值 / 前期峰值 - 1) × 100% | 组合风险水平 |
| 胜率 | 盈利交易数 / 总交易数 × 100% | 已完整平仓的交易 |
| 连续失败 | 连续净盈亏 <= 0 的交易笔数 | 触发预警 |
| 夏普比率 | 预留，需 >= 20 个交易日 | 风险调整后收益 |
| 超额收益 | 组合总收益率 - 沪深300总收益率 | 相对基准表现 |

### 5.2 每日荐股专属归因指标

| 指标 | 说明 |
|:-----|:-----|
| 评分-收益相关性 | TotalScore 与实际盈亏的 Spearman 秩相关 |
| 子维度贡献度 | S_Fund/S_Tech/S_Money 等 7 维各自与收益的相关性 |
| 板块阶段胜率 | 主升/主升调整/潜伏期 各自的交易胜率 |
| 题材路径表现 | 周期成长/新兴成长/价值防御 各自的盈亏统计 |

### 5.3 自动预警条件

| 条件 | 动作 |
|:-----|:-----|
| 单日回撤 > 5% | 红旗，触发减仓 |
| 单日回撤 > 3% | 黄旗，次日停开仓 |
| 最大回撤 > 10% | 黑旗，暂停系统 |
| 连续亏损 >= 6 笔 | 黄旗，审视信号 |
| 胜率 < 35% 且交易 >= 15 笔 | 黄旗，审视开仓条件 |
| 胜率 < 25% 且交易 >= 30 笔 | 红旗，方法论可能存在问题 |

## 六、策略迭代与归因闭环

### 6.1 归因数据流

```
模拟交易盈亏 → 关联入场时的评分明细 → 统计各维度对盈亏的贡献 → 形成调整建议 → 人工确认 → 更新评分参数
```

### 6.2 归因分析维度

每笔完整平仓后，按以下维度分组统计：

| 归因维度 | 数据来源 | 分析问题 |
|:---------|:---------|:---------|
| TotalScore 分段 | EntryScore | 高评分是否对应高胜率？ |
| S_Fund 贡献 | EntryScoreDetail.S_Fund | 基本面因子是否有区分度？ |
| S_Tech 贡献 | EntryScoreDetail.S_Tech | 技术面因子的最佳阈值？ |
| S_Money 贡献 | EntryScoreDetail.S_Money | 资金面信号是否有效？ |
| SectorPhase | EntrySectorPhase | 哪个板块阶段胜率最高？ |
| ThemePath | EntryThemePath | 哪种题材路线最稳定？ |
| 出场原因 | Reason | 止损/止盈/趋势破坏各占比？ |

### 6.3 三级响应机制

与重点股票系统共享同一套三级响应框架（参见重点股票模拟交易白皮书 §9），根据每日荐股专属基线调整：

| 指标 | 第一级触发 | 第二级触发 | 第三级触发 |
|:-----|:----------|:----------|:----------|
| 连续亏损 | 4 笔 | >= 6 笔 | >= 10 笔 |
| 最大回撤 | > 3% | > 5% | > 10% |
| 胜率（交易 >= 15） | < 45% | < 35% | < 25% |
| 累计亏损 | > 3% | > 7% | > 12% |
| 数据积累 | — | >= 30 笔交易 | >= 100 笔交易 |

### 6.4 复盘周期

| 周期 | 频率 | 内容 | 输出 |
|:-----|:-----|:-----|:-----|
| 日复盘 | 每交易日 | 当日交易执行情况、异常标记 | 日志 |
| 周复盘 | 每周五 | 本周归因：盈亏来源、子维度有效性 | 周报 |
| 月复盘 | 每月末 | 完整绩效 + 策略参数评估 + 评分体系反馈 | 月报 + 参数调整建议 |
| 季复盘 | 每季度 | 系统性审视 + 两赛道对照分析 | 季度报告 |

## 七、涨跌停与特殊处理

### 7.1 涨停

- 检测：ChangePct >= 9.4%（主板）/ 19.4%（创业板/科创板）
- 处理：跳过该股当日开仓，日志记录"涨停跳过"

### 7.2 跌停

- 检测：ChangePct <= -9.4%（主板）/ -19.4%（创业板/科创板）
- 处理：若触发出场条件但跌停，标记"未成交"，持续跟踪至恢复流动性

### 7.3 除权除息

- 使用调整因子法（Ratio = 除权后开盘价 / 除权前收盘价）
- 调整入场价：入场价 × Ratio
- 调整止损/止盈线：止损价 × Ratio、止盈价 × Ratio
- 配置文件：ex_dividend_dates.json（与重点股票共享）

### 7.4 数据质量检查

| 检查项 | 规则 | 失败处理 |
|:------|:-----|:---------|
| TotalScore 范围 | 0 ~ 100 | 跳过该股 |
| Price 有效 | > 0 | 跳过该股 |
| MA 值有效 | MA5/MA10/MA20 均 > 0 | 跳过趋势条件，仅用评分条件 |
| RSI 有效 | 0 ~ 100 | 跳过 RSI 条件 |
| SectorPhase 有效 | 非空 | 跳过板块过滤条件 |
| 必要字段存在 | Code/Name/Price/TotalScore | 跳过该股 |

## 八、风险说明

### 8.1 模拟与实盘差异

与重点股票系统共享同一份差异说明（参见重点股票模拟交易白皮书 §8.1），每日荐股赛道额外关注：

| 差异项 | 每日荐股特有风险 |
|:-------|:----------------|
| 小盘股流动性 | 候选池含创业板/小市值股票，实盘滑点可能远超 0.1% |
| 数据覆盖度 | 部分小票的行情 API 数据可能不完整 |
| 评分稳定性 | 每日荐股评分每天重新计算，同一股票连续两天的评分可能有较大波动 |

### 8.2 已知限制

| 限制 | 说明 |
|:-----|:-----|
| MA 滞后 | P2 趋势破坏依赖 MA 交叉，存在天然滞后 |
| 评分滞后 | P3 评分恶化的数据来自最近一次评分（可能是 T-1 日） |
| 单次入场 | 不支持同一股票分批建仓，每次只能一次性买入 |
| 盘中不可见 | 引擎每日仅运行一次，盘中价格波动不可见 |

### 8.3 免责声明

> 本模拟交易系统仅供策略验证和研究参考，不构成任何投资建议。模拟交易的历史表现不代表未来收益。所有交易决策均基于模型输出，可能存在模型缺陷、数据误差或系统故障导致的偏差。使用者应独立判断并承担全部投资风险。

## 十、与重点股票赛道的关系

### 10.1 共享模块

两个赛道共享以下基础模块（位于 `模拟交易/共享模块/`）：

| 模块 | 功能 |
|:-----|:-----|
| quote_engine.ps1 | 行情获取（1+2架构，腾讯→新浪→缓存） |
| trade_utils.ps1 | 费用计算、交易日计数、涨跌停检测 |
| risk_framework.ps1 | 组合风控（单日回撤/累计回撤/连败检测） |

### 10.2 数据对照

两个赛道的绩效数据定期对照分析：
- 每日荐股的板块表现 → 指导重点股票的选池方向
- 重点股票的深度归因 → 验证每日荐股评分维度的合理性
- 两赛道共同的衰退信号 → 可能是市场结构问题而非策略问题
