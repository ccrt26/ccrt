## 1. 前置结论

### 1.1 本轮的核心判断

不是所有优化都应该改 `深度分析_v1.5.md`。深度分析逻辑.md 只负责一件事——**数据进了报告之后怎么分析、怎么展示**。数据能不能进报告、数据够不够长、外部事实是谁采集的，这些应属于不同的落点。

具体来说：

| 优化类型 | 该不该改深度分析逻辑.md | 该改哪里 |
|:---------|:---------------------|:---------|
| 字段已经在管线里，但分析没有引用 | **是** — 分析模板缺字段 | 深度分析_v1.5.md 的章节模板 |
| 数据长度不够，分析师想用也用不好 | **少量引用** — 先判断长度够不够才决定是否纳入 | L2数据实装 / 缓存策略 / 历史归档 |
| 外部事实（客户订单、产业景气、并购进度）系统内没有 | **部分引用** — 分析中保留入口/指令位 | 信鸽采集 / 日报指令 / 证据等级定义 |

### 1.2 三个文件的分工（画清楚边界）

```
┌──────────────────────────────────────────────┐
│  分析逻辑重构_G1G2口径表_v1.0.md              │
│  （上层逻辑：周报定位、三层结构、状态机）       │
├──────────────────────────────────────────────┤
│  ↓ 定义"需要什么数据"                         │
├──────────────────────────────────────────────┤
│  本文件（数据使用与能力缺口）                    │
│  （桥接：数据已有未用、能力不足、外部缺口）      │
├──────────────────────────────────────────────┤
│  ↓ 判断"质量够不够"    ↓ 分析怎么做            │
├────────────┬─────────────────────────────────┤
│ 数据地基    │ 深度分析_v1.5.md                  │
│ L2实装      │ （数据进报告后的分析展示）          │
│ 缓存/归档   │                                  │
│ 字段契约    │                                  │
└────────────┴─────────────────────────────────┘
```

- **分析逻辑重构口径表**：定义周报为什么写、给谁看、怎么写。
- **本文件（桥接文件）**：梳理"哪些数据有但没用、哪些数据不达标、哪些数据根本没有"。
- **深度分析_v1.5.md**：负责"数据进来之后怎么分析、怎么展示结论"。
- **数据运用优化方案_v1.3.md**：作为数据资产清单和审计结果，被本文件引用但不废弃。

## 2. 三类缺口定义（大白话）

### 2.1 已有未用

> **厨房里有米有菜，但厨师没做进菜里。**

管线的数据系统里已经拉了这些数据，但深度分析报告（或日报、后评估）没有充分引用。不是因为数据不存在，而是：
- 分析时不知道它存在（数据资产清单没同步到分析师）
- 分析时觉得不重要（没在模板里留位置）
- 分析时嫌麻烦（多字段多一行公式）
- 分析结论写完了忘了补（数据在但没人去读缓存目录）

### 2.2 能力不足

> **厨师想做这道菜，但米不够、锅不够、以后还可能找不回来。**

数据不是完全没有，但在以下方面不达标：
- **长度不够**：K线只有120天（目标250天稳定），评分历史只有7条（目标750条做IC）
- **稳定性不够**：没有形成"每次深度分析必有"的契约保证（如财务同比20季）
- **可追溯不够**：数据换API后无法回溯补齐
- **新鲜度规则不完善**：不知道数据是昨天的还是上周的
- **冷数据保留不明确**：数据用完删了，明年想复盘找不回来

### 2.3 外部缺口

> **厨房里没有这道菜的关键食材，需要去外面买或人工确认。**

系统内不生产、也拉不到的数据。必须通过以下方式获得：
- 信鸽人工采集/核实
- 阅读公告全文（PDF下载+人工解析）
- 外部付费数据源
- 行业/产业数据库
- 不可量化的判断（例如"这个催化剂有没有落地"）

## 3. 三类缺口与落点关系表

| 缺口类型 | 解决对象 | 主要落点 | 是否改深度分析_v1.5.md | 是否改数据地基 | 是否改信鸽/证据采集 | 是否进入G3前置 |
|:---------|:---------|:---------|:---------------------|:-------------|:------------------|:-------------|
| **已有未用** | 数据已经有但未进入分析 | 深度分析模板 / 周报口径 / 日报字段 / 后评估字段 | **是** — 模板节补字段、表格补行 | 否 | 可能 — 分类标签对齐 | **是** |
| **能力不足** | 数据长度/稳定性/契约不够 | L2数据实装 / 缓存策略 / 历史归档 / 字段契约 | **否或少量引用** — 先判断长度是否符合基线门槛（如<250天K线不做周线趋势分析） | **是** | 否 | **是** |
| **外部缺口** | 系统内没有可验证事实 | 信鸽采集 / 公告全文 / 证据等级L2a/L2b判定 / 日报指令清单 | **部分引用** — 分析中保留"待验证"入口位 / 证据等级按规则判定 | 可能 — 如需全文索引 | **是** | 是（但需评估采集可行性） |

### 3.1 关键原则

- **已有未用**是"触手可及"的优化——数据已有，改模板即可，没有新成本。应最先处理。
- **能力不足**需要工程投入（L2实装、缓存改造），但一旦补齐会解决多个分析共同的问题。建议与分析逻辑重构并行推进。
- **外部缺口**是"不可控"的部分——取决于信鸽是否采集到、外部是否披露。分析时需要在报告里明确标注"待验证"而不是假装数据存在。
