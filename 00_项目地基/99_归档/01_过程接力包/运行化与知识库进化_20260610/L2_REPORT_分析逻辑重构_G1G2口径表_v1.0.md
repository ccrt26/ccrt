## 1. 前置结论

本轮讨论后的核心判断是：

深度分析周报不应首先被理解为“给用户看的长篇结论报告”，而应在内部被理解为“给金融团队看的周度逻辑校准与日报指导书”。

正式报告名称、归档习惯和用户侧入口暂不改名，仍保留“深度分析周报”口径；金融团队使用的主体内容则应服务于：

1. 冻结本周中期逻辑与关键假设。
2. 指导未来一周每日分析应检查什么。
3. 记录本周使用的数据、参数、证据等级和判断规则。
4. 为下周后评估提供可复盘的基准。
5. 通过后评估反向优化字段、阈值、权重、证据等级和分析逻辑。

一句话原则：

> 周报定逻辑，日报验状态，后评估改参数。

## 3. 深度分析周报的新定位

### 3.1 旧定位问题

当前深度分析周报的问题不是“数据不够”，而是：

1. 数据、解释、结论都存在，但读者难以知道下周应关注什么。
2. 周报没有明确给日报下发任务，导致日报容易每天重新分析一遍。
3. 报告中的参数和判断规则没有形成可追踪版本。
4. 后评估难以判断是数据错、参数错、权重错，还是分析逻辑错。
5. 用户读完知道“这家公司怎么样”，但不知道“下一周如何验证它还值不值得继续跟踪”。

### 3.2 新定位

建议保留外部名称：

> 深度分析周报。

建议将其内部工作定位定义为：

> 重点股票周度逻辑校准与日报指导书。

它的主服务对象是金融团队和日报生产流程；用户阅读的是其派生出的简版摘要。正式文件名、归档路径和用户习惯暂不因本轮 G1/G2 讨论改变。

### 3.3 三层产物关系

| 层级 | 标签 | 服务对象 | 内容形态 | 主要问题 |
|:-----|:-----|:---------|:---------|:---------|
| 金融团队作业层 | 【A层】 | 金融团队、复盘人员、日报维护者 | 完整周报指导书 | 本周逻辑、参数、证据和下周日报任务是什么 |
| 后评估基准层 | 【B层】 | 后评估流程、参数优化流程 | 假设表、触发表、复盘表 | 判断对错后应如何修正字段、阈值和权重 |
| 用户摘要层 | 【C层】 | 用户、模拟交易观察者 | 1页以内摘要 | 继续跟踪、等待、降级还是移出 |

说明：A/B/C 是报告内部标签，不是文件名，不要求改变归档目录。

## 4. 服务对象口径

| 场景 | 周报应提供什么 | 日报应执行什么 | 用户摘要应显示什么 |
|:-----|:---------------|:---------------|:-------------------|
| 盘前 | 给出当日关键观察位、公告窗口、风险触发线 | 检查开盘是否触发预设条件 | 今天重点看什么，不追什么 |
| 盘中 | 给出盘中只允许观察的触发项，不做频繁重估 | 标记是否触发价格、量能、公告、异动条件 | 是否出现需要关注的状态变化 |
| 盘后 | 对照周报规则复盘当天是否升级、降级、等待 | 更新状态机和触发记录 | 今天状态变了没有，风险在哪里 |
| 模拟交易 | 提供试探、加仓、减仓、退出的条件框架 | 只按规则触发，不临时发挥 | 当前是否满足模拟动作条件 |
| 后评估 | 提供可验证假设和参数快照 | 下周回填结果和误差归因 | 不直接展示，除非需要解释调整原因 |

## 5. 决策问题口径

深度分析周报必须回答五个问题：

| 决策问题 | 输出要求 | 禁止写法 |
|:---------|:---------|:---------|
| 为什么还值得跟踪 | 用 1-3 条中期主线表达，不复述公司百科 | 只堆公司介绍和行业背景 |
| 本周什么改变了判断 | 只列会增强、削弱或验证假设的事实 | 把所有新闻都列为催化 |
| 下周该盯什么 | 最多 5 个观察变量，每个变量有触发阈值 | 写“持续关注”但不说明怎么关注 |
| 什么情况升级/等待/降级/否决 | 输出状态机和触发条件 | 只给“谨慎乐观”等形容词 |
| 下周如何后评估 | 写清下周回来检查哪些问题 | 只给一次性结论，不留复盘入口 |

## 6. 输入字段口径

### 6.0 证据等级口径

原 L2 等级覆盖过宽，本轮拆分为 L2a/L2b。

| 级别 | 定义 | 举例 | 使用口径 |
|:-----|:-----|:-----|:---------|
| L1 | 已公告、财报、披露的硬事实 | 订单已确认、财报已发布、正式公告落地 | 可直接支撑核心假设 |
| L2a | 有明确预期窗口的推进事项 | 并购待注册、项目预计 3-6 个月落地 | 可支撑假设，但必须标注有效期 |
| L2b | 有方向但无时间表的战略叙事 | 第二成长曲线、产能方向、业务布局 | 只能作为背景或观察项，不作为核心假设的主要支撑 |
| L3 | 推测、概念、无法落地的叙事 | 无订单支撑的概念映射 | 不得作为单独核心假设 |

后评估时，L2a 未如期兑现视为假设部分失败；L2b 未兑现不直接视为假设失败，但应评估是否继续保留观察价值。

### 6.1 保留字段

| 字段 | 保留原因 | 使用方式 |
|:-----|:---------|:---------|
| 公司主营与业务结构 | 判断中期逻辑是否有业务承载 | 只保留与主线相关部分 |
| 核心投资逻辑 | 形成周报核心假设 | 必须拆成可验证假设 |
| 催化剂清单 | 指导日报事件跟踪 | 必须区分已发生、待落地、未证实 |
| 财务趋势 | 验证基本面是否支撑估值 | 重点看营收、毛利率、ROE、现金流 |
| 估值框架 | 判断风险收益边界 | PE/PEG/PS/PB 需说明适用场景 |
| 技术关键位 | 指导下周观察和风控 | 只保留与状态机相关的价位 |
| 资金面变化 | 判断短期交易状态 | 不得单独决定中期逻辑 |
| 风险情景 | 定义降级和否决边界 | 必须有触发条件 |
| 证据等级 | 区分事实、推进、预期 | L1/L2a/L2b/L3 需可追溯 |

### 6.2 降权字段

| 字段 | 降权原因 | 新用途 |
|:-----|:---------|:-------|
| 长篇行业背景 | 对下周日报指导价值有限 | 压缩为主线支撑材料 |
| 大量同业罗列 | 容易稀释决策重点 | 只保留估值或竞争位势必要对标 |
| 综合评分 | 容易遮蔽触发逻辑 | 作为摘要，不作为唯一判断 |
| 概念标签 | 容易制造叙事幻觉 | 必须绑定证据等级 |
| 历史技术形态复述 | 若不产生下周阈值，价值有限 | 只保留关键支撑/阻力/失效位 |

### 6.3 删除或不进入主报告字段

| 字段 | 删除原因 |
|:-----|:---------|
| 无触发条件的“持续关注” | 无法指导日报和后评估 |
| 无来源或无证据等级的概念映射 | 容易误导估值和催化判断 |
| 无解释的自动评分 | 不能作为深度分析基本面分数 |
| 与核心假设无关的指标堆叠 | 增加阅读负担，不提高决策质量 |
| 情绪性结论 | 无法复盘，也无法指导下一步动作 |

### 6.4 新增字段

| 新增字段 | 用途 | 是否必填 |
|:---------|:-----|:---------|
| 周度核心假设表 | 固定本周判断的逻辑底座 | 必填 |
| 证据等级快照 | 记录每条逻辑的证据强度 | 必填 |
| 日报指令清单 | 指导未来一周每日分析 | 必填 |
| 状态机 | 定义看、等、试探、升级、降级、否决 | 必填 |
| 后评估问题 | 下周复盘入口 | 必填 |
| 参数快照 | 记录关键价位、阈值、概率、权重 | 必填 |
| 误差归因栏 | 后评估时标记问题来源 | 必填 |
| 反证条件 | 判断中期逻辑是否失效 | 必填 |
| 用户摘要派生规则 | 说明给用户看的结论如何从作业层生成 | 建议必填 |
| M 覆写记录 | 记录宏观突变是否临时压过个股状态 | 条件触发时必填 |

## 7. 周报主体结构口径

建议新版深度分析周报采用以下结构。

### 7.1 A 层：金融团队作业层

| 章节 | 目的 | 输出要求 |
|:-----|:-----|:---------|
| 0. 本周版本与样本说明 | 固定报告版本和数据边界 | 日期、数据源、样本、缺失项 |
| 1. 一句话工作结论 | 给团队统一口径 | 继续跟踪/等待/降级/移出 |
| 2. 周度核心假设表 | 固定中期逻辑 | 每条假设必须有证据等级和反证条件 |
| 3. 本周变化归因 | 说明本周哪些事实改变判断 | 分为增强、削弱、中性、待验证 |
| 4. 下周日报指令 | 告诉日报每天查什么 | 字段、阈值、触发后的动作 |
| 5. 状态机与触发规则 | 让日报按规则更新状态 | 看、等、试探、升级、降级、否决 |
| 6. 参数快照 | 为后评估固定参数版本 | 技术位、估值阈值、事件窗口、风险阈值 |
| 7. 风险边界 | 说明什么会推翻判断 | 技术、基本面、事件、估值、流动性 |
| 8. 下周后评估问题 | 给复盘留下题目 | 至少 5 个可回答问题 |

### 7.2 B 层：后评估基准层

| 章节 | 目的 | 输出要求 |
|:-----|:-----|:---------|
| 9. 假设命中记录 | 记录假设是否被验证 | 命中/未命中/待验证 |
| 10. 参数误差归因 | 判断错在什么地方 | 数据、阈值、权重、证据等级、逻辑 |
| 11. 字段价值评估 | 判断哪些字段真的有用 | 保留、降权、删除、新增 |
| 12. 规则修正建议 | 进入下一版 G1/G2 或 G3 的依据 | 仅建议，不自动改代码 |

### 7.3 C 层：用户摘要层

| 章节 | 目的 | 输出要求 |
|:-----|:-----|:---------|
| 用户一句话结论 | 降低阅读负担 | 当前状态和下一步 |
| 下周只看这几件事 | 明确观察重点 | 不超过 5 条 |
| 风险在哪 | 明确降级/回避条件 | 不超过 3 条 |
| 当前不做什么 | 防止误用报告 | 如不追高、不提前加仓 |

用户摘要生成口径：

1. 模板可从 A 层和 B 层半自动派生摘要初稿。
2. 腰子必须人工精修正式用户摘要，目标控制在每只标的额外 3 分钟以内。
3. 自动摘要不得直接作为最终结论发布。
4. 人工精修重点是语气、风险边界、动作边界和是否存在微观判断遗漏。

### 7.4 C 层动作化格式

C 层用户摘要必须从“信息描述”改为“动作边界”。

| 字段 | 写法要求 | 禁止写法 |
|:-----|:---------|:---------|
| 下周可做 | 写清满足什么条件后继续跟踪、试探或恢复 | 只写“关注某价位” |
| 下周不做 | 写清未触发前不追、不加、不扩大仓位 | 只写“谨慎” |
| 触发后变化 | 写清触发后进入 A/B/C/D/E 哪个状态 | 只写“看情况” |
| 风险边界 | 写清什么情况降级、移出或重评 | 只写“注意风险” |

示例格式：

```text
下周可做：若收盘重新站稳核心支撑且量能收缩，维持 B 状态观察，可讨论是否进入 E 子状态。
下周不做：未企稳前不追高、不提前加仓。
触发后变化：若放量跌破硬风控位，转 C；若出现 L1 反证，转 D。
```

### 7.5 人工精修检查清单

腰子精修用户摘要时至少检查：

1. 是否遗漏风险边界。
2. 动作指令是否能落到 A/B/C/D/E 状态。
3. 是否存在“谨慎乐观”“持续关注”等无法执行表述。
4. 是否把 L2b 叙事写成了核心支撑。
5. 是否明确“可做”和“不做”。
6. 是否存在自动摘要过度缓和或过度武断的问题。

## 8. 日报指令口径

深度周报必须向未来一周日报下发“指令清单”。日报不应每天重写深度逻辑，而应回答：

> 今天是否触发了周报设定的状态变化？

日报指令至少包含：

| 指令类型 | 示例 | 日报输出 |
|:---------|:-----|:---------|
| 价格指令 | 是否守住核心支撑位 | 未触发/触发/次日待确认 |
| 量能指令 | 是否从放量下跌转为缩量整理 | 健康/分歧/恶化 |
| 事件指令 | 是否有并购、订单、产能、客户公告 | 增强/削弱/无变化 |
| 财务指令 | 是否出现业绩预告或财务反证 | 支撑/不支撑/待验证 |
| 行业指令 | 下游需求和竞品是否变化 | 增强/削弱/无变化 |
| 风控指令 | 是否触发降级或否决项 | 继续/降级/移出 |

事件指令与信鸽采集工作流的衔接口径：

1. 周报事件指令标签复用信鸽既有五层分类体系，不另起事件标签体系。
2. 周报事件指令只是“已知需跟踪项”，不是“限死项”。
3. 信鸽采集到 P0 级事件时，即使周报未写入指令清单，也应直接推送腰子。
4. P0 事件包括但不限于招标取消、并购叫停、重大监管处罚、核心客户或订单实质变化。
5. P0 事件进入日报后，应同步写入后评估记录，避免周报指令遗漏变成静默风险。

日报的标准输出应是：

1. 今日状态是否变更。
2. 哪条周报指令被触发。
3. 触发后进入哪个状态。
4. 是否需要金融团队人工复核。
5. 是否需要更新后评估记录。

### 8.1 日报指令最小模板

为降低冷启动成本，日报指令清单必须区分“必填核心项”和“可选扩展项”。必填项缺失时，本周周报不得输出强结论。

| 指令类型 | 必填核心项 | 可选扩展项 |
|:---------|:-----------|:-----------|
| 价格指令 | 核心支撑/压力位、触发后状态、确认规则（盘中/收盘/次日） | 分时异动阈值、波动率区间、跳空缺口处理 |
| 量能指令 | 放量/缩量判定口径、与几日均量比较、触发后动作 | 换手率区间、成交额阈值、量价背离说明 |
| 事件指令 | 事件类型、证据等级 L1/L2a/L2b/L3、触发后增强/削弱动作 | 事件落地窗口、市场预期偏差、信鸽标签 |
| 财务指令 | 核心财务反证项、最新可得数据窗口、触发后状态 | 同业对比、环比修复阈值、财务质量补充项 |
| 行业指令 | 下游需求或竞品变化、行业证据等级、触发后影响 | 政策窗口、价格链变化、库存/排产数据 |
| 风控指令 | 降级/否决触发项、硬风控位、是否需要人工复核 | 仓位动作、风险暴露估算、恢复条件 |

最小写法示例：

```text
价格指令：观察核心支撑 35.16；若收盘跌破且次日不能收回，B -> C；若缩量守住 2 日，B 可讨论 E。
事件指令：跟踪并购公告，当前 L2a；若公告落地，增强核心假设；若延期且无解释，B -> C。
风控指令：若出现 L1 级反证，直接 D，并触发 mini 深度分析前置检查。
```

### 8.2 Shadow 指令执行栏

日报指令不应在第一轮直接强制改日报结构。建议先保留日报原有结构，新增金融团队可见的 Shadow 指令执行栏。

| 字段 | 填写要求 |
|:-----|:---------|
| 周报指令编号 | 对应周报中的指令 ID 或序号 |
| 今日是否触发 | 未触发/触发/待确认 |
| 触发证据 | 价格、量能、事件、财务、行业或风控证据 |
| 状态变化 | A/B/C/D/E/M 是否变化 |
| 未执行原因 | 数据缺失、未到窗口、人工复核中、指令不清 |
| 是否进入后评估 | 是/否 |

Shadow 运行建议先跑 2 周。2 周后统计指令执行率和状态切换准确率，再决定是否转为日报强制章节。

## 9. 状态机口径

深度分析周报必须给出状态机。

主状态为 A/B/C/D，E 是 B 的子状态，不作为独立档位。

```text
A 继续跟踪 <-> B 等待确认 <-> C 降级观察 -> D 移出/否决
                  |
                  E 试探跟踪（B 的子状态）
```

| 状态 | 含义 | 允许动作 | 进入条件 | 退出条件 |
|:-----|:-----|:---------|:---------|:---------|
| A 继续跟踪 | 中期逻辑成立，短期无重大恶化 | 日报正常跟踪 | 核心假设未证伪 | 触发等待、降级或否决 |
| B 等待确认 | 中期逻辑未坏，但短期信号分歧 | 只观察，不追 | 技术、资金、事件或估值信号分歧 | 企稳后回 A，恶化后到 C |
| E 试探跟踪 | B 状态下满足模拟试探条件 | 仅供模拟交易试探 | 标的已在 B，且风险可控、触发试探条件 | 成功回 A，失败回 B，试探期间出问题到 C |
| C 降级观察 | 风险明显升高，短期不宜动作 | 降低展示优先级 | 跌破关键位、资金恶化、催化延后 | 修复后回 B，恶化后到 D |
| D 移出/否决 | 中期逻辑或风险边界被破坏 | 停止推荐，等待重评 | 核心反证出现 | 满足恢复路径后只能回 B |

说明：状态机用于指导报告和模拟交易，不构成投资建议。

### 9.1 M 层宏观覆写

M 层不是个股状态，而是个股状态机上方的临时覆写层。

| 项目 | 口径 |
|:-----|:-----|
| 触发定义 | 政策转向、利率突变、系统流动性事件、市场风格急剧切换等宏观突变 |
| 发起角色 | 山猫发现宏观突变并提出覆写建议 |
| 裁决路径 | 山猫报告腰子，腰子 + 山猫双签后触发 |
| 覆写动作 | 可批量暂停、降级或冻结所有 A/B 状态标的动作 |
| 状态保留 | 个股原 A/B/C/D 状态保留，M 只临时覆写展示和动作 |
| 解除路径 | 宏观稳定后，由腰子逐个或批量恢复，必要时重新评估 |

M 层设计应保持克制，不做复杂自动化联动，避免误触发。

### 9.2 D 状态恢复路径

D 状态不是永久移出，但恢复门槛必须高于普通状态切换。

| 环节 | 口径 |
|:-----|:-----|
| 发起 | 腰子或青山可发起重评 |
| 门槛 | 必须至少出现 1 个 L1 级新事实 |
| 流程 | 走 mini 深度分析，不需完整九章，但必须全团咨询 |
| 通过后状态 | 不得直接回 A，只能先回 B 等待确认 |
| 观察期 | 回 B 后观察 2 周，再决定转 A 或 C |
| 后评估 | D 恢复必须记录原否决原因是否被新事实修复 |

### 9.3 状态切换最小举证清单

状态切换必须有最小举证。若证据不足，日报只能标记“待确认”，不得擅自切换状态。

| 状态 | 进入最小举证 | 退出最小举证 |
|:-----|:-------------|:-------------|
| A 继续跟踪 | 至少 1 条 L1 或强 L2a 支撑核心假设，且无硬风控触发；日报指令可执行 | 出现 1 类核心信号分歧进入 B；出现降级项进入 C；出现 L1 反证进入 D |
| B 等待确认 | 至少 2 类普通信号分歧（如技术 + 资金），或 1 类核心信号分歧（如 L2a 催化延后） | 1 类核心信号修复且分歧消失回 A；风险扩大到 C；满足试探条件进入 E 子状态 |
| E 试探跟踪 | 标的已在 B；至少 1 类核心风险可控；试探触发条件和止损边界明确 | 试探成功回 A；试探失败回 B；试探期间出现降级项到 C |
| C 降级观察 | 至少 1 条降级项触发，或 2 类风险信号共同恶化 | 风险修复且无新增反证回 B；出现 L1 反证或核心假设破坏到 D |
| D 移出/否决 | 1 条 L1 级反证材料，或硬风控位失效并无法收回，且有核心假设证伪记录 | mini 深度分析 + 1 条 L1 级新事实 + 全团咨询记录，且只能回 B |

### 9.4 M 层宏观信号阈值表

M 层阈值用于约束宏观覆写，不作为自动触发代码规则。正式阈值需由山猫和青山继续校准。

| 宏观场景 | 初始触发阈值 | 覆写范围 | 备注 |
|:---------|:-------------|:---------|:-----|
| 行业政策转向 | 行业核心政策发布，且直接改变盈利、需求或估值假设 | 该行业所有相关标的 | 需山猫说明政策影响链 |
| 系统流动性事件 | 市场流动性指标或融资环境出现显著异常，并影响成长股风险偏好 | 全池 A/B 标的动作冻结或降级观察 | 需腰子 + 山猫双签 |
| 市场风格切换 | 成长/价值因子收益差连续 3 日超过 5% | 全池标的，仅覆写动作，不改变基础状态 | 阈值为初始参考，需青山后评估校准 |
| 利率或汇率突变 | 利率/汇率单周变化达到足以改变行业估值或成本假设的程度 | 受影响行业或全池 | 不做自动批量结论 |
| 外部冲击 | 地缘、监管、交易制度等影响市场风险偏好的事件 | 由腰子 + 山猫定义范围 | 必须记录覆写开始和解除时间 |

## 10. 否决项与降级项

### 10.1 直接否决项

| 否决项 | 处理 |
|:-------|:-----|
| 核心业务逻辑被公告或财报证伪 | 移出跟踪，要求重做深度分析 |
| 重大财务真实性风险 | 停止推荐，进入风险复核 |
| 关键催化失败且原估值主要依赖该催化 | 降至 D 状态 |
| 价格跌破硬风控位且无法收回 | 停止短线动作，重新评估中期逻辑 |
| 数据源关键字段缺失且无法解释 | 不输出强结论 |

### 10.2 降级项

| 降级项 | 处理 |
|:-------|:-----|
| 放量跌破核心支撑 | 降级观察，次日确认 |
| 资金面持续恶化 | 降低短期评级，不改变中期逻辑 |
| 催化推迟但未失败 | 从继续跟踪降为等待确认 |
| 估值上行但基本面未同步 | 降低风险收益比评价 |
| 证据等级从 L1/L2a 下修，或 L2b 长期无进展 | 重写核心假设表或降为背景观察 |

## 12. 后评估口径

后评估不是评价“报告写得好不好”，而是评价：

1. 哪些字段真的帮助判断。
2. 哪些参数阈值过紧或过松。
3. 哪些证据等级被高估。
4. 哪些催化概率设定不合理。
5. 哪些风险触发出现得太晚。
6. 日报是否忠实执行周报指令。
7. 用户摘要是否准确反映金融团队作业层。
8. 是否存在策略环境变化导致逻辑正确但结论偏离。

### 12.1 后评估归因分类

| 归因类型 | 含义 | 示例 |
|:---------|:-----|:-----|
| 数据问题 | 数据缺失、延迟、口径错误 | 价格、财务、公告字段不一致 |
| 参数问题 | 阈值设置不合理 | 支撑位、量能倍数、估值阈值失真 |
| 权重问题 | 某类因素影响被高估或低估 | 资金面压过基本面或相反 |
| 证据等级问题 | 把预期当事实 | L3 概念被当作 L1 订单 |
| 分析逻辑问题 | 因果链条不成立 | 产能扩张被直接等同于订单增长 |
| 展示问题 | 信息表达未支持决策 | 用户不知道下周该看什么 |
| 执行问题 | 日报未执行周报指令 | 触发降级但日报未标记 |
| 策略环境变化 | 分析参数和逻辑本身合理，但市场因子有效性或风格环境切换 | 成长因子失效、市场风格转向高股息、流动性急剧收缩 |

策略环境变化由青山主判，必要时联动山猫判断宏观背景；不得把所有错误都归因于策略环境变化。

### 12.2 后评估输出

每次后评估应输出：

1. 本周核心假设命中情况。
2. 日报指令执行情况。
3. 触发规则是否合理。
4. 字段保留、降权、删除、新增建议。
5. 下版周报参数修正建议。
6. 是否需要进入 G3 模板或脚本实现。

### 12.3 后评估量化指标

后评估必须从“总结经验”升级为“修正参数”。以下阈值为 G1/G2 初始口径，后续可由后评估校准。

| 归因类型 | 量化指标 | 初始修正阈值 | 处理 |
|:---------|:---------|:-------------|:-----|
| 参数问题 | 阈值偏差率 = abs(实际触发值 - 预设阈值) / abs(预设阈值) | >= 10% | 复核参数口径，必要时下版修正 |
| 证据等级问题 | L2a 未兑现率 = 当期未兑现 L2a 数 / 总 L2a 数 | >= 30% | 重审 L2a 判定标准和有效期 |
| 执行问题 | 日报指令执行率 = 已执行指令数 / 总指令数 | < 80% | 分析未执行原因，修正指令或执行流程 |
| 状态切换问题 | 状态切换准确率 = 后评估认可的切换数 / 总切换数 | < 70% | 复核状态机举证清单 |
| 展示问题 | 用户摘要返工率 = 需腰子重写摘要数 / 摘要总数 | > 30% | 修正 C 层摘要派生规则 |
| 字段价值问题 | 字段命中率 = 被复盘引用字段数 / 周报展示字段数 | < 50% | 将低价值字段降权或移出主报告 |
| 策略环境变化 | 因子偏离天数 = 主要因子异常表现天数 | 连续 3 日或以上 | 由青山主判是否触发策略环境归因 |

说明：量化指标用于触发复核，不等于自动改参数；所有参数修正仍需进入后评估记录。

### 12.4 后评估双周期

后评估采用“双周期并行”：

| 周期 | 覆盖对象 | 时间要求 | 输出重点 |
|:-----|:---------|:---------|:---------|
| 常规周度复盘 | 所有跟踪标的 | 每周一次 | 指令执行率、假设命中数、状态切换准确率、字段价值 |
| 催化节点复盘 | 存在 L1/L2a 催化的标的 | 催化落地或落空后 48 小时内 | 催化兑现、证据等级修正、参数窗口是否失效 |

若催化节点复盘与周度复盘时间接近，可以合并成一份复盘文件，但必须保留催化节点的独立结论。

## 13. 样稿验证计划

本文件先冻结思路口径，不展开东睦股份新版周报细节。后续进入样稿验证时，必须手工写两类样稿：

| 样稿 | 目的 | 进入 G3 前要求 |
|:-----|:-----|:---------------|
| 东睦股份正/争议样稿 | 验证三层结构、日报指令、状态机和后评估问题能否指导真实周报 | 必须完成，且由金融团队评审 |
| 坏反例样稿 | 只跑“当前不该进深度跟踪”的负例，验证否决项是否可用 | 必须完成，且不能只写结论，要展示否决触发链 |

东睦股份样稿应另开文件，不塞入本口径文件正文。坏反例样稿也应独立成文，作为 G3 前的否决项验收材料。

### 13.1 坏反例双维度选取标准

坏反例样稿必须覆盖两个来源，避免只验证准入或只验证退出。

| 来源 | 选取标准 | 验证目的 |
|:-----|:---------|:---------|
| 已跟踪池 | 曾触发 D 状态但未及时移出，后续风险继续扩大的标的 | 验证否决项是否滞后，状态机是否过宽 |
| 候选池 | 依赖 L3 概念或 L2b 叙事、无 L1/L2a 支撑、无反证条件的标的 | 验证准入否决项是否有效 |

坏反例样稿必须展示“为什么不该进深度跟踪”或“为什么应该移出”，不得只写一句否决结论。

## 14. 验收样例

### 14.1 正例

标的满足：

1. 中期主线有 L1 或强 L2a 证据。
2. 本周有可验证的基本面或事件进展。
3. 下周有明确观察窗口。
4. 风险边界清晰。
5. 日报能根据周报指令每日更新状态。

预期周报输出：

继续跟踪或等待确认；给出日报指令和后评估问题。

### 14.2 负例

标的满足：

1. 主要逻辑依赖 L3 概念。
2. 无订单、客户、财务或公告支撑。
3. 技术面已破关键风控位。
4. 日报无法找到可验证变量。
5. 只有 L2b 叙事，且无法给出时间窗口或反证条件。

预期周报输出：

不推荐进入深度跟踪；若已在池中，应降级或移出。

### 14.3 争议例

标的满足：

1. 基本面较好，但短线价格和资金面明显恶化。
2. 核心催化未失败，但落地时间不确定。
3. 估值偏高但同业相对不贵。

预期周报输出：

等待确认；明确哪些条件触发 B 子状态 E，哪些条件触发降级，不允许用单一综合评分掩盖分歧。

### 15.6 渐进式过渡方案

为避免 G2 验证后直接跳 G3 导致衔接断层，采用“两步走”。

| 阶段 | 做法 | 边界 |
|:-----|:-----|:-----|
| G2 验证期 | 核心字段在 Markdown 中结构化标注，使用固定表格和标签格式 | 不改生产代码，不改数据库 schema |
| G3 预备期 | 将结构化字段迁移到临时数据表或旁路文件，验证字段可用性 | 不写入正式生产库，不替换正式日报入口 |
| G3 实施期 | 字段稳定后再评估正式落库、模板化和脚本化 | 必须另行授权 |

G2 验证期建议优先结构化以下字段：

1. 周度核心假设表。
2. 证据等级快照。
3. 状态机当前状态。
4. 日报指令清单。
5. 参数快照。
6. 后评估问题。
7. Shadow 指令执行栏。

### 15.7 Shadow 运行达标口径

Shadow 运行至少 2 周，不改变原日报展示结构。达标后才讨论是否将指令栏转为强制章节。

| 指标 | 达标参考 | 未达标处理 |
|:-----|:---------|:-----------|
| 日报指令执行率 | >= 80% | 修正指令模板或减少必填项 |
| 状态切换准确率 | >= 70% | 复核状态机举证清单 |
| 人工返工率 | <= 30% | 优化 C 层摘要和精修检查清单 |
| 缺失字段率 | <= 20% | 与 L2 STEP-B 对齐字段来源 |
| 金融团队可接受度 | 无 BLOCK 意见 | 回到 G1/G2 修改口径 |
