# STEP-C 与分析逻辑重构解耦方案 G2 v1.0

> 日期：2026-06-09
> 流程编号：F-ANALYSIS + F-DATA + F-GATE
> 阶段门：G0/G1/G2；本文件不授权 G3 实施
> 目标：在不切生产、不把旧分析结论当真值的前提下，先验证新地基事实数据，再重构分析逻辑，最后做新分析输出的 shadow 验证。

---

## 1. 前置判断

当前问题不是单纯的 STEP-C 是否执行，而是验证对象发生了分层：

| 层级 | 当前判断 | 是否适合直接 STEP-C |
|:-----|:---------|:--------------------|
| 数据事实层 | 老路径与 L2 可对比价格、日期、字段、fallback | 适合 |
| 分析逻辑层 | 重点股票、深度分析、每日分析、每日荐股可能存在逻辑问题 | 不适合把旧输出当真值 |
| 展示表达层 | 当前展示字段可能信息价值不足 | 需重设展示口径后再验 |
| 生产入口层 | 日报和深度分析仍应保持 BAU | 不切 |

结论：继续执行 STEP-C，但收窄为 `STEP-C-Data`；分析逻辑重构另起 `Logic-G1/G2`，待规则冻结后再进入 `STEP-C-Analysis`。

---

## 2. 总原则

1. 不把旧分析结论当正确答案，只把旧系统当 legacy baseline。
2. 数据正确性、分析有效性、展示可读性分开验收。
3. 每阶段只验证一个主变量，避免差异无法归因。
4. 所有新逻辑先 shadow-only，不改变正式日报、深度分析、每日荐股生产入口。
5. 先做可观测、可回滚、可解释的小闭环，再扩大范围。

---

## 3. 最小三阶段路线

| 阶段 | 名称 | 目标 | 主变量 | 产物 | 是否依赖前一阶段 |
|:----:|:-----|:-----|:-------|:-----|:----------------|
| A | STEP-C-Data | 证明新地基能稳定拿到事实数据 | 数据源与字段质量 | shadow diff 日志、差异归因表 | 否，可立即做 |
| B | Logic-G1/G2 | 重定分析逻辑和展示口径 | 分析规则与输出结构 | 分析逻辑口径表、字段价值矩阵、验收样例 | 不依赖 A 完成 |
| C | STEP-C-Analysis | 用新逻辑旁路生成分析结果并验收 | 新分析逻辑 | 新旧输出差异说明、人工评审记录、上线评估 | 依赖 A 稳定与 B 冻结 |

该路线把原先“数据 shadow + 分析 shadow + 入口切换”拆开，但只保留三个必要阶段。A 和 B 可并行，C 必须在 A/B 都满足准入后启动。

---

## 4. 阶段 A：STEP-C-Data

### 4.1 目标

验证新地基 L2/UDS 是否能作为事实数据候选，而不是验证分析结论。

### 4.2 范围

| 项目 | 要求 |
|:-----|:-----|
| 价格 | 老路径 close/open/high/low 与 L2 对比 |
| 日期 | L2 最新交易日不得无解释落后 |
| 字段 | 必填字段缺失必须显式记录 |
| fallback | L2 缺失时必须安全回旧路径 |
| 解释 | 差异必须能归因到缺失、延迟、复权、口径或异常 |

### 4.3 通过条件

1. 至少覆盖重点股票、每日荐股候选池、深度分析样本三类对象。
2. 连续 3 个交易日或 3 批样本 shadow 可运行。
3. 差异日志中不存在静默错读。
4. fallback 触发可追溯，不影响正式报告生成。
5. 生产入口 diff 证明未切换。

### 4.4 不做事项

1. 不评价荐股是否合理。
2. 不评价深度分析结论优劣。
3. 不修改日报展示字段。
4. 不把旧分析文本作为正确答案。

---

## 5. 阶段 B：Logic-G1/G2

### 5.1 目标

把重点股票、深度分析、每日分析、每日荐股的分析逻辑重新定义成可审计规则，而不是直接改代码。

### 5.2 核心问题

| 问题 | 必须产出 |
|:-----|:---------|
| 服务对象是谁 | 面向盘前决策、盘中观察、盘后复盘或模拟交易 |
| 输出要解决什么问题 | 买不买、看不看、等不等、风险在哪里 |
| 哪些字段有价值 | 字段价值矩阵：保留、降权、删除、新增 |
| 推荐如何排序 | 候选池、过滤条件、评分维度、否决项 |
| 风险如何表达 | 必填风险字段、触发条件、禁止乐观包装 |
| 如何验收 | 历史样例、反例、人工评审表、后评估指标 |

### 5.3 三类逻辑分开定义

| 场景 | 主要目标 | 不应混入 |
|:-----|:---------|:---------|
| 重点股票每日分析 | 跟踪已关注标的状态变化 | 不承担全市场荐股 |
| 深度分析 | 建立中期逻辑、催化、风险和反证框架 | 不追求每日短线排序 |
| 每日荐股 | 从候选池中选择次日更值得观察的标的 | 不复写深度分析全文 |

### 5.4 通过条件

1. 每个场景都有独立输入、处理、输出定义。
2. 每个场景都有否决项和降级策略。
3. 展示字段能说明用途，不能只有“看起来丰富”。
4. 至少选取历史正例、负例、争议例各一组作为验收样例。
5. 形成冻结版 G2 口径后，才允许进入代码实现。

### 5.5 不做事项

1. 不在本阶段改生产脚本。
2. 不直接替换日报模板。
3. 不把短期收益率作为唯一正确性标准。
4. 不让单一角色或单一模型直接给出最终金融结论。

## 6. 阶段 C：STEP-C-Analysis

### 6.1 启动条件

| 条件 | 要求 |
|:-----|:-----|
| A 数据 shadow | PASS 或仅非阻断 WARN |
| B 分析口径 | G2 冻结，有样例和验收表 |
| 生产入口 | 保持旧路径 |
| 用户确认 | 明确授权进入 G3 实现 |

### 6.2 目标

让新分析逻辑像“新员工模拟答题”一样旁路生成结果，但不发布、不替代正式日报。

### 6.3 验证方式

| 验证项 | 方法 | 通过标准 |
|:-------|:-----|:---------|
| 输入一致性 | 同一批样本，旧生产与新逻辑使用可追溯数据包 | 数据版本可复现 |
| 结论差异 | 新旧输出只做差异解释，不判旧为真 | 差异能归因 |
| 规则命中 | 检查新规则、否决项、降级项是否按预期触发 | 无静默跳过 |
| 展示价值 | 人工评审字段是否支持决策 | 无明显废话字段 |
| 后评估 | 结合次日/多日结果观察，不做单日定胜负 | 指标持续记录 |

### 6.4 输出物

1. 新逻辑 shadow 报告。
2. 新旧输出差异说明。
3. 字段展示价值评审表。
4. 失败样例和反例库更新建议。
5. 是否进入 STEP-D/guarded cutover 的评估结论。

---

## 7. 解耦边界

| 边界 | 说明 |
|:-----|:-----|
| A 不依赖 B | 数据 shadow 只看事实，不等分析逻辑改好 |
| B 不依赖 A | 业务口径可先定，数据问题只影响字段可用性 |
| C 依赖 A+B | 新分析 shadow 必须同时具备可靠数据和冻结规则 |
| STEP-D 依赖 C | 未完成新分析 shadow 前，不建议切正式入口 |

## 11. 建议结论

建议采用“数据先 shadow，逻辑并行重构，分析后 shadow”的路线：

1. 立即执行 `STEP-C-Data`，只验证事实数据链路。
2. 同步启动 `Logic-G1/G2`，重定重点股票、深度分析、每日分析、每日荐股的分析口径。
3. 数据稳定且逻辑冻结后，再做 `STEP-C-Analysis`。
4. 未完成 `STEP-C-Analysis` 前，不进入正式报告入口切换。

本方案减少了不必要的等待：A 和 B 可并行；同时避免把旧分析逻辑误当真值，保留了科学验证所需的变量隔离。
