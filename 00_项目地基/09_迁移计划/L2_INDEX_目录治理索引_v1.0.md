## 二、当前旧目录处理原则

### 核心原则（8条）

1. **先建索引，不先搬文件** — 00_项目地基/ 先建立位置索引，旧文件原地不动
2. **新地基文件从 00_项目地基/ 开始** — 新 schema/contract/registry 直接写入地基目录
3. **旧业务产物不批量移动** — 报告产物原地工作，只通过索引定位
4. **历史报告不改路径** — 已归档历史报告保持当前位置
5. **代码脚本不随意搬迁** — 分界维持现状
6. **Schema 迁移保留兼容入口** — 迁移后原位置保留 symlink，确保 import 路径不变
7. **每次迁移必须有映射表** — 格式：`旧路径 → 新路径 | 日期 | 影响范围 | 兼容入口`
8. **每次迁移必须有回滚方案** — 删除新副本 + 恢复旧位置 + 恢复引用

## 六、迁移红线

> 以下红线在迁移过程中任何阶段不得触犯。

| 编号 | 红线 | 违规后果 |
|:----:|:-----|:---------|
| M-R01 | ⛔ 不得一次性搬迁整个目录 | 破坏正在运行的业务 |
| M-R02 | ⛔ 不得迁移报告产物到地基目录 | 地基是索引不是报告仓库 |
| M-R03 | ⛔ 不得删除旧目录的兼容入口（symlink），除非所有消费者已迁移 | 破坏 import 链 |
| M-R04 | ⛔ 不得无映射表就执行迁移 | 无法回滚 |
| M-R05 | ⛔ 不得无回滚方案就执行迁移 | 失败无人负责 |
| M-R06 | ⛔ 地基目录不得存放业务代码 | 违反目录定位 |
| M-R07 | ⛔ 地基文件不得依赖旧目录路径（只允许旧文件依赖新文件，使用符号链接） | 防止反向依赖 |
| M-R08 | ⛔ 地理文件中不得出现业务数据正文（CSV/JSON原始数据） | 地基不是数据仓库 |
