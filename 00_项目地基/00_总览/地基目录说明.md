## 一、目录定位

**00_项目地基/** 是铁律量化项目的文件治理中枢，承担以下职责：

1. **注册与索引** — 所有项目的 schema、contract、baseline、registry 的统一注册入口
2. **迁移映射** — 旧目录到新目录的迁移计划和工作进度
3. **闭环绑定** — 报告对象定义、后评估闭环、知识进化路径
4. **审计闸门** — 一致性闸门定义、审计报告索引

### 它不是

- ❌ 不是新的代码仓库主目录
- ❌ 不是报告产物的存储位置
- ❌ 不是数据文件的实际存储位置
- ❌ 不是已有旧目录的替代品（旧目录原地运行，不迁移）

## 三、不允许存放的内容

以下内容 **严禁** 放入 00_项目地基/ 的任何子目录：

1. **代码文件**（.py / .ps1 / .sh）— 保留在 `代码文件/` 或 `scripts/`
2. **报告产物**（.pdf / .html / .md 报告正文）— 保留在 `重点股票/`、`docs/`、`每日荐股/` 等
3. **数据文件**（.csv / .json 业务数据）— 保留在 `历史数据/`、`daily_data_pack/`
4. **原始 schema 副本** — 00_项目地基/ 只存权威副本和索引，迁移时在原位置保留兼容入口
5. **角色定义正文**（agent .md）— 保留在 `.claude/agents/`
6. **流程模板正文**（flow_*.json）— 保留在 `templates/`
7. **金融规则正文**（规则红线 v*.md）— 保留在 `金融铁律/`
8. **爬虫缓存/临时文件** — 保留在原缓存目录

## 五、旧目录暂不迁移原则

`00_项目地基/` 不是旧目录的替代品。所有旧目录原地运行：

1. **先建索引，不先搬文件** — 先通过 00_项目地基/ 建立文件位置索引，物理迁移在后续阶段逐步进行
2. **旧业务产物不批量移动** — `重点股票/股票报告/`、`docs/daily_reports/`、`历史数据/03_分析报告/` 等保持现有位置
3. **历史报告不改路径** — 已归档历史报告保留当前位置
4. **代码脚本不随意搬迁** — `scripts/` 和 `代码文件/` 的分界维持现状
5. **Schema 迁移保留兼容入口** — 迁移后原位置保留 symlink 或索引，确保现有代码 import 路径不受影响
6. **每次迁移必须有映射表和回滚方案** — 映射表存入 09_迁移计划/
