## 三、执行者身份规则

1. **DeepSeek / Claude / Codex 是执行模型，不是项目角色。**
2. 项目治理主体是项目内 **13 个角色团队**（阿黑、情墨、红结、新安、千光、红枫、腰子、山猫、信鸽、玉夜、流金、青山、旧影）。
3. 执行模型不得自行承担角色职责（如自行做金融分析、自行设计架构等）。
4. 执行模型在 **G3 执行实现**阶段承接编码/文档编写任务。
5. 执行模型不得跳阶段、不得扩大范围、不得绕过验收。

## 六、一键唤醒（第1.5补修）

自第1.5补修起，用户只需一句话唤醒标准流程：

| 用户说 | 阿黑做 |
|:-------|:-------|
| `阿黑，按照标准流程启动：xxx` | 自动路由 → 输出设计 → 等待确认，**不改文件** |
| `阿黑，按照标准流程执行：xxx` | 自动路由 → 若需G1/G2先输出方案 → 确认后执行 |
| `阿黑，复查：xxx` | 读取验收报告 → 对照验收命令 → 输出复查结论 |

**用户无需手填 F-xxx、G0~G6、角色名单。** 阿黑自动完成路由和派单。

自动路由步骤：
1. 读取项目唤醒卡 → 了解项目状态
2. 读取阶段总账 → 了解当前/已完成阶段
3. 读取流程路由表 → 匹配流程编号
4. 读取角色唤醒协议 → 确定唤醒角色
5. 检索相关目录和文件 → 确认影响范围
6. 判断流程编号（F-xxx）
7. 判断阶段门（G0~G6，含跳过理由）
8. 判断是否能执行（是否先需设计）
9. 生成轻量派单卡
