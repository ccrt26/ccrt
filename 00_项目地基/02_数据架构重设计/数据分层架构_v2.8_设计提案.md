# 第一篇：数据分层架构——设计为业务服务

## 1.1 设计动机：当前架构的三个业务瓶颈

### 1.1.1 瓶颈一：D04 未注册，能力链路断裂

`capability_registry.json` 注册了 D01/D03/D05/D06/D07，**D04 是空的**。

```
当前链路：
  D01(信鸽·采集) → D03(玉夜·治理) → D05(青山·证据) → D06(青山·信号) → D07(腰子·解读)

                                                          ↑ 没有D04 ← 所有下游只能拿到当日截面
```

**业务影响**：青山做因子分析只有 16 天历史数据，流金的动态风控无法计算最大回撤，腰子的统一解读缺少历史分位数参照。

### 1.1.2 瓶颈二：保留期设计来自"存证据"思维，不是"做分析"思维

| 指标 | 当前 | 引擎需要 | 业务缺口 |
|:-----|:----|:--------|:---------|
| kline_cache K线 | 122天 | 250天(52周高) | 腰子看不清年线趋势 |
| 评分历史 | 16天 | 750天(因子IC) | 青山无法做因子分析 |
| 财务数据 | 当前季度 | 同比(20个季度) | 估值口径缺同比参照 |
| 冷数据保留 | 90天裁剪 | 永久 | 审计不可追溯 |

**根因**：archive_data.py 的 `RETENTION_DAYS=90` 是从"不要撑爆 git"角度定的，从没问过腰子和青山"你需要多少天"。

### 1.1.3 瓶颈三：冷数据零回读，K线散落三处

`历史数据/04_原始数据/` 37MB的全量快照，**程序没有任何一个地方读它**。

K线数据散落三处且互不同步：
```
代码文件/数据/data_full.json       → KClose 嵌入60天
代码文件/数据/kline_cache/*.json   → K线122天
代码文件/每日荐股/scripts/data_cache/ → technical.py 的另一份K线缓存
```

### 各层存储选型理由

| 层 | 选型 | 为什么不选别的 |
|:---|:-----|:--------------|
| **L1 JSON** | 引擎已写死 `data_full["Stocks"]`，全量4.9MB读毫秒级，git diff 可追踪调试 | 改数据库=破坏引擎，改存储格式=丢 human readable |
| **L2 SQLite** | 索引查询、SQL JOIN（跨期对比/IC需 JOIN score_history+returns）、单文件零运维 | PostgreSQL太重量级，Parquet需要pyarrow依赖，SQLite Python自带 |
| **L3 JSON/年目录** | 永久存档、通用格式、`cp` 就备份、万年后也能读 | 数据库文件有版本兼容风险 |

> **⚠️ L3 存储决策**：L3 JSON 按年分目录存入 git（~176MB/年），与 archive_data.py 原 RETENTION_DAYS=90（防 git 膨胀）存在矛盾。当前决策理由：① 176MB/年在 2026 年 git 承受范围内；② git push 远端 = 天然异地备份。**若未来项目仓库总大小超过 1GB→L3 移出 git 改为独立文件存储，保留本地软链接。**

## 1.6 接口契约矩阵（消费者视角）

| 统一接口 | 用途 | 数据新鲜度 | 响应时间 | 消费方 |
|:---------|:-----|:----------|:--------|:-------|
| `get_quote(code)` | 当前行情读数 | 当日 | <1ms | D05/D06/D07/D08 |
| `get_kline(code, days)` | K线历史查询 | ≤122天:+当日 / >122天:历史 | <10ms | D05/D06/D08 |
| `get_score_history(code, from, to)` | 评分历史追溯 | 95% L2命中 | <50ms | D05/D06/D07 |
| `compare_current_vs_historical(code, field, w)` | 历史分位数 | 当日(缓存) | <10ms | **D07 腰子·统一解读** |
| `compute_factor_ic(factor, w)` | 因子IC计算（仅内置因子①） | 截至昨日 | <5s | **D06 青山·信号** |
| `get_max_drawdown(code)` | 最大回撤 | 最新交易日 | <10ms(缓存命中) / <1s(实时计算降级) | **D08 流金·风控** |
| `export_factor_panel(list, from, to)` | 宽表导出 | 截至昨日 | <30s | **D06 青山·离线分析** |

> ① 内置因子列表：TotalScore, S_Base, S_Fund, S_Tech, S_Money, S_News, S_Risk, S_SectorTrend。自定义因子的 IC 计算由 D06（青山）自行完成，D04 不提供自定义因子 IC 服务。
>
> ② 注：compute_factor_ic、compare_current_vs_historical、get_max_drawdown(实时计算) 当前暂存 D04，属于边界漂移（违背 D04 "只存、索引、查"的定位）。**腰子定调：Phase 3 评估迁移**——compute_factor_ic → D06，compare_current_vs_historical → D07，get_max_drawdown(实时计算) → D08。

> **接口返回格式统一准则（P1 优化项）**：所有接口返回外层包裹标准字典（含 `data_source` 字段），内层携带业务数据。后续迭代中逐步统一为：
> ```python
> {"code": "...", "data_source": "l2|l1|archive",
>  "data": {...}, "requested_at": "2026-06-07T12:00:00"}
> ```

```sql

-- Tier: 2 (日频数据) | TTL: 24h | 访问规则: 盘后更新，盘中读缓存

-- 财务指标表
```

### 2.3.1 初始化与连接

```python
import json, os, sqlite3, logging
from datetime import datetime, timedelta, date
from pathlib import Path
from typing import Optional

class UnifiedDataSource:
    """C-D04-0001 数据中台统一接口"""

    SCHEMA_VERSION = 1    # 表结构版本号，变更时递增

    def __init__(self):
        root = Path(__file__).resolve().parent.parent.parent
        self._l1_dir = root / "代码文件" / "数据"
        self._l2_db = root / "代码文件" / "数据" / "l2_cache" / "l2_cache.db"
```

```python
    # === 因子IC计算（青山信号计算） ===
    def compute_factor_ic(self, factor: str = "S_Tech", window: int = 250) -> dict:
        """每日因子值 vs 次日收益的 Spearman 相关系数

        仅支持内置原子因子：在 score_history 表中有列的字段。
        当前支持的因子列表：TotalScore, S_Base, S_Fund, S_Tech, S_Money,
                            S_News, S_Risk, S_SectorTrend
        自定义因子的IC计算由 D06（青山）自己完成，D04 不提供自定义因子IC服务。
        """
        with self._l2_conn() as conn:
            cur = conn.execute(f"""SELECT s.date, s.{factor} as fv, r.ret_t1
                FROM score_history s JOIN returns r ON s.code=r.code AND s.date=r.date
                WHERE r.ret_t1 IS NOT NULL AND s.date>=date('now','-{window} days')
                ORDER BY s.date, s.{factor} DESC""")
            from collections import defaultdict
            daily = defaultdict(list)
            for row in cur:
                daily[row["date"]].append({"factor": row["fv"], "ret": row["ret_t1"]})
            results = []
            for dt, items in sorted(daily.items()):
                if len(items) < 10: continue
                ic = self._spearman([d["factor"] for d in items], [d["ret"] for d in items])
                results.append({"date": dt, "ic": round(ic, 4), "n_stocks": len(items)})
            if not results:
                return {"factor": factor, "daily_ic": [], "error": "insufficient data",
                        "ret_t1_missing_rate": 1.0, "missing_dates": [],
                        "diagnosis": "returns 表中无 ret_t1 数据，请确认后评估脚本(run_daily_eval)是否已执行",
                        "data_source": "l2_cache"}

            # 统计 ret_t1 缺失率
            total_dates = window if window > 0 else 250
            missing_rate = 1.0 - (len(results) / total_dates)
            all_dates_in_range = sorted(set(
                r["date"] for r in self._query_l2_score_history_all(window)
            ))
            dates_with_data = set(r["date"] for r in results)
            missing_dates = [d for d in all_dates_in_range if d not in dates_with_data]

            ic_vals = [r["ic"] for r in results]
            mean = sum(ic_vals) / len(ic_vals)
            std = (sum((x-mean)**2 for x in ic_vals) / len(ic_vals))**0.5
            return {"factor": factor, "daily_ic": results,
                    "ic_mean": round(mean, 4), "ic_std": round(std, 4),
                    "icir": round(mean/std, 4) if std > 0 else 0, "n_days": len(results),
                    "ret_t1_missing_rate": round(missing_rate, 4),
                    "missing_dates": missing_dates[:20],  # 只返回前 20 条缺失日期
                    "diagnosis": "数据完整" if missing_rate < 0.1 else f"ret_t1 缺失 {missing_rate*100:.1f}%，请检查后评估是否漏跑",
                    "data_source": "l2_cache"}
```

```python
    # === 数据库连接 ===
    def _l2_conn(self):
        self._ensure_l2_db()
        conn = sqlite3.connect(str(self._l2_db))
        conn.row_factory = sqlite3.Row
        conn.execute("PRAGMA journal_mode=WAL")  # M17: 提升读并发
        return conn

    def _ensure_l2_db(self):
        if self._l2_db.exists():
            with sqlite3.connect(str(self._l2_db)) as conn:
                ver = conn.execute("PRAGMA user_version").fetchone()[0]
                if ver == self.SCHEMA_VERSION: return
                # M2: 逐版本迁移
                migrations = {}
                for v in range(ver+1, self.SCHEMA_VERSION+1):
                    for sql in migrations.get(v, []):
                        conn.execute(sql)
                conn.execute(f"PRAGMA user_version = {self.SCHEMA_VERSION}")
                conn.commit()
            return
        # 首次创建
        self._l2_db.parent.mkdir(parents=True, exist_ok=True)
        conn = sqlite3.connect(str(self._l2_db))
        conn.executescript("""CREATE TABLE kline (...) ... 所有7张表""")
        conn.execute(f"PRAGMA user_version = {self.SCHEMA_VERSION}")
        conn.commit()
        conn.close()

    def _read_l2_kline(self, code: str, days: int) -> list:
        with self._l2_conn() as conn:

            if cnt == 0:
                logging.warning(f"D04 L2 空数据: {code}, 降级到L1")
                l1_bars = self._read_l1_kline(code)
                for b in l1_bars:
                    b["data_source"] = "fallback_l1"
                return l1_bars   # M1: 降级但不归零
            cur = conn.execute("SELECT date,open,high,low,close,volume,quality_flag FROM kline "
                               "WHERE code=? ORDER BY date ASC LIMIT ?", (code, days))

            for b in bars:
                b["data_source"] = "l2_cache"
            return bars

    @staticmethod
    def _is_trading_day(check_date: str) -> bool:
        """交易日判断——统一基准函数
        
        调用 is_market_open.py 脚本判断。
        全代码所有涉及"今天"的日期判定必须走此函数，不得用自然日替代。
        腰子定调："交易日统一基准原则"——任何新加日期判断都必须走此函数。
        """
        import subprocess
        try:
            script = Path(__file__).parent / "scripts" / "is_market_open.py"
            if script.exists():
                result = subprocess.run(["python3", str(script), check_date],
                                        capture_output=True, timeout=10)
                return result.returncode == 0
        except Exception as e:
            logging.error(f"交易日判断失败({check_date}): {e}——默认非交易日，不触发L1降级")
        return False  # 判断失败时默认 False（保守模式），不走 L1 降级

    def _check_sentinel(self):

        哨兵状态为 WARN_LOW_DATA 且当前为交易日时 → _l2_ready = False
        哨兵状态为 OK / 非交易日 → _l2_ready = True

        sf = Path("代码文件/数据/l2_cache/last_update.txt")
        if not sf.exists():
            logging.warning("D04 L2 哨兵文件不存在——可能从未更新")
            self._l2_ready = False
            return

        age = (datetime.now() - datetime.fromisoformat(s["last_update"])).total_seconds() / 3600
        today_str = datetime.now().strftime("%Y-%m-%d")
        status = s.get("status", "OK")

        # 核心判断逻辑：交易日 + 数据异常 → 切 L1
        if self._is_trading_day(today_str) and status in ("WARN_LOW_DATA", "FAIL"):
            logging.error(f"D04 L2 哨兵异常({status}), 降级到 L1")
            self._l2_ready = False
        else:
            self._l2_ready = True

        if age > 24:

    # === 一致性校验（M12） ===
    def verify_consistency(self, sample_size: int = 10) -> list:
        """返回差异列表，而非 assert

        校验范围：
          1. K线 close（L1 vs L2）——必须 < 0.5% 相对差异
          2. 评分数据（L1 data_scored vs L2 score_history）——TotalScore 必须一致
          3. 财务数据（L1 Financials vs L2 financials）——EPS/BPS 偏差 < 1%
        """
        codes = [s["Code"] for s in self.get_all_stocks() if s.get("Code")]
        import random
        sample = random.sample(codes, min(sample_size, len(codes)))
        failures = []

        today = datetime.now().strftime("%Y-%m-%d")
        for code in sample:
            # 检查 1：K线 close 一致性
            l1 = self._read_l1_kline(code)
            l2 = self._read_l2_kline(code, 1)
            if l1 and l2:
                l1c, l2c = l1[-1]["close"], l2[-1]["close"]
                diff_pct = abs(l1c - l2c) / max(l1c, l2c) if max(l1c, l2c) > 0 else 0
                if diff_pct > 0.005:
                    failures.append({"type": "kline_close", "code": code,
                                     "l1": l1c, "l2": l2c, "diff_pct": round(diff_pct*100, 2)})

            # 检查 2：评分数据一致性
            scored = self._load_data_full().get("Stocks", [])
            l1_score = next((s.get("TotalScore") for s in scored if s.get("Code") == code), None)
            if l1_score is not None:
                with self._l2_conn() as conn:
                    cur = conn.execute(
                        "SELECT total_score FROM score_history WHERE code=? ORDER BY date DESC LIMIT 1", (code,))
                    row = cur.fetchone()
                    if row and row["total_score"] != l1_score:
                        failures.append({"type": "score", "code": code,
                                         "l1_score": l1_score, "l2_score": row["total_score"]})

            # 检查 3：财务数据一致性
            with self._l2_conn() as conn:
                cur = conn.execute(
                    "SELECT eps FROM financials WHERE code=? ORDER BY report_date DESC LIMIT 1", (code,))
                l2_eps = cur.fetchone()
                # L1 财务数据目前不在 data_full.json 顶层，跳过 L1 对比
                # 只做 L2 财务数据的合理性检查
                if l2_eps and l2_eps["eps"] is not None and l2_eps["eps"] < 0:
                    failures.append({"type": "financial_eps_negative", "code": code,
                                     "l2_eps": l2_eps["eps"]})

        # 写入失败记录（供旧影审计 H-2 查阅）
        if failures:
            Path("代码文件/数据/l2_cache/consistency_failures.jsonl").open("a").write(
                json.dumps({"timestamp": datetime.now().isoformat(), "sample_size": sample_size,
                            "failures": failures}) + "\n")
        return failures

    @staticmethod
    def _spearman(x: list, y: list) -> float:
        """Spearman 秩相关系数——自动过滤 NULL/None 值"""
        # 过滤掉 x 或 y 中为 None/NaN 的配对
        clean = [(a, b) for a, b in zip(x, y) if a is not None and b is not None]
        if len(clean) < 10: return 0.0  # 样本太少不计算
        xc, yc = zip(*clean)
        n = len(xc)
        xr = {v: i for i, v in enumerate(sorted(set(xc)))}
        yr = {v: i for i, v in enumerate(sorted(set(yc)))}
        d = sum((xr[a]-yr[b])**2 for a, b in zip(xc, yc))
        return 1 - (6*d)/(n*(n**2-1)) if n > 1 else 0.0
```

**重试机制（指数退避）**：

```python
import time, random, logging, os

def tushare_request_with_retry(fn, max_retries=3, base_delay=3.0):
    """tushare API 调用通用重试包装

    策略：指数退避 + 随机抖动
    第1次失败 → 等待 3s
    第2次失败 → 等待 6s (加倍)
    第3次失败 → 等待 12s (加倍) + 0-3s 随机抖动
    3次均失败 → 抛出异常，由调用方处理
    """
    for attempt in range(max_retries):
        try:
            result = fn()
            if result is not None and (isinstance(result, list) and len(result) > 0):
                return result
            if isinstance(result, dict) and result.get("items"):
                return result
        except Exception as e:
            logging.warning(f"tushare 请求失败 (第{attempt+1}次): {e}")
        if attempt < max_retries - 1:
            delay = base_delay * (2 ** attempt) + random.uniform(0, 3)
            time.sleep(delay)
    raise RuntimeError(f"tushare 请求重试{max_retries}次均失败")
```

```python
class TushareRateLimiter:
    """tushare 调用频率限制器"""
    def __init__(self, min_interval=3.1):
```

### 2.5.5 数据口径标准化

**问题**：L1（通达信来源）、L2（tushare 来源）、L3（归档快照）三套数据源的 K 线复权规则可能不一致。tushare 默认返回前复权，而 L1 kline_cache 可能为不复权或后复权。同一天同一只股票跨层查询时口径分裂，导致技术指标断层、因子收益计算失真。

**规则**：
```
所有写入 L2 的 K 线统一为前复权。
L1 作为原始缓存保持原样（不复权），标注 adjust_flag = 'none'。
L2 数据写入时标注 adjust_flag = 'forward'。
L3 归档以 L2 为准，标注 adjust_flag = 'forward'。
```

**实现**：

```python
# update_l2_cache.py 写入 L2 时强制前复权标准化
def standardize_adjustment(row: dict) -> dict:
    """K 线口径标准化：统一为前复权

    当前策略：tushare 已返回前复权数据，直接透传。
    如果未来接入其他数据源（东方财富/新浪），在此函数中做复权转换。
    """
    row["adjust_flag"] = "forward"  # 标注复权方式
    # 数据源校验：close 不应为 0 或负数
    if row.get("close", 0) <= 0:
        logging.warning(f"K线 close 异常: {row.get('code')} {row.get('date')} close={row.get('close')}")
    return row
```

**复权交叉校验**（写入 L2 前自动执行）：

```python
def verify_adjustment_consistency(l1_close: float, l2_close: float, code: str, date: str):
    """L1（不复权）vs L2（前复权）的同日期收盘价交叉校验

    规则：偏差 > 1% 时告警+人工复核，不阻断写入（偏差可能因除权正常导致）
    """
    if l1_close is None or l2_close is None or l1_close <= 0 or l2_close <= 0:
        return  # 数据不完整，跳过校验
    diff_pct = abs(l1_close - l2_close) / max(l1_close, l2_close)
    if diff_pct > 0.01:  # 偏差超过 1%
        logging.warning(
            f"口径偏差告警: {code} {date} L1_close={l1_close} L2_close={l2_close} "
            f"偏差={diff_pct*100:.2f}%"
        )
        # 写入偏差记录（供旧影 H-3 审计查阅）
        with open("代码文件/数据/l2_cache/adjustment_deviation.log", "a") as f:
            f.write(f"{datetime.now().isoformat()} | {code} | {date} | "
                    f"L1={l1_close} | L2={l2_close} | {diff_pct*100:.2f}%\n")

# 在 update_l2_cache.py 中调用
```

### quality_flag 传递规则

**设计原则**：L1 是原始缓存，不确定质量 → `unverified`。只有经过 D03 治理验证的数据才标 `complete`。D04 不自行判定数据质量。

**边界值定义**：

| quality_flag | 优先级 | 含义 | 来源 | 谁设置 |
|:-------------|:------:|:-----|:-----|:-------|
| `complete` | **4** | 数据经过 D03 治理验证，质量可靠 | D03 产出 | D03 玉夜 |
| `pending_review` | **3** | 数据已写入但 D03 尚未验证 | L1→L2 同步默认值 | D04 红结 |
| `unverified` | **2** | 数据来源不明或未治理 | L1 原始缓存无 quality_flag 时的兜底 | D04 红结 |
| `invalid` | **1** | 数据非法（close≤0、high<low 等） | D04 写入层自行判断 | D04 红结 |

> ⚠️ **quality_flag 比较必须用数字优先级，不得直接用字符串比较**。因为字符串 `"pending_review" >= "complete"` 在字典序下为 True，但语义上 pending_review(3) < complete(4) 应为 False。违反此规则将导致脏数据覆盖干净数据。

**L1→L2 同步时的兜底逻辑**：

```python
# 从 L1 读取 K 线写到 L2 时
if l1_row.get("quality_flag") is None:
    # L1 没有 quality_flag → 标 pending_review（非 complete）
    quality_flag = "pending_review"
else:
    # L1 有 quality_flag → 透传
    quality_flag = l1_row["quality_flag"]
```

**L1 数据合法性校验**（写入 L2 前执行）：

```python
        return "invalid"

```

```python
def get_kline_batch_safe(self, codes: list, days: int = 60) -> dict:
    """分页批量查询——防止 IN 参数超过 SQLite 变量上限"""

                FROM kline WHERE code IN ({ph}) ORDER BY code, date

                c = row["code"]
                if result[c] is None: result[c] = []
                result[c].append(dict(row))

    import pandas as pd

                            f"WHERE date BETWEEN '{date_from}' AND '{date_to}' "

                         f"WHERE code IN ({ph}) AND date BETWEEN ? AND ? ORDER BY date, code",
                         conn, params=codes + [date_from, date_to])

            "dates": sorted(df["date"].unique()),
            "panels": {f: df.pivot_table(index="date", columns="code", values=f).fillna(0).values.tolist()
```

```python
def write_checksum():
    with l2_conn() as conn:
        summary = {}
        for table in ["kline", "score_history", "returns", "risk_metrics"]:
            cur = conn.execute(f"""SELECT COUNT(*) as rows,
                COALESCE(ROUND(AVG(close),2),0) as avg_close,
```

```python
def _ensure_l2_db(self):
    if self._l2_db.exists():
        with sqlite3.connect(str(self._l2_db)) as conn:
            ver = conn.execute("PRAGMA user_version").fetchone()[0]
            if ver == self.SCHEMA_VERSION:
                return
            # 迁移前备份（回滚依据）
            import shutil
            backup_path = str(self._l2_db) + f".pre_v{self.SCHEMA_VERSION}"
            if not os.path.exists(backup_path):
                shutil.copy2(str(self._l2_db), backup_path)

            migrations = {
                1: ["ALTER TABLE kline ADD COLUMN turnover REAL"],
                2: ["ALTER TABLE macro ADD COLUMN region TEXT DEFAULT 'CN'"],
            }
            try:
                for v in range(ver+1, self.SCHEMA_VERSION+1):
                    for sql in migrations.get(v, []):
                        conn.execute(sql)
                conn.execute(f"PRAGMA user_version = {self.SCHEMA_VERSION}")
```

### 3.5.2 L3 快照与 L1/L2 的一致性校验

```python
def verify_archive_consistency(archive_date: str):
    """L3 快照生成后，与 L1/L2 抽样对比关键字段"""
    # 从 L3 归档文件读取
    archive_path = f"历史数据/04_原始数据/{archive_date[:4]}/{archive_date}_data_final.json"
    archive = json.load(open(archive_path))
    archive_stocks = {s["Code"]: s for s in archive.get("Stocks", []) if s.get("Code")}

    # 从 L1 读取
    l1 = json.load(open("代码文件/数据/data_full.json"))
    l1_stocks = {s["Code"]: s for s in l1.get("Stocks", []) if s.get("Code")}

    # 抽样 10 只比对 TotalScore
    import random
    common_codes = list(set(archive_stocks) & set(l1_stocks))
    sample = random.sample(common_codes, min(10, len(common_codes)))
    mismatches = []
    for code in sample:
        a = archive_stocks[code].get("TotalScore")
        b = l1_stocks[code].get("TotalScore")
        if a is not None and b is not None and a != b:
            mismatches.append(f"{code}: L3={a} L1={b}")

    if mismatches:
        logging.error(f"L3 归档一致性校验失败: {mismatches}")
        # 写入失败记录（供旧影审计查阅）
        with open("历史数据/04_原始数据/archive_consistency_failures.log", "a") as f:
            f.write(f"{datetime.now().isoformat()} | {archive_date} | {mismatches}\n")
        return False
    return True
```

### 3.5.4 L3 归档元数据索引

**问题**：L3 周级快照逐年累积，审计追溯特定日期/特定股票时需要遍历目录查找，效率低。

**方案**：每次周级归档生成时同步更新 `历史数据/04_原始数据/archive_index.json`：

```python
# archive_data.py 归档时追加索引
def update_archive_index(archive_date: str, stocks: list):
    index_path = "历史数据/04_原始数据/archive_index.json"
    index = {}
    if os.path.exists(index_path):
        index = json.load(open(index_path))

    year = archive_date[:4]
    if year not in index:
        index[year] = {"files": [], "stock_count": 0, "date_range": [archive_date, archive_date]}

    # 追加本次归档记录
    index[year]["files"].append({
        "date": archive_date,
        "filename": f"{archive_date}_data_final.json",
        "stock_count": len(stocks),
        "codes": [s["Code"] for s in stocks if s.get("Code")][:5],  # 只存前5个供预览
    })
    index[year]["stock_count"] = len(stocks)
    index[year]["date_range"][1] = archive_date  # 更新最晚日期

    json.dump(index, open(index_path, "w"), ensure_ascii=False, indent=2)
```

**索引结构示例**：

```json
{
  "2026": {
    "files": [
      {"date": "20260605", "filename": "20260605_data_final.json", "stock_count": 200, "codes": ["600114", "002230", ...]},
      {"date": "20260612", "filename": "20260612_data_final.json", "stock_count": 198, "codes": [...]}
    ],
    "stock_count": 200,
    "date_range": ["2026-06-05", "2026-06-12"]
  }
}
```

**审计用途**：旧影月检 H-6 直接读 `archive_index.json` 即可获取归档结构和日期范围，无需遍历目录。


```
检测者: 旧影周检 H-3 FAIL

流程:
  1. 旧影记录 FAIL（P0 级）→ 立即通知千光+红结
  2. 一键降级：通知所有消费方（D05/D06/D07/D08）切到 L1 JSON 直读
  3. 从 l2_cache/backup/ 恢复最近备份
     → cp backup/l2_cache_{latest}.db l2_cache.db
  4. 验证完整性：PRAGMA integrity_check → ok
  5. 切回 D04：通知消费方恢复正常
  6. 旧影确认 H-3 PASS → 关闭 FAIL

恢复时效: 1 小时内
参与方: 旧影(发现) → 千光(恢复) → 红结(确认) → 旧影(复核)
注意: 过程中 L1 JSON 不停服务，仅 L2 分析型查询不可用
```

### 场景4：L3 归档文件损坏（审计发现）

```
触发条件: 最近 3 个归档文件中有 ≥2 个 JSON 解析失败
检测者: 旧影月检 H-6 FAIL

流程:
  1. 旧影记录 FAIL → 通知玉夜
  2. 玉夜检查 L1 是否有对应日期的完整数据
  3. 重新归档：
     → 从 L1 data_full.json 重新生成归档文件
     → 写入 L3 年目录
  4. 玉夜确认归档文件可解析
  5. 旧影月检复查 PASS → 关闭 FAIL

恢复时效: 当天内
参与方: 旧影(发现) → 玉夜(修复) → 旧影(复核)
```

### 场景5：D04 整体不可用（紧急）

```
触发条件: 任何检查项产生不可恢复的红牌（如 SQLite 损坏且备份也损坏）
检测者: 任何角色

流程:
  1. 即时通知全团
  2. 紧急降级:
     → D05/D06/D07/D08 所有 UnifiedDataSource 调用改为 L1 JSON 直读
     → 回滚方式：去掉 `ds = UnifiedDataSource()`，改回 `json.load(open("data_full.json"))`
     → 降级期间 L2 分析服务（跨期对比/IC计算/风控预计算）不可用
  3. 重建 D04：
     → 重新执行 build_l2_cache.py（~30分钟）
  4. 恢复后切回 D04
  5. 旧影执行全量 H-1~H-8 检查
  6. 所有 PASS 后关闭紧急状态

恢复时效: 30 分钟完成降级，2 小时内完成重建
参与方: 全团
```

## 5.5 D04 需求变更流程

**目的**：防止 D04 随意膨胀——新增接口/指标/预计算能力必须经过评审。

**触发条件**：任何人（青山/流金/腰子/信鸽）希望 D04 新增一项预计算指标或数据服务。

**流程**：

```
提出需求 → 玉夜评估 → 情墨审批 → 红结实现 → 旧影审计
  │          │           │          │          │
 青山/流金   ① D04是否   ③架构评审   ④编码实现  ⑤上线后
 腰子/信鸽   适合承载？   签字放行    +GM验证   首轮审计
  提需求     ② 还是应
             放在 D05/
             D06/D08？
```

**详细步骤**：

| 步骤 | 角色 | 动作 | 时限 | 输出 |
|:-----|:-----|:-----|:-----|:-----|
| 1 | 需求方 | 填写"D04 新指标申请表"（新增接口名、输入、输出、消费场景） | — | 申请表 |
| 2 | **玉夜** | 评估：① 该指标是否属于 D04 能力域（存/索引/查/预计算）？② 是否应归属 D05/D06/D08？③ 是否有已有接口可替代？ | 1 个工作日 | 评估意见（通过/转交/拒绝） |
| 3 | **情墨** | 架构评审：是否影响现有接口契约？code_level 是否需要变更？是否触发 Golden Master？ | 1 个工作日 | 签字放行 |
| 4 | **红结** | 编码实现，追加 Golden Master 回归测试 | 按复杂度 | 代码+GM验证通过 |
| 5 | **旧影** | 上线后首轮审计：检查接口契约是否更新、数据源标注是否完整、审计项是否覆盖 | 上线后 3 天内 | 审计关闭 |

**拒绝案例**：
| 需求 | 拒绝原因 | 转交 |
|:-----|:---------|:-----|
| "我想在 D04 加一个回测接口" | 回测是 D06 的职责 | → 青山 D06 |
| "D04 能不能直接输出交易信号" | 交易决策是场景编排层 | → 场景编排 |
| "加一个新的自定义因子的 IC 计算" | 自定义因子 IC 应由 D06 完成 | → 青山 D06 |
