# 变更生命周期与阶段门

> 版本: 1.0 | 创建: 2026-06-02 | 维护人: 阿黑+情墨

---

## 一、阶段门定义

项目所有变更必须经过以下阶段门。任何变更**不得默认直接进入 G3**。

| 阶段门 | 名称 | 作用 | 可否跳过 |
|:------:|:-----|:------|:--------:|
| **G0** | 需求识别与流程路由 | 判断任务属于哪个流程编号，确定启用/跳过的阶段门 | 不可跳过 |
| **G1** | 业务/金融/角色口径设计 | 金融分析、角色解释、业务规则先定稿 | 金融分析变更不可跳过 |
| **G2** | 技术方案设计 | 决定改哪些文件、脚本、schema、闸门 | 定点修复可简化 |
| **G3** | 执行实现 | 执行模型编码/改文档 | 不可跳过 |
| **G4** | 执行者自检 | 执行者跑命令并写执行报告 | 不可跳过 |
| **G5** | 独立复查 | 旧影/阿黑复查，不通过则补修 | 不可跳过 |
| **G6** | 放行归档 | 腰子/阿黑放行，总账更新 | 不可跳过 |

---

## 二、跳过阶段门规则

| 阶段门 | 跳过的条件 |
|:------:|:-----------|
| **G1** | 仅当变更不涉及金融分析逻辑、角色协作口径、业务规则。如：纯闸门脚本新增、目录迁移、定点数据修复（依据已明确的规则）。必须说明依据。 |
| **G2** | 仅当变更范围极小且方案明确无需设计评审（如：定点修复一个已知的字段值）。必须说明依据。 |

---

## 三、不可绕过规则

| 规则 | 说明 |
|:-----|:------|
| ⛔ 金融分析逻辑变更必须经过 G1 | 技术团队不得反向决定金融口径 |
| ⛔ 角色协作变更必须经过 G1 | 解释对象、角色边界调整必须先定口径 |
| ⛔ 后评估评分口径变更必须经过 G1 | 评分规则、胜率判定标准调整必须先定规则 |
| ⛔ 闸门/脚本变更必须经过 G2 | 新增/修改检查脚本必须设计字段映射和检查逻辑 |
| ⛔ 任何变更不得默认直接进入 G3 | 必须先走 G0 路由 |

---

## 四、阶段门启用声明

每个阶段报告必须声明：
- **启用阶段门**：实际启用了哪些
- **跳过阶段门**：跳过了哪些，并说明原因

## 五、典型流程路径

| 流程 | 路径 |
|:-----|:------|
| **F-ANALYSIS**（分析逻辑变更） | `G0 → G1 → G2 → G3 → G4 → G5 → G6` |

| **F-MIGRATE**（目录迁移） | `G0 → G2 → G3 → G4 → G5 → G6` |
| **F-FEATURE**（功能新增） | `G0 → G1 → G2 → G3 → G4 → G5 → G6` |
| **F-KNOW**（知识进化） | `G0 → G1 → G2 → G3 → G4 → G5 → G6` |
| **F-EVAL**（后评估变更） | `G0 → G1 → G2 → G3 → G4 → G5 → G6` |
