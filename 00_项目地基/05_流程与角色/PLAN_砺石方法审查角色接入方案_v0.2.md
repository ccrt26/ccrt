# PLAN：砺石方法审查角色接入方案 v0.2

> 状态：方案稿，未进入正式落地  
> 目的：定义新增“砺石”方法校准角色的职责、场景接入方式、知识库进化路径与后续程序落地边界  
> 适用流程：F-ROLE + F-ANALYSIS + F-KNOW  
> 当前阶段：G1/G2 方案设计，不等同于角色正式启用  
> 代码名建议：LISHI

---

## 1. 前置结论

本方案建议新增角色 **砺石**，定位为金融分析链路中的 **方法校准官 / 反证审查官**。

砺石不输出投资方向，不参与多数投票，不替代腰子裁决，也不替代旧影审计。其核心价值是：

```text
在腰子形成最终金融结论前，为结论提供方法校准参考，审查推理链是否存在隐含假设、同源证据重复计票、反证不足、相关性误作因果、结论强度过高、群体共识污染等问题。
```

砺石不是“反对者”，而是“校准者”。其目标是提升结论鲁棒性，而非单纯否定现有推理。

场景接入采用分层策略：

| 场景 | 接入策略 | 说明 |
|:-----|:---------|:-----|
| 日报 | 灰度影子接入 | 初期仅抽取 10%-20% 样本，不改正文结构 |
| 深度分析 | 关键节点影子接入 | 审风险章后、综合结论前，并抽查核心推理章 |
| 每日荐股 | 优化期预留接入 | 场景未定稿，后续优化时同步设计砺石节点 |
| 模拟交易 | 优化期预留接入 | 场景未定稿，后续优化时同步设计砺石节点 |
| 保护机制 | 暂不接入 | 用户计划后续去除 |
| 临时分析 | 暂不接入 | 用户计划后续去除 |

闸门策略：

```text
第一阶段不新增 U-11。
先将砺石审查并入 U-9 的方法审查扩展，待效果经后评估验证后，再评估是否独立为 U-11 方法审查闸门。
```

## 2. 角色定位

### 2.1 角色名称

```text
角色名：砺石
代码名：LISHI
角色线：金融线 / 方法校准
角色定位：方法校准官、反证审查官
```

“砺石”的命名含义是磨砺结论，让结论在被挑战和校准后仍能站住。

### 2.2 一句话职责

```text
砺石负责审查金融结论的推理链质量，为腰子提供方法校准参考，不负责给出投资方向。
```

### 2.3 协同边界

| 角色 | 核心审查维度 | 砺石的差异化边界 |
|:-----|:-------------|:-----------------|
| 旧影 | 流程合规性、阶段复查 | 砺石审推理逻辑合理性，不审流程合规 |
| 青山 | 信号有效性、因子胜率、后评估 | 砺石不审信号对不对，审用信号推导结论是否合理 |
| 腰子 | 最终裁决、结论整合 | 砺石不替代决策；腰子驳回砺石建议时需记录理由 |
| 玉夜 | 数据事实准确性、数据源状态 | 砺石不审数据真假，审数据到结论的推导是否合理 |
| 流金 | 风控边界、仓位、止损、动作审计 | 砺石不设风控边界，审动作强度是否被证据支持 |

### 2.4 能做

- 识别显性假设和隐性假设。
- 检查多角色证据是否同源重复。
- 提出最强反论证。
- 提出替代解释。
- 检查相关性是否被写成因果。
- 检查结论强度是否超过证据强度。
- 检查失效条件是否具体、可验证。
- 对反证质量评分，识别套话反证。
- 建议腰子降低置信度、降低动作强度或暂缓动作。
- 在未来已定稿的强动作场景中给出 WARN / BLOCK。

### 2.5 不能做

- 不给 BUY / SELL / HOLD / WATCH 方向。
- 不替代腰子裁决。
- 不替代玉夜确认数据事实。
- 不替代流金设定仓位、止损、冷却期。
- 不替代青山解释信号有效性。
- 不替代旧影做流程审计。
- 不以否定现有推理为目标；核心目标是提升结论鲁棒性。

## 3. 场景接入方案

### 3.1 日报：灰度影子接入

日报已经基本定稿，砺石不应打乱正文结构。

初期建议只对 10%-20% 日报样本进行影子审查，不默认影响日报正文和操作建议生成效率。

建议接入点：

```text
玉夜 / 山猫 / 信鸽 / 青山 / 流金
  -> 砺石灰度影子审查
  -> 腰子整合
  -> U-9 / U-10
  -> 日报生成
```

日报只检查六项：

| 检查项 | 目标 |
|:-------|:-----|
| 有效反证 | 防止只填套话反证 |
| 反证质量评分 | 评分 <= 2 时触发 WARN |
| 同源证据 | 防止多角色重复引用同一事实造成假共识 |
| 相关性/因果 | 防止“因为 X 所以一定 Y” |
| 结论强度 | 防止 WATCH 级证据写成 BUY |
| 失效条件 | 防止失效条件不可观察、不可验证 |

建议结构化字段：

```json
{
  "method_review": {
    "challenge_id": "",
    "role": "砺石",
    "role_code": "LISHI",
    "result": "PASS|WARN|BLOCK",
    "main_challenge": "",
    "check_item": "counter_evidence|same_source|causality|conclusion_strength|invalidation",
    "anti_evidence_quality": 1,
    "confidence_adjustment": "NONE|HIGH_TO_MEDIUM|MEDIUM_TO_LOW",
    "adjustment_reason": "",
    "action_adjustment": "NONE|BUY_TO_WATCH|SELL_TO_WATCH",
    "review_time_budget": "5m",
    "review_time_actual": ""
  }
}
```

日报处置规则：

| 砺石结果 | 日报处理 |
|:---------|:---------|
| PASS | 正常进入腰子整合 |
| WARN | 降低置信度或在结构化对象中标注，不默认改正文 |
| BLOCK | 仅在强动作场景阻断；灰度期先记录，不直接改正文 |

### 3.2 深度分析：关键节点影子接入

深度分析也基本定稿，不建议每章都加入砺石。

建议固定审查两个位置：

```text
第八章 风险结论后
第九章 综合结论 / 操作建议前
```

同时新增核心推理章抽查机制：

```text
若“核心投资逻辑”或同等核心推理章节依赖单一信号、单一事件、单一数据源或单一假设，砺石必须进行针对性审查。
```

深度分析砺石输出应比日报更完整，但仍建议先放入附录或结构化 sidecar，不影响正文主结构。

输出字段：

```text
explicit_assumptions：显性假设，正文已写明
implicit_assumptions：隐性假设，正文未写明但推理依赖
最强反论证
替代解释
同源证据风险
结论强度校验
需要腰子回应的问题
anti_evidence_quality：1-5
review_time_budget：15m
review_time_actual
结论：PASS / WARN / BLOCK
```

处置规则：

| 砺石结果 | 深度分析处理 |
|:---------|:-------------|
| PASS | 综合结论正常生成 |
| WARN | 腰子必须在裁决理由中回应 |
| BLOCK | 综合结论不得输出强动作，需补充证据或降级 |

### 3.3 每日荐股：优化期预留接入

每日荐股后续仍要优化，因此不应把砺石强行接入当前未定稿流程。

这里的“接入”不是现在落程序闸门，也不是把现有每日荐股流程立即改成砺石参与；更准确的含义是：

```text
在每日荐股下一轮优化方案中，把砺石作为流程节点、字段需求、触发阈值、后评估指标一起纳入设计。
```

建议未来节点：

```text
候选池评分
  -> 青山信号验证
  -> 流金风控边界
  -> 砺石方法校准
  -> 腰子最终入选 / 剔除 / 降级
  -> U-9 / U-10 / eval_hook
```

推荐位置：

```text
青山信号验证后、腰子裁决前。
```

未来触发条件建议先预留，不写死数值：

| 触发条件 | 说明 |
|:---------|:-----|
| HIGH 置信候选 | 当前体系若无百分制，不使用“80%”硬阈值 |
| BUY / SELL 强动作候选 | 强动作优先审 |
| Top N 入围候选 | N 在每日荐股主流程优化时确定 |
| 单一信号推高候选 | 防止单一证据支撑强结论 |
| 候选分歧较大 | 多角色输入不一致时触发 |

快速通过机制：

```text
可设计“快速通过”，但不设置无审查白名单。
任何快速通过都必须记录理由，并进入后评估。
强动作不得完全豁免砺石审查。
```

未来可能的处置规则：

| 砺石结果 | 每日荐股处理 |
|:---------|:-------------|
| PASS | 保留候选 |
| WARN | 降低置信度、降低排名或 BUY 降为 WATCH |
| BLOCK | 移出荐股列表，记录为“方法审查剔除” |

### 3.4 模拟交易：优化期预留接入

模拟交易后续仍要优化，因此不应在当前未定稿交易链路中先写死砺石闸门。

这里的“接入”不是现在拦截交易，也不是先改现有执行器；更准确的含义是：

```text
在模拟交易下一轮优化方案中，把砺石设计成可选的交易前方法校准节点，并预留后评估字段。
```

推荐位置：

```text
风控确认后、腰子动作确认前。
```

建议未来节点：

```text
交易信号触发
  -> 青山确认信号
  -> 流金确认仓位 / 止损 / 冷却期
  -> 砺石快速方法校准
  -> 腰子确认动作
  -> 下单 / 取消 / 降级
```

未来触发条件建议先预留，不写死金额：

| 触发条件 | 说明 |
|:---------|:-----|
| BUY / SELL 强动作 | 强动作优先审 |
| 单票仓位超过阈值 | 阈值在模拟交易主流程优化时确定 |
| 单日交易金额超过阈值 | 阈值在模拟交易主流程优化时确定 |
| 单一信号触发动作 | 防止信号孤证驱动交易 |
| 近期同类失败样本存在 | 先作为 L5-seed，验证后再升级 |

未来可能的处置规则：

| 砺石结果 | 模拟交易处理 |
|:---------|:-------------|
| PASS | 正常交易 |
| WARN | 仓位减半、BUY 改 WATCH、延迟确认 |
| BLOCK | 禁止下单 |

模拟交易后续若正式接入，后评估必须统计：

```text
砺石拦下的交易如果执行会怎样
砺石降级的交易是否改善回撤
砺石误 BLOCK 的机会成本
砺石 WARN 后的收益/风险变化
```

### 4.4 字段校验规则

```text

若 confidence_adjustment != NONE，则 adjustment_reason 不能为空。
若 anti_evidence_quality <= 2，则 result 至少为 WARN。
若 action_adjustment != NONE，则必须说明对应的结论强度问题。
若腰子驳回砺石建议，则必须记录 rejected_reason，进入后评估。
```

## 5. 知识库与知识进化接入

砺石需要独立知识库，但其知识类型不是股票事实，而是方法审查规则。

### 5.1 建议新增文件

```text
统一解读/角色解释包/砺石_方法审查包.md
00_项目地基/07_知识进化/knowledge/roles/lishi/01_角色职责.md
统一解读/六库/方法反证库_v1.0.md
```

### 5.2 初期优先落地规则

第一阶段只落三类高频高影响规则，避免初期规则过多导致输出复杂：

```text
同源证据识别
因果混淆识别
结论强度校验
```

后续再逐步加入：

```text
失败样本相似性
过度一致预警
动作降级规则
行业/风格场景化反证规则
```

### 5.3 来源等级原则

砺石初始方法知识不得默认成为强动作依据。

| 知识类型 | 初始等级 |
|:---------|:---------|
| 外部方法论 | L4 |
| 项目经验总结 | L5 |
| 未验证反证模式 | L5-seed |
| 失败样本相似性规则 | L5-seed |
| 经后评估验证有效的方法规则 | L2 |

### 5.4 失败样本相似性标签

失败样本相似性不应使用单一通用规则，应绑定场景标签：

```text
行业/风格：消费股 / 周期股 / 科技股 / 金融股 / 资源股
驱动类型：财报驱动 / 政策驱动 / 资金驱动 / 事件驱动 / 技术驱动
动作类型：买入 / 卖出 / 加仓 / 减仓 / 观察
市场环境：趋势上涨 / 震荡偏多 / 震荡 / 震荡偏空 / 趋势下跌
```

### 5.5 纳入 15 步知识进化状态机

砺石知识必须进入现有知识进化流程：

```text
SourceCandidate
-> QualityScore
-> LiteratureCard
-> RuleCandidate
-> RuleCandidateValidationTask
-> ScenarioTrace
-> WeeklyValidationSummary
-> ValidationReview
-> RoleConfirmation
-> KnowledgeMergeCheck
-> PromotionDecision
-> ActiveRule
-> KnowledgeAdoptionRecord
-> PerformanceMonitor
-> RoleKnowledgeMetrics
```

禁止将单次成功挑战直接升级为 active rule。

### 5.6 离线模拟审查

在进入在线流程前，建议先用历史报告做离线模拟审查：

```text
样本范围：过去 3 个月日报 / 深度分析样本
方法：用砺石规则离线复审历史解释链
目标：验证是否能识别当时未被处理的推理漏洞
输出：规则命中率、有效挑战率、误伤率、可解释案例
```

离线模拟审查可以加速 L5-seed 规则验证，但不能替代正式知识进化流程。

### 5.7 砺石指标

建议新增 RoleKnowledgeMetrics：

```text
挑战次数
被腰子采纳次数
采纳率
采纳后命中率变化
BLOCK 后避免损失次数
误 BLOCK 次数
WARN 后降级是否改善结果
反证套话率
同源证据识别命中率
强动作降级后收益/回撤变化
```

### 5.8 后评估责任调整

现有后评估中的“反方有效性”建议调整为：

```text
砺石：owner
青山 + 腰子：reviewer
旧影：auditor
```

## 6. 后评估口径

### 6.1 指标定义

| 指标 | 口径 |
|:-----|:-----|
| 有效挑战 | 砺石提出的挑战被腰子采纳，且后评估显示结论质量改善 |
| 采纳率 | 被腰子采纳的砺石建议 / 砺石建议总数 |
| 采纳后命中率变化 | 采纳砺石建议的结论命中率 - 未采纳砺石建议的结论命中率 |
| 误 BLOCK | 砺石 BLOCK 的交易或候选，后续回测收益率达到预设机会阈值 |
| 误 WARN | 砺石 WARN 导致降级，但后续表现显著优于原判断 |
| 套话反证率 | anti_evidence_quality <= 2 的样本占比 |

收益率阈值、机会阈值不在本方案写死，后续由对应场景主流程定义。

### 6.2 月度迭代闭环

建议建立月度规则迭代：

```text
每月统计砺石指标
若某规则误 BLOCK 率过高，则降级或修订
若某规则有效挑战率持续较高，则申请升级
若某规则长期无触发，则标记 review_required
若套话反证率持续较高，则收紧反证质量校验
```

## 7. 程序落地边界

### 7.1 第一阶段：制度、模板、培训

建议先落地：

```text
ROLE_角色唤醒与输出规范_v1.0.md
role_matrix.json
统一解读/角色解释包/砺石_方法审查包.md

统一解读/接入方案/全场景接入方案_v1.0.md
```

第一阶段增加角色培训环节：

```text
腰子、青山、玉夜、流金、旧影需要理解砺石字段含义。
重点说明砺石是方法校准参考，不是决策指令。
```

第一阶段不改日报生成器、深度分析生成器、每日荐股引擎、模拟交易执行器。

### 7.2 第二阶段：离线字段校验

建议先做离线校验，再在线落地：

```text
从历史报告中提取解释链
离线填充 method_review 字段
验证字段是否足够表达真实问题
检查 anti_evidence_quality 是否能识别套话反证
确认字段不会破坏现有日报 / 深度分析结构
```

涉及文件：

```text
interpretation_schema.json
interpretation_rules.json
knowledge_registry.json
knowledge_entries.jsonl
validate_interpretation.py
write_eval_hook.py
```

### 7.3 第三阶段：日报 / 深度分析灰度影子接入

```text
日报：10%-20% 样本灰度，不改正文。
深度分析：关键节点影子审查，不改正文主结构。
```

### 7.4 第四阶段：每日荐股与模拟交易随优化接入

第四阶段不应独立改造每日荐股或模拟交易的现有未定稿流程。正确顺序是：

```text
先完成每日荐股 / 模拟交易各自的主流程优化
再把砺石作为其中一个流程节点纳入
最后才落 WARN / BLOCK 处置逻辑
```

### 7.5 暂不落地范围

```text
保护机制

已定稿深度分析正文结构

每日荐股 / 模拟交易当前未定稿流程的强行接入
```

## 8. 验收建议

### 8.1 文档阶段验收

```text
1. 角色职责边界清晰，不与腰子/玉夜/流金/青山/旧影重叠。
2. 砺石定位为方法校准官，而非单纯反对者。
3. 场景接入策略与用户决策一致：保护机制、临时分析暂不接入。
4. 日报为 10%-20% 灰度影子接入，不破坏定稿结构。
5. 深度分析为关键节点影子接入，不破坏定稿结构。
6. 每日荐股、模拟交易为优化期预留接入，不在当前未定稿流程中强行启用正式闸门。
7. 知识库进化路径纳入 15 步状态机。
8. 后评估能追踪砺石的实际有效性。
9. 第一阶段先并入 U-9 扩展，不新增 U-11。
```

### 8.2 程序阶段验收

后续进入程序落地时，至少需要验证：

```text
JSON schema 校验通过
角色枚举包含砺石 / LISHI
method_review 字段可写入
anti_evidence_quality <= 2 能触发 WARN
result=BLOCK 时 main_challenge 和 check_item 必填
confidence_adjustment 非 NONE 时 adjustment_reason 必填
日报/深度影子字段不影响现有正文
每日荐股主流程定稿后，WARN/BLOCK 能正确降级或剔除
模拟交易主流程定稿后，WARN/BLOCK 能正确减仓/延迟/阻断
eval_hook 能记录砺石影响
knowledge_registry 能注册砺石知识条目
```

## 9. 暂停点

本方案文件仅用于确认设计方向。下一步不应直接进入代码实现，应先确认：

```text
1. 角色名是否确认使用“砺石”，代码名是否确认使用 LISHI。
2. 日报是否接受 10%-20% 灰度影子审查。
3. 深度分析是否接受“风险章后 + 综合结论前 + 核心推理章抽查”。
4. 每日荐股下一轮优化时，砺石是否放在青山信号验证后、腰子裁决前。
5. 模拟交易下一轮优化时，砺石是否放在风控确认后、腰子动作确认前。
6. 第一阶段是否确认不新增 U-11，先并入 U-9 扩展。
7. 是否先做过去 3 个月历史报告的离线模拟审查。
```

确认后，再进入 F-ROLE/F-KNOW/F-ANALYSIS 的正式 G2 文件级落地方案。
