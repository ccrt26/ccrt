# 自动路由判定表

> 版本: 1.0 | 创建: 2026-06-02 | 维护人: 阿黑

---

## 一、用户自然语言 → 流程编号映射

阿黑收到用户需求后，按以下映射自动识别流程编号：

| 用户关键词 | 流程编号 | 路由优先级 |
|:-----------|:---------|:----------:|
| 修改分析逻辑、操作规则、白皮书、金融规则 | **F-ANALYSIS** | P1 |
| 新增分析功能、模块、指标、能力 | **F-FEATURE** | P1 |
| 日报格式调整、MD/JSON/HTML生成逻辑 | **F-REPORT** | P2 |
| 数字错了、来源不一致、数据事实修正 | **F-DATA** | P2 |
| P0闸门捕获的具体问题、定比修复 | **F-FIX** | P0 |
| 新增闸门、check脚本、schema、policy | **F-GATE** | P2 |
| 统一解读、角色协作、角色唤醒、解释对象 | **F-ROLE** | P1 |
| 后评估、eval_hooks、回填、复盘、评分 | **F-EVAL** | P1 |
| 知识库、信号库、五库、六库、L5升级 | **F-KNOW** | P1 |
| 目录整理、迁移、归档、索引 | **F-MIGRATE** | P2 |
| 地基、流程、制度、阶段门、唤醒协议 | **F-ARCH** | P2 |

**路由优先级**：P0 > P1 > P2。同一需求匹配多个流程时，取优先级最高的。

---

## 二、多流程冲突处理

当同一需求可路由到多个流程编号时：

| 冲突类型 | 处理方式 |
|:---------|:---------|
| F-FIX + F-DATA | → **F-FIX**（定点修复优先） |
| F-ANALYSIS + F-REPORT | → **F-ANALYSIS**（分析逻辑优先） |
| F-FEATURE + F-REPORT | → **F-FEATURE**（功能新增优先） |
| F-ARCH + F-MIGRATE | → **F-ARCH**（架构决策优先） |
| F-FEATURE + F-KNOW | → 分步：先 F-FEATURE 完成后再 F-KNOW |
| F-ANALYSIS + F-ROLE | → 合并：两阶段分别完成 G1 口径 |
| 无法判明 | → 输出路由建议，让用户选择 |

---

## 三、模糊需求处理

当用户需求不足以明确映射到唯一流程编号时：

1. 阿黑**最多问 3 个问题**进行澄清
2. 3 个问题后必须做出路由判定（即使不完全确信）
3. 判定原则：**宁可多启用阶段门，不可漏启**

示例：

| 用户说 | 阿黑问 | 判定 |
|:-------|:-------|:-----|
| "改一下分析" | 问：改分析逻辑还是改分析报告格式？ | 分析逻辑→F-ANALYSIS；格式→F-REPORT |
| "数据不对" | 问：哪个字段不对？如何确认？ | 闸门已确认→F-FIX；未确认→F-DATA |
| "加个检查" | 问：检查什么？数据还是报告？ | 数据→F-GATE；报告→F-REPORT |

---

## 四、足够明确时不得反问

以下情况阿黑**必须自行判定，不得反问**：

| 输入包含 | 判定 | 理由 |
|:---------|:-----|:------|
| "板块相位不一致" | **F-FIX** | P0-B 闸门已确认的问题 |
| "baseline_id 不一致" | **F-FIX** | P0-A 闸门已确认的问题 |
| "止损价格 MD/sidecar 不一致" | **F-FIX** | P0-D 闸门已确认的问题 |
| "融资日期不对" | **F-FIX** 或 **F-DATA** | 看是否 P0-C 闸门已确认 |
| "新增一个 check 脚本" | **F-GATE** | 明确指向闸门流程 |
| "迁移目录" | **F-MIGRATE** | 明确指向迁移流程 |
| "更新阶段总账" | **F-ARCH** | 明确指向地基流程 |
| "按标准流程启动第X阶段" | **F-ARCH** | 阶段内流程由任务决定 |

---

## 五、路由输出格式

路由判定后必须输出以下信息：

```
路由结果：
  流程编号：F-xxx
  任务类型：xxx
  启用阶段门：G0/G1/G2/G3/G4/G5/G6
  跳过阶段门及原因：
    - G1：跳过（不涉及金融/角色/业务口径）
    - G2：跳过（改为完整方案，在G0中说明）
  唤醒角色：xxx
  是否涉及金融/业务/角色口径：是/否
  是否需要先设计：是/否
  是否允许进入执行：是/否
  下一步动作：输出轻量派单卡 / 等待确认 / 可以执行
```
