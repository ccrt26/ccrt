# TASK：阶段派单与执行模板 v1.0

> **定位：** 承接文件，整合 `阶段执行标准.md` + `阶段派单模板.md` + `轻量派单卡.md`
> **用途：** 任务需要阶段执行标准或生成派单时读取
> **维护人：** 阿黑

---

## 1. 阶段编号规则

| 前缀 | 含义 |
|:-----|:------|
| **第-X** | 启动和审计阶段（X=负数或0） |
| **第0.X** | 固化/标准化阶段 |
| **P0-X** | 最小强制地基闸门包（只检测不修复） |
| **P0-FIX** | P0 级问题定点修复 |
| **第X** | 正式重构阶段 |
| **第X.5** | 流程标准化/制度固化 |

## 2. 阶段生命周期

```
设计 → 路由 → 阶段门判断 → 角色唤醒 → 派单 → 执行 → 自检 → 报告 → 复查 → 通过/补修 → 下一阶段
```

| 步骤 | 负责人 |
|:-----|:-------|
| 设计 | 阿黑/情墨 |
| 路由/阶段门/角色唤醒/派单 | 阿黑 |
| 执行 | 执行模型或角色 |
| 自检 | 执行模型 |
| 复查 | 旧影/阿黑 |

## 3. 阶段边界规则

每个阶段必须明确：允许新增、允许修改、禁止修改、是否可碰旧文件/数据/脚本/配置。

## 4. 阶段派单模板

```text
你现在执行：【阶段编号】：【阶段名称】

流程编号：【F-xxx】
启用阶段门：【G0/G1/G2/G3/G4/G5/G6】
跳过阶段门：【列出并说明原因】
唤醒角色：【角色列表】
执行模型：【DeepSeek/Codex/Claude】

一、阶段目标
二、G1 业务/金融/角色口径（如适用）
三、G2 技术方案（如适用）
四、允许修改范围
五、禁止修改范围
六、必须完成任务
七、实现要求
八、验收命令
九、验收报告要求
十、最终回复格式
十一、禁止事项
```

## 5. 阶段通过条件

1. ✅ 所有允许范围内文件已创建/修改
2. ✅ 所有验收命令通过
3. ✅ 未修改允许范围外文件
4. ✅ git status 已解释
5. ✅ 无静默失败
6. ✅ 未跳过必须的阶段门
7. ✅ 验收报告已提交

## 6. 补修规则

| 规则 | 内容 |
|:-----|:------|
| 补修必须在同一阶段 | 不得另开新阶段 |
| 补修不得扩大范围 | 只能修已暴露的问题 |
| 补修同样需要验收 | 补修后重跑全部验收命令 |

## 7. 文件操作分类

| 代码 | 含义 |
|:----:|:------|
| N | 新增 |
| M | 修改 |
| D | 删除 |
| R | 移动 |
| ?? | 未跟踪（必须说明来源） |

## 8. 验收命令规则

| 文件类型 | 必跑命令 |
|:---------|:---------|
| JSON | `python3 -m json.tool <路径>` |
| Python | `python3 -c "import py_compile; ..."` |
| 闸门脚本 | 单票 + `--all` |
| git status | 必须 path-limited |
