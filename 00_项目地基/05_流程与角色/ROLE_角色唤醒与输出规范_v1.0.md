# ROLE：角色唤醒与输出规范 v1.0

> **定位：** 承接文件，整合 `角色唤醒协议.md` + `角色实唤醒与输出证据协议.md` + `角色输出矩阵.md`
> **用途：** 任务需要角色唤醒判定或输出规范时读取
> **维护人：** 阿黑

---

## 1. 核心原则

1. **执行模型（DeepSeek/Claude/Codex）不是项目角色。** 不得以角色身份签字。
2. **阿黑**是调度者，负责流程路由和阶段调度，**不得代签**其他角色结论。
3. **腰子**是金融口径裁决者。
4. **旧影**负责独立审计和阶段复查。
5. **玉夜**负责数据事实审查。
6. **砺石**负责方法校准与反证审查，为腰子提供推理链质量参考。
7. **情墨**负责流程制度和文档秩序。
8. **"列出角色 ≠ 实际唤醒"** — 只写"唤醒角色：阿黑、情墨、旧影"不算角色已参与。

## 4. 角色唤醒时序

```
G0: 阿黑（路由）
  ↓
G1: 金融团队（腰子+山猫+信鸽+玉夜+流金+青山）
  ↓  （若涉及报告也引入情墨）
G2: 情墨（架构设计）+ 玉夜（数据方案）
  ↓
G3: 执行模型（编码/改文档）
  ↓
G4: 执行模型（自检）
  ↓
G5: 旧影（独立复查）
  ↓
G6: 阿黑（放行）+ 腰子（签字）
```

## 5. 角色输出格式

每个被唤醒角色输出必须包含：

```text
角色名：【】
参与阶段门：【G0/G1/G2/G3/G4/G5/G6】
本阶段职责：【一句话说明】
检查对象：【路径/文件/范围】
结论：【PASS / BLOCK / WARN】
依据：【文件/命令/规则编号】
遗留问题：【如有】
```

## 6. 角色输出通过规则

| 情况 | 处理 |
|:-----|:------|
| 必唤醒角色未输出结论 | ⛔ BLOCK |
| 阿黑代签角色结论 | ⛔ BLOCK |
| 执行模型以角色身份签结论 | ⛔ BLOCK |
| G5 复查缺失 | ⛔ BLOCK |
| 角色输出 BLOCK | ⛔ 转化为阶段 BLOCK |
| 角色输出 PASS/WARN | ✅ 汇总到验收报告 |

## 7. G5 独立复查格式

```text
复查角色：旧影
复查范围：【验收报告+命令+文件】
复查结果：【命令通过率 / 文件范围合规 / 角色输出完备性】
总体结论：【建议通过 / 需补修 / 不通过】
遗留问题：【如有】
```

## 8. 跳过角色必须说明

跳过必唤醒角色时，必须在验收报告中逐条说明：跳过角色、跳过原因、是否影响阶段结论。

## 9. 按需唤醒角色规则

部分角色不在任何流程的"必唤醒"列表中，由流程负责人或金融线负责人根据实际需要选择激活。

| 角色 | 所属线 | 职责 | 唤醒条件 |
|:-----|:-------|:-----|:---------|
| 砺石 | 金融线 | 方法校准、反证审查 | 腰子判断推理链需要独立方法审查时按需唤醒 |

### 按需唤醒行为规则

1. 按需唤醒角色的输出**不影响**流程阻塞判定（仅"必唤醒角色"缺失触发 BLOCK）
2. 按需唤醒角色**一经唤醒**，其输出必须纳入全团意见并记录在相应的整合单中
3. 腰子决定唤醒砺石后，不得以"按需"为由忽视其审查结论
4. 按需唤醒角色不改变 G0-G6 时序（不占用独立阶段门）
