# FLOW：流程路由与阶段门 v1.0

> **定位：** 承接文件，整合 `流程路由表.md`、`变更生命周期与阶段门.md`、`自动路由判定表.md`、`一键唤醒与自动路由协议.md` 核心内容
> **用途：** 任务需要流程路由或阶段门判定时读取
> **维护人：** 阿黑

---

## 1. 流程编号总览

| 编号 | 名称 | 适用场景 |
|:-----|:------|:---------|
| **F-ARCH** | 地基/架构变更 | 目录、契约、总账、阶段制度 |
| **F-DATA** | 数据事实变更 | 数值、日期、来源、sidecar 事实字段 |
| **F-REPORT** | 报告生成/日报逻辑变更 | 日报模板、MD/JSON 生成逻辑 |
| **F-ANALYSIS** | 金融分析逻辑变更 | 分析白皮书、操作规则、风控规则 |
| **F-ROLE** | 角色协作/统一解读变更 | 13 角色、解释对象、协作协议 |
| **F-EVAL** | 后评估/eval_hooks 变更 | T+1/T+5、回填、评分、复盘 |
| **F-KNOW** | 知识库/信号库进化 | 六库、信号沉淀、L5→L2 升级 |
| **F-GATE** | 闸门/验收脚本变更 | check_*.py、schema、policy |
| **F-FIX** | 定点问题修复 | 闸门已抓到的具体数据/文档修复 |
| **F-MIGRATE** | 目录迁移/归档 | 文件搬家、索引、历史资产治理 |
| **F-FEATURE** | 分析功能新增/修改 | 新增分析能力、指标、模块 |
| **F-SCHEDULE** | 调度/运行入口/跨平台迁移 | 调度权威锁定、运行时入口注册 |

## 2. 自然语言路由示例

| 用户说 | 路由结果 |
|:-------|:---------|
| "修改分析逻辑" | → F-ANALYSIS |
| "修数据不一致" | → F-DATA 或 F-FIX |
| "新增检查脚本" | → F-GATE |
| "目录整理" | → F-MIGRATE |
| "统一解读角色协作" | → F-ROLE |
| "报告格式调整" | → F-REPORT |
| "架构调整/目录重构" | → F-ARCH |
| "调度乱/定时任务" | → F-SCHEDULE |

**路由优先级：** F-FIX > F-DATA | F-ANALYSIS > F-REPORT | F-FEATURE > F-REPORT | F-ARCH > F-MIGRATE

## 3. 阶段门定义

| 阶段门 | 名称 | 可否跳过 |
|:------:|:------|:--------:|
| **G0** | 需求识别与流程路由 | 不可跳过 |
| **G1** | 业务/金融/角色口径设计 | 金融变更不可跳过 |
| **G2** | 技术方案设计 | 定点修复可简化 |
| **G3** | 执行实现 | 不可跳过 |
| **G4** | 执行者自检 | 不可跳过 |
| **G5** | 独立复查 | 不可跳过 |
| **G6** | 放行归档 | 不可跳过 |

**典型路径：** F-GATE → G0→G2→G3→G4→G5→G6 | F-ANALYSIS → G0→G1→G2→G3→G4→G5→G6 | F-FIX → G0→G1/G2简化→G3→G4→G5→G6

## 4. 一键唤醒自动路由（用户最小输入）

> **本节的"按照标准流程启动/执行"是用户入口句/触发语，不是独立流程。** 入口句由阿黑路由到 F-xxx + G0-G6 标准流程后执行。

用户只需说一句话：
- `阿黑，按照标准流程启动：xxx` → 自动路由 → 输出设计 → 不直接改文件
- `阿黑，按照标准流程执行：xxx` → 自动路由 → 确认后执行
- `阿黑，复查：xxx` → 读取验收报告 → 输出复查结论

**阿黑自动路由步骤：**
1. 读取 STATE 了解项目状态
2. 读取本文件匹配流程编号
3. 读取 ROLE 确定唤醒角色
4. 检索影响范围
5. 判断阶段门（含跳过理由）
6. 生成派单

**用户无需手填 F-xxx、G0~G6、角色名单。**

## 5. 文件修改权限

| 流程 | 可修改目录 | 禁止修改目录 |
|:-----|:-----------|:-------------|
| F-ARCH | 00_项目地基/ | 重点股票/每日荐股/统一解读/交易/风控 |
| F-DATA | 报告 sidecar/日报/缓存 | baseline_registry/流程脚本/架构文档 |
| F-REPORT | 代码文件/tools/报告生成 | 数据缓存/金融规则/角色定义 |
| F-ANALYSIS | 金融铁律/分析逻辑/白皮书 | 数据缓存/流程脚本/日报 |
| F-FIX | 按指定范围 | 范围外不得修改 |
| F-MIGRATE | 指定迁移目录 | 非迁移目标目录 |

## 6. 不可绕过规则

| 规则 | 说明 |
|:-----|:------|
| ⛔ 金融分析逻辑变更必须经过 G1 | 技术团队不得反向决定金融口径 |
| ⛔ 角色协作变更必须经过 G1 | 解释对象、角色边界调整必须先定口径 |
| ⛔ 闸门/脚本变更必须经过 G2 | 必须设计字段映射和检查逻辑 |
| ⛔ 任何变更不得默认直接进入 G3 | 必须先走 G0 路由 |
