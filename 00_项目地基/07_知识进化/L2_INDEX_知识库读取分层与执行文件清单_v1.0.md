## 1. 定位与边界

### 1.1 本文件是什么

本文件是 KRM 知识库读取清单的权威文件（Knowledge Reading Manifest）。

它不替代角色入口 `.md`，而是由角色入口 `.md` 启动后调用。

它也是**知识库读取路由索引**。它回答的核心问题是：

> 角色参与任务时，应该读哪些文件？哪些是执行规则，哪些只是过程归档？外部长文档能不能直接进上下文？

### 1.2 本文件做什么

1. 定义文件类型分层（执行规则 / 角色知识 / 场景适配器 / 索引 / 归档 / 外部资料）。
2. 定义 4 级读取层级（L0 必读 / L1 场景 / L2 按需 / L3 追溯）。
3. 定义角色启动时的读取包结构。
4. 定义冲突时的文件执行优先级。
5. 定义外部长文档的入库规则。

### 1.3 本文件不做什么

| 禁止项 | 说明 |
|:-------|:-----|
| ⛔ 不是角色知识库正文 | `.claude/agents/*-知识库/` 不动 |
| ⛔ 不是生产入口 | 不改变任何现有报告逻辑 |
| ⛔ 不要求角色全量读取所有 md | 按任务装配，不全量读 |
| ⛔ 不改变现有报告逻辑 | 日报/周报/荐股/模拟交易逻辑不变 |

## 2. 读取总原则

| 原则 | 说明 |
|:-----|:------|
| **按任务装配，不全量读取** | 角色启动时只读当前任务需要的文件 |
| **先读索引，再读场景，再读角色知识** | 索引定位 → 适配器选场景 → 角色知识按需 |
| **过程文件默认不进启动上下文** | G1G2/G4/G5/G6 只在复查/审计时读 |
| **外部长文档默认不进启动上下文** | 只读摘要卡片，原文按需查证 |
| **执行以「执行规则文件」为准** | 方案/归档/复查只是审计证据 |
| **上下文预算优先给当前任务/角色/场景** | 短、精、约束强 |

## 3. 文件类型分层

### 3.0 文件类型标记机制

从本文件生效后，所有新增或改版的地基 `.md` 文件必须在标题后的元信息区声明 KRM 文件头。历史文件不强制逐个回填；无文件头的历史文件按 §3.0.4 默认归类，以节省迁移额度。

#### 3.0.1 KRM 文件头模板

```markdown
> 文件类型：执行规则 / 角色知识 / 场景适配器 / 索引路由 / 过程归档 / 外部资料摘要
> 读取级别：必读 / 场景必读 / 按需 / 审计时读
> 适用角色：玉夜 / 青山 / 流金 / 信鸽 / 山猫 / 腰子 / 全角色
> 是否进入启动上下文：是 / 否
```

#### 3.0.2 字段裁决口径

| 字段 | 允许值 | 裁决规则 |
|:-----|:-------|:---------|
| 文件类型 | 执行规则 / 角色知识 / 场景适配器 / 索引路由 / 过程归档 / 外部资料摘要 | 决定文件能否约束角色输出 |
| 读取级别 | 必读 / 场景必读 / 按需 / 审计时读 | 决定是否进入本次任务读取包 |
| 适用角色 | 单角色 / 多角色 / 全角色 | 决定是否跨角色读取 |
| 是否进入启动上下文 | 是 / 否 | 决定角色启动时是否可直接加载 |

#### 3.0.3 启动裁决一条规则

角色启动时只做一次 KRM 装配：

```
先读 L0 START_HERE
  → 判断任务类型和角色
  → 若涉及知识库/角色读取，读取本文相关段落
  → 输出本次读取包：必读 / 场景必读 / 按需 / 明确不读
  → 按读取包加载文件
```

未进入读取包的文件，一律不得因“可能有用”而全文加载。

#### 3.0.4 历史无文件头默认归类

| 命名或路径特征 | 默认文件类型 | 默认读取级别 | 默认启动上下文 |
|:---------------|:-------------|:-------------|:---------------|
| `L1_FLOW_` / `L1_ROLE_` / `L1_TASK_` | 执行规则 | 必读 | 是 |
| `scenario_adapters/*.md` | 场景适配器 | 场景必读 | 否；仅当前场景进入 |
| `L2_SCHEMA_` / `counterexamples/L2_COUNTEREXAMPLE_INDEX_` / `parameters/L2_PARAMETER_INDEX_` | 执行规则 | 场景必读 | 否；仅知识进化任务进入 |
| `.claude/agents/*-知识库/` 或角色解释包 | 角色知识 | 按需 | 否 |
| `L0_INDEX_` / `L1_INDEX_` / `L2_INDEX_` | 索引路由 | 按需 | 否；L0 START_HERE 例外 |
| `G1G2` / `G3` / `G4` / `G5` / `G6` / `REPORT_STEP` / `迁移计划` / `99_归档` | 过程归档 | 审计时读 | 否 |
| 外部研报、论文、资料摘要、文献卡片 | 外部资料摘要 | 按需 | 否；只允许摘要进入 |

> 历史无文件头文件与命名规则冲突时，以更保守的读取级别为准：能按需则不场景必读，能审计时读则不按需。

## 6. 文件执行优先级

### 6.1 优先级总表

```
生产入口 / 正式运行规则          ← 最高优先级
  > 当前阶段派单
    > 执行规则文件
      > 场景适配器
        > 角色核心知识
          > 参数库 applied 规则
            > 反例库 confirmed 记录
              > 方案文件
                > G4/G5/G6 过程归档
                  > 外部资料摘要
                    > 外部原文           ← 最低优先级
```

### 6.2 优先级规则

| 规则 | 说明 |
|:-----|:------|
| `proposed` 候选不具备执行效力 | 只能作为观察项 |
| `approved` 但未 `applied` 的参数不具备生产效力 | 需等待腰子终审 |
| 反例不是正式规则 | 除非升级并通过确认 |
| 外部资料不能直接覆写项目规则 | 需经过项目验证和角色确认 |
| 方案文件优先级低于执行规则文件 | 执行以冻结规则为准 |
| G4/G5/G6 是审计证据，不是执行依据 | 任务执行时不引用归档结论作为规则来源 |

## 7. 外部文档入库规则

### 7.1 三层保存结构

```
外部资料（原文层）
  → 摘要卡片（摘要层）
    → 项目验证 + 角色确认（规则层）
```

### 7.2 各层要求

| 层级 | 内容 | 是否进启动上下文 | 说明 |
|:-----|:-----|:----------------:|:-----|
| 原文层 | 链接、PDF、出处、日期、版本 | ❌ 不进 | 按需查证时读取 |
| 摘要层 | 来源+日期+适用范围+核心结论+适用/不适用条件+证据等级+有效期+关联角色+可能转化的规则 | ✅ 摘要卡片可进 | 原文仍不进 |
| 规则层 | 经过验证和确认后的正式候选 | 按候选状态 | 需走完整候选流程 |

### 7.3 摘要卡片最小字段

| 字段 | 说明 |
|:-----|:-----|
| source_ref | 原始资料路径/链接 |
| source_level | S/A/B/C（按 G1G2 方案 §7.2.2） |
| published_at | 发布日期 |
| applicable_scope | A 股适用性 |
| core_conclusion | 核心结论摘要 |
| applicable_conditions | 适用条件 |
| not_applicable_conditions | 不适用条件 |
| evidence_level | 证据等级 |
| expiry_or_review_cycle | 有效期或复核周期 |
| owner_role | 关联角色 |
| potential_rules | 可能转化的规则 |

> 外部资料不得直接成为 `applied` 规则。必须经过项目验证→角色确认→腰子终审→旧影审计流程。

## 9. 场景映射（KRM 场景调用清单）

根据当前任务场景，KRM 必须明确以下文件的读取状态。

> **未来 adapter 缺失处理规则**：若 KRM 指定读取的 adapter 尚未创建（如日报、荐股、模拟交易），不得将该场景视为正式可启动场景。应优先触发 adapter 建设或补建设计流程，在此之前不得以 adapter 不存在为由跳过 KRM 声明不读义务。

### 9.1 周报
- KRM 必读：深度周报 adapter
- KRM 声明不读：非当前标的的角色知识库、历史周报全文

### 9.2 B 层后评估
- KRM 必读：B 层后评估 adapter、KnowledgeUpdateCandidate schema、反例库索引、参数库索引
- KRM 声明不读：非当前评估标的的角色知识正文、历史后评估全文

### 9.3 日报
- KRM 必读：日报 adapter、周报/日报指令引用规则
- KRM 声明不读：非当前标的角色知识库、历史日报全文

### 9.4 荐股
- KRM 必读：荐股 adapter、风控边界、参数库相关项
- KRM 声明不读：无关场景 adapter、历史荐股全量记录

### 9.5 模拟交易
- KRM 必读：模拟交易 adapter、交易纪律、风险日志
- KRM 声明不读：非交易参数库内容、非实时风险日志

### 9.6 审计/复查
- KRM 必读：当前阶段验收报告、G4/G5/G6 过程文件、相关历史归档

## 12. 旧库全文与新知识库读取规则

### 12.1 角色启动读取路径

```
角色启动
  → .claude/agents/*.md（瘦身入口）
    → KRM 读取分层索引
      → knowledge/roles/<role>/（精华包：默认启动读取 README + 01/02/03/05/07）
        → knowledge/sources/legacy_role_kb/<role>/（旧库全文保真层：深度分析/争议复查/审计时读取）
```

### 12.2 读取层级

| 层级 | 内容 | 读取条件 |
|:-----|:-----|:---------|
| startup | knowledge/roles/<role>/README + 01/02/03/05 + 07_深度读取触发器 | 角色参与任务时默认读取 |
| task | knowledge/roles/<role>/04/06 | 输出或后评估任务时按需读取 |
| deep | knowledge/sources/legacy_role_kb/<role>/ | 深度分析/争议复查/后评估/G5/G6审计时读取 |
| audit | knowledge/roles/<role>/00_旧库来源索引 + sources/legacy_role_kb/<role>/SOURCE_INDEX + manifest.json | 仅溯源追溯时读取 |

### 12.3 禁止

- 角色启动时不得默认读取 sources/ 目录
- 旧 `.claude/agents/*-知识库/` 不再是任何角色的正式入口
- sources/legacy_role_kb 仅在 manifest 和 SOURCE_INDEX 指引下按需读取

### 12.4 能力不下降规则

1. 精华包不是旧库全文替代品；精华包负责读取路由，source 原文负责能力保真。
2. 角色参与金融分析、周报、日报执行追踪、B 层后评估、争议复查、G5/G6 审计时，必须先读取 `07_深度读取触发器.md`。
3. 若触发器命中 deep 读取条件，必须读取 `sources/legacy_role_kb/<role>/` 对应原文或 `SOURCE_INDEX.md` 指定文件。
4. 触发 deep 但未读取 source 原文时，角色不得输出强结论，只能输出 WARN、WAIT 或要求补证据。
5. 所有 `07_深度读取触发器.md` 中引用的 source 路径必须真实存在；不存在则 G4 BLOCK。
6. KRM README 与本索引冲突时，以更严格规则为准。

## 13. KRM 任务路由表

1. 角色启动后不直接猜测读取包。
2. 遇到流程、金融红线、证据质量、信号有效性、事件催化、宏观环境、整合裁决、后评估、输出格式问题时，应先匹配 `knowledge/routing/krm_task_router_v1.0.json`。
3. router 输出 must_read / optional_read / deep_read。
4. must_read 必须读取。
5. optional_read 按任务复杂度读取。
6. deep_read 只有触发深度判断时读取。
7. router 不替代 FLOW / ROLE / TASK / KRM / 角色知识，只负责定位读取包。
8. router 与 KRM 冲突时，以更严格读取规则为准。
