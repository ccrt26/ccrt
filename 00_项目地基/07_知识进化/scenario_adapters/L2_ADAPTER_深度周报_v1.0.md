## 1. 阶段与用途

### 1.1 文件定位

本文件是**深度周报场景适配器**，属于五层知识结构的 L-K2（场景适配器）层。它回答的核心问题是：

> 角色核心知识在深度周报这个具体场景中，应该怎么被引用、怎么输出、怎么产出后评估知识更新候选。

### 1.2 本文件做什么

1. 定义深度周报 A/B/C 三层如何引用六个角色的稳定知识。
2. 定义 B 层后评估如何生成 `KnowledgeUpdateCandidate` 草案。
3. 定义周报如何引用候选状态（不把候选当成已生效规则）。
4. 定义东睦周报作为首个样例的适配检查点。

### 1.3 本文件不做什么

| 禁止项 | 说明 |
|:-------|:-----|
| ⛔ 不修改角色核心知识库 | `.claude/agents/*-知识库/` 的修改需走角色确认+腰子终审流程 |
| ⛔ 不修改报告生成脚本 | 深度周报生成脚本不变 |
| ⛔ 不写入真实 KnowledgeUpdateCandidate 数据 | 候选数据需后评估产生 |
| ⛔ 不修改生产报告模板 | 周报模板不受本文件影响 |
| ⛔ 不授权 G3-3 | 反例库/参数库/东睦样例不在本阶段创建 |

## 3. A/B/C 三层适配

### 3.1 A 层：金融团队作业层

**使用角色**：腰子、玉夜、青山、流金、信鸽、山猫

**用途**：

| 角色 | A 层职责 | 引用的知识类型 |
|:-----|:---------|:--------------|
| 腰子 | 确定核心假设、状态机裁决、结论强度、整合终审 | 整合裁决规则、状态机、结论强度口径 |
| 玉夜 | 数据质量声明、字段口径说明、数据可用等级 | 数据质量规则、字段可信等级、TTL 红线 |
| 青山 | 信号有效性判断、因子胜率、策略环境归因 | 信号有效性、样本门槛、因子规则 |
| 流金 | 风险边界、否决项检查、动作审计 | 风控红线、否决项、恢复条件 |
| 信鸽 | 事件分级、公告证据、催化窗口判断 | 事件等级、证据规则、催化窗口 |
| 山猫 | 宏观覆写、行业相位、市场风格 | 宏观覆写规则、行业相位、M 层规则 |

**禁止**：
- 在 A 层直接修改角色核心知识库。
- 在 A 层把单次判断写成通用规则。
- 在 A 层越过流金风控红线。

### 3.2 B 层：后评估基准层

**使用角色**：青山、玉夜、流金、信鸽、山猫、腰子

**用途**：

B 层后评估基于 A 层核心假设和日报执行记录，完成以下任务：

| 角色 | B 层职责 | 产出 |
|:-----|:---------|:-----|
| 青山 | 信号胜率统计、参数偏差归因 | 信号有效性候选 / 参数候选 |
| 玉夜 | 数据质量验证、字段口径偏差 | 数据可信等级候选 / 反例候选 |
| 流金 | 风控边界验证、动作审计 | 风控候选 / 反例候选 |
| 信鸽 | 催化兑现/落空验证 | 事件窗口候选 / 反例候选 |
| 山猫 | 宏观环境变化验证 | 宏观覆写候选 / 策略环境候选 |
| 腰子 | 整合裁决偏差归因 | 结论强度候选 / 核心知识候选 |

**禁止**：
- 直接把后评估结论写入正式规则。
- 把单次偏差当成永久结论。

### 3.3 C 层：用户摘要层

**使用角色**：腰子、流金

**用途**：

| 角色 | C 层职责 | 引用的知识类型 |
|:-----|:---------|:--------------|
| 腰子 | 摘要表达、结论强度、用户可读性 | 结论强度口径、状态机 |
| 流金 | 动作边界检查、风险提示 | 动作红线、风控边界 |

**禁止**：
- C 层摘要越过流金动作红线或腰子结论强度。
- C 层引用未 `applied` 的候选作为动作依据。
- C 层使用超出周报证据等级的语言（不能把 L3 猜测写成 L1 事实）。

## 4. 角色知识引用矩阵

| 角色 | 周报使用位置 | 引用知识类型 | 是否允许自动改核心知识 |
|:-----|:------------|:------------|:---------------------:|
| 腰子 | A/C | 状态机、结论强度、整合裁决 | **否** |
| 玉夜 | A/B | 数据质量、字段口径、数据可用等级 | **否** |
| 青山 | A/B | 信号有效性、因子胜率、样本约束 | **否** |
| 流金 | A/B/C | 风险边界、否决项、动作审计 | **否** |
| 信鸽 | A/B | 事件分级、公告证据、催化窗口 | **否** |
| 山猫 | A/B | 宏观覆写、行业相位、市场环境 | **否** |

> 所有角色在周报中引用的知识类型，均为"只读引用"。修改核心知识须经过候选→角色确认→腰子终审→旧影审计流程。

## 5. KnowledgeUpdateCandidate 生成规则

### 5.1 最小流程

```
周报 A 层核心假设
  → 日报执行记录（跟踪 A 层指令的执行情况）
  → B 层后评估（对比假设与市场实际）
  → 偏差归因（数据/参数/证据/逻辑/展示/执行/环境）
  → KnowledgeUpdateCandidate 草案（依据 SCHEMA 字段生成）
  → owner_role 角色确认（对应角色评审候选）
  → 腰子终审（金融口径终审）
  → 旧影审计（检查代签/单次入库/越界）
  → 写入目标库：反例库 / 参数库 / 场景适配器 / 核心知识库候选
```

### 5.2 周报本身不生成最终候选

周报的 B 层后评估只产出 **候选草案**，不是最终候选。候选草案必须经过以下校验才成为正式 KnowledgeUpdateCandidate：

1. 满足 SCHEMA 完整性检查（§6.3）。
2. `owner_role` 角色确认。
3. 腰子终审（金融相关）。
4. 旧影审计（单次入库检查）。

### 5.3 候选草案的最小字段

B 层产出的候选草案至少包含：

| 字段 | 说明 |
|:-----|:-----|
| source_ref | 来源周报路径或 EvalHook ID |
| attribution_type | 归因类型（数据/参数/权重/证据等级/分析逻辑/展示/执行/环境） |
| observed_failure | 观察到的问题 |
| proposed_update | 建议更新 |
| target_layer | adapter / counterexample / parameter / core |
| owner_role | 首要确认角色 |
| confidence | low / medium / high |

完整字段集见 `L2_SCHEMA_KnowledgeUpdateCandidate_v1.0.md`。

## 6. 周报适配器输出字段

深度周报（含 A/B/C 三层）至少输出以下字段，供日报执行和后评估追踪：

| 字段 | 用途 | 必填 | 示例 |
|:-----|:-----|:----:|:-----|
| weekly_hypothesis_id | 周报核心假设 ID | 是 | WH-20260610-YAOZI-001 |
| evidence_level | 该假设的证据等级 | 是 | L1 / L2a / L2b / L3 |
| owner_role | 该假设首要责任角色 | 是 | 青山 |
| related_roles | 需要联审的角色 | 否 | ["玉夜", "腰子"] |
| daily_instruction_ref | 日报执行指令 | 是 | "跟踪 600114 技术修复后的量能变化" |
| eval_question | B 层后评估问题 | 是 | "技术修复后股价是否在 5 个交易日内延续上涨？" |
| candidate_trigger | 何种偏差会触发候选 | 是 | "突破信号有效天数低于 3 日" |
| candidate_target_layer | 候选预期落层 | 是 | adapter / counterexample / parameter / core |
| status_reference | 候选当前状态引用 | 是 | "参考 KUC-20260610-QINGSHAN-001：已 proposed" |

> **注意**：`status_reference` 引用的候选状态不等同于已生效规则。规则状态判定见 §7。

## 7. 候选状态引用规则

### 7.1 引用规则总表

周报可以引用候选的任意状态，但不同状态在周报中含义不同：

| 候选状态 | 周报引用含义 | 是否可作为动作依据 | 说明 |
|:---------|:------------|:------------------:|:-----|
| proposed | 已提出候选，待评审 | **否** | 仅作为观察项 |
| role_review | 角色正在评审 | **否** | 仅作为观察项 |
| approved | 角色确认可更新 | **否** | 等待腰子终审 |
| final_review | 腰子终审中 | **否** | 等待最终裁决 |
| **applied** | ✅ **已生效规则** | **是** | 可作为动作依据 |
| rejected | 已否决 | 否 | 关闭项 |
| parked | 暂存待样本 | 否 | 不作为动作依据 |
| superseded | 已被替代 | 否 | 引用新候选 |
| closed | 流程关闭 | 视具体状态 | 若为 applied 后 closed 则有效 |

### 7.2 核心规则

| 规则 | 说明 |
|:-----|:-----|
| **只有 `applied` 可以作为已生效规则引用** | 周报 A 层和 C 层只能以 `applied` 状态的候选作为确定性依据 |
| `proposed`/`role_review`/`approved`/`final_review`/`parked` 只能作为观察或待确认事项 | 周报可提及"候选正在评审中"，但不得作为确定性结论引用 |
| **C 层用户摘要不得引用未 applied 候选作为动作依据** | 用户摘要只能使用已生效规则，不把未确认候选展示给用户 |
| 周报必须标注 `status_reference` 中候选的当前状态 | 不能隐藏候选状态，不能伪称候选已生效 |

## 8. 东睦周报适配检查点

### 8.1 检查点定义

东睦后续 B 层后评估时，本适配器要求检查以下 6 个方面。这些是**检查点**，不是真实候选。东睦后评估完成后才能产出候选。

| 检查点 | 检查内容 | 首要角色 |
|:-------|:---------|:---------|
| D-01 | 技术修复后走势是否延续 | 青山 |
| D-02 | moneyflow 口径是否误导（资金流向 vs 实际流动性） | 玉夜 |
| D-03 | C 层动作是否过激（用户摘要是否越过风控红线） | 流金 + 腰子 |
| D-04 | 中期逻辑判断是否过强（证据等级与结论强度是否匹配） | 腰子 |
| D-05 | 催化窗口是否落空（事件驱动是否按预期兑现） | 信鸽 |
| D-06 | 市场风格是否压制成长线索（宏观环境是否覆盖了个股判断） | 山猫 + 青山 |

### 8.2 检查点使用规则

1. 东睦后评估时针对 D-01 至 D-06 逐项检查。
2. 若某项检查发现偏差，则生成对应的 KnowledgeUpdateCandidate 草案。
3. 检查点本身不是候选，仅为后评估检查的提示。
4. 候选的具体内容、置信度和 target_layer 由后评估结论决定。

> ⛔ 本文件**不创建** `evolution_candidates/L2_SAMPLE_东睦后评估知识候选要求_v1.0.md`。该文件属于 G3-3。
