## 1. 定位与边界

### 1.1 文件定位

本文件是 **B 层后评估执行适配器**，属于五层知识结构的 L-K2（场景适配器）层。它回答的核心问题是：

> 未来后评估应该按什么标准动作执行、如何归因、如何生成 KnowledgeUpdateCandidate、如何分流到反例库/参数库/场景适配器/核心知识候选。

### 1.2 本文件是什么

| 性质 | 说明 |
|:-----|:------|
| 后评估的标准操作规程 | 规定触发条件、标准动作、归因方法、候选生成门槛 |
| L-K2 场景适配器 | 与深度周报适配器同级，专用于后评估场景 |

### 1.3 本文件不是什么

| 不是 | 说明 |
|:-----|:-----|
| ❌ **不是后评估报告** | 不包含任何具体标的的判断结论 |
| ❌ **不是真实候选** | 不产出任何真实 KnowledgeUpdateCandidate 数据 |
| ❌ **不是日报重构** | 只定义日报留痕最低字段，不改日报执行 |
| ❌ **不是生产规则** | 不触发任何自动化生产逻辑 |
| ❌ **不是角色核心知识** | 不修改 `.claude/agents/*-知识库/` |

## 2. B 层后评估触发条件

后评估可以在以下任一条件满足时触发：

| 触发条件 | 说明 | 优先级 |
|:---------|:-----|:------:|
| 周报发布后经过日报执行周期 | 正常周期性后评估 | 常规 |
| 日报连续跟踪形成执行记录 | 至少 3 个交易日以上有效跟踪 | 常规 |
| 催化节点落地或落空 | 事件驱动的关键检查点 | 高 |
| 判断结果明显偏离原假设 | 周报核心假设与实际走势出现显著偏差 | 高 |
| 市场环境或行业相位明显变化 | 宏观/行业环境变化可能覆写原判断 | 中 |
| 用户或角色要求专项复盘 | 针对特定标的或特定问题的回溯 | 按需 |

> 常规后评估不在每个交易日触发的；建议在周报执行周期结束后（通常 1-2 周）统一执行。

## 3. 后评估标准动作

每次后评估必须回答以下 6 个问题：

### 3.1 六个必答问题

| # | 问题 | 回答要求 |
|:-:|:-----|:---------|
| Q1 | 当初周报判断了什么？ | 引用 `weekly_hypothesis_id` 和 `evidence_level` |
| Q2 | 日报是否执行了对应周报指令？ | 检查 `daily_instruction_ref` 的执行记录 |
| Q3 | 原假设是否兑现？ | 选择：fully_realized / partially_realized / not_realized / undetermined |
| Q4 | 偏差归因属于哪一类？ | 选择：data / parameter / analysis_logic / presentation / execution / strategy_environment |
| Q5 | 是否满足生成 KnowledgeUpdateCandidate 的门槛？ | 按 §5 公式判断：可归因 + 可重复 + 有证据 + 可行动 + 有影响 |
| Q6 | 候选应分流到哪一层？ | 选择：counterexample / parameter / adapter / core_candidate / parked |

### 3.2 偏差归因分类

| 归因类型 | 含义 | 判定线索 |
|:---------|:-----|:---------|
| data | 数据问题 | 字段值错误、缺失、延迟、口径误导 |
| parameter | 参数问题 | 阈值过紧/过松、窗口过长/过短 |
| analysis_logic | 分析逻辑问题 | 因果链条不成立、假设方向错误 |
| presentation | 展示问题 | 用户摘要表达过激/过保守、C 层越界 |
| execution | 执行问题 | 日报未执行周报指令、执行记录缺失 |
| strategy_environment | 策略环境变化 | 市场风格切换、行业相位变化、宏观覆写 |

## 4. 日报执行留痕最低字段

后评估的输入之一是日报执行记录。日报至少留下以下字段供后评估调用：

| 字段 | 必填 | 说明 | 示例 |
|:-----|:----:|:-----|:-----|
| weekly_report_ref | 是 | 关联周报路径或编号 | `周报/2026W24/深度分析_东睦股份_v1.0.md` |
| weekly_instruction_id | 是 | 执行的周报指令 ID | DI-20260610-QINGSHAN-001 |
| tracked_hypothesis | 是 | 跟踪的原假设 | "技术修复后股价应在 5 个交易日内延续上涨" |
| observed_evidence | 是 | 当天新增证据 | "收盘价 +2.1%，量能 1.3×20日均量" |
| evidence_type | 是 | 证据类型 | price / volume / announcement / moneyflow / industry / macro / risk |
| evidence_strength | 是 | 证据强度 | weak / medium / strong |
| execution_status | 是 | 执行状态 | tracked / missed / blocked / not_applicable |
| state_change | 是 | 状态变化 | continue_watch / wait_confirm / downgrade / risk_triggered / remove_watch / maintain |
| reason | 是 | 状态变化原因 | "量能持续萎缩，转为 wait_confirm" |
| created_at | 是 | 记录日期 | 2026-06-10 |

> 注意：本字段定义是**最低接口规范**，不是日报重构。日报具体输出格式不受本文件影响。

## 5. KnowledgeUpdateCandidate 生成门槛

### 5.1 冻结公式

**可归因 + 可重复 + 有证据 + 可行动 + 有影响 = 可生成 KnowledgeUpdateCandidate**

| 门槛条件 | 说明 | 不满足时如何处理 |
|:---------|:-----|:-----------------|
| 可归因 | 能明确归因到 6 类之一 | 无法归因 → 不生成候选，仅复盘备注 |
| 可重复 | 同类偏差在不同标的不同周期可能出现 | 偶然波动且无复用价值 → 不生成候选 |
| 有证据 | 有至少 1 条可追溯的 evidence_refs | 无证据引用 → 不生成候选 |
| 可行动 | 能形成可执行修正规则 | 不能形成修正规则 → 不生成候选 |
| 有影响 | 对结论强度/动作边界/判断/执行/用户理解有实际影响 | 无影响 → 不生成候选 |

### 5.2 不应生成候选的情况

| 情况 | 处理 |
|:-----|:-----|
| 结果错但无法归因 | 不生成候选，仅在后评估记录中备注"归因不足" |
| 单次偶然波动且无复用价值 | 不生成候选 |
| 没有证据引用 | 不生成候选 |
| 不能形成可执行修正规则 | 不生成候选 |
| 对结论强度/动作边界/角色判断/日报执行/用户理解均无影响 | 不生成候选 |

### 5.3 可生成候选的示例

| 情况 | 5 项门槛 | 结果 |
|:-----|:---------|:-----|
| 技术修复窗口参数过短导致频繁误触发 | 可归因(parameter)+可重复+有证据+可行动(修窗口)+有影响(信号质量) | ✅ 生成候选 |
| 某日随机下跌无任何关联因素 | 可归因(?) + 不可重复 + 无可行动 | ❌ 不生成 |
| moneyflow 口径与实际流向不符导致判断偏差 | 可归因(data)+可重复+有证据+可行动(调口径)+有影响(结论质量) | ✅ 生成候选 |

## 6. KnowledgeUpdateCandidate 必填字段

后评估产出的候选草案必须包含以下字段，引用 G3-1 `L2_SCHEMA_KnowledgeUpdateCandidate_v1.0.md`：

| 字段 | 必填 | 说明 |
|:-----|:----:|:-----|
| candidate_id | 是 | 格式：KUC-YYYYMMDD-ROLE-NNN |
| source_type | 是 | weekly_report / daily_report / stock_pick / sim_trade / eval |
| source_ref | 是 | 来源后评估文件路径 |
| stock_code | 否 | 涉及标的时填写 |
| scenario | 是 | 固定为 `后评估` |
| owner_role | 是 | 归因类型对应的首要确认角色 |
| attribution_type | 是 | 归因类型（6 类之一） |
| observed_failure | 是 | 观察到的问题 |
| proposed_update | 是 | 建议更新内容 |
| target_layer | 是 | counterexample / parameter / adapter / core |
| confidence | 是 | low / medium / high |
| evidence_refs | 是 | 证据引用，至少 1 条 |
| risk_if_applied | 是 | 采纳风险 |
| risk_if_ignored | 是 | 忽略风险 |
| decision_status | 是 | **初始值固定为 `proposed`** |

### 6.1 初始状态限制

| 规则 | 说明 |
|:-----|:-----|
| ⛔ 初始状态只能是 `proposed` | 后评估生成的候选草案不得直接设为 `approved` / `applied` |
| `proposed` → 必须经过角色评审 | 对应角色确认后才能进入下一状态 |
| 禁止绕过角色评审 | 不得由执行模型代签角色确认 |

## 7. 候选分流规则

后评估确定归因类型后，候选按以下规则分流：

| 归因特征 | 优先落点 | 说明 | 何时升级 |
|:---------|:---------|:-----|:---------|
| 单次失败、原因未充分确认、特殊环境失效 | **反例库** | 不直接改核心规则 | 连续 3 次同类失败后生成核心知识候选 |
| 阈值偏差、窗口偏差、权重偏差、证据有效期、字段可信等级 | **参数库** | 修参数不重写逻辑 | 后续评估确认参数稳定性后 applied |
| 日报未执行周报指令、C 层表达过激/过保守、场景输出断裂 | **场景适配器** | 修适配器不改角色知识 | 场景变更确认后固化 |
| 跨标的、跨周期、连续多次验证的稳定问题 | **核心知识库候选** | 须经角色确认+腰子终审+旧影审计 | 走完整候选评审流程 |
| 无法归因或样本不足 | **parked / 仅复盘备注** | 不进入 applied | 等待更多样本 |

### 7.1 分流判断路径

```
后评估完成 → 归因确定
  ├→ data                   → 玉夜确认 → 反例库 / 参数库
  ├→ parameter              → 青山+流金确认 → 参数库
  ├→ analysis_logic         → 腰子+青山确认 → 反例库 / 核心候选
  ├→ presentation           → 腰子+流金确认 → 场景适配器
  ├→ execution              → 阿黑路由 → 场景适配器
  ├→ strategy_environment   → 山猫+青山确认 → 参数库 / 适配器
  └→ 无法归因               → parked / 仅复盘备注
```

## 9. 角色确认规则

后评估产生的候选按归因类型由对应角色确认：

| 归因类型 | 确认角色 | 联审角色 | 裁决角色 |
|:---------|:---------|:---------|:---------|
| data（数据口径问题） | 玉夜 | 腰子 | 腰子 |
| parameter / weight（技术信号/因子有效性） | 青山 | 流金 / 腰子 | 腰子 |
| presentation / risk（风险边界/动作表达） | 流金 | 腰子 | 腰子 |
| evidence_level（事件证据/催化窗口） | 信鸽 | 腰子 | 腰子 |
| strategy_environment（宏观覆写/行业相位） | 山猫 | 青山 / 腰子 | 腰子 |
| analysis_logic（结论强度/状态机/整合裁决） | 腰子 | 流金 / 青山 | 腰子 |

### 9.1 审计与路由

| 角色 | 职责 | 禁止 |
|:-----|:-----|:-----|
| 旧影 | G5 独立复查 | 不代签、不执行、不裁决 |
| 阿黑 | 流程路由和汇总 | 不代签、不实现、不裁决 |
