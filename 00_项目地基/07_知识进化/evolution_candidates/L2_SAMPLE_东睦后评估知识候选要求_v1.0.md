## 1. 定位与边界

### 1.1 本文件是什么

本文件规定东睦股份后续 B 层后评估时**必须产出哪些 KnowledgeUpdateCandidate 检查项**。

它是知识进化机制的首个验证样例模板，用来确保：
- 后评估不只是写判断对错。
- 单次失败先进入反例库，不直接改核心规则。
- 候选按 SCHEMA 字段生成，经过角色确认后进入评审流程。

### 1.2 本文件不是什么

| 不是 | 说明 |
|:-----|:-----|
| ❌ 不是东睦后评估报告 | 后评估报告需 B 层实际执行后产生 |
| ❌ 不是东睦投资结论 | 不包含买入/卖出/持有建议 |
| ❌ 不是默认真实候选已生效 | 候选需角色确认+腰子终审后才能 applied |
| ❌ 不是周报补丁 | 不改东睦周报正文 |
| ❌ 不是日报执行规则 | 日报执行规则不受本文件影响 |

### 1.3 本文件不做什么

| 禁止项 | 说明 |
|:-------|:-----|
| ⛔ 不生成真实东睦候选 | 后评估完成后才可能生成 |
| ⛔ 不写东睦投资结论 | 不包含任何交易建议 |
| ⛔ 不改东睦周报 | 周报正文不受本文件影响 |
| ⛔ 不改日报执行规则 | 日报执行规则不变 |
| ⛔ 不改参数真实值 | 参数修改需走完整流程 |
| ⛔ 不把检查点当成已发生事实 | 检查点是提示项，不是结论 |

## 2. 东睦样例的作用

东睦股份是知识进化机制的第一个验证样例。通过东睦后评估，检验以下链路是否通顺：

### 2.1 验证目标

| 验证项 | 预期 | 检验方式 |
|:-------|:-----|:---------|
| 周报核心假设是否能被日报执行 | 日报有明确的执行记录 | 检查 daily_instruction_ref 与实际日报匹配 |
| B 层后评估是否能产出候选 | 后评估至少产出 1 条候选 | 检查后评估报告中 KnowledgeUpdateCandidate 段 |
| 候选是否能进入反例库/参数库 | 候选有 role_review → approved 的流转 | 检查候选的状态迁移记录 |
| 单次失败能否被拦在反例库 | 后评估的失败归因不硬改核心规则 | 检查候选的 target_layer 是否为 counterexample |

### 2.2 东睦样例的阶段位置

```
东睦周报 A 层核心假设
  → 日报执行（持续 1-2 周）
  → 催化节点落地/落空
  → B 层后评估
  → 生成 KnowledgeUpdateCandidate 草案
  → owner_role 确认
  → 腰子终审
  → 反例库 / 参数库 / 适配器候选
```

## 3. 必须产出的 6 类候选检查项

东睦后续 B 层后评估必须检查以下 6 个方面。每项检查发现问题时应生成对应的 KnowledgeUpdateCandidate 草案。

| 检查项 | 归因类型 | owner_role | target_layer | 初始处理 |
|:-------|:---------|:-----------|:-------------|:---------|
| D-01 技术修复后没有延续 | parameter / analysis_logic | 青山 | parameter / counterexample | 检查技术信号有效性和样本门槛 |
| D-02 moneyflow 口径误导 | data | 玉夜 | counterexample / parameter | 检查资金字段可信等级和使用限制 |
| D-03 C 层动作太激进 | presentation / risk | 流金 | adapter / counterexample | 修动作表达红线，不直接改核心逻辑 |
| D-04 中期逻辑判断过强 | analysis_logic | 腰子 | counterexample / core_candidate | 检查证据等级与状态机升级条件 |
| D-05 催化窗口落空 | evidence_level / parameter | 信鸽 | parameter / counterexample | 检查 L2a 有效期和公告证据等级 |
| D-06 市场风格压制成长线索 | strategy_environment | 山猫 | parameter / adapter | 判断是否属于策略环境变化 |

### 3.1 检查项使用规则

1. 每个检查项不要求必须产生候选——无偏差时只需记录"无异常"。
2. 多项可合并为同一候选——如果 moneyflow 误导和 C 层动作过激同源，可合并。
3. 一项可拆分为多个候选——如果技术修复问题既涉及参数又涉及分析逻辑，可分两条。
4. 候选草案的 target_layer 由后评估决定，不强制锁死。

## 4. 每个候选必须包含的字段

根据 `L2_SCHEMA_KnowledgeUpdateCandidate_v1.0.md`，东睦后评估产出的候选必须包含以下字段：

| 字段 | 必填 | 说明 |
|:-----|:----:|:-----|
| candidate_id | 是 | 格式：KUC-YYYYMMDD-ROLE-NNN |
| source_type | 是 | 固定为 `weekly_report` |
| source_ref | 是 | 东睦周报路径或后评估路径 |
| stock_code | 是 | 600114 |
| scenario | 是 | 深度周报 |
| owner_role | 是 | 按 6 类检查项 owner_role 填写 |
| attribution_type | 是 | 按 6 类检查项归因类型填写 |
| observed_failure | 是 | 后评估观察到的问题描述 |
| proposed_update | 是 | 建议更新内容 |
| target_layer | 是 | 按 6 类检查项 target_layer 选择 |
| confidence | 是 | low / medium / high |
| evidence_refs | 是 | 证据引用，至少 1 条 |
| risk_if_applied | 是 | 采纳风险 |
| risk_if_ignored | 是 | 忽略风险 |
| decision_status | 是 | 初始值为 proposed |

## 5. 东睦候选生成时机

| 时机 | 可触发的候选 | 说明 |
|:-----|:------------|:-----|
| 周报发布后 | 不立即生成候选 | 需等待日报执行记录 |
| 日报执行记录形成后（1-2 周） | D-01 技术修复 / D-02 moneyflow | 日报数据可验证技术假设和资金流向 |
| 催化节点落地/落空后 48 小时内 | D-05 催化窗口 | 事件驱动结果明确后触发 |
| B 层后评估执行时 | 全部 6 项 | 正式后评估时全面检查 |
| 市场风格明显切换时 | D-06 市场风格 | 山猫环境归因触发 |

### 5.1 不确定时的处理

| 情况 | 处理 |
|:-----|:-----|
| 无法归因（信息不足） | 候选进入 parked，注明原因 |
| 归因方向不明确（多个可能） | 候选标注 confidence=low，列出假设 |
| 偏差为随机波动 | 不生成候选，仅在后评估记录中说明 |

> **禁止**：无法归因时硬写结论，或把未确认候选提交为 role_review。
