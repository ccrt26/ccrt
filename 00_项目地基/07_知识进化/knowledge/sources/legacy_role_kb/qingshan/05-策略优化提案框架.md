## 一、优化哲学：先问"要不要改"，再问"怎么改"

### 1.1 优化的四个前置问题

在提出任何策略优化提案之前，青山必须回答四个问题：

```
Q1: 策略哪里表现不好？
  → 用数据量化缺陷：超额收益、胜率、最大回撤、ICIR

Q2: 不好的原因是策略设计问题还是市场环境问题？
  → 市场环境问题 → 等环境恢复，不轻易改策略
  → 策略设计问题 → 进入优化提案流程

Q3: 改动的预期收益是否能覆盖改动的风险？
  → 每次改动都有成本：灰度测试的人力、可能的回退、未知风险

Q4: 有没有更简单的方法达到同样的效果？
  → 奥卡姆剃刀原则：能调一个参数解决问题的，不要重构整个维度
```

### 1.2 过优化的危险信号

以下任何一种情况出现，青山应立即停止优化并反思：

```
⚠️ 危险信号清单：

1. "这个参数精确到0.01能让夏普提高0.2"
   → 过度精确的参数=过拟合的证据

2. "回测表现完美，最大回撤仅0.5%"
   → 真实策略不可能有这个水平（A股正常的日波动率就>1%）

3. "改了4个参数后，回测大幅改善，但不清楚哪个参数起的作用"
   → 多变量同时调整=不可控的实验

4. "这组参数在20个交易日的样本上表现最好"
   → 小样本选最优参数=数据挖掘

5. "同样的优化方法，应用到上个月数据反而表现更差"
   → 参数不稳定，说明原始策略不够稳健
```

## 二、优化触发条件

### 2.1 定量触发阈值

不是每次策略表现波动就要优化。以下定量条件才触发优化流程：

```
触发条件 A：策略表现系统性落后（满足任一）
  ├── 滚动60日超额收益 < -5%（vs沪深300），且连续2个月
  ├── 月胜率 < 40%（不是市场整体下跌导致的——全市场等权跌幅
  │   如果也很大，说明是市场原因而非策略问题）
  └── 最大回撤 > 历史最大回撤 × 1.5

触发条件 B：因子预测力结构性下降（满足任一）
  ├── 核心因子的ICIR（近30日滚动）连续3个月 < 0.1
  ├── 核心因子的IC（近30日均值）连续2个月 < 0
  └── 分组单调性连续20个交易日不通过

触发条件 C：交易成本侵蚀超额（满足任一）
  ├── 策略换手率月化 > 80%（单边）
  └── 估算的交易成本 > 策略超额收益的50%

触发条件 D：新信息出现
  ├── 外部因子研究有重大发现（如新因子被验证在A股有效）
  ├── 市场制度变更（如交易规则、费率结构变化）
  └── 月度后评估发现可复现的失败模式
```

### 2.2 不应触发的假信号

以下情况不应触发策略优化：

```
✗ 单日大幅跑输 → 正常波动
✗ 某一板块表现差 → 行业轮动的正常结果
✗ IC偶尔一天为负 → 单日噪声
✗ 个别股票否决后大涨 → 否决的预期内失误（不可能100%准确）
✗ 全市场暴跌中策略也跌 → 系统性风险，非策略问题
```

## 三、参数优化方法

### 3.1 网格搜索（Grid Search）

最基础、最可解释、最不容易过拟合的方法。青山的默认推荐。

```
方法：
  参数空间 = [值1, 值2, 值3, ..., 值k]
  对每个参数组合评估策略表现
  选出最优组合

适用范围：
  ├── 参数数量 <= 3（否则组合爆炸，如10个参数各10个值=10^10组合）
  ├── 每个参数候选值 <= 5
  └── 数据量 >= 参数组合数 × 10

本项目示例（评分阈值优化）：
  参数1：评分阈值（候选值：40, 45, 50, 55, 60）
  参数2：最低仓位（候选值：5%, 10%, 15%）
  参数3：最高仓位（候选值：20%, 25%, 30%）
  
  组合数：5 × 3 × 3 = 45
  所需最少交易日：45 × 10 = 450（远超当前数据量！）
  
  → 在当前数据不足时，网格搜索不可行
  → 替代：敏感性分析（一次只变一个参数）
```

### 3.2 贝叶斯优化（Bayesian Optimization）

适合参数空间连续、回测成本高的场景。比网格搜索更高效。

```
核心思想：
  ├── 用高斯过程（Gaussian Process）建模参数→表现的映射
  ├── 每次选择"最值得探索"的参数点（最大化获取函数）
  └── 通常用10-20次迭代就能找到接近最优的参数

适用范围：
  ├── 参数数量 <= 10（再多需要特殊的高维贝叶斯优化）
  ├── 参数是连续的（如阈值从0.01到0.99）
  └── 每次回测的成本较高（如需要完整的历史模拟）

本项目适用性：
  数据量不足时（<100个交易日），贝叶斯优化会过拟合
  → 当前不推荐，未来数据充足后是首选方法
```

### 3.3 遗传算法（Genetic Algorithm）

适合非连续、非凸、有大量局部最优的参数空间。

```
核心思想：
  ├── 初始化：随机生成N组参数组合（种群）
  ├── 选择：保留表现最好的M组
  ├── 交叉：M组之间交换参数片段
  ├── 变异：小概率随机修改参数
  └── 迭代：重复选择→交叉→变异，直到收敛

优点：能跳出局部最优
缺点：随机性强，可解释性差，容易过拟合
本项目建议：暂不使用（数据量不足+过拟合风险高）
```

### 3.4 本项目推荐的参数优化策略（小样本版）

在数据不足60个交易日的情况下，参数优化必须极度保守：

```
Step 1: 单参数敏感性分析（一次只变一个参数）
  保持其他所有参数不变，测试目标参数±10%/±20%的影响
  观察：参数变化是否导致策略表现的显著变化？
    ├── 是 → 该参数敏感，值得优化（但也意味着过拟合风险高）
    └── 否 → 该参数不敏感，不需要优化（当前设置可能已经够好）

Step 2: 方向确认
  参数值↑ → 策略表现↑ 还是 ↓？
  确认方向后，选择一个温和的调整幅度（如10-15%而非50%）

Step 3: 样本外确认
  在调整前的数据上（没有任何用于决策的数据）验证
  如果样本外验证不通过 → 放弃此次调整

Step 4: 灰度上线
  新旧参数并行5个交易日，确认新参数表现>=旧参数
```

## 四、权重优化

### 4.1 权重优化的六种方法

| 方法 | 公式/核心思想 | 适用场景 | 本项目适用性 |
|:-----|:------------|:---------|:----------:|
| 等权重 | w_i = 1/N | 对各因子完全不了解时 | 当前部分维度近似等权 |
| IC加权 | w_i = IC_i / ΣIC_j | IC高的因子权重高 | 简单但忽略ICIR差异 |
| ICIR加权 | w_i = ICIR_i / ΣICIR_j | 兼顾预测力和稳定性 | **推荐**（数据充足后） |
| 波动率倒数 | w_i = (1/σ_i) / Σ(1/σ_j) | 降低高波动因子的影响 | 适合风险控制优先 |
| 最大夏普 | 优化 max(return/risk) | 追求风险调整后最优 | 需要大量数据 |
| 风险平价 | 各因子对组合风险的贡献相等 | 适合多资产配置 | 需要较长数据和协方差矩阵 |

### 4.2 ICIR加权——青山的首选推荐

```
算法：

Step 1: 计算每个因子的近N日滚动ICIR
  ICIR_i = mean(IC_i[t-N:t]) / std(IC_i[t-N:t])

Step 2: 归一化
  w_i = max(0, ICIR_i) / Σ(max(0, ICIR_j))
  
  （负ICIR的因子权重固定为0——不留负贡献因子在组合中）

Step 3: 设置上下限
  w_i = min(max(w_i, 0.05), 0.40)
  （单因子权重不低于5%，不高于40%——防止过度集中）

Step 4: 平滑调整
  w_i_final = 0.7 × w_i_new + 0.3 × w_i_old
  （平滑过渡——避免权重大幅跳变带来的交易成本）
```

### 4.3 本项目的权重调整历史

| 版本 | 技术面 | 基本面 | 资金面 | 消息面 | 板块动量 | 调整依据 |
|:----:|:-----:|:-----:|:-----:|:-----:|:------:|:---------|
| v2.3 | 25 | 20 | 20 | 20 | 15 | (基准版本) |
| v2.4 | 30 | 15 | 20 | 15 | 20 | v1.5后评估Spearman |

青山对v2.4调整的评估：
- 调整方向符合Spearman信号（正相关↑、负相关↓）
- 但调整幅度缺乏统计支持（20个交易日不足以做权重优化）
- 应在积累60个交易日数据后，用ICIR加权方法重新校准所有维度权重

## 五、周期优化

### 5.1 调仓频率的取舍

| 调仓频率 | 优势 | 劣势 | A股适用性 |
|:--------|:-----|:-----|:--------:|
| 日频 | 快速捕捉信号、信息衰减小 | 交易成本高、噪声大 | 仅高频+低换手因子的组合可行 |
| 周频 | 平衡信号时效性和成本 | 可能错过日内极端信号 | 适合大多数A股量价因子 |
| 双周频 | 进一步降低成本 | 信号衰减风险上升 | 适合基本面因子+资金面因子 |
| 月频 | 成本最低 | 信号衰减严重（A股短线因子1-2周就衰减） | 仅适合纯基本面因子+长期价值因子 |

### 5.2 混合频率设计

青山推荐的理想方案是不同因子使用不同的调仓频率：

```
技术面因子（动量/反转）：周频调仓
  ├── 信号有效期约5-10个交易日
  └── 理由：量价信号衰减快

基本面因子（质量/价值）：月频调仓
  ├── 信号有效期约1-3个月
  └── 理由：基本面变化慢

资金面因子：周频调仓
  ├── 信号有效期约5-15个交易日
  └── 理由：资金流向变化较快

板块动量：双周频调仓
  ├── 行业动量有效期约2-4周
  └── 理由：行业轮动介于个股和宏观之间
```

### 5.3 本项目的现状

项目当前采用日频评分+日频选股，且所有维度使用同一频率。这是一个简化但有代价的设计：

- 基本面因子日频评分意义不大（基本面每天变化极小）
- 日内噪声被放大（每日调仓增加了随机性）

改进方向：在模拟交易引擎中实现混合频率调仓逻辑。

## 六、阈值敏感性分析

### 6.1 阈值优化的通用框架

对于策略中的任何阈值（评分阈值、否决阈值、止盈止损线、仓位线等）：

```
Step 1: 确定阈值的当前值和合理范围
  例如：评分阈值当前=45，合理范围=[35, 55]

Step 2: 敏感性曲线
  阈值    胜率    平均收益  最大回撤   换手率
  35      48%     +0.8%     -3.2%     55%
  40      52%     +1.0%     -2.8%     45%
  45(现)  55%     +1.1%     -2.5%     38%
  50      56%     +1.0%     -2.6%     32%
  55      53%     +0.7%     -3.0%     25%

Step 3: 分析曲线形状
  ├── 平滑曲线：阈值在此范围内表现稳定（好——策略稳健）
  ├── 尖锐峰值：只有特定阈值表现好（差——可能过拟合）
  └── 平坦曲线：阈值变化对结果影响小（中性——阈值不重要）

Step 4: 选择
  在"胜率-换手率"的tradeoff之间选择平衡点
  优先选择：
    ├── 敏感性曲线平坦区间的值（更稳健）
    └── 而非"全局最优"的那个孤立尖峰（更可能过拟合）
```

### 6.2 本项目关键阈值一览

| 阈值 | 当前值 | 敏感性（估） | 优化优先级 |
|:-----|:-----:|:---------:|:--------:|
| 评分入选线（≥45） | 45 | 中 | P1 |
| 各档仓位映射（≥80/65/45/30） | 四档 | 高 | P0 |
| PE否决线 | 行业相关 | 中 | P2 |
| 单票仓位上限（25%） | 25% | 中 | P2 |
| 止损线（-8%） | -8% | 高 | P1 |
| 冷却期（3日） | 3 | 高 | P1 |

### 7.2 新因子优先级评估矩阵

青山在提交多个新因子提案时，使用以下矩阵排序：

```
优先级 = 预期ICIR × (1 - 与现因子最大相关) × (1 - 月换手率/100%) × 数据可得性

数据可得性：
  1.0 = 数据已在项目数据管线中
  0.8 = 数据可通过现有API获取
  0.5 = 需要新增数据源
  0.2 = 数据获取困难

得分越高，优先级越高。
```

## 八、灰度测试制度

### 8.1 测试流程

```
Phase 1: 离线回测（由Claude执行）
  ├── 时间：1-2个工作日
  ├── 内容：用历史数据验证因子/策略变更的基本有效性
  └── 通过标准：IC>0.03, ICIR>0.2, 分组单调性通过

Phase 2: 纸上并行（Paper Parallel）
  ├── 时间：5个交易日
  ├── 内容：新旧规则同时产生选股列表，但只执行旧规则的交易
  ├── 记录：逐日对比新旧选股的次日表现
  └── 通过标准：新规则选股的5日平均胜率 >= 旧规则胜率 + 3%

Phase 3: 小仓位实盘验证（Mini Live）
  ├── 时间：5个交易日
  ├── 内容：新规则以20%的仓位权重参与实盘
  ├── 对比：新规则负责的20%仓位 vs 旧规则负责的80%仓位
  └── 通过标准：新规则的夏普 >= 旧规则夏普

Phase 4: 全量切换
  ├── 新规则承担100%仓位
  ├── 保留旧版本代码和参数（用于回滚）
  └── 开始正常监控周期
```

**注意**：本项目为模拟交易，Phase 3的"实盘"=模拟交易。

### 8.2 灰度期的监控要项

| 监控项 | 频率 | 异常阈值 |
|:-------|:----:|:--------|
| 新旧选股重叠率 | 每日 | 如果<30%，说明新旧差异极大，需更谨慎 |
| 新规则选股的换手率 | 每日 | 如果>旧规则×1.5，交易成本可能大幅上升 |
| 新规则的否决率 | 每日 | 如果>50%或<5%，否决可能失当 |
| 新规则选股的行业分布 | 每日 | 如果单行业>40%，行业集中度过高 |
| 新规则选股vs旧规则选股的次日表现差 | 每日 | 如果连续3天新<旧，提前终止灰度 |

### 8.3 灰度测试的提前终止条件

```
满足任一条件，立即终止灰度测试：

├── 连续3个交易日，新规则选股的平均收益 < 旧规则 - 2%
├── 新规则单日最大回撤 > 旧规则历史最大回撤 × 2
├── 新规则触发了任何红线违规（如编造数据、删除PDF等）
└── 灰度期间发现新规则存在逻辑缺陷或实施错误
```

## 十一、自测题

**题1**：策略近5天表现不佳（日胜率从55%降至40%），应该在什么时候触发优化？

**答案**：5天不足以触发优化。单周是正常的随机波动——A股单周市场风格的变化足以导致策略表现波动。应做的是：（1）记录这5天的具体数据，判断是哪个维度拖了后腿；（2）检查是否全市场都在跌（如果是，这不是策略问题）；（3）如果连续10-15个交易日持续跑输、且非全市场原因，再开始考虑优化。过早优化（在噪声上做决策）是最常见的策略研究错误之一。

**题2**：网格搜索vs贝叶斯优化vs遗传算法——在本项目当前阶段（<60个交易日数据）应该用哪个？

**答案**：都不应该用。网格搜索需要参数组合数×10的样本量，当前数据远不满足。贝叶斯优化在小样本上过拟合风险极高。遗传算法更是数据饥渴。当前阶段唯一可行的参数优化方法是：单参数敏感性分析 + 方向确认 + 保守幅度（10-15%变化） + 样本外验证（5-10个交易日）。在数据积累到至少120个交易日前，任何"自动化"或"智能化"的优化方法都应被视为过拟合风险极高。

**题3**：灰度测试5个交易日真的够吗？有什么局限性？

**答案**：5个交易日确实不够——这更多是一个"最低安全网"而非"统计验证"。5个交易日的局限性：（1）样本太小，受1-2个异常交易日的影响大；（2）如果恰好是极端市场（如连续暴涨），表现好不代表策略真的好；（3）只能排除"灾难性失败"，不能确认"真的更好"。青山的建议是：在5日灰度通过后，将新策略标记为"观察期"至少再持续10个交易日（共15日），期间每日对比新旧表现。只有在15日均确认新>=旧后，才做正式切换。如果数据积累到60+交易日，灰度期应延长至10个交易日。
