## 规则 R01 — 数据置信度规则

**来源案例：** A-001 东睦复盘

### 问题陈述

分析中资金流向（东方财富算法估算）和行情价（交易所数据）被并列使用，未区分可信度层级。这导致"主力净流入1.11亿"被赋予了和"今日涨停10.01%"相同的证据权重。

### 规则

所有关键数据必须标注类型：

| 等级 | 类型 | 数据举例 | 规则 |
|:-----|:-----|:---------|:-----|
| **硬数据** 🟢 | 交易所直发、官方公告 | 价格、成交量、涨跌幅、公告原文、财务报表 | 可直接用于论证，权重高 |
| **软数据** 🟡 | 平台算法推算 | 资金流向、主力净流入、龙虎榜、筹码分布 | 须标注推算方法，权重打折 |
| **估算数据** 🔴 | 分析师推断 | 主力意图、控盘程度、情绪阶段、筹码稳定性 | 不得作为核心结论的唯一支撑 |

### 责任角色

玉夜 — 发布数据时强制标注。腰子 — 整合时核对置信度分布。

### 处罚

软数据/估算数据被当作硬数据用于核心结论 → WARN，退回腰子重审。

## 规则 R02 — 事件时间映射规则

**来源案例：** A-001 东睦复盘

### 问题陈述

事件分析只列了"过去发生了什么"（M&A 4/30过会、购地5/27公告），但没给出"下一步可能什么时候发生"（CSRC注册通常需要多久）。导致外部观点提出"需要新催化剂"时，团队无法判断这个催化剂是否在预期时间窗口内。

### 规则

涉及审批、注册、项目建设、并购进程时，信鸽必须：

1. 列出**已发生事件 & 时间戳**
2. 列出**下一步关键事件 & 预期时间窗口**（参考同类案例周期）
3. 标注 **不确定性区间**（如：同类案例注册周期3-9个月，取中值5个月）
4. 标注**可提前/延后的触发信号**（如：问询函、反馈意见）

### 责任角色

信鸽 — 采集时产出时间映射。腰子 — 在整合单中引用。

### 处罚

涉及审批/注册类事件但未做时间映射 → WARN。连续2次未执行 → B1级缺陷。

## 规则 R03 — 不可证伪叙事规则

**来源案例：** A-001 东睦复盘

### 问题陈述

"洗盘""换庄""主力诱空""吸筹"等叙述几乎没有反证条件——只要走势和预期相反，都可以用"主力在洗盘/诱空"来解释。是A股分析中被滥用最严重的叙事陷阱。

### 规则

分析中出现以下词汇时，自动触发反证审查：

> 洗盘、出货、吸筹、换庄、主力控盘、诱多、诱空、震仓、试盘

反证审查必须包含：

- **叙事成立条件**：什么证据存在时该叙述才成立
- **叙事失效条件**：当出现什么信号时该叙述自动推翻
- **观察窗口**：在哪个时间范围/价格区间内验证

### 责任角色

流金 — 识别叙事类型、发起反证审查、写入风险评估。

### 违规处理

核心结论依赖"洗盘/换庄"解释但无反证条件 → BLOCK（禁止发布正式分析）。

## 规则 R04 — 替代情景规则

**来源案例：** A-001 东睦复盘

### 问题陈述

团队天然倾向于输出一个最可能的结论（"洗盘概率大"），但不主动问"如果不是洗盘呢？如果是换庄呢？如果是趋势衰竭呢？"——缺少对抗性论证，容易掉入确认偏误。

### 规则

腰子整合单**必须**新增一个固定字段：`why_not_alternatives`

至少比较**主情景**与**一个反向情景**：

| 字段 | 说明 |
|:-----|:------|
| 主情景 | 综合判断最可能的走向，赋概率权重 |
| 反向情景 | 与主情景相反的走向，赋概率权重 |
| 区别信号 | 什么观测值出现时，应放弃主情景转向反向情景 |
| 决策韧性 | 反向情景成立时对当前持仓的影响 |

### 责任角色

腰子 — 整合时执行。各角色 — 在主情景结论外试提一个反向情景。

### 处罚

整合单缺替代情景段 → WARN。连续3次缺 → B级缺陷。

## 规则 R05 — 叙事偏好校正规则

**来源案例：** A-001 东睦复盘

### 问题陈述

分析结论如果是"洗盘结束/反包确认/继续持有"，会让持仓者感到安心——而"换庄/风险/再观察"则让人不安。这导致团队在无意识中更偏向产出一个让自己也舒服的结论。自我修正有难度，但必须标示。

### 规则

当结论偏向以下方向时，青山必须标记偏好校正：

> 反包确认、洗盘结束、继续拉升、主升浪、格局持有、加仓机会

校正方式：
1. 明确回答：**当前结论是否让持仓者更安心？**
2. 如果有安心偏差，描述偏差方向
3. 用反方前提重推一次结论是否仍然成立

### 责任角色

青山 — 输出因子信号时附带偏好校核。腰子 — 在裁决中确认是否进行了校正。

### 处罚

持有/加仓类建议未做偏好校正 → WARN。连续2次未做 → 腰子介入强制校正。

## 规则 R06 — 影子角色规则

**来源案例：** A-001 东睦复盘

### 问题陈述

全团5人全部输出后形成一致意见——有共识是好事，但没有异议者就意味着可能存在**集体盲区**。本次分析有DeepSeek和豆包扮演了外部反对者角色，但日常分析中不一定有这样的外部输入。

### 规则

**触发条件：** 以下任一时，腰子必须指定一个影子角色：

- 涉及重大分歧（外部专家观点对立、核心数据矛盾、高P0决策）
- 全团咨询后意见高度一致（无任何分歧）

**影子角色职责：**

- 不用输出主流观点，专门输出**一个站得住的相反框架**
- 影子角色不追求正确，追求**暴露盲区**
- 影子角色建议不需要完整数据支撑，但必须有逻辑起点

**选择规则：**

- 本轮影子角色不固定，腰子按分析类型指定
- 连续2次指定同一人 → 下次换人
- 腰子本人可兼任

**输出格式：**

```
[影子角色 - 角色名]
主流共识：________
挑战框架：________
盲区假设：________
如果主流共识错误，最可能的原因：________
```

### 责任角色

腰子 — 判断是否触发 + 指定影子角色。被指定角色 — 执行影子输出。

### 处罚

应触发但未指定影子角色 → WARN。连续2次应触发未触发 → B级流程缺陷。
