## 1. 定位与边界

### 1.1 反例库属于 L-K4

反例库是五层知识结构的第四层（L-K4），用于保存**证明某条规则不能直接泛化的失败样本**。

核心原则：

| 原则 | 说明 |
|:-----|:-----|
| 单次失败优先进入反例库 | 不直接修改核心知识库 |
| 反例不是正式规则 | 反例记录失败路径，不授权生产行为 |
| 反例可升级为候选 | 连续 3 次同类失败后进入核心知识库评审 |
| 反例可标注边界 | 标记规则的适用环境和不适用环境 |

### 1.2 反例库不做什么

| 禁止项 | 说明 |
|:-------|:-----|
| ⛔ 不直接改角色核心知识库 | `.claude/agents/*-知识库/` 不动 |
| ⛔ 不自动改参数 | 参数库单独管理 |
| ⛔ 不自动改报告模板 | 报告模板不受反例影响 |
| ⛔ 不自动写入生产 | 反例不触发生产逻辑 |
| ⛔ 不代签角色 | 反例确认需对应角色签字 |

## 2. 反例进入条件

满足以下任一条件即可进入反例库：

| 条件 | 说明 | 示例 |
|:-----|:-----|:-----|
| 单次失败但归因未充分确认 | 知道错了但不知道确切原因 | 技术修复后走势未延续，无法确定是参数问题还是市场环境 |
| 规则在特殊环境中失效 | 规则本身正确，但在特定市场/行业不适用 | 动量因子在震荡市中频繁失效 |
| 数据口径误导结论 | 错误的数据导致错误的判断 | moneyflow 字段口径与实际流动性不符 |
| 动作表达过激或过保守 | 报告语言偏离了合适的动作边界 | C 层摘要用了"强力推荐"但证据等级只有 L2b |
| 证据等级错配 | 把预期/传闻/叙事误当强证据 | 把媒体报道当 L1 证据 |
| 周报/日报执行断裂 | 日报未按周报指令执行，导致判断落空 | 周报要求跟踪但日报未采集 |
| 策略环境变化导致原逻辑短期失效 | 市场风格切换使原有逻辑失真 | 成长因子在价值风格下短期失效 |

## 3. 反例最小字段

### 3.1 字段定义

| 字段 | 必填 | 说明 | 示例 |
|:-----|:----:|:-----|:-----|
| case_id | 是 | 反例 ID | CE-20260610-QINGSHAN-001 |
| source_ref | 是 | 来源报告/后评估/EvalHook | `06_后评估闭环/东睦周报后评估_v1.0.md` |
| stock_code | 否 | 标的代码 | 600114 |
| scenario | 是 | 场景 | weekly_report / daily_report / stock_pick / sim_trade / eval |
| failed_rule_or_assumption | 是 | 失败的规则或假设 | "技术修复后 3 个交易日内应延续上涨" |
| context | 是 | 市场环境、行业相位、标的状态快照 | 震荡市，成长板块受风格压制 |
| failure_path | 是 | 从判断到失败的路径描述 | 周报判断技术修复→日报跟踪量能不足→后评估确认未延续 |
| attribution_type | 是 | 归因类型 | data / parameter / evidence_level / analysis_logic / presentation / execution / strategy_environment |
| confirmed_cause | 是 | 已确认原因；未确认时填 unknown | 技术修复窗口参数过短 |
| reusable_lesson | 是 | 可复用教训 | 技术修复确认窗口应延至 5 个交易日 |
| target_layer | 是 | 建议修正落层 | counterexample / parameter / adapter / core_candidate |
| linked_candidates | 否 | 关联 KnowledgeUpdateCandidate ID | KUC-20260610-QINGSHAN-001 |
| owner_role | 是 | 首要确认角色 | 青山 |
| review_status | 是 | 审核状态 | proposed / confirmed / archived / superseded |
| evidence_refs | 是 | 证据引用，至少 1 条 | 后评估记录、EvalHook 数据 |
| created_at | 是 | 创建日期 | 2026-06-10 |
| reviewed_at | 否 | 最近复核日期 | 2026-06-10 |

### 3.2 review_status 状态机

```
                    ┌──────────┐
                    │ proposed │  ← 新反例
                    └─────┬────┘
                          │
               ┌──────────┼──────────┐
               │          │          │
         ┌─────▼────┐  ╔══╧══╗   ┌──▼──────┐
         │confirmed │  ║ARCH ║   │archived │
         │ 已确认   │  ╚═════╝   │ 超过有效期│
         └─────┬────┘            └─────────┘
               │
         ┌─────▼──────┐
         │ superseded │  ← 被新反例替代
         └────────────┘
```

| 状态 | 含义 | 允许下一步 |
|:-----|:-----|:-----------|
| proposed | 新反例，待确认 | confirmed / archived |
| confirmed | 已确认的反例 | superseded / archived |
| archived | 超过有效期或已关闭 | 不再流转 |
| superseded | 被新反例替代 | archived |

## 4. 反例升级规则

### 4.1 升级门槛

| 条件 | 操作 | 说明 |
|:-----|:-----|:-----|
| 单次反例 | 留在反例库 | 不直接改核心规则 |
| 同类反例连续 3 次，跨≥2 标的或 2 个周期 | 生成核心知识库候选 | 可进入核心知识库评审 |
| 参数偏差明确的 | 优先进入参数库 | 不重写分析逻辑 |
| 场景表达问题 | 优先修适配器 | 不改主报告逻辑 |
| 数据口径问题 | 交玉夜确认 | 玉夜调度字段可信等级 |
| 信号有效性证据充足的 | 交青山确认 | 青山确认后走候选流程 |
| 动作边界反复越界 | 交流金+腰子确认 | 流金和腰子联合检查风控 |

### 4.2 禁止规则

| 禁止项 | 说明 |
|:-------|:-----|
| ⛔ 单次反例不得直接升级为核心规则 | 需连续 3 次确认 |
| ⛔ 不得把反例当正式规则写入报告 | 反例不是生效知识 |
| ⛔ 不得越过角色确认升级 | 反例升级必须 owner_role 签字 |

## 5. 反例库目录结构

反例库按标的和时间组织：

```
counterexamples/
└── L2_COUNTEREXAMPLE_INDEX_v1.0.md     ← 本文件，总索引
```
