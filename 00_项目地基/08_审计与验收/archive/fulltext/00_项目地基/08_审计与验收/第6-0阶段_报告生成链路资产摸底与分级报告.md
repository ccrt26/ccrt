## 二、当前日报生成链路图

```
batch_data_collector.py ─→ data_full.json + margin_detail/*.json
    │
    ▼
daily_orchestrator.py (983行) ───→ context dict
    │                                  │
    │                              ┌───┴──────────┐
    │                              ▼              ▼
    │                         signal_daily    extract_stock_daily_context()
    │                         (JSON signal)   ─→ 直接产出日报内容
    │                                          (非 canonical 对象)
    ▼
daily_workflow.py (编排) ─→ run_daily_eval.py ─→ P0闸门(C1-C6)
    │
    ▼
重点股票/ 下脚本（报告生成/后评估）
    │
    ▼
pdf_gate_v36.py ─→ convert_md_to_pdf.py ─→ PDF
    │
    ▼
check_md_sidecar_consistency.py ─→ check_numeric_source_consistency.py ─→ ...
    │
    ▼
每日荐股/ 生成 HTML（gen_daily_html.py，独立链路，不交叉）
```

**关键发现：** 当前日报生成不是"先建 canonical 对象再渲染"，而是 `daily_orchestrator.py` 直接产出 sidecar 风格的 context dict 并写入 signal。MD/JSON/HTML/PDF 各端各自渲染，**缺乏统一的中间报告对象**。

### R1：sync_report_json.py 可能污染 sidecar

| 维度 | 说明 |
|:-----|:------|
| 风险 | `sync_report_json.py` 为缺少 JSON 的历史报告生成结构化 JSON。如果该脚本逻辑不完整，可能生成与闸门预期不符的 sidecar |

| 建议 | 第6阶段引入 canonical 前，确认 sync_report_json 是否应继续运行，或改为只读模式 |

### R2：golden_master_diff.py 不适用于日报 canonical

| 维度 | 说明 |
|:-----|:------|
| 风险 | 误以为 golden_master_diff.py 可复用为日报 canonical 对比工具 |
| 定位 | scripts/golden_master_diff.py |
| 解释 | golden_master_diff.py 是**评分引擎**的 Golden Master，对比 **评分/排序/否决标记/相位分类**四项，与日报字段完全不重叠。**不能直接复用。** 日报 canonical 的 Golden Diff 需新建脚本或扩展现有 check 逻辑 |
| 建议 | 第6-A 不从 golden_master_diff.py 继承代码 |
