## 四、未显性风险清单

> 以下风险多数**未被现有闸门、契约或检查覆盖**，属于第6阶段前需处理的盲区。

### R-01（P0）：manifest.json 存在但不被消费

| 维度 | 说明 |
|:-----|:------|
| 现状 | `tushare/manifest.json` 记录了每轮数据采集的完成时间 (updated: 2026-06-03T21:47)，包含每只股票14类数据的记录数和大小。但 **没有任何闸门或 orchestrator 模块读取此文件** |
| 风险 | 日报生成时无法判断数据采集是否已完成；采集时序问题只能尾部检测而无法前置检测 |
| 建议 | 第6-A 前至少由 daily_orchestrator 读取 manifest，若 < current_trade_date 则标记 degraded |

### R-02（P0）：sync_report_json.py 可写 sidecar 但不经闸门

| 维度 | 说明 |
|:-----|:------|
| 现状 | `sync_report_json.py` 扫描报告目录，为缺少 JSON 的 HTML/PDF 报告生成结构化 JSON。**写入位置与日报 sidecar 路径重叠**，但生成的 JSON 不含 report_generated_at、source_snapshot 等字段 |
| 风险 | 可能生成与 P0 闸门预期不符的 sidecar，导致闸门判断失真 |
| 建议 | 第6-A 前将此脚本改为 dry-run 只读模式，或禁止写入重点股票/股票报告/ 目录 |

### R-03（P1）：source_snapshot 仅覆盖 margin，未覆盖 K 线/资金/板块

| 维度 | 说明 |
|:-----|:------|
| 现状 | 第5.5-C 实现的 source_snapshot 只记录了 margin 数据快照。`_load_kline()`、`_load_fund_flow()`、`_load_sector_phase()` 均无 snapshot 记录 |
| 风险 | 如果 K 线或资金数据在报告生成后更新，P0-B 无法区分"发布后更新"和"报告错误" |
| 建议 | 第6-A 内扩展 source_snapshot 到 kline 和 fund_flow |

### R-04（P1）：data_scored 无新鲜度/版本检查

| 维度 | 说明 |
|:-----|:------|
| 现状 | data_scored 有 BuildTime (2026-06-03T15:35) 但无版本号或新鲜度规则。日报生成时使用 data_scored 的 SectorPhase，但如果评分引擎未更新，相位信息可能滞后 |
| 风险 | `check_numeric_source_consistency.py` 检查相位一致性，但不检查 data_scored 是否适用于当前 trade_date |
| 建议 | 在 data_scored 中增加 trade_date 字段，或在数值契约中补充 version 规则 |

### R-05（P1）：300736 百邦科技融资数据长期缺失无处理策略

| 维度 | 说明 |
|:-----|:------|
| 现状 | margin_detail/300736.json 始终不存在。日报 sidecar 和 P0-C 均输出 WARN。**没有任何自动化的处理或升级机制** |
| 风险 | 如果融资数据缺失影响风控判断（如质押判断需融资数据），当前无策略 |
| 建议 | 明确：① 确认 Tushare 是否提供 300736 融资数据 ② 如不提供，在日报模版中固定写"数据不可用" ③ 如提供但采集失败，修复采集链路 |

### R-06（P1）：P0-B 与 P0-C 的 WARN 边界口径过宽

| 维度 | 说明 |
|:-----|:------|
| 现状 | check_numeric_source_consistency.py 中 `check_margin()` 对「MD 未明确提及融资日期」返回 PASS（跳过）。check_freshness_degradation.py 中 `check_margin_freshness()` 对已声明降级的融资延迟返回 WARN 而非 BLOCK |
| 风险 | 若融资数据缺失但报告不声明，P0-C 仍可 PASS（不声明则不触发 WARN）。两个闸门之间缺少"融资声明完整性"的交叉检查 |
| 建议 | 第6-A 增加 MD 融资声明完整性检查：如果 sidecar 有 degraded_items 但 MD 无融资日期声明 → BLOCK |

### R-07（P2）：Golden Master 缺日报专用 diff

| 维度 | 说明 |
|:-----|:------|
| 现状 | `golden_master_diff.py` 是评分引擎 GM，比对评分/排序/否决/相位4项，与日报字段不重叠 |
| 风险 | 日报生成链路没有自己的 Golden Master，无法在 canonical 迁移时验证前后一致性 |
| 建议 | 第6-A 创建 `scripts/check_daily_golden_diff.py`，使用现有 20260602 日报作为基准 |

### R-08（P2）：现役 .ps1 仍可写数据

| 维度 | 说明 |
|:-----|:------|
| 现状 | 110 个现役 PS1 中部分仍能读取和写入缓存数据（如 `run_keystock_analysis.ps1` 读 margin_detail）。第5.5-C 已建立检测但未物理阻断 |
| 风险 | 若 PS1 被手动执行，可能写入与 Python 版不同步的数据 |
| 建议 | 第6-B 前完成 PS1 阻断清单：将 E 级有 Python 替代的 PS1 从现役目录迁出 |

### R-09（P2）：临时脚本可被误执行

| 维度 | 说明 |
|:-----|:------|
| 现状 | `临时报告/` 下存在可执行的生成脚本（如 gen_all_pdfs.py、convert_reports_html_pdf.py），`代码文件/tools/batch_convert_pdf.py` 仍可运行 |
| 风险 | 临时脚本可能绕过闸门直接写报告 |
| 建议 | 第6-B 范围明确排除 `临时报告/`，临时脚本加 DEPRECATED 头部注释 |

### R-10（P2）：历史数据目录可能被误当权威源

| 维度 | 说明 |
|:-----|:------|
| 现状 | `历史数据/` 包含旧日报、旧基线、旧评分。report_authority_lineage_contract 已声明旧日报不作为权威源，但无自动化闸门防止读取 |
| 风险 | 执行模型可能在 prompt 中引用历史数据内容 |
| 建议 | 第6-B 考虑增加 `check_report_authority_lineage.py` 中对历史数据引用的检测 |
