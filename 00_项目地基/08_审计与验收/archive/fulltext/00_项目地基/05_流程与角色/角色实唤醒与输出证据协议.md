# 角色实唤醒与输出证据协议

> 版本: 1.0 | 创建: 2026-06-02 | 维护人: 阿黑

---

## 一、核心原则

**"列出角色 ≠ 实际唤醒"。** 只写"唤醒角色：阿黑、情墨、旧影"不算角色已参与。

每个被唤醒角色必须有：
1. 角色名
2. 参与阶段门
3. 本阶段职责
4. 检查对象
5. 结论：PASS / BLOCK / WARN
6. 依据
7. 遗留问题

---

## 二、角色输出结论是阶段通过的必要证据

1. 阶段验收报告中必须包含**角色输出证据表**
2. 缺少必唤醒角色输出结论 → **⛔ BLOCK**，不得建议通过
3. 角色只列出未输出 → 等于该角色未参与
4. G5 独立复查结论必须单独成节，不得与其他结论混用

---

## 三、阿黑职责与禁止

### 阿黑可以
| 职责 | 说明 |
|:-----|:------|
| 路由 | 自动识别流程编号和阶段门 |
| 派单 | 生成轻量派单卡，含角色输出要求 |
| 汇总 | 收集各角色输出结论，汇总到验收报告 |
| 推进 | 在 G6 放行前确认全部角色证据完备 |
| 调度 | 协调角色唤醒时序 |

### 阿黑禁止
| 禁止 | 说明 |
|:-----|:------|
| ⛔ 代签角色结论 | 阿黑不得代替情墨做架构结论、代替玉夜做数据结论、代替旧影做复查结论 |
| ⛔ 替旧影做独立复查 | G5 必须由旧影或复查方独立完成 |
| ⛔ 替腰子做金融裁决 | 金融口径只能由腰子输出 |

---

## 四、执行模型禁止

| 禁止 | 说明 |
|:-----|:------|
| ⛔ 执行模型不得代替项目角色出结论 | DeepSeek/Claude/Codex 在验收报告的角色输出证据表中不得以角色身份出现 |
| ⛔ 执行模型不得在 G1/G5/G6 阶段签结论 | 执行模型只参与 G3 编码和 G4 自检 |

---

## 五、被唤醒角色的输出格式

每个被唤醒角色输出时必须包含以下内容：

```text
角色名：【】
参与阶段门：【G0/G1/G2/G3/G4/G5/G6】
本阶段职责：【一句话说明】
检查对象：【路径/文件/范围】
结论：【PASS / BLOCK / WARN】
依据：【文件/命令/规则编号】
遗留问题：【如有】
```

---

## 六、G5 独立复查必须单独成节

验收报告中的角色输出证据表必须包含 G5 独立复查节，复查输出格式：

```text
复查角色：旧影
复查时间：【YYYY-MM-DD】
复查范围：【验收报告+验收命令+文件清单】
复查结果：
  命令通过率：【X/Y 命令通过】
  文件范围合规：【PASS / BLOCK】
  角色输出完备性：【PASS / BLOCK（若缺角色输出）】
  是否修改范围外文件：【是/否】
总体结论：【建议通过 / 需补修 / 不通过】
遗留问题：【如有】
```

---

## 七、跳过角色必须说明

如果阶段跳过了某个必唤醒角色，必须在验收报告中逐条说明：

```
跳过角色：【角色名】
跳过原因：【具体理由，如"不涉及金融口径，跳过腰子"】
是否影响阶段结论：【否】
```

---

## 八、缺少角色输出证据的处理

| 情况 | 处理方式 |
|:-----|:---------|
| 必唤醒角色未输出任何结论 | ⛔ BLOCK，验收报告不得建议通过 |
| 阿黑自行代签角色结论 | ⛔ BLOCK，退回补修 |
| 执行模型以角色身份签结论 | ⛔ BLOCK，退回补修 |
| G5 复查缺失 | ⛔ BLOCK，不得放行 |
| 角色已输出但结论为 BLOCK | ⛔ 该角色 BLOCK 转化为阶段 BLOCK |
| 角色已输出且结论为 PASS/WARN | ✅ 可汇总到验收报告 |
