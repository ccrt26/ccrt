# 一键唤醒与自动路由协议

> 版本: 1.0 | 创建: 2026-06-02 | 维护人: 阿黑

---

## 一、用户最小输入格式

用户只需说一句话，阿黑负责自动路由和派单：

| 用户输入 | 含义 | 阿黑动作 |
|:---------|:-----|:---------|
| `阿黑，按照标准流程启动：xxx` | 启动一个变更任务（先设计） | 自动路由 → 输出设计 → 等待确认 → 不直接改文件 |
| `阿黑，按照标准流程执行：xxx` | 执行一个变更任务（可执行） | 自动路由 → 若需 G1/G2 先输出方案 → 确认后执行 |
| `阿黑，复查：xxx` | 复查已完成的阶段 | 读取验收报告 → 对照验收命令 → 输出复查结论 |
| `阿黑，补修：xxx` | 对已通过阶段进行补充修复 | 读取原阶段范围 → 输出补修方案 → 确认后执行 |

**用户无需手填 F-xxx、G0~G6、角色名单。** 流程表是阿黑内部使用，不是用户填写义务。

---

## 二、阿黑自动路由步骤

收到用户需求后，按以下顺序自动执行：

```
Step 1: 读取项目唤醒卡 → 了解项目状态
Step 2: 读取阶段总账 → 了解当前阶段和已完成阶段
Step 3: 读取流程路由表 → 匹配流程编号
Step 4: 读取角色唤醒协议 → 确定唤醒角色
Step 5: 检索相关目录和文件 → 确认影响范围
Step 6: 判断流程编号（F-xxx）
Step 7: 判断阶段门（G0~G6，含跳过理由）
Step 8: 判断是否能执行（是否先需设计）
Step 9: 生成轻量派单卡（不由用户填写）
```

---

## 三、"启动"和"执行"的区别

| 维度 | 启动 | 执行 |
|:-----|:-----|:-----|
| **时机** | 新任务开始时 | 方案已明确或用户直接要求 |
| **G0 路由** | ✅ 必须 | ✅ 必须 |
| **G1 口径** | ✅ 必须输出方案 | 若涉及金融/业务/角色 → 必须输出方案 |
| **G2 设计** | ✅ 必须输出方案 | 若涉及闸门/脚本/功能 → 必须输出方案 |
| **是否改文件** | ❌ 不改文件 | 仅 F-FIX 且边界明确时可改 |
| **输出** | 轻量派单卡（纯设计） | 轻量派单卡+执行+验收 |
| **确认流程** | 等待用户确认设计 | 等待用户确认方案（如需） |

---

## 四、何时必须停在设计阶段

以下情况必须输出方案，**不得直接改文件**：

1. 金融分析逻辑、操作规则、白皮书修改 → 必须等 G1 口径确认
2. 角色协作、统一解读协议调整 → 必须等 G1 口径确认
3. 新增检查脚本、修改 schema → 必须等 G2 设计确认
4. 新增分析功能、指标、模块 → 必须等 G1+G2 确认
5. 目录迁移、架构调整 → 必须等 G2 设计确认
6. 用户说的"启动" → 默认停在设计阶段

---

## 五、何时允许进入执行阶段

1. **F-FIX**：闸门已明确捕获的问题，边界已知 → 简化 G1/G2 后直接执行
2. **F-ARCH**：流程制度新增（如本阶段）→ 先出设计，确认后可执行
3. **F-GATE**：新增检查脚本，字段映射和逻辑清晰 → 出设计，确认后可执行
4. **F-MIGRATE**：迁移目标明确 → 出设计，确认后可执行
5. 用户说"执行"且不涉及金融/角色/业务口径 → 出方案，确认后可执行

---

## 六、何时必须询问用户

以下情况必须暂停自动路由，询问用户：

1. 需求严重模糊，无法确定涉及哪个流程编号
2. 需求同时涉及多个流程编号，需要用户确认优先级
3. 修改范围跨目录且边界不清晰
4. 当前阶段未验收通过，但用户要求进入下一阶段
5. 用户要求的修改与已有验收记录冲突

> 模糊需求时阿黑最多问 3 个问题，之后必须做出路由判定。

---

## 七、何时不得询问用户、应自行判断

以下情况阿黑必须自行判断路由，不得反问：

1. 需求中的关键词直接匹配流程路由表中的自然语言示例
2. 需求涉及的目录/文件明确指向某个流程编号
3. 需求类型在阶段总账"当前阶段"范围内
4. P0 闸门已捕获的具体问题（字段名、代码、日期已知）
5. 需求明确指向 F-FIX 且问题边界清晰

---

## 八、自动路由保证

| 保证 | 说明 |
|:-----|:------|
| 流程表是阿黑内部使用 | **不是用户填写义务** |
| 用户无需知到 F-xxx | 阿黑自动匹配 |
| 用户无需填 G0~G6 | 阿黑根据流程编号自动判断 |
| 用户无需唤醒角色 | 阿黑根据流程编号自动确定 |
| 用户无需声明修改范围 | 阿黑根据流程路由表自动确定允许/禁止目录 |
| 复杂任务先出设计 | 不直接编码 |
| 金融/业务/角色变更必须先过 G1 | 技术团队不得反向决定口径 |
| 闸门/脚本变更必须先过 G2 | 不可直接编码 |
