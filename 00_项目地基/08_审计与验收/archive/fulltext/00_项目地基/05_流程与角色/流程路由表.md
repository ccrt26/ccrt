## 一、流程编号总览

| 编号 | 名称 | 适用场景 |
|:-----|:------|:---------|
| **F-ARCH** | 地基/架构变更流程 | 目录、契约、总账、阶段制度 |
| **F-DATA** | 数据事实变更流程 | 数值、日期、来源、sidecar 事实字段 |
| **F-REPORT** | 报告生成/日报逻辑变更流程 | 日报模板、MD/JSON 生成逻辑 |
| **F-ANALYSIS** | 金融分析逻辑变更流程 | 分析白皮书、操作规则、风控规则 |
| **F-ROLE** | 角色协作/统一解读变更流程 | 13角色、解释对象、协作协议 |
| **F-EVAL** | 后评估/eval_hooks 变更流程 | T+1/T+5、回填、评分、复盘 |
| **F-KNOW** | 知识库/信号库进化流程 | 六库、信号沉淀、L5→L2 升级 |
| **F-GATE** | 闸门/验收脚本变更流程 | check_*.py、schema、policy |
| **F-FIX** | 定点问题修复流程 | 闸门已抓住的具体数据/文档修复 |
| **F-MIGRATE** | 目录迁移/归档流程 | 文件搬家、索引、历史资产治理 |
| **F-FEATURE** | 分析功能新增/修改流程 | 新增分析能力、指标、模块、自动化功能 |
| **F-SCHEDULE** | 调度/运行入口/跨平台脚本迁移流程 | 调度权威锁定、运行时入口注册、PS1 双入口治理、launchd 调度 |

## 二、流程路由指南

| 任务描述 | 流程编号 | 备注 |
|:---------|:---------|:------|
| 修改分析逻辑/操作规则 | **F-ANALYSIS** | 必须经过 G1 |
| 新增分析功能 | **F-FEATURE** | 若涉及报告生成则追加 F-REPORT |
| 新增指标/信号 | **F-FEATURE** + **F-KNOW** | 分步或并行 |
| 修数据不一致 | **F-DATA** 或 **F-FIX** | F-FIX 适用于已知范围 |
| 新增检查脚本 | **F-GATE** | 必须经过 G2 |
| 目录整理/文件迁移 | **F-MIGRATE** | 需先建索引 |
| 统一解读角色协作 | **F-ROLE** | 必须经过 G1 |
| 后评估/复盘/反哺 | **F-EVAL** | 必须经过 G1 |
| 知识库/信号库 | **F-KNOW** | 必须经过 G1 |
| 报告生成逻辑 | **F-REPORT** | 必须经过 G1 + G2 |
| 地基/制度新建 | **F-ARCH** | 需情墨+旧影参与 |

## 四、路由优先级

当同一任务可路由到多个流程编号时，按以下优先级选择：

1. **F-FIX** > F-DATA（定点修复优先于全量审查）
2. **F-ANALYSIS** > F-REPORT（分析逻辑变更优先）
3. **F-FEATURE** > F-REPORT（功能新增优先于报告微调）
4. **F-ARCH** > F-MIGRATE（架构决策优先于迁移执行）
