### 判断1：Windows 调度文档仍被当作现行方案

**✅ 存在风险。**

证据：
- `信息采集-信鸽.md` 第64-65行：明确写着 `Windows Task Scheduler TieLv-Pigeon (19:00)` 和 `TieLv-PigeonBoot`

- `红枫-知识库/06-备份策略与恢复操作手册.md`：第113行仍引用 `batch_data_collector.ps1`
- `register_pigeon_scheduler.ps1`、`setup_scheduler.ps1`、`register_tasks.ps1` 均在现役目录

### 判断2：Python 迁移未完成但旧 PS 仍可被调用

**✅ 存在风险。**

证据：
- 26 个 Python 替代中 22 个对应的 PS1 仍在现役目录（84.6%）
- 110 个现役 PS1 中仅 26 个有 Python 替代（23.6%），**79 个完全无 Python 替代**
- 知识库文档仍引用 PS1 版本（如 `红枫-06` 的 `batch_data_collector.ps1`）
- 未发现 Python→PS1 fallback 调用，但双入口本身就意味着「任一路径都可执行」

### 判断3：数据采集和日报生成顺序不锁定

**✅ 存在风险。**

证据（来自第5.5-A 审计）：
- `margin_detail` mtime 均为 `2026-06-03T21:46`
- `manifest.json` 更新时间为 `2026-06-03T21:47`

- `daily_orchestrator.py` 与数据采集脚本之间无依赖锁定
