## 二、修复内容

### R-01：manifest 不被消费

| 维度 | 说明 |
|:-----|:------|
| 修改文件 | `daily_orchestrator.py` (`check_v36_data_readiness()`) |
| 新增逻辑 | 在函数开头读取 `tushare/manifest.json`，提取 `updated` 时间戳；若 manifest 缺失、解析失败、updated_at 为空、或 updated 日期早于 target_date，则标记 `degraded=True` 并记录原因 |
| 输出位置 | manifest_meta 写入 detail 返回值的 `manifest` 字段，随 v36_data_readiness 一同输出到 signal |
| 退回策略 | 不直接 BLOCK（仍允许以 degraded 状态继续），但 manifest 状态可供 daily_orchestrator 或后续闸门判断 |

### R-02：sync_report_json 不经闸门写 sidecar

| 维度 | 说明 |
|:-----|:------|
| 修改文件 | `sync_report_json.py` |
| 默认行为 | **默认禁止写入** `重点股票/股票报告/` 下的 sidecar JSON。无参数时扫描到重点股票目录会输出 `⛔ BLOCKED` 并跳过 |
| 恢复写权限 | 增加 `--allow-write-key-stock-reports` 参数，指定后允许写入 |
| 单文件模式 | 同样检查目标路径，属于重点股票路径且无 flag 时阻止 |
| 每日荐股目录 | `每日荐股/股票报告/` 不受影响（不在风险范围） |
