# 后评估流程定义 v1.0

> **来源：** M9 后评估与知识进化闭环
> **用途：** 后评估流程、概率校准、知识入库边界、RuleUpdateCandidate 流向
> **版次：** v1.0

---

## 1. 后评估定位

后评估承接 EvalHook，对历史判断进行验证、校准、归因。**不直接改规则。**

| 后评估是 | 后评估不是 |
|:---------|:-----------|
| 对历史预测的验证 | 不是新的分析 |
| 对偏差的归因和校准 | 不是规则的直接修改 |
| 产出 RuleUpdateCandidate 的入口 | 不是规则升级通道 |
| 概率校准的统计基础 | 不是定性判断工具 |

**知识进化定位：** 沉淀可复用经验、失败样本、规则更新候选，但必须经过 M4 治理流程。**单次报告结论不能直接成为规则。**

---

## 2. 后评估 7 步流程

```
预判记录（场景完成时写入 EvalHook）
  │  角色：青山/腰子
  │  输出：EvalHook（含预测断言、验证窗口、置信度）
  ▼
到期触发（验证窗口关闭后自动触发）
  │  角色：千光（调度）
  │  条件：到达验证窗口截止日期
  ▼
实际结果回填（查询实际行情/数据）
  │  角色：信鸽（数据查询）/ 青山
  │  输出：实际结果标注
  ▼
情景命中判断（预测 vs 实际）
  │  角色：青山
  │  判定：命中 / 偏离 / 数据不足无法判断
  ▼
偏差归因（偏离原因分析）
  │  角色：青山 + 腰子（重大偏差）
  │  归因方向：规则偏差 / 数据偏差 / 假设偏差 / 随机偏差
  ▼
生成复盘结论
  │  角色：青山
  │  输出：复盘报告（关联 EvalHook ID）
  ▼
必要时产出 RuleUpdateCandidate
  │  角色：青山（发现规则需更新时）
  │  去向：M4 规则资产治理流程
  │  约束：不能直接修改规则资产
```

**流程约束：**
- 后评估不产生新的分析结论
- 后评估不修改规则（那是 M4 的职责）
- 后评估不删除历史记录（只能标记为 superseded）

## 3. 概率校准机制

| 校准维度 | 统计口径 | 周期 | 责任角色 |
|:---------|:---------|:-----|:---------|
| 偏乐观度 | 预测上涨概率 vs 实际涨幅 | 周/月 | 青山 |
| 偏悲观度 | 预测下跌概率 vs 实际跌幅 | 周/月 | 青山 |
| 过度自信 | 高置信度（>80%）预测的命中率 | 周/月 | 青山 |
| 样本不足 | 预测频率低但置信度高的个案标注 | 月 | 青山 |
| 情景命中率 | 整体情景假设的命中/偏离比例 | 月 | 青山 |
| 反方有效性 | 反方挑战被采纳后实际改善程度 | 月 | 青山 + 腰子 |

**校准输出：**
- 概率校准报告（月度），含各角色的预测偏差分布
- 校准结论记录到 `calibration_summary` / `calibration_refs`；如涉及规则复查，只记录 `related_rule_refs`
- 不作为规则更新的直接依据，只作为 RuleUpdateCandidate 的支撑

## 4. 知识入库边界

| 可进入知识库 | 不可进入知识库 |
|:-------------|:---------------|
| 经过复盘+审计确认的可复用经验 | 单次报告结论（产物对象不是规则） |
| 已验证的失败样本（含完整上下文） | AI 分析过程中产生的未经验证片段 |
| 经 M4 流程放行的规则更新 | 未经过 audit 的个人判断 |
| 概率校准的统计结果 | 未被后评估回填的 EvalHook |

**知识库维护责任：**
- 青山：复盘经验、失败样本、胜率统计的入库初审
- 玉夜：数据相关的知识沉淀
- 腰子：金融知识的入库审核（内容终审）
- 阿黑：非金融/结构知识的入库审核（内容终审）
- 旧影：知识入库合规审计（检查是否越界），不负责内容终审

## 5. RuleUpdateCandidate 流向

```
后评估发现规则需更新
  │
  ▼
青山起草 RuleUpdateCandidate
  │  含：来源 EvalHook ID、发现的问题、建议修改内容、影响评估
  ▼
腰子审核（金融相关规则）或阿黑审核（其他规则）
  │  确认建议合理，不产生副作用
  ▼
RuleUpdateCandidate 进入 M4 规则资产治理流程
  │  M4 流程：提出 → 影响评估 → 审核 → shadow → 放行 → 归档
  │  不能跳过 M4 流程直接修改规则资产
  ▼
旧影记录审计
  │  记录 RuleUpdateCandidate 的来源、流转、最终结果
```

---

## 6. 责任矩阵

| 角色 | 在后评估与知识进化中的责任 |
|:-----|:---------------------------|
| 青山(owner) | EvalHook 预测记录、实际结果回填、概率校准、复盘分析、RuleUpdateCandidate 起草、知识库初审 |
| 腰子(reviewer) | 重大偏差复盘审核、金融相关 RuleUpdateCandidate 审核、知识库金融内容终审 |
| 玉夜(contributor) | 数据相关后评估分析、数据质量经验沉淀 |
| 千光(executor) | 后评估到期调度、EvalHook 状态管理 |
| 旧影(auditor) | 后评估过程审计、复盘造假风险检测、规则违规引用检测、知识入库审计 |
| 阿黑(reviewer) | 非金融 RuleUpdateCandidate 审核、知识库结构维护 |
| 红结(executor) | 后评估相关脚本的代码实现 |

**青山在后评估中的边界：**
- 能做：预测记录、回填验证、偏差归因、概率统计、复盘报告、RuleUpdateCandidate 起草
- 不能做：直接修改规则资产、删除历史 EvalHook、将单次报告结论入库为规则

**旧影在后评估中的边界：**
- 能做：审计后评估过程、记录缺失、违规引用、复盘造假风险
- 不能做：负责业务结论的判断、代青山写复盘报告
