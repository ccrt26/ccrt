# U-10 动作审计闸门定义

> 负责人：流金 | 类型：自动化闸门 | 运行时机：腰子整合单生成后、正式动作输出前
> 实现：`统一解读/validate_interpretation.py --u10`

---

## 一、闸门定位

U-10 是解读链路中含义→动作段的审计闸门。它检查解释对象的 action_bias、trigger_condition、price_range、position_limit、time_window、confidence 六个字段，确保动作可执行、边界明确、风险可控。

## 二、检查项

### U10-01 触发条件量化

- 检查对象：trigger_condition
- 方法：action_bias∈{BUY,SELL}时，trigger_condition 必须存在且非空
- 判定：缺失→BLOCK
- 原因：强动作没有触发条件=不可执行的空话

### U10-02 置信度与动作匹配

- 检查对象：confidence + action_bias
- 方法：confidence=LOW 且 action_bias∈{BUY,SELL}→BLOCK
- 判定：命中→BLOCK
- 原因：低置信度不允许给出强动作

### U10-03 动作三要素

- 检查对象：price_range + position_limit + time_window
- 方法：action_bias∈{BUY,SELL}时，三者必须全部存在且非空
- 判定：缺失任一→BLOCK
- 原因：强动作缺三要素=无法执行

### U10-04 仓位边界合规

- 检查对象：position_limit
- 方法：检查是否超过流金给出的仓位上限（需跨对象比对）
- 判定：超出→BLOCK
- 注意：当前版本为手动检查，未来版本自动化

### U10-05 模板污染-BLOCK

- 检查对象：全部文本内容
- 方法：正则匹配禁用表达列表（见模板污染检查库 B-01至B-10）
- 判定：命中任一→BLOCK
- 原因：使用禁用表达=不可量化/不可验证的结论

### U10-06 模板污染-WARN

- 检查对象：全部文本内容
- 方法：正则匹配警告表达列表（见模板污染检查库 W-01至W-15）
- 判定：累计命中≥3条→WARN
- 原因：多次使用模糊表达降低解读质量

### U10-07 动作可执行性

- 检查对象：trigger_condition + time_window
- 方法：action_bias∈{BUY,SELL,WATCH}时，至少具备触发条件或时间窗口之一
- 判定：两者皆无→WARN
- 原因：WATCH级别也需可执行的观察指标

### U10-08 止损条件

- 检查对象：stop_loss
- 方法：action_bias=BUY时，检查是否包含止损条件（跨对象比对）
- 判定：无止损→WARN
- 原因：买入必须有止损（I-03规则）

## 三、结果判定

| 结果 | 条件 | 后果 |
|:-----|:-----|:-----|
| PASS | 全部检查通过 | 允许输出正式动作 |
| WARN | 存在WARN项（无BLOCK） | 允许观察/等待，不允许强动作(BUY/SELL) |
| BLOCK | 存在BLOCK项 | 禁止发布正式分析，打回腰子重做 |

## 四、综合判定逻辑

```
if 任何BLOCK项命中:
    return BLOCK
elif 任何WARN项命中:
    return WARN
else:
    return PASS
```
