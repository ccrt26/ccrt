# U-9 事实审计闸门定义

> 负责人：旧影 | 类型：自动化闸门 | 运行时机：每个解释对象生成后、腰子整合单输出前
> 实现：`统一解读/validate_interpretation.py --u9`

---

## 一、闸门定位

U-9 是解读链路中事实→含义段的审计闸门。它检查解释对象的 data_fact、interpretation_hypothesis、supporting_evidence、counter_evidence、invalidation_condition 五个字段，确保事实和观点分离、逻辑链完整、结论可验证。

## 二、检查项

### U9-01 事实与观点分离

- 检查对象：data_fact 全部文本内容
- 方法：正则匹配结论性词汇（建议/看好/推荐/买入/卖出/增持/减持/值得/机会/风险小/安全边际/估值偏低/估值偏高/超跌/超买/底部/顶部/见底/见顶）
- 判定：命中任一→WARN（退回重写data_fact段）
- 边界：允许在 data_fact.note 中描述数据特征（如"成交额放大"），但不允许写投资结论（如"成交额放大说明资金看好"）

### U9-02 数据来源真实性

- 检查对象：data_fact.source + supporting_evidence[].source + counter_evidence[].source
- 方法：检查每条 evidence 是否引用了具体数据来源
- 判定：无 source 或 source 为"无"/"未知"→WARN
- 边界：允许"基于Tushare数据"等泛指，但不允许完全无来源

### U9-03 单一信号→强结论

- 检查对象：supporting_evidence + action_bias
- 方法：supporting_evidence仅1条且 action_bias∈{BUY,SELL}→WARN
- 判定：命中→WARN
- 原因：单一信号不足以支撑强动作

### U9-04 反证存在

- 检查对象：counter_evidence
- 方法：counter_evidence为空或不存在→BLOCK
- 判定：命中→BLOCK

### U9-05 反证质量

- 检查对象：counter_evidence
- 方法：counter_evidence仅1条且 evidence 匹配套话模式（市场风险/政策风险/系统性风险/不确定性/大盘波动）→WARN
- 判定：命中→WARN
- 原因：套话式的反证等于没有反证

### U9-06 失效条件存在

- 检查对象：invalidation_condition
- 方法：invalidation_condition 为空或长度<15字→BLOCK
- 判定：命中→BLOCK

### U9-07 相关性≠因果

- 检查对象：interpretation_hypothesis + investment_implication
- 方法：正则匹配因果断言模式（"因为...所以..."/"由于...导致..."/"...推动...上涨"）
- 判定：命中→WARN
- 注意：只标记，不阻断（因果判断有时可以成立）

### U9-08 数据缺失标注

- 检查对象：data_fact.completeness
- 方法：data_fact 中任何关键值缺失但 completeness 未标注"部分缺失"或"严重缺失"→WARN
- 判定：命中→WARN

## 三、结果判定

| 结果 | 条件 | 后果 |
|:-----|:-----|:-----|
| PASS | 全部检查通过 | 允许进入投资含义和动作段 |
| WARN | 存在WARN项（无BLOCK） | 允许继续但需修正后重审，不允许强动作(BUY/SELL) |
| BLOCK | 存在BLOCK项 | 禁止发布，打回角色重做 |

## 四、综合判定逻辑

```
if 任何BLOCK项命中:
    return BLOCK
elif 任何WARN项命中:
    return WARN
else:
    return PASS
```
