# 后评估库 v1.0

> 负责人：青山 | 来源等级：L1-L3 | 适用范围：所有解释对象的T+1/T+3/T+5后评估
> 更新规则：月度review，更新胜率数据 | 审计规则：旧影每两周检查eval_hooks回填完成率
> 入库标准：解释对象通过U-9/U-10闸门后自动生成 | 废弃标准：关联规则已被废弃

---

## 一、后评估生命周期

```
解释对象生成 → eval_hook创建 → T+1回填 → T+3回填 → T+5回填 → 综合判定 → 归因 → 规则更新候选
```

## 二、回填时间表

| 节点 | 回填时间 | 回填内容 | 责任人 |
|:-----|:--------|:--------|:------|
| T+1 | 次日开盘前9:00 | price_change, signal_direction, 初步判定 | 玉夜(数据)+青山(判定) |
| T+3 | T+3日收盘后 | price_change_3d, trend_consistency, 中期判定 | 青山 |
| T+5 | T+5日收盘后 | price_change_5d, final_trend, 综合判定+归因 | 青山+旧影(审计) |

## 三、综合判定标准

| 判定 | 条件 | 后续动作 |
|:-----|:-----|:--------|
| 命中 | T+1/T+3/T+5全部满足success_criteria，且价格方向与预测一致 | 记录胜率数据，confidence可上调 |
| 部分命中 | ≥1个窗口满足success_criteria，但非全部 | 记录，标注偏差窗口 |
| 失败 | 全部窗口不满足success_criteria | 记录归因，连续2次同归因→rule_update_candidate |
| 不可评估 | 标的发生停牌/涨跌停限制等导致无法判断 | 记录原因，不计入胜率统计 |
| 数据不足 | T+5后仍缺乏判定所需数据 | 玉夜追溯数据，最晚T+10补判 |

## 四、失败归因分类

| 归因 | 判断标准 | 修正方向 |
|:-----|:--------|:--------|
| 数据问题 | 回填时发现原始数据有误或缺失 | 玉夜修正数据采集流程 |
| 规则问题 | 规则适用环境判断错误 | 青山修正信号胜率库 |
| 角色问题 | 某角色输出被后续事实证明错误 | 对应角色review知识库 |
| 腰子整合问题 | 多信号综合时权重分配失当 | 腰子修正整合权重 |
| 动作过强 | 置信度与动作不匹配 | 流金收紧U-10标准 |
| 市场突变 | T+1窗口内发生不可预见重大事件 | 不调整规则，标注事件 |

## 五、eval_hooks 模板

### 模板1：技术信号类

```json
{
  "claim": "基于{MACD金叉/RSI超卖/均线突破}信号，预计{T+1/T+3/T+5}股价{上涨/下跌}超过{X%}",
  "t1_check": {"metric": "price_change_pct", "expected": "direction=UP, magnitude>0.5%", "actual": "", "result": "待评估"},
  "t3_check": {"metric": "price_change_3d_pct", "expected": "direction=UP, magnitude>1.5%", "actual": "", "result": "待评估"},
  "t5_check": {"metric": "price_change_5d_pct", "expected": "direction=UP, magnitude>2%", "actual": "", "result": "待评估"},
  "success_criteria": "T+5累计涨幅>2%且T+1方向正确",
  "failure_criteria": "T+5累计涨幅<0%或T+1方向错误"
}
```

### 模板2：资金流信号类

```json
{
  "claim": "基于{北向/主力/融资}资金净流入信号，预计{T+1/T+3/T+5}资金面继续改善，股价{上涨}",
  "t1_check": {"metric": "fund_flow_direction+price_change_pct", "expected": "资金继续净流入+股价正收益", "actual": "", "result": "待评估"},
  "t3_check": {"metric": "cum_fund_flow_3d+price_change_3d_pct", "expected": "3日累计净流入+股价正收益", "actual": "", "result": "待评估"},
  "t5_check": {"metric": "cum_fund_flow_5d+price_change_5d_pct", "expected": "5日累计净流入+股价正收益", "actual": "", "result": "待评估"},
  "success_criteria": "T+5资金累计净流入且股价正收益",
  "failure_criteria": "T+3资金转为净流出或股价负收益"
}
```

### 模板3：事件驱动类

```json
{
  "claim": "基于{P0/P1}事件{业绩超预期/政策催化/增持}，预计事件窗口内股价{上涨}超过{X%}",
  "t1_check": {"metric": "price_change_pct+event_progress", "expected": "事件发酵+股价正反应", "actual": "", "result": "待评估"},
  "t3_check": {"metric": "price_change_3d_pct", "expected": "事件驱动持续+股价正收益", "actual": "", "result": "待评估"},
  "t5_check": {"metric": "price_change_5d_pct+event_fulfillment", "expected": "事件兑现或持续+股价正收益", "actual": "", "result": "待评估"},
  "success_criteria": "事件如期兑现或持续发酵+T+5股价正收益",
  "failure_criteria": "事件落空或T+3已转为负收益"
}
```

## 六、eval_hook 生成规则

1. 每个解释对象必须生成1个eval_hook（可生成多个，每个对应一个独立主张）
2. eval_hook.claim必须从解释对象的investment_implication中提炼，可量化
3. claim中的数字必须基于置信度：HIGH→精确值、MEDIUM→范围、LOW→方向
4. eval_hook生成后立即入库，T+1/T+3/T+5由青山调度回填
