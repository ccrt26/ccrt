## 一、L1-L5 来源等级定义（v1.1 修正版）

| 等级 | 名称 | 定义 | 可信度 | 示例 |
|:-----|:-----|:-----|:------|:-----|
| **L1** | 项目铁律 | 写入金融铁律/项目宪章的硬性规则、用户明确规则、系统硬闸门 | 最高（不可违反） | 金融铁律_v1.17, constitution.md, 统一解读协议 §四 |
| **L2** | 项目实证 | 来自项目自身后评估、模拟交易记录、历史复盘、真实 backtest records 的统计结论 | 高（项目验证） | eval_hooks 回填数据, 模拟交易 PnL 记录, Golden Master diff |
| **L3** | 官方事实 | 官方公告、财报、交易所披露、监管文件、政府/央行统计数据 | 高（权威来源） | 年报/季报, 央行公告, 证监会文件, 国家统计局数据 |
| **L4** | 外部研究 | 学术论文、券商方法论、经典金融理论、行业研究报告 | 中（外部验证） | Fama-French, 券商因子报告, 学术期刊 |
| **L5** | 经验假设 | 角色个人经验、市场观察、未经项目回测验证的假设 | 低（未验证） | "根据经验"、"历史规律表明"（无回测支撑） |

## 二、硬规则（⛔ 闸门级）

### 2.1 L5 动作限制

> ⛔ **L5 来源不得支持强动作。** 任何解释对象中，若支撑 BUY/SELL 的核心证据全部来自 L5，U-10 闸门必须 BLOCK。

| 来源等级组合 | 允许动作 |
|:------------|:--------|
| 至少1条 L1 或 L2 或 L3 支撑 | BUY / SELL / HOLD / WATCH / NEUTRAL |
| 仅 L4 支撑（无 L1/L2/L3） | HOLD / WATCH / NEUTRAL（禁 BUY/SELL） |
| 仅 L5 支撑（无 L1-L4） | WATCH / NEUTRAL / HOLD（禁 BUY/SELL/WATCH升级） |

### 2.2 信号胜率 L5-seed 规则

> ⛔ **信号胜率未能追溯到项目 records/backtest 时，必须标注 `seed_estimate=true`，来源等级标 L5-seed，不得标 L2。**

- `seed_estimate=true` 的信号胜率仅作参考，不得用于动作升级（参考信号组合规则）
- 累积 ≥20 条项目自身回填的 eval_hooks 结果后，可申请升级为 L2
- 升级需青山提案 + 腰子审批 + 旧影审计确认

### 2.3 L5→L2 升级路径

```
L5-seed (种子估计)
  → 累积20条项目真实后评估结果
  → 青山重新计算胜率
  → 腰子审批
  → 旧影审计确认数据完整
  → L2 (项目实证)
```

## 三、各角色知识库来源等级补齐要求

每个角色必须在其知识库的每个条目中标注：

```markdown
> 来源等级：L{X} | 来源：{具体来源} | 最后验证：{日期}
```

| 角色 | 知识库条目数 | 要求 |
|:-----|:----------|:-----|
| 腰子 | 19 | 每条标注来源等级，L1引用铁律条款编号 |
| 山猫 | 9 | 宏观数据引用→L3（统计局/央行），政策解读→L3，市场状态判定→L2（如经回测）或L5 |
| 信鸽 | 7 | P0分类标准→L1（铁律参照），过滤规则→L5（待回测验证） |
| 玉夜 | 9 | 数据源列表→L1，降级路径→L1，异常检测→L3/L5 |
| 流金 | 9 | 红线检查→L1，风控阈值→L2（模拟交易验证），交易纪律→L2/L5 |
| 青山 | 9 | 因子定义→L4，胜率统计→L2（如有records）或L5-seed，IC→L4 |

## 四、U-9/U-10 来源等级检查

### U-9 检查项（新增）
- U9-09: 解释对象的 supporting_evidence 是否标注了每条证据的来源等级
- U9-10: 是否存在 L5 证据被标注为 L2（虚标来源等级）

### U-10 检查项（新增）
- U10-09: 强动作(BUY/SELL)的核心证据中是否有 ≥1 条 L1/L2/L3
- U10-10: 是否所有支撑证据都来自 L5（→ BLOCK）
