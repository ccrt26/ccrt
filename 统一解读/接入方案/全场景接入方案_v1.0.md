## 二、各场景详细接入方案

### 2.1 日报接入

**触发**: 每个交易日收盘后，`/日报` 命令

**接入点**: 日报10段结构中的第6-7段（操作建议段）生成前

**流程**:
```
1. 日报模板读取 → 对每只重点股票:
2.   玉夜生成 data_fact
3.   山猫生成 macro_fact (共用，一次)
4.   信鸽生成 event_fact
5.   青山生成 signal_assessment
6.   流金生成 risk_boundary + U-10预检
7.   腰子生成 yaozi_integration
8.   旧影运行 U-9 + U-10 闸门
9.  闸门PASS → 写入日报操作建议段
    闸门WARN → 标注风险，操作建议降级
    闸门BLOCK → 该股票跳过操作建议，标注"闸门阻断"
10. 每只股票生成 eval_hook
```

**日报输出新增字段**:
```json
{
  "daily_report": {
    "date": "YYYY-MM-DD",
    "stocks": [
      {
        "code": "000001",
        "interpretation_id": "INT-...",
        "yaozi_integration_id": "YAOZI-...",
        "u9_result": "PASS|WARN|BLOCK",
        "u10_result": "PASS|WARN|BLOCK",
        "eval_hook_id": "EVAL-...",
        "action": { ... }
      }
    ]
  }
}
```

### 2.2 深度分析接入

**触发**: 每周五 `/深度分析` 命令

**接入点**: 九章报告每章产出时

**流程**:
```
1. 深度分析启动 → 对目标股票:
2.   第一章(宏观环境): 山猫生成解释对象 → U-9
3.   第二章(行业分析): 腰子+青山生成 → U-9
4.   第三章(公司基本面): 腰子+玉夜生成 → U-9
5.   第四章(财务分析): 玉夜+腰子生成 → U-9
6.   第五章(技术分析): 青山生成 → U-9
7.   第六章(资金面): 玉夜+青山生成 → U-9
8.   第七章(事件): 信鸽生成 → U-9
9.   第八章(风险): 流金生成 → U-9+U-10
10.  第九章(综合结论与操作建议): 腰子整合全团 → U-9+U-10
11. 整份报告生成 eval_hooks (每章1个+综合1个=9个)
```

### 2.3 每日荐股接入

**触发**: 每日荐股白皮书流程

**接入点**: 荐股生成时

**流程**:
```
1. 每只荐股:
2.   腰子评分 → 生成解释对象
3.   青山验证信号胜率
4.   流金给出风险边界
5.   U-9 + U-10 闸门
6.  闸门PASS → 纳入荐股列表
    闸门WARN → 标注风险，保留荐股但降级标记
    闸门BLOCK → 移出荐股列表
7. 生成 eval_hook
```

### 2.4 模拟交易接入

**触发**: 模拟交易白皮书流程

**接入点**: 每笔交易决策时

**流程**:
```
1. 交易信号触发:
2.   生成解释对象 (腰子)
3.   流金U-10审计 (重点关注仓位/止损/冷却期)
4.   旧影U-9审计
5.  闸门PASS → 执行交易
    闸门WARN → 降级（BUY→HOLD，或减半仓位）
    闸门BLOCK → 取消交易
6. 生成 eval_hook
```

### 2.5 保护机制接入

**触发**: 保护机制触发或解除时

**接入点**: 保护触发/解除事件

**流程**:
```
1. 保护触发:
2.   流金生成解释对象 (action_bias=SELL或HOLD)
3.   U-10审计 (确保动作合理)
4.   腰子确认
5. 保护解除:
6.   流金生成解释对象 (action_bias=WATCH)
7.   U-10审计
8.   腰子确认
```

### 2.6 临时分析接入

**触发**: 用户发起的任意个股/市场分析

**接入点**: 阿黑路由→腰子判断后

**流程**:
```
1. 阿黑识别意图 → 路由到腰子
2. 腰子判断需要哪些角色:
   - 涉及数据→玉夜
   - 涉及宏观→山猫
   - 涉及事件→信鸽
   - 涉及信号→青山
   - 涉及风控→流金
3. 按需召集角色 → 各角色生成解释片段
4. 腰子整合 → U-9+U-10
5. 输出解释对象 + eval_hook
```
