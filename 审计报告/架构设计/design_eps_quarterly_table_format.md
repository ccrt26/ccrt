## 一、需求分析

### 1.1 现状

8 份深度分析报告中，"单季EPS走势"数据使用 fenced code block 展示：

```
         Q1'25  Q2'25  Q3'25  Q4'25  Q1'26
EPS:      0.33   0.42   0.39   0.47   0.32
```

问题：
- 代码块渲染为 `<pre><code>`，字体为等宽字体（即使已修复 font-family，仍缺乏表格的结构感）
- 对齐依赖空格，在不同渲染器下可能错位
- 与上下文的财务数据表格风格不统一

### 1.2 目标格式

替换为与上文"分阶段财务数据"表格风格一致的 markdown 表格：

```markdown
**单季EPS走势**（还原为独立季度）：

| 季度 | Q1'25 | Q2'25 | Q3'25 | Q4'25 | Q1'26 |
|:----|:----:|:----:|:----:|:----:|:----:|
| EPS | 0.33 | 0.42 | 0.39 | 0.47 | 0.32 |
```

### 1.3 涉及文件

8 份 MD 报告（`临时报告/<代码>_<名称>_深度分析_20260525.md`），每份修改 ~5 行（删除代码块，插入表格）。

## 二、设计决策

### 2.1 表格结构

| 决策 | 选择 | 理由 |
|:-----|:-----|:-----|
| 列方向 | 季度为列（横向展开） | 季度是时间序列，横向排列符合阅读习惯 |
| 对齐 | 首列左对齐，数据列居中 | 与上文财务数据表格一致 |
| 表头 | Q1'25 ~ Q1'26 | 精简标签，与原有代码块内容一致 |
| 行标签 | "EPS" | 单行数据，无需多行 |

### 2.2 为什么不用 chi-table（特征表）？

数据只有 1 行（EPS）× 5 列（季度），结构极简。使用 markdown 原生表格即可，无需特殊组件。
