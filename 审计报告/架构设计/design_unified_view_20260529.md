# 模拟交易统一视图 — 架构设计

> **pipeline_stage**: complete | **日期**: 2026-05-29 | **设计者**: 情墨

---

## 一、产品定位

将散落在 6 类文件中的模拟交易数据，融合成**单一 HTML 页面**：按时间线展示每个交易日的操作、触发信号、策略思路、结果解读，顶部附累计绩效仪表盘。交易时段直接打开浏览器即可复盘全部历史。

## 二、输出格式选择

| 方案 | 评价 |
|:-----|:-----|
| MD | 无交互，净值曲线只能用ASCII，体验差 |
| HTML 单文件 | 净值曲线可交互、暗色主题、浏览器直接打开、无依赖、可托管GitHub Pages |
| PDF | 静态归档用，可作为HTML的打印导出，不单独生成 |

**选择：HTML 单文件（自包含 CSS/JS），可选打印为 PDF。** 与项目现有 `持仓仪表盘.html` 风格一致。

## 三、数据流


## 五、策略注解机制

HTML 中嵌入策略注解数据（从代码无法自动提取的部分）：

每张操作卡片包含四个区块：
1. **触发信号** — 自动从日志/snapshot提取（P1/P2/...触发条件、价格、阈值）
2. **操作** — 自动从 transactions.csv 提取（买卖、价格、股数、费用）
3. **结果** — 自动从 snapshot 计算（当日净值变化、持仓浮动盈亏）
4. **策略思路** — 半自动：读取 `trade_context.json` 中的事件标注 + 手工维护的 `strategy_annotations.json`

其中第4块首次运行时为空模板，后续由腰子团队复盘时填充。

## 六、生成脚本设计

`模拟交易/分析/generate_unified_view.py` (L0)

```python
# 用法
python3 generate_unified_view.py [--date YYYYMMDD] [--output 临时报告/xxx.html]

# 核心逻辑
1. 扫描 snapshot_*.json → 提取净值时间序列 → 绘制净值曲线
2. 读取 transactions.csv → 构建每日交易列表
3. 读取 sim_*.log → 提取触发信号文本
4. 读取 perf_summary.json → 累计指标
5. 读取 trade_context.json → 事件关联
6. 渲染 HTML 模板 → 写入输出文件
```

## 七、HTML 技术选型

- 纯 HTML+CSS+JS，零外部依赖
- Chart: 使用内联 `<canvas>` + 手写迷你折线图（<50行JS），不引入 Chart.js
- 暗色主题：品牌色 `#1a1a2e` 背景，`#e74c3c` 涨/`#27ae60` 跌
- 卡片折叠：默认全部展开，点击标题折叠
- 响应式：桌面端优化，移动端降级为单列
