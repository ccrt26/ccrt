## 二、修复A：评估数据加载韧性

### 2.1 当前逻辑
```python
eval_data = load_json(data_file)
stocks_eval = {s["Code"]: s for s in eval_data.get("Stocks", [])}
```
无格式检测，无兼容性检查，无覆盖率闸门。

### 2.2 新逻辑
```
Step 3: 读取评估数据
  ├─ 加载JSON
  ├─ 检测格式：检查顶层键名
  │   ├─ "Stocks" 存在 → Format A（引擎兼容格式）→ 正常加载
  │   ├─ "stocks" 存在（且 "Stocks" 不存在）→ Format B（报告提取格式）
  │   │   └─ 记录 WARN，标注格式来源(meta.generated_by)
  │   │   └─ 尝试回退：往前翻最近5个交易日文件，找第一个含 "Stocks" 键的
  │   │       ├─ 找到 → 加载，标注 "数据回退至T-N日"
  │   │       └─ 找不到 → FATAL sys.exit(1)
  │   └─ 两者都不存在 → FATAL sys.exit(1): "评估数据格式未知"
  │
  ├─ 构建 stocks_eval（大小写兼容：Code/code 都尝试）
  └─ 覆盖率闸门
      ├─ matched >= CODE_MAP * 0.5 → 通过
      └─ matched < CODE_MAP * 0.5 → FATAL sys.exit(1): "覆盖率过低"
```

### 2.3 设计要点

- **不尝试兼容 Format B 的内容**：Format B 缺少 Prediction.Short、TrendHealth.Label、KeyLevels.StopLoss——这些是风控必需字段。强行映射残缺数据比回退到旧数据更危险。
- **回退上限 5 日**：平衡数据新鲜度与可用性。5日前的评估数据对当前交易参考价值大幅下降。
- **FATAL 退出而非 WARN**：数据不可用时引擎不产生交易记录，比静默产出不可靠记录更安全。
- **大小写兼容**：Format A 内部也存在 Code/code 混用（5/26 文件用 "code"），构建 stocks_eval 时做 `s.get("Code") or s.get("code")` 兜底。

### 2.4 代码改动点

`sim_trading.py` Step 3（约 L148-168），替换为上述逻辑。新增约40行。

### 2.5 接口影响

- 函数签名不变
- 输入：评估数据文件路径不变
- 输出：stocks_eval 字典结构不变
- 新增行为：可能 sys.exit(1) 或回退到旧文件

## 三、修复B：交易记录重建

### 3.1 数据来源

| 20260526 | 600114 | SELL | 39.26 | 1200 | P4全部止盈 | sim_20260526.log |
| 20260526 | 301075 | SELL | 76.38 | 1100 | P1止损 | sim_20260526.log |

| 20260527-28 | 603019 | SELL | ~91 | 900 | 待确认 | snapshot_20260529.json(消失) |

### 3.2 费用计算

按 A 股费率（佣金万分之2.5，最低5元；卖出印花税千分之1）：

**600114 止盈减仓 (5/25)：**
- 卖出 1100 × 37.75 = 41,525.00
- 佣金 = max(41525×0.00025, 5) = 10.38
- 印花税 = 41525×0.001 = 41.53
- 净收入 = 41525 - 10.38 - 41.53 = 41,473.09

**600114 全部止盈 (5/26)：**
- 卖出 1200 × 39.26 = 47,112.00
- 佣金 = max(47112×0.00025, 5) = 11.78
- 印花税 = 47112×0.001 = 47.11
- 净收入 = 47112 - 11.78 - 47.11 = 47,053.11

**301075 止损 (5/26)：**
- 卖出 1100 × 76.38 = 84,018.00
- 佣金 = max(84018×0.00025, 5) = 21.00
- 印花税 = 84018×0.001 = 84.02
- 净收入 = 84018 - 21.00 - 84.02 = 83,912.98

**603019 BUY (5/26)：**
- 价格 94.44，股数 900 → 需从快照推算精确 cost（含滑点）
- snapshot 显示 AvgCost=94.44，推测无滑点调整

**603019 SELL (5/27-5/28)：**
- 日志缺失，需从日报评估数据推算卖出价
- 5/27 eval: 中科曙光 Short=中性 → P3预判转空触发（最可能的出场原因）

### 3.3 操作方式

直接编辑 `历史数据/00_核心交易/transactions.csv`，按 v1.7 格式（17列）追加记录，shadow 列留空。

603019 的买入和卖出在日志中无完整记录，标记 `reason` 为 "重建_待验证"，待后续核对。
