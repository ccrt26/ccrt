## 一、L2/L1/L0 分层形式化

### 1.1 三层定义

```
L2 硬底线 (引擎强制执行，腰子不可覆盖)
  ├── P1 止损: currentPrice <= StopLoss → 强制卖出
  ├── P2 趋势恶化: TrendHealth.Label == "危险" → 强制卖出
  ├── 回撤熔断: 单日回撤 > 5% → 自动减仓50%
  ├── 仓位上限: 持仓数 >= MaxPositions → 禁止新开仓
  ├── 冷却期: 止损/止盈冷却期内禁止同股开仓
  └── 单股上限: SingleStockLimitPct 上限

L1 量化信号 (引擎自动规则，腰子可覆盖)
  ├── P3 预判转空: Short方向由多→中性/看空
  ├── P4 全部止盈: 现价 >= R3 → 全卖
  ├── P5 止盈减仓: 现价 >= R2 → 减半仓
  ├── 腰子HOLD: 腰子明确HOLD → 跳过P3/P4/P5
  └── 自动开仓: 评分+信号+仓位+状态达标 → 自动开仓

L0 腰子决策 (人工判断，覆盖L1但不覆盖L2)
  ├── 腰子SELL: 在P1/P2安全网之下，P3/P4/P5之上
  ├── 腰子SELL_HALF: 减半仓锁利
  ├── 腰子BUY: 优先于自动开仓
  └── 腰子HOLD: 阻止P3/P4/P5自动卖出
```

### 1.2 不可覆盖边界（代码级强制）

在引擎中，以下检查**不接受腰子指令覆盖**：

```powershell
# L2 硬底线检查——腰子HOLD指令也不能跳过
if ($currentPrice -le $adjStopLoss) { ... P1止损 执行 }
if ($evalStock.TrendHealth.Label -eq "危险") { ... P2趋势恶化 执行 }
if ($dailyDD -gt 5) { ... 回撤熔断 执行 }
if ($currentPosCount -ge $config.MaxPositions) { ... 仓位上限 跳过 }
```

**实现原则**: L2检查代码位于腰子指令检查之上（先执行），不读取`$yaoziHolds`/`$yaoziSells`。腰子HOLD指令仅对L1信号(P3/P4/P5)生效。

## 二、risk_override 闭合实现

### 2.1 数据流

```
腰子指令JSON (§3.2 schema)
  │
  ├── risk_override = false → 正常执行，INFO级别
  │
  └── risk_override = true → 引擎特殊处理:
        ├── 日志: WARN级别 "[风险覆盖] $code $action"
        ├── CSV reason: 追加 " | [风险覆盖]流金警告:$risk_override_reason"
        ├── CSV source: "manual_override" (区分于普通"manual")
        └── 后评估: 单独分组统计
```

### 2.2 引擎代码变更（sim_trading.ps1）

| 行号 | 变更 | 说明 |
|:----:|:-----|:-----|
| ~700 | 腰子SELL分支增加risk_override检查 | 读取`$yd.risk_override`，为true时日志升级WARN |
| ~720 | CSV reason追加风险覆盖标记 | `$yd.reason + " | [风险覆盖]" + $yd.risk_override_reason` |
| ~718 | CSV source区分 | `manual_override` (risk_override=true) vs `manual` (false) |
| ~891 | 腰子BUY分支同上 | 买入也需risk_override追踪 |
| ~1176 | 指令状态更新 | 回写时保留risk_override标记到指令文件 |

### 2.3 后评估对接

现有后评估CSV分组：
```
source IN ('manual', 'auto')
```

新增分组：
```
source IN ('manual', 'manual_override', 'auto')
```

统计维度：
- 腰子常规决策胜率 (source='manual')
- 腰子覆盖决策胜率 (source='manual_override')
- 覆盖决策连续亏损计数 → >=3次触发L3升级

## 三、指令格式桥

### 3.1 问题

当前：腰子输出Markdown (`交易指令_YYYYMMDD.md`)，引擎读取JSON (`交易指令_YYYYMMDD.json`)

### 3.2 方案

腰子输出两份文件：
- `交易指令_YYYYMMDD.md` — 人类阅读的决策记录
- `交易指令_YYYYMMDD.json` — 引擎读取的结构化指令

JSON格式即v2.2 §3.2定义的schema，腰子产出时同时生成。

生成方式：腰子在Markdown中写决策 → 同时构建JSON对象 → 两份文件一并写入。

### 3.3 JSON最小样例

```json
{
  "date": "20260525",
  "generated_by": "腰子",
  "generated_at": "2026-05-25T19:00:00",
  "decisions": [
    {
      "action": "SELL",
      "code": "301075",
      "name": "多瑞医药",
      "shares": 1100,
      "reason": "MACD死叉+毛利率崩溃+五红旗全红",
      "priority": "P0_腰子",
      "status": "pending",
      "risk_override": false,
      "risk_override_reason": ""
    }
  ]
}
```

### 4.1 日志级别

| 场景 | 级别 | 示例 |

| L2底线触发 | WARN | `MARKET CB: level=RED \| 新仓封锁` |
| 数据降级 | WARN | `当日评估数据不存在，回退至评估数据_20260524.json` |
