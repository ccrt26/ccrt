# 周度深度分析报告调度系统 — 架构设计

> **设计人**：情墨 | **日期**：2026-05-25 | **版本**：v1.0  
> **pipeline_stage**: complete | **L级**：L1（涉及策略/报告产出，不涉及L2风控/交易逻辑）

---

## 1. 需求摘要

用户要求：每周五晚20:30自动产出重点股票深度分析报告，输出到 `重点股票/深度分析/东睦股份(600114)深度分析报告_YYYYMMDD.md`，严格遵循《重点股票跟踪分析逻辑白皮书 v3.3》的分析逻辑和《报告样式基线 v1.2》的样式规范。

---

## 2. 架构总览

```
┌──────────────────────────────────────────────────────────┐
│  Cron (Fri 20:30 CST, durable)                           │
│  ↓                                                        │

│  ↓                                                        │

└──────────────────────────────────────────────────────────┘
```

## 3. 模块设计

### 3.1 调度层 — Cron Job [L0]

| 属性 | 值 |
|:-----|:---|
| 类型 | Claude Code CronCreate (durable) |
| Cron表达式 | `30 20 * * 5` (每周五20:30 CST) |
| 持久化 | `.claude/scheduled_tasks.json` |
| 过期策略 | 7天自动续期（recurring默认行为） |

**选型理由**：深度分析本质是AI生成任务，非确定性数据管线。用Claude Code cron而非Windows Task Scheduler + 独立脚本，保持调度在项目边界内统一管理。

### 3.2 分析层 — 深度分析Command [L1]

| 属性 | 值 |
|:-----|:---|
| 文件 | `.claude/commands/深度分析.md` |
| 角色链 | 腰子(主) → 山猫→玉夜→流金→青山 (全团) |
| 分析框架 | 白皮书v3.3 六章完整结构 |
| 输出格式 | Markdown + 可选HTML |

**章节结构（与白皮书v3.3一一对应）**：

| 章 | 内容 | 数据源 |
|:--:|:-----|:------|
| 一 | 多维度分析（技术/基本/消息/板块/资金/宏观） | [2][3][7][8][9][10][11][12]→[5] |
| 二 | 三周期预判（短/中/长期 + 综合矩阵） | 第一章结论综合 |
| 三 | 综合评分与评级（六维评分 + 趋势健康度） | 第一章量化汇总 |
| 四 | 操作建议与交易计划（价格分层 + 三周期操作 + 情景应对） | [2]→[5]价格计算 |
| 五 | 风险提示与极端事件应对 | 流金评估 |
| 六 | 数据源标注 + 免责声明 | 玉夜审计 |

### 3.3 输出层 — 文件生成 [L0]

| 属性 | 值 |
|:-----|:---|
| 输出目录 | `重点股票/深度分析/` |
| MD命名 | `东睦股份(600114)深度分析报告_YYYYMMDD.md` |
| HTML命名 | `东睦股份(600114)深度分析报告_YYYYMMDD.html` |
| HTML CSS | 复用 `run_keystock_analysis.ps1` L970-1040 冻结CSS |

## 4. 数据流

```
① Cron触发 (Fri 20:30)
  ↓
② 腰子读取白皮书v3.3 → 确认分析框架
  ↓
③ 玉夜巡检数据源 (主→备→缓存三层)
  ├─ K线[2] / 财务[3] / 板块[7] / 北向[8] / 主力[9][10] / 研报[11] / 两融[12]
  └─ 降级路径标注 + 缓存兜底
  ↓
④ 山猫出宏观/政策/情绪 → 玉夜确认数据 → 流金出风险 → 青山出策略
  ↓
⑤ 腰子综合 → 生成六章完整MD报告
  ↓
⑥ [可选] HTML生成 (gen_doc.ps1 或 md_to_docx.py 路径)
  ↓
⑦ 文件写入 → 完成
```

## 5. 接口契约

### 5.1 Cron → Command 接口

```
Cron prompt:
  "执行深度分析：对东睦股份(600114)进行周度深度分析，
   输出报告到 重点股票/深度分析/东睦股份(600114)深度分析报告_{date}.md
   严格遵循白皮书v3.3和样式基线v1.2 §2ter"
```

### 5.2 报告文件命名契约

- 模板: `{股票名称}({股票代码})深度分析报告_{YYYYMMDD}.md`
- YYYYMMDD = 报告产出日期（周五日期）
- 旧版不覆盖，每期独立文件

## 6. 技术决策

| 决策点 | 选择 | 替代方案 | 选择理由 |
|:-------|:-----|:--------|:--------|
| 调度方式 | Claude Code CronCreate | Windows Task Scheduler | 统一在项目边界内，AI任务无需独立进程 |
| 报告格式 | MD主输出 + HTML可选 | 纯HTML | MD便于版本管理和diff；HTML按需生成 |
| 触发粒度 | 单次prompt完整报告 | 分步触发(数据→分析→输出) | 深度分析各维度相互依赖，分步会丢失上下文 |
| 单股vs多股 | 单股(东睦股份)起步 | 多股批量 | 用户明确指定单股；架构预留扩展参数 |

## 8. 风险与降级

| 风险 | 概率 | 影响 | 降级方案 |
|:-----|:----:|:----:|:--------|
| 周五晚数据源不可用 | 低 | 报告缺数据字段 | 玉夜1+2架构：备源→缓存[C]兜底，标注降级路径 |
| Cron错过触发（Claude Code不在运行） | 中 | 报告未生成 | durable cron在下次Claude Code启动时补触发；或周六手动 `/深度分析` |
| Token超限（报告>50K tokens） | 低 | 输出截断 | 分两段生成：先分析+评分，后操作建议 |
| API调用超时 | 低 | 部分维度缺失 | 标注"数据不可获取"，不编造数字 |
