## 1. 问题诊断（用户PDF截图反推）

用户打开PDF后发现4类问题：

| # | PDF表现 | MD源正确？ | 根因定位 |
|:--|:-----|:--------|:-----|
| 1 | 表格中出现 `:--` `:---` `:-:` 等符号 | MD正确 | `html.replace('---', '<hr>')` 在53行先于表格处理(67行)执行，把对齐行 `\|:-----\|` 破坏为 `\|:<hr>--\|`，导致对齐检测失效 |
| 2 | "不做清单"5项全部挤成一段 | MD正确，`- ` 列表项 | `md_to_html()` 无列表处理逻辑，`- text` 未转为 `<ul><li>` |
| 3 | PDF每页顶部出现 `file:///C:/Users/...` 路径 | — | Edge headless 默认打印页眉页脚，`file:///` URL 被印在PDF上 |
| 4 | 整个报告拥挤无排版 | MD正确，段落/引用分隔清晰 | 转换器未将文本块包入 `<p>` 标签，浏览器将连续文本折叠为一段 |

**核心结论**：四个问题全部出在 `convert_daily_brief_pdf.py` 的 `md_to_html()` 函数，MD源文件没有问题。

---

## 2. 修复方案

### 2.1 重写 md_to_html() — 状态机解析

**改前架构**：5个独立正则替换 + 1个表格循环，存在顺序依赖bug。

**改后架构**：单次遍历 + 行类型识别 + 同类型分组：

```
for line in lines:
    if 空行 → skip
    if ---  → <hr> (仅独立行，不在表格内)
    if #/##/### → 标题
    if |...| → 表格组(收集连续表格行，对齐行跳过，首行=th)
    if > ... → 引用组(收集连续>行，合并为一个<blockquote>)
    if - ... → 列表组(收集连续-行，包裹<ul><li>)
    else    → <p>段落
```

**关键变更**：
- 表格对齐行在**表格处理内部**跳过，不受外部 `---`→`<hr>` 影响
- 新增列表处理：连续 `- ` 行 → `<ul><li>…</li></ul>`
- 引用块合并：连续 `> ` 行 → 单个 `<blockquote>` 内 `<br>` 连接
- 文本块：裸文本行 → `<p>…</p>` 确保段落间距

### 2.2 Edge PDF 页眉页脚

`msedge` 命令增加 `--no-pdf-header-footer` 参数。

### 2.3 CSS 补充

新增 `p`、`ul`、`li` 样式规则。

## 4. 需求→代码核对清单

| # | 需求 | 实现点 | 验证方法 |
|:--|:-----|:-----|:-----|
| 1 | 表格对齐行不显示为内容 | 状态机内对齐检测跳过，不依赖replace顺序 | 打开PDF检查`:--`等符号不出现 |
