## 六、发现与建议

### 6.1 架构问题

1. **盘符硬编码 (行23)**: `ROOT = r"C:\Users\34269\Documents\Claude\股票分析"` 违反跨平台规则。建议改为 `os.path.dirname(os.path.dirname(os.path.abspath(__file__)))` 推导或通过环境变量/配置文件注入。

2. **死代码 (行233)**: `_commodity_sector_map = None` 声明但从未被赋值或使用。`_score_cyclical_growth` 中实际调用的是 `_get_commodity_trend` 直接遍历参数，未用到此缓存。建议删除。

3. **单文件 2360 行**: 远超 500 行阈值。建议按功能域拆分：
   - `tech_indicators.py` (111-179): calc_ma/ema/atr/rsi/macd
   - `theme_classifier.py` (181-353): 题材三分类+C7纯度
   - `pe_scoring.py` (355-706): 三路径PE评分+板块相关性
   - `veto_rules.py` (708-862): 绝对否决+条件否决
   - `sector_momentum.py` (874-1217): 板块动量+趋势+豁免
   - `tech_scoring.py` (1256-1732): 技术面8子项评分
   - `main_pipeline.py` (1865-2360): 数据质量、历史落库、主入口

4. **全局变量 → 函数强耦合**: 9 个函数直接读取模块级全局变量 (行764 `check_absolute_vetoes` 和 行1735 `check_conditional_vetoes` 各引用最多全局)。建议将配置注入为函数参数或通过配置类封装，提高可测试性。

### 6.2 潜在风险

5. **主循环内定义闭包 (行2095-2134)**: `get_sector_info` 和 `get_sector_trend_info` 在 `main()` 中定义为闭包，每次 `main()` 调用时重新创建。虽为局部函数，但逻辑较复杂（含三段式回退查找），建议提升为模块级函数以便测试。

6. **`check_conditional_vetoes` 重复调用 `load_industry_whitelist()`**: 该函数内调用 `classify_theme` 和 `check_theme_purity` 时各自调用一次 `load_industry_whitelist()`，导致同一个 JSON 文件被读取 2-3 次。建议在调用方缓存结果后传入。

### 6.3 正面特征

7. **67% 函数为纯函数**: 39 个函数中有 26 个不引用任何全局变量，可独立进行单元测试。
8. **内部函数命名规范**: 所有私有函数使用 `_` 前缀，公共 API 边界清晰。
9. **明确的职责分层**: 技术指标(5) → 题材分类(5) → PE评分(4) → 板块分析(6) → 否决(4) → 诊断(5) → 技术子项(8) → 主入口(2)，层次分明。
