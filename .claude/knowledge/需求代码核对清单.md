# 需求→代码逐项核对清单

> 用途：每次腰子提出新金融需求、经情墨设计后，情墨+腰子+红结+红枫四角色分阶段勾签
> 位置：附在情墨设计文档末尾，用 ```json 代码块包裹
> 版本 v2.0 | 2026-05-29
> 变更：增加JSON schema + G段部署验证 + 四角色签章 + 红结回填code_ref机制

---

## 一、使用规则

1. **触发时机**：腰子提出新金融需求 → 情墨完成架构设计后
2. **阶段① 情墨**：填写A-F设计侧 + G段预期部署项 → 勾签 signoffs.情墨
3. **阶段①a 腰子**：核对A-F金融参数与白皮书一致 → 勾签 signoffs.腰子
4. **阶段①b 旧影**：运行 `check_checklist.py` 校验清单结构+双签
5. **阶段④ 红结**：编码后回填每项 code_ref（实际文件:行号）→ 勾签 signoffs.红结
6. **阶段⑤ 新安**：运行 `trace_requirements.py` 自动全量+人工抽查
7. **阶段⑥ 红枫**：部署后回填G段 → 勾签 signoffs.红枫 → 旧影运行 `verify_deployment.py`
8. **核查人**：旧影在审计中抽查清单完整性

## 三、字段说明

### sections 字段

| 字段 | 类型 | 填充者 | 说明 |
|:-----|:-----|:------|:-----|
| `id` | string | 情墨 | 唯一标识（段字母+序号） |
| `item` | string | 情墨 | 需求描述 |
| `clause` | string | 情墨 | 对应的白皮书/红线条款 |
| `code_ref` | string | **红结** | 实现代码的文件路径:行号（编码后回填） |
| `coder_ok` | bool | **红结** | 编码完成确认（编码后回填为true） |

### G段额外字段

| 字段 | 类型 | 填充者 | 说明 |
|:-----|:-----|:------|:-----|
| `target` | string | 情墨（预期）/ 红枫（实际） | 部署目标路径/命令 |
| `deployed` | bool | **红枫** | 部署完成确认 |
| `deployer_ok` | bool | **红枫** | 部署验证通过确认 |

### signoffs 字段

| 字段 | 类型 | 说明 |
|:-----|:-----|:-----|
| `signed` | bool | 是否已签字 |
| `date` | string | 签字日期 (YYYY-MM-DD) |
| `scope` | string | 该角色负责的范围说明 |

---

## 四、核查工具链

| 工具 | 运行者 | 阶段 | 功能 |
|:-----|:------|:----:|:-----|
| `check_checklist.py` | 旧影 | gate_1b | 校验JSON结构+情墨腰子双签 |
| `trace_requirements.py` | 新安 | gate_2 | 自动全量验证code_ref+人工抽查语义 |
| `verify_deployment.py` | 旧影 | gate_3 | 验证G段每项部署操作实际完成 |
