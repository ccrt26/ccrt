# 保护 — 详细流程（从 .claude/commands/保护.md 拆分）

> 本文档为保护机制的完整操作手册。入口见 `.claude/commands/保护.md`。

## 前置步骤（所有子命令共享）

1. **读取 `保护机制/保护快照.json`**（优先，v3.0 新增）
2. 检查快照 stale_seconds：若 > 600 秒（10分钟），标记数据过期
3. 读取 `保护机制/持仓账本.json`
4. 读取 `保护机制/知识库/行为模式.md`
5. 读取 `保护机制/知识库/个人风控参数.md`
6. 读取 `保护机制/知识库/风控口径.md`（v3.0 新增）
7. 读取 `保护机制/知识库/陷阱日历.md`
8. 读取 `保护机制/知识库/持仓关键位.md`
9. 读取 `holidays_2026.csv`，判断当日是否交易日

### 快照刷新策略

- 快照过期（>10分钟）→ 尝试运行 `python3 代码文件/tools/build_protection_snapshot.py` 重建
- 重建失败 → 盘前输出降级简报；刹车默认"等"
- 数据状态 missing/conflict → 腰子默认"今日少动或不动"

## 一、盘前简报

### 触发
- Cron: 交易日 8:57（读 8:53 生成的快照）
- Cron: 交易日 9:25（读 9:23 重新生成的快照）
- 手动: `/保护 盘前`

### 前置过滤
- 节假日 → 输出"节假日跳过" → 结束
- 持仓为空 → 输出"无持仓数据，跳过盘前简报" → 结束
- 快照 data_status=missing → 输出降级简报，腰子默认"今日少动或不动"

### 8:57 阶段流程

按序执行，每角色输出后接力。**所有数据从保护快照.json读取，不调实时API。**

**① 山猫** — 读取 market_guard 段，输出：
- 隔夜外盘（overnight段）
- 情绪温度（market_sentiment）+ 支撑指标（sentiment_indicators）
- 市场禁止规则（market_forbid_rules）
- ≤50 字

**② 信鸽** — 读取 event_guard 段，输出：
- 近期事件（recent_events）
- 事件方向（event_direction）/ 有效催化（has_valid_catalyst）
- 敏感事件触发（sensitive_event_hit）
- ≤40 字

**③ 玉夜** — 读取 meta.data_status + data_quality_flags，输出：
- 数据质量状态（normal/degraded/stale/conflict/missing）
- 各源标记摘要
- ≤30 字

**④ 流金** — 读取 real_account + behavior_guard + positions[]，输出：
- 持仓摘要（每只：成本、浮盈浮亏%）
- 有效止损（effective_stop_loss）
- 仓位上限（已用%/剩余%）
- 今日禁止模式（behavior_guard.forbidden_patterns_hit + known_impulse_patterns）
- 冷却期状态
- ≤60 字

**⑤ 青山** — 读取 positions[].key_levels + triggered_signals，输出：
- 每只持仓的信号方向 + 合理区间 + 当前价格位置
- 偏离预警（价格偏离区间 >10%）
- ≤50 字

**⑥ 腰子** — 综合读取 final_guard.hard_blocks + soft_warnings + 以上五角色输出：
- 今日一句话操作纪律
- 结论固定为四值之一：可 / 等 / 否 / 强制冷却
- ≤30 字

### 8:57 飞书消息格式（≤12 行）

决策卡片，10 秒可读。结论先行，不输出角色长段落。

```
【保护】盘前 · MM-DD

结论：<等/不加仓/只观察/可操作>

今天先看：
1. <标的>：成本<X>，现价<Y>，浮亏/浮盈<Z%>
2. 有效止损：<X>，<距止损状态>
3. 催化：<有/无>，数据：<normal/degraded/stale>

今日禁止：
- <最多3条，从hard_blocks+forbidden_patterns取最严重>

动作：
<一句话，可执行，如"开盘30分钟不买""跌破X止损">

详情：回复 /保护 盘前 详细
```

压缩规则：
- "今天先看"最多 3 行，每行一个关键数字。
- "今日禁止"最多 3 条，不展开解释。
- "动作"必须是用户可直接执行的句子。
- 不出现【山猫】【信鸽】【玉夜】【流金】【青山】标记。
- 不出现表格。
- 数据异常时结论加注"⚠️ 数据降级，保守为主"。

### 9:25 阶段流程

**① 山猫** — 竞价数据（读快照 positions[] 价格变化），≤40 字
**② 腰子** — 判断是否修正 8:57 定调，≤40 字

### 9:25 飞书消息格式（≤8 行）

只说是否修正，不重复盘前全文。

```
【保护】竞价 · HH:MM

结论：<维持等/修正为更谨慎/修正为可操作>

变化：
1. <标的>竞价：<±X%>
2. <是否突破关键位>
3. <有无新增催化>

动作：
<一句话，如"不因竞价波动临时买入，继续等开盘30分钟">
```

规则：
- 只输出"有修正"或"无修正"，不重复 8:57 内容。
- 持仓多只时只列有异动的标的。
- 无修正时"变化"可只保留一行。

## 二、盘中刹车

### 触发
```
保留兼容：/保护 刹车 <标的代码> <买入/卖出> <价格>
推荐格式：/保护 刹车 <标的代码> <买入/卖出> <价格> <金额或股数> <操作理由> <止损依据>
```

### 前置步骤
1. 读 `保护机制/保护快照.json`
2. 检查 stale_seconds > 600？→ 尝试重建快照；重建失败→默认"等"
3. 匹配标的信息（positions[]）
4. 判断已持有/未持有；若持有，计算浮盈浮亏

### 四层判定逻辑

**第一层：硬阻断**（任一命中 → "否"或"强制冷却"）

| # | 阻断条件 | 数据来源 |
|:-:|:--------|:--------|
| 1 | 当前处于冷却期 | real_account.cooling_period_active |
| 2 | 数据状态为 missing / conflict | meta.data_status |
| 3 | 买入发生在 9:30-10:00 且为追涨 | behavior_guard.open_30min_block |
| 4 | 无事件催化且涨幅超过 3% | behavior_guard.chase_without_event_block |
| 5 | 已持有且浮亏时继续买入 | positions[].unrealized_pnl_pct < 0 AND action=buy |
| 6 | 单票仓位将超过上限 | position_pct + new > single_position_limit_pct |
| 7 | 总仓位将超过上限 | total_position_pct + new > total_position_limit_pct |
| 8 | 当日亏损超过阈值 | real_account.daily_pnl_limit_hit |
| 9 | 有低胜率信号(<50%)仍作为主要买入理由 | positions[].signal_winrate < 0.5 |
| 10 | 止损口径冲突且用户仍要求买入 | positions[].stop_loss_conflict |

**第二层：软警告**（命中 → 默认"等"）

| # | 警告条件 | 数据来源 |
|:-:|:--------|:--------|
| 1 | 数据 stale | meta.data_status = stale |
| 2 | 信号胜率偏低 | positions[].signal_winrate < 0.55 |
| 3 | 报告结论为 wait/neutral | positions[].report_direction |
| 4 | 当前价接近压力位 | positions[].key_levels.current_zone = near_resistance |
| 5 | 目标收益/止损风险比 < 2:1 | 计算盈亏比 |

**第三层：盈亏比检查**

```
盈亏比 = |target_price - entry_price| / |entry_price - effective_stop_loss|
< 2:1 → "等"，提示不满足最低盈亏比要求
```

**第四层：行为模式匹配**

匹配 behavior_guard.known_impulse_patterns + 行为模式库 → 警告用户当前行为匹配已知冲动模式

### 缺参数处理

缺少"金额/理由/止损依据"任一项 → 不得给"可"，最多给"等/否"。

输出时直接给可复制模板，不大段解释。

### 飞书消息格式（默认精简，≤15 行）

决策卡片。第一行标的+动作，第二行结论，为什么最多 3 条。

```
【保护】刹车 · <标的名称> <方向><价格>

结论：<可/等/否/强制冷却>

为什么：
1. <最严重原因>
2. <次严重原因>
3. <第三原因，如适用>

现在怎么做：
- <具体动作1，如"不买"/"先确认站稳XX再考虑">
- <具体动作2>
- <如缺参数，给出可复制模板>

风险：<催化状态> | <报告方向> | 快照<normal/stale>

详情：回复 /保护 刹车 <代码> <方向> <价格> 详细
```

### 卖出/止损场景

卖出不能套用买入模板。区分"执行纪律"和"恐慌割肉"。

```
【保护】刹车 · <标的名称> <方向><价格>

结论：<可减仓/触发止损/等/否>

判断：
1. <是否跌破有效止损>
2. <是执行纪律还是情绪割肉>
3. <仓位建议>

动作：
<具体操作，如"先减半不反手""按纪律执行">
```

- 跌破有效止损 → 可给"可减仓/触发止损"。
- 未跌破但情绪割肉 → 默认"等"。
- 不得简单输出"否"。

### 详细模式（≤40 行）

用户输入含 `详细` 时，先给精简结论，再展开完整证据。

### 缺参数时的输出模板

如果用户只发 `/保护 刹车 600114 买入 36`（缺金额/理由/止损）：

```
【保护】刹车 · <标的名称> 买入<价格>

结论：否

为什么：
1. 缺少金额、理由、止损依据
2. <根据持仓/市场补充的具体风险>
3. <第三条，如适用>

现在怎么做：
如果还想操作，重新发送：
/保护 刹车 600114 买入 36 <数量> 因为___ 止损___

详情：回复 /保护 刹车 600114 买入 36 详细
```

## 三、盘后复盘

### 触发
`/保护 复盘`（有交易日时，手动或 Cron 19:37）

### 流程
1. 读 `保护机制/保护快照.json`
2. 检查持仓账本 history：今日有无交易？无 → 静默跳过
3. 读取当日刹车记录
4. 逐笔对比：每笔操作 vs 盘前简报纪律卡片
5. 产出偏差分析
6. 纪律评分（1-10）
7. 若发现新行为模式 → 追加到 `行为模式.md`
8. 写入 `保护机制/复盘记录/YYYY-MM-DD.md`

### 飞书消息格式（≤12 行）

```
【保护】复盘 · MM-DD

操作：<方向> <标的> · <价格>

对比盘前：
操作：<描述> | 信号：<盘前信号> | 偏差：<类型> | 根因：<分析>

纪律：<X>/10

改进：<一句话>

详情：回复 /保护 复盘 详细
```

## 消息行数闸门

| 类型 | 最大行数 |
|:-----|:-------:|
| 8:57 盘前 | 12 |
| 9:25 竞价 | 8 |
| 盘中刹车 | 15 |
| 卖出/止损 | 12 |
| 盘后复盘 | 12 |
| 详细模式 | 40 |
| 缺参数刹车 | 12 |

超出必须压缩。空行计入行数。

## 输出铁律

- 所有产物写入 `保护机制/`（盘前简报/刹车记录/复盘记录）
- 不写入任何 `代码文件/` 路径
- 不触发 `pipeline_engine`
- 不直接调用行情 API（数据来自保护快照）
- 数据缺失时说"数据不可获取"，不推测
- 结论枚举固定：`可 / 等 / 否 / 强制冷却`
- **结论必须第一屏可见**（消息前 3 行内）
- **默认精简，详细模式才展开**
- **"为什么"最多 3 条，"今日禁止"最多 3 条**
- **"动作"必须是可执行句子**
