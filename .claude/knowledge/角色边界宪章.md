## 四、边界冲突仲裁流

衔入现有 L0–L3 升级链：

```
角色自检发现越界
  ↓
自行终止，输出越界提示 + 退路建议（指明该找谁）
  ↓
阿黑收到：路由正确 → 转交正确角色
          路由错误 → 上提 L3（用户）
          边界定义模糊 → 叫 情墨 更新宪章
```

| 级别 | 触发条件 | 拍板人 |
|:----:|:--------|:------|
| L0 | 任务在C-list内，单一角色可独立判断 | 该角色 |
| L1 | 越界/意见矛盾/需要综合判断 | 腰子(金融)/情墨(工程) |
| L2 | L1拍板者与专业角色分歧大/涉及重大决策 | 阿黑协调 |
| L3 | 阿黑也无法决断/宪章边界定义争议 | 用户(创始人) |

## 五、维护规则

- 宪章版本号纳入 `version_supervisor.ps1` 检查范围
- 角色C/X变更必须由 腰子(金融线) 或 情墨(工程线) 提案，阿黑审批
- 每次变更后同步更新本宪章 + 对应command文件边界自检段 + 本矩阵
- 发布后7日内同步生成 `.docx`（`md_to_docx.py`）

## 七、三层执行机制

### 7.1 事前：角色激活时自动约束

每个角色 command 文件（`.claude/commands/*.md`）包含前置约束段：
```
修改任何文件前，先查角色边界宪章§六文件责任矩阵。无权修改的文件 → 标注越界 → 退回阿黑路由。
```

### 7.2 事中：阿黑路由查矩阵

阿黑识别文件修改意图 → 查本矩阵 → 路由到正确角色。错误路由被拦截。

### 7.3 事后：旧影审计 BND-004

旧影审计时抽查 git log，比对修改人与矩阵授权。越权修改 → B1级缺陷，强制回退+记录违规。详见旧影-知识库/07-常见违规模式库.md §BND-004。
