# 重点分析日报 — 每日操作简报

## 前置约束
修改任何文件前，先查 `.claude/knowledge/角色边界宪章.md` §六文件责任矩阵。无权修改的文件 → 标注越界 → 退回阿黑路由。

> ⛔ 每个交易日15:37自动触发。定位：以深度分析为baseline，每日做delta验证+trigger判断，服务"明日怎么操作"。
> **权威方法论**: `重点股票/分析逻辑/重点股票跟踪分析逻辑白皮书_v3.6.md`（当前执行版本 v3.6.2）
> **详细流程**: `.claude/knowledge/日报-详细流程.md`

## 核心铁律
1. 日报不是行情快照，不重做深度分析。只做 baseline→delta→trigger 三层验证
2. 用户版MD禁止出现 machine-only、数据源编号、数据完整度工程表、信号快照机读字段
3. 机器字段存放在同名 JSON sidecar
4. P0明日决策卡九字段缺一不可，禁止"待baseline确认"类空话
5. 必须经过 U检查+PDF gate 双闸门通过后才生成PDF
6. ⛔ **统一解读强制**：每只股票生成解释对象(interpretation_schema.json) → U-9/U-10闸门 → eval_hooks → 写入sidecar的 role_interpretations/yaozi_integration/audit_u9/audit_u10/eval_hooks 字段
   ⛔ sidecar audit_u9/audit_u10 必须来自真实U检查结果，不允许生成时预填 passed:true。

### 发布前硬规则（P0修复 2026-06-03）
7. 读取 `.claude/signal_daily_report.json` 时，如果 `publish_allowed == false` 或 `skip_data_check == true`，禁止生成 MD/HTML/PDF。
8. 日报正文成交量只能使用 `days[].volume_wan_shou`（万手单位），禁止使用 `days[].volume_shares` 或 `days[].v` 自行换算。
9. sidecar `fund_flow_4level` 必须完整写入 `super_large_net/large_net/medium_net/small_net/main_force_net` 五项。
10. sidecar 必须写入 `sector_phase.phase`。
11. PDF/门户发布前必须先跑 `scripts/check_daily_release_gate.py --date YYYYMMDD`，全部 PASS 才允许发布。

## 10段正文结构

1. P0明日决策卡（九字段+一句话结论）
2. baseline引用（深度分析结论、关键价位、仓位上限、风险边界）
3. 今日delta（近4日价格/量能/K线对比）
4. 四档资金（超大单/大单/中单/小单/主力合计/结构判断/操作影响）
   ⛔ 资金段不得只输出表格。每份MD必须在资金表后追加人话解释段，包含："这说明"+"对明日影响"，说明是否能增强买入/是否只能观察/是否需要等T+1数据确认。
5. 融资融券+北向+筹码（融资、北向、质押、解禁、股东人数；无缓存时必须写“不用于增强动作”，不得省略字段）
6. 大盘与板块（板块相位五阶段标签）
7. 消息事件（T+1/T+3/T+5跟踪；即使无新增事件，也必须输出验证表）
8. 信号胜率（样本数、T+1/T+5胜率、是否降权、对明日动作影响）
   ⛔ 信号段不得只输出表格。每份MD必须在信号表后追加人话解释段。低样本(<20)或低于50%胜率的信号必须写"不能单独触发买入/加仓"。
9. 风控红黄绿灯（必须输出7项风险：质押、解禁、融资、估值/财务、技术、事件、资金/板块；必须输出“仓位折扣”）
10. 明日情景应对+T+5展望+不做清单

## 产出
- MD→HTML→PDF缺一不可
- 生成后执行门户同步：`generate_portal.py` → `git push`

## 样式锁定
- 日报 HTML/PDF 只能通过 `代码文件/tools/convert_md_to_pdf.py` 生成
- 禁止AI手写HTML、禁止自定义CSS、禁止使用极简CSS
- 任何日报HTML中若未包含母版CSS，视为发布阻断
- 发布前必须通过 `scripts/check_daily_report_style.py --date YYYYMMDD`

## 全域解读协作制度
- 凡涉及数据、指标、政策、事件、资金、信号、风控、仓位、明日动作、T+5展望的解释，必须由对应角色先提交结构化解释，再由腰子整合
- 禁止单个AI直接从数据跳到动作
- MD中的所有解释句必须能追溯到sidecar的daily_synthesis
- 发布前必须通过 scripts/check_daily_collaborative_interpretation.py

### 个股化硬规则
- daily_synthesis不能只有字段非空,必须是每只股票的个股化解释
- 禁止把"近4日K线已更新""信号可参考""S1守住+量缩+资金改善"等工程句/模板句当作解释
- 明日动作必须来自角色解释包和腰子整合,不允许批量生成统一话术
- 发布前必须通过协作解读闸门的同质化检查
- **daily_synthesis 每个解释对象必须包含"个股事实→因果解释→明日动作影响"，不得只写标签词**
- **禁止使用「估值可接受/趋势判断/板块中性/风险可控/真空期/不改变/综合/参考」作为完整解释**
- **9只股票不能批量复用同一解释骨架；同一 interpretation/action/trigger 归一化后重复≥3只，禁止发布**
- **role_interpretations 不能只罗列事实，必须输出该角色对明日动作的判断依据**
