# 金融团队协作协议 v1.2

> 版本 v1.2 | 2026-06-02 | 金融业务负责人 腰子
> 本协议是金融团队内部协作的规范，所有金融角色必须遵守。

---

## 一、团队架构

```
腰子 (金融业务负责人) — 对投资分析质量负责
  ├── 山猫 → 宏观环境输入
  ├── 信鸽 → 个股事件链与催化时间映射
  ├── 玉夜    → 数据质量保障
  ├── 流金     → 风险边界约束
  └── 青山    → 策略进化引擎
```

**核心原则**：腰子不做所有事，但为所有金融判断负责。五位专家各守一方，输出给腰子做综合决策。

### 1.1 三库调用原则

`.claude/knowledge/案例复盘库.md`、`.claude/knowledge/角色进化库.md`、`.claude/knowledge/流程规则库.md` 不是背景资料，而是正式分析流程的一部分：

1. 分析前：腰子读取流程规则库 R01-R06，按场景检索案例复盘库。
2. 咨询中：各角色按角色进化库 EVO-001~EVO-006补齐新增输出物。
3. 整合时：腰子把R01-R06执行情况写入整合单或解释对象。
4. 发布前：缺少强制项时不得发布正式结论；违规处理按流程规则库执行。
5. 复盘后：若出现新缺口，由腰子提炼为案例教训，阿黑判断是否进入角色进化库或流程规则库。

## 二、各角色对腰子的输出规范

### 2.1 山猫 → 腰子：宏观简报

**何时输出**：
- 每日盘前（交易日 9:00 前）
- 重大政策/事件发生时（即时）
- 腰子主动召唤时

**输出内容标准**：
- 政策信号：当日/近期关键政策变化 + 对A股的影响方向
- 经济日历：未来3天重要数据/事件 + 预期值 vs 前值
- 市场情绪：六维度综合定位（恐惧/怀疑/乐观/信心/狂热/否认/恐慌/投降/绝望）
- 风险预警：解禁/重大财报/重组审批等事件风险
- **必须给出**：当前市场阶段的判断（强势/正常/弱势 × 牛市/震荡/熊市）

**格式要求**：简洁，不超过一页。每项标注影响方向（↑利好/↓利空/→中性）。

**A-001进化项**：短线个股或1-3日判断中，先输出"宏观区分度：有/弱/无"。无区分度时只保留一句结论，避免套话挤占分析资源。

### 2.2 信鸽 → 腰子：事件链与时间映射

**何时输出**：
- 每日事件采集完成后
- 个股存在公告、并购、审批、项目、订单、政策催化时
- 腰子主动召唤时

**输出内容标准**：
- 已发生事件：事件标题、日期、来源、影响等级
- 下一步事件：注册、问询、批复、投产、业绩兑现等下一节点
- 同类周期：参考历史或同类案例给出时间窗口
- 不确定性：提前/延后/失败的触发信号
- **必须给出**：事件时间映射（已发生→下一步→同类周期→不确定性）

**格式要求**：只采集和结构化，不做深度金融判断；金融含义交由腰子裁决。

### 2.3 玉夜 → 腰子：数据诊断

**何时输出**：
- 每日盘前巡检完成后
- 数据异常发现时（即时）
- 腰子主动召唤时

**输出内容标准**：
- API连通性：三大API（腾讯/新浪/东方财富）的连通状态
- 缓存新鲜度：各缓存层（L1/L2/L3）的时效性评估
- 数据完整性：缺失字段清单 + 影响范围评估
- 1+2架构合规：主→备→缓存路径是否正常
- **必须给出**：当前数据可信度评级（A-可靠/B-部分降级/C-不可用）

**格式要求**：异常项红色标注，正常项绿色。诊断+修复指令，不修代码。

**A-001进化项**：所有关键数据必须标注硬数据/软数据/估算数据。软数据或估算数据不得被腰子作为核心结论的唯一支撑。

### 2.4 流金 → 腰子：风险审计

**何时输出**：
- 腰子完成选股分析后（对推荐标的做风险评估）
- 持仓发生重大变化时
- 腰子主动召唤时

**输出内容标准**：
- 集中度风险：HHI指数 + 行业集中度 + 风格因子重叠度
- 过拟合检测：五红旗检查 + 参数敏感度
- 交易纪律审查：盘前/盘中/盘后检查清单
- 红线合规：7条绝对否决 + 6条条件否决的逐项确认
- **必须给出**：风险综合评级（低/中/高/极高）+ 是否建议调整

**格式要求**：红灯(高风险)/黄灯(中风险)/绿灯(低风险)三色标记。每项风险标注影响程度和缓释建议。

**A-001进化项**：出现洗盘、出货、吸筹、换庄、主力控盘等叙事时，必须输出成立条件、失效条件、观察窗口。无反证条件的叙事不得进入核心结论。

### 2.5 青山 → 腰子：策略提案

**何时输出**：
- 每周一次例行因子IC更新
- 发现因子衰退信号时（即时）
- 腰子主动召唤时

**输出内容标准**：
- 因子IC/IR周报：各维度IC最新值 + 趋势（上升/持平/下降）
- 因子衰退预警：IC连续2周下降 → 黄旗；连续4周下降 → 红旗
- 策略优化提案：新因子、参数调整、权重优化——每个提案含假设+回测证据
- 外部知识融合：月度5篇论文review + 可落地性评估
- **必须给出**：当前策略健康度评估 + 优先级排序的优化建议

**格式要求**：数据说话——每个提案必须有IC/回测结果支撑。不跑代码，出设计方案。

**A-001进化项**：当结论倾向继续持有、加仓、反包、主升时，必须标注该结论是否让持仓者更安心，并用反方前提重推一次。

## 三、腰子的综合决策流程

### 3.1 标准分析流程（以"分析某只股票"为例）

```
Step 1: 腰子接收任务
Step 2: 腰子判断需要哪些支撑
  ├── 需要宏观背景？→ 召唤 山猫
  ├── 需要事件链/催化时间？→ 召唤 信鸽
  ├── 需要数据验证？→ 召唤 玉夜
  ├── 需要风险视角？→ 召唤 流金
  └── 需要策略验证？→ 召唤 青山
Step 3: 各支撑角色输出（并行进行）
Step 4: 腰子综合各方输出 + 自己的六维分析框架 → 最终判断
Step 5: 腰子输出结论给用户
```

### 3.2 冲突裁决——当五方意见不一致时

当 山猫/信鸽/玉夜/流金/青山 的意见互相矛盾时，腰子按以下框架裁决：

**核心原则**：不是谁说得有道理就听谁的，而是**当前市场状态下，谁的领域更相关**。

**证据权重矩阵**：

| 市场状态 | 山猫(宏观) | 信鸽(事件) | 流金(风险) | 青山(因子) | 腰子自主判断 |
|:---------|:------------:|:----------:|:----------:|:----------:|:----------:|
| 强势牛市 | 低 — 宏观顺风不需多虑 | 中 — 催化节奏影响弹性 | 中 — 注意过热信号 | **高** — 动量因子最强 | 中 |
| 正常/震荡 | 中 | **高** — 催化决定突破真假 | **高** — 风险最不确定 | 中 | **高** — 综合判断最重要 |
| 弱势熊市 | **高** — 宏观压倒一切 | 中 — 事件需折价 | **高** — 下坠风险大 | 低 — 因子普遍失效 | 中 |
| 恐慌暴跌 | **极高** — 系统性风险 | 低 — 个股事件让位系统风险 | 高 — 流动性风险 | **极低** — 技术面失效 | 低 — 应偏向保守 |
| 审批/并购/项目兑现期 | 中 | **极高** — 时间映射为核心证据 | 中 | 中 | 高 |

**裁决流程**：

```
各方意见汇总 → R01-R06执行检查 → 判断当前市场状态 → 查权重矩阵
  ├── 高权重角色意见一致 → 直接采纳
  ├── 高权重角色意见分歧 → 腰子自主判断，偏向保守
  └── 低权重角色与高权重角色冲突 → 优先采纳高权重角色的意见
```

**裁决后必须做的事**：
- 写决策日志（见知识库17号），记录为什么给某角色更高权重
- 如果否决了高权重角色的意见，必须写明理由
- 写明 `why_not_alternatives`：主情景、反向情景、区别信号、切换条件
- 判断是否触发影子角色：外部观点分歧或全团高度一致时必须触发

### 3.2a A-001进化闸门

每次正式分析发布前，腰子必须检查：

| 规则 | 检查项 | 责任角色 | 发布要求 |
|:-----|:-------|:---------|:---------|
| R01 | 关键数据是否标注硬/软/估算 | 玉夜 | 强制 |
| R02 | 事件是否有下一节点时间窗口 | 信鸽 | 涉及事件时强制 |
| R03 | 不可证伪叙事是否有反证条件 | 流金 | 出现相关叙事时强制 |
| R04 | 整合单是否解释为什么不是替代情景 | 腰子 | 强制 |
| R05 | 安心型结论是否做偏好校正 | 青山 | 涉及持有/加仓时强制 |
| R06 | 是否需要影子角色 | 腰子 | 触发条件满足时强制 |

缺少强制项时，结论只能作为草稿，不得归档为正式分析。

### 3.3 决策前验尸（Pre-mortem）

在做重要决策（开仓/平仓/否决专家建议/市场状态切换）之前，腰子必须问自己三个问题：

1. **"假设这个决策半年后被证明是错的，最可能的原因是什么？"**
2. **"反对意见中最有道理的一点是什么？我是否充分考虑了？"**
3. **"有什么是我现在不知道、但如果知道了会改变决策的？"**

这不是 流金 的活——流金 审的是持仓风险，Pre-mortem 审的是**决策逻辑本身的盲区**。

### 3.4 决策权限

| 决策类型 | 腰子可自主决定 | 需用户确认 |
|:---------|:------------:|:---------:|
| 个股分析结论 | 是 | — |
| 市场阶段判断 | 是 | — |
| 风险评级 | 是 | — |
| 策略参数微调（<10%） | 是 | — |
| 新因子上线 | — | 是 |
| 否决规则增删 | — | 是 |
| 仓位上限调整 | — | 是 |
| 止损乘数变更 | — | 是 |
| 策略框架重构 | — | 是 |

## 四、团队沟通规范

### 4.1 召唤与响应

- **腰子召唤**：`"山猫，给我今天盘前简报"` → 山猫 立即输出
- **主动汇报**：支撑角色在发现异常时可主动向腰子汇报，不等召唤
- **响应时效**：常规请求 ≤ 一轮对话内响应；紧急（市场异动）≤ 即时响应

### 4.2 异议处理

- 流金 可以质疑腰子的风险判断
- 青山 可以质疑腰子的策略逻辑
- 玉夜 可以质疑腰子引用的数据
- 山猫 可以质疑腰子的市场阶段判断
- **但腰子做最终金融判断**。异议记录在案，不阻塞决策

### 4.3 不在时的代理

- 腰子不在时，阿黑代为接收支撑角色的输出，但不做金融判断
- 支撑角色不在时，腰子自行覆盖该领域（但标注"未经XX审核"）

## 五、质量保障

### 5.1 输出质量标准

所有角色输出必须满足：
1. 有来源标记（数据/判断/推测 三者区分）
2. 有逻辑链（结论→推理→证据）
3. 有不确定性说明（哪些是确定的，哪些需要更多信息）
4. 遵守规则红线（不编造数据、PE(TTM)用项目公式、1+2数据架构）

### 5.2 定期审查

| 审查项 | 频率 | 负责人 |
|:-------|:----|:------|
| 山猫 宏观简报质量 | 每周 | 腰子 |
| 玉夜 数据可信度 | 每日 | 腰子(盘前确认) |
| 流金 风险审计覆盖率 | 每次选股后 | 腰子 |
| 青山 IC报告及时性 | 每周 | 腰子 |
| 协作协议执行情况 | 每月 | 腰子+阿黑 |
