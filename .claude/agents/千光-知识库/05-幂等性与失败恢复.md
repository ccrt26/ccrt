# 05 — 幂等性与失败恢复

> **定位**：千光（构建工程师）本地知识库 —— 确保自动化流水线在出错时不会把事情搞得更糟
> **更新**：2026-05-23 | **关联文件**：01-CI流水线设计、02-定时任务编排、04-构建脚本规范

---

## 一、核心命题

### 1.1 失败是必然的

在每日自动化流水线中，以下失败场景必然会发生：

| 场景 | 发生概率 | 典型原因 |
|:-----|:------:|:--------|
| API超时 | 每周1-2次 | 东方财富/新浪API限流、网络波动 |
| 部分数据缺失 | 每周1次 | 某只股票停牌、某数据字段未更新 |
| 脚本中途崩溃 | 每月1-2次 | PowerShell内存/编码问题、文件锁冲突 |
| 磁盘空间不足 | 极少 | 日志堆积、PDF堆积 |
| 依赖版本冲突 | 极少 | Windows更新、Python/PowerShell升级 |

### 1.2 幂等性的定义

一个操作是幂等的，当且仅当：**执行1次和执行N次，结果完全相同**。

```
非幂等：每天生成一份新报告 → 重跑会生成两份报告
幂等：  每天生成当天日期的报告 → 重跑覆盖同名文件，结果不变
```

## 二、幂等设计模式

### 2.1 基于日期的天然幂等

当前项目中大部分脚本已经是日期驱动的，天然具有幂等性：

```powershell
# ✅ 幂等：按日期命名，同一天多次执行覆盖同名文件
$htmlFile = "拓普集团(601689)_20260522.html"
$pdfFile = "拓普集团(601689)分析报告__20260522.pdf"
$evalFile = "评估数据_20260522.json"

# ❌ 非幂等：追加式写入，每次执行增加新行
Add-Content transactions.csv "$date,$code,$name,BUY,..."
```

### 2.2 Append型操作的保护

对于**必须追加写入**的操作（如transactions.csv），需要添加防重机制：

```powershell
# 方案A：写入前检查（推荐）
function Add-Transaction {
    param($Date, $Code, $Action, $Price, $Shares)
    
    # 计算交易指纹（日期+代码+动作+价格+股数的hash）
    $fingerprint = "$Date|$Code|$Action|$Price|$Shares"
    $hash = [System.BitConverter]::ToString(
        [System.Security.Cryptography.SHA256]::Create().ComputeHash(
            [System.Text.Encoding]::UTF8.GetBytes($fingerprint)
        )
    )
    
    # 检查今天是否已有相同交易
    $todayTransactions = Get-Content $csvFile | Where-Object { $_ -like "$Date*$Code*$Action*" }
    if ($todayTransactions) {
        Write-Warning "交易已存在，跳过: $fingerprint"
        return
    }
    
    # 写入新交易
    "$date,$code,$name,$action,$price,$shares,..." | Add-Content $csvFile
}

# 方案B：先写临时文件，确认无重复后合并
```

### 2.3 文件覆盖 vs 文件追加

| 操作类型 | 安全方式 | 不安全的替代 |
|:--------|:--------|:-----------|
| 报告生成(HTML/PDF) | 覆盖写入同名文件 | ❌ 每次生成新文件名 |
| 交易流水 | 防重检查+追加 | ❌ 无条件追加 |
| 每日快照 | 覆盖写入同名文件 | ❌ 版本号递增 |
| 评估数据JSON | 覆盖写入(date驱动) | ❌ 追加到数组 |
| 缓存数据 | 覆盖写入 | ✅ 本来就是覆盖 |
| 日志文件 | 日期驱动文件名 | ❌ 单个日志文件无限追加 |

### 2.4 文件写入的安全序列

```powershell
# 安全写入模式：先写临时文件，验证后再替换目标
function SafeWrite-File {
    param($Content, $TargetPath)
    
    $tempFile = "$TargetPath.tmp.$(Get-Random)"
    
    try {
        # 1. 写入临时文件
        Set-Content $tempFile -Value $Content -Encoding UTF8
        
        # 2. 验证临时文件完整性（大小>0，编码正确）
        $tempSize = (Get-Item $tempFile).Length
        if ($tempSize -eq 0) { throw "写入失败：文件大小为0" }
        
        # 3. 原子替换（PowerShell中Rename最接近原子操作）
        if (Test-Path $TargetPath) { Remove-Item $TargetPath -Force }
        Rename-Item $tempFile $TargetPath -Force
        
    } catch {
        Write-Error "安全写入失败: $_"
        if (Test-Path $tempFile) { Remove-Item $tempFile -Force }
        throw
    }
}
```

## 三、失败检测与分类

### 3.1 失败三级分类

| 级别 | 定义 | 举例 | 响应策略 |
|:----|:-----|:-----|:--------|
| **P0 — 致命** | 核心流程无法完成，且无法降级 | 6只股票行情全部获取失败 | 立即告警、暂停后续流程 |
| **P1 — 可降级** | 某步骤失败但有替代方案 | 主API超时→备API可用 | 自动降级、继续流程、标记降级 |
| **P2 — 可跳过** | 非核心数据缺失，不影响主流程 | 某只股票研报获取失败 | 跳过该项、标注"数据不足"、继续 |

### 3.2 失败检测点

在 `daily_workflow.ps1` 和 `run_keystock_analysis.ps1` 中的关键检测点：

```
流水线阶段：
  [检测点1] 数据拉取 → 关键字段是否全部有值？
  [检测点2] 评分计算 → 综合分是否在0-100合理范围？
  [检测点3] 报告生成 → HTML文件是否成功写入且>10KB？
  [检测点4] PDF转换   → PDF文件是否成功写入且>MinSize？
  [检测点5] 评估数据   → JSON是否可解析？
  
  任一检测点失败 → 记录失败阶段 + 原因 → 决定是否继续
```

### 3.3 部分失败的决策矩阵

```
                    只影响1只股票          影响3-6只股票
                  
仅行情数据失败     继续(标注缺失)         暂停，人工检查
仅财务数据失败     继续(使用缓存)         继续(使用缓存)，标注
仅研报数据失败     继续(标注"无研报")      继续，标注
仅PDF转换失败     继续(保留HTML)          继续，告警
评分计算异常       跳过该股(标注)          暂停，检查评分引擎
HTML生成失败       跳过该股(标注)          暂停，检查模板
```

## 四、重试策略

### 4.1 退避策略

```powershell
function Invoke-WithRetry {
    param(
        [ScriptBlock]$ScriptBlock,
        [int]$MaxRetries = 3,
        [int]$BaseDelayMs = 2000
    )
    
    $attempt = 0
    while ($attempt -lt $MaxRetries) {
        $attempt++
        try {
            $result = & $ScriptBlock
            return $result  # 成功，直接返回
        } catch {
            Write-Warning "第${attempt}次尝试失败: $_"
            if ($attempt -eq $MaxRetries) {
                throw "重试${MaxRetries}次后仍失败: $_"
            }
            # 指数退避：2s → 4s → 8s
            $delay = $BaseDelayMs * [Math]::Pow(2, $attempt - 1)
            Start-Sleep -Milliseconds $delay
        }
    }
}
```

### 4.2 重试规则

| API/操作 | 最大重试 | 退避策略 | 重试间隔 | 备注 |
|:--------|:------:|:--------|:------:|:-----|
| 腾讯行情API | 3 | 线性 2s→4s→6s | 2s | 超时后再重试 |
| 新浪行情API | 2 | 线性 2s→4s | 2s | 仅作备源 |
| 东方财富财务 | 3 | 指数 2s→4s→8s | 2s | 易触发限流 |
| 同花顺THS(备) | 2 | 线性 3s→6s | 3s | 仅作备源 |
| PDF转换(Edge) | 2 | 线性 5s→10s | 5s | 第2次尝试不带扩展参数 |
| 文件写入 | 0(不重试) | N/A | N/A | 写入失败=环境问题，重试无意义 |

### 4.3 全局重试 vs 局部重试

```
❌ 错误做法：整个脚本重跑
$ .\run_keystock_analysis.ps1   # 第5只股票失败→重跑全部6只

✅ 正确做法：只重跑失败的部分
$ .\run_keystock_analysis.ps1 -Stocks @("000967")  # 只重跑盈峰环境
```

**建议**：所有分析脚本支持 `-Stocks` 参数，允许指定只处理部分股票。

## 五、状态一致性校验

### 5.1 流水线状态自检

每次脚本运行结束后，自动运行一致性校验：

```powershell
function Invoke-ConsistencyCheck {
    param($Date)
    
    $issues = @()
    
    # 检查1：HTML和PDF是否成对存在
    foreach ($stock in $stocks) {
        $html = Get-ReportPath $stock $Date "html"
        $pdf = Get-ReportPath $stock $Date "pdf"
        $htmlExists = Test-Path $html
        $pdfExists = Test-Path $pdf
        
        if ($htmlExists -and -not $pdfExists) {
            $issues += "PDF缺失: $($stock.Name) — HTML存在但PDF不存在"
        }
        if ($pdf.Size -lt 30000) {
            $issues += "PDF异常过小: $($stock.Name) — $($pdf.Size) bytes"
        }
    }
    
    # 检查2：评估数据JSON是否包含全部股票
    $eval = Get-Content "评估数据_${Date}.json" | ConvertFrom-Json
    if ($eval.Stocks.Count -ne 6) {
        $issues += "评估数据不完整: 预期6只，实际$($eval.Stocks.Count)只"
    }
    
    # 检查3：评分数据是否在合理范围
    foreach ($s in $eval.Stocks) {
        $score = $s.Scores.Composite
        if ($score -lt 0 -or $score -gt 100) {
            $issues += "评分异常: $($s.Name) 综合分=$score (应在0-100)"
        }
    }
    
    # 输出检查结果
    if ($issues.Count -eq 0) {
        Write-Host "✅ 一致性校验通过"
    } else {
        Write-Warning "⚠ 一致性校验发现 $($issues.Count) 个问题:"
        $issues | ForEach-Object { Write-Warning "  - $_" }
    }
    
    return @{ Passed = ($issues.Count -eq 0); Issues = $issues }
}
```

### 5.2 跨文件引用校验

| 校验规则 | 检查方式 |
|:--------|:--------|
| transaction.csv中的code必须出现在评估数据中 | 交叉比对 |
| positions.json中的持仓必须在6只重点股票范围内 | 硬编码白名单 |
| snapshot中的TotalValue = Cash + StockValue | 数值校验(容差±0.01) |
| eval数据中的日期必须与文件名日期一致 | 字符串比对 |

## 六、调度安全机制

### 6.1 防止重复执行

```powershell
# 基于锁文件的互斥机制
$lockFile = Join-Path $env:TEMP "keystock_analysis_$dateStr.lock"

if (Test-Path $lockFile) {
    $lockAge = (Get-Date) - (Get-Item $lockFile).LastWriteTime
    if ($lockAge.TotalMinutes -lt 30) {
        Write-Warning "脚本正在运行中(锁文件$lockAge前创建)，跳过本次执行"
        exit 0
    } else {
        Write-Warning "锁文件超过30分钟，可能上次执行崩溃，强制继续"
        Remove-Item $lockFile -Force
    }
}

# 创建锁文件
New-Item $lockFile -ItemType File -Force | Out-Null

try {
    # ... 主流程 ...
} finally {
    # 无论成功失败，清理锁文件
    if (Test-Path $lockFile) { Remove-Item $lockFile -Force }
}
```

### 6.2 失败后的自动恢复

```
调度器(cron/任务计划)触发
    │
    ▼
检查锁文件 → 已存在且新鲜 → 跳过
    │
    ▼
检查上次执行状态
    │
    ├── 上次成功 → 正常执行
    │
    ├── 上次部分失败 → 只执行失败部分(-Stocks参数)
    │
    └── 上次完全失败 → 告警，人工介入
```
