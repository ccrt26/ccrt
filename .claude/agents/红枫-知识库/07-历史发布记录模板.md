## 一、发布记录模板

```
【发布 #YYYYMMDD-NN】

版本信息：
  发布版本号：[语义版本号]
  发布日期：[YYYY-MM-DD]
  发布类型：[新功能/修复/优化/回滚]
  关联PR/Commit：[链接/hash]

变更内容：
  - [变更项1] (涉及文件/模块)
  - [变更项2]

灰度方案：
  灰度范围：[时间窗口/用户比例/股票范围]
  灰度开始：[YYYY-MM-DD HH:MM]
  灰度时长：[X小时/X天]
  监控指标：[API成功率/报告生成时间/评分一致性]

回滚方案：
  触发条件：[具体条件+阈值]
  回滚步骤：[命令+步骤]
  回滚验证：[验证方式]

发布结果：
  状态：[成功/部分成功/失败/已回滚]
  灰度期间异常：[有/无——具体描述]
  全量上线时间：[YYYY-MM-DD HH:MM]

后续追踪：
  24小时验证：[通过/未通过]
  72小时验证：[通过/未通过]
  关联事件：[编号]
```

```
【发布前 — 闸门3检查清单】

闸门状态：
[ ] 闸门2 PASS（新安四层验证全部通过）
[ ] 无未关闭的B0/B1缺陷

灰度方案：
[ ] 灰度范围已定义(时间/范围)
[ ] 监控指标已配置

回滚方案：
[ ] 回滚触发条件已明确

[ ] 备份已验证(最近备份完整)

上线：
[ ] 闸门3判定：PASS

```

---

## 四、回滚触发条件(标准)

| 条件 | 动作 | 级别 |
|:-----|:-----|:----:|
| 评分引擎结果与Golden Master偏离>5% | 暂停灰度→回溯 | P1 |
| API调用失败率>10%且持续>30分钟 | 回滚至上一版本 | P1 |
| 新报告格式错误(乱码/数据错误) | 回滚报告模块 | P0 |
| 缓存系统故障导致数据全空 | 回滚+恢复缓存 | P1 |
| 连续2次P1/P0告警 | 全量回滚 | P0 |

---

## 五、维护规则

- 每次发布(含灰度→全量)即时填写记录
- 发布后24h/72h更新验证结果
- 回滚后的发布记录标注"已回滚"+原因
- 每季度统计发布成功率(成功/部分成功/失败/回滚比例)
