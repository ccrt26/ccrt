# 03 — 开机审计与调度策略

> **定位**：Gauge（审计官）知识库 —— 机器不是每天都开机，审计不能因为断了一天就永远跳过
> **关联**：01-审计框架与方法 → 02-红线审计标准 → **03-开机审计策略**

---

## 一、问题场景

### 1.1 典型场景

```
周一开机 → 日检执行 ✓
周二关机 → 日检错过 ✗
周三关机 → 日检错过 ✗
周四开机 → 审计系统检查发现：
  - 上次日检是周一
  - 已经跳过2天
  - 如果已过周日，还需要补周检
```

### 1.2 核心需求

1. **开机自动触发**：不需要用户手动运行审计
2. **智能补齐**：根据距离上次审计的天数，自动决定审计深度
3. **不重复执行**：如果当日已审计过，不浪费时间再跑
4. **交易日感知**：非交易日降低审计优先级（但仍执行基础检查）

## 二、开机审计决策树

```
系统启动
    │
    ▼
  audit_on_boot.ps1 (AT STARTUP 触发)
    │
    ▼
  检查: 今天是否已执行过日检？
    │ (检查 audit_boot_summary.json 或 最新 audit_report 时间戳)
    │
    ├── 是 → 跳过，exit 0
    │
    └── 否 → 继续判断
            │
            计算: 上次审计距今多少天？
            │
            ├── 0-1天 → 执行日检 (Quick: Section A子集 + F + G)
            │
            ├── 2-6天 → 执行日检 + 补齐检查
            │         (如果跳过的日子里包含周日，追加周检)
            │
            └── ≥7天 → 执行完整周检 (Section A~G)
                      (如果跨月且上月月检未执行，追加月度深度)
```

### 2.1 审计级别定义

| 级别 | 触发条件 | 内容 | 耗时 |
|:----:|:--------|:-----|:---:|
| **SKIP** | 今日已审计 | 无 | 0s |
| **QUICK** | 上次审计在2天内 | Section A子集 + F + G | ~5s |
| **CATCHUP** | 上次审计2-6天前 | Quick + 补齐错过的日检 | ~10s |
| **FULL** | 上次审计≥7天 或 跨周日 | Section A~G 全部 | ~30s |
| **DEEP** | 跨月且月检未执行 | FULL + 第一级目标对齐 | ~60s |

### 2.2 交易日感知

```
if (非交易日):
    审计要求降低：
    - 不检查"今日流水线是否执行"（非交易日无需执行）
    - 不检查"今日数据是否更新"（非交易日无新数据）
    - 仍检查：缓存健康、编码健康、文件卫生、上次审计遗留问题
else (交易日):
    全量按级别执行
```

## 三、Windows Task Scheduler 注册

### 3.1 AT STARTUP 触发器

```powershell
# 注册开机审计任务（需管理员权限）
schtasks /CREATE /SC ONSTART `
  /TN "TieLv-BootAudit" `
  /TR "powershell.exe -NoProfile -ExecutionPolicy Bypass -File `"C:\Users\34269\Documents\Claude\股票分析\代码文件\监督机制\audit_on_boot.ps1`"" `
  /RL HIGHEST `
  /F
```

### 3.2 任务验证

```powershell
# 查看已注册任务
schtasks /QUERY /TN "TieLv-BootAudit" /FO LIST

# 手动触发测试
schtasks /RUN /TN "TieLv-BootAudit"

# 查看上次运行结果
schtasks /QUERY /TN "TieLv-BootAudit" /FO LIST | Select-String "Last"
```

### 3.3 与现有任务共存

Gauge 开机审计是**补充**，不是替代：

| 任务 | 触发 | 用途 | 关系 |
|:-----|:-----|:-----|:-----|
| TieLv-Evaluation | 每日19:00 | 后评估 | 独立定时 |
| TieLv-DailyStock | 每日20:00 | 每日荐股 | 独立定时 |
| TieLv-MonthlySummary | 每月1日09:00 | 月度汇总 | 独立定时 |
| **TieLv-BootAudit** | **系统启动** | **补齐遗漏审计** | **新增** |

- 如果机器在定时任务时间点恰好开着 → 定时任务正常执行
- 如果机器在定时任务时间点关机 → 开机审计检测到遗漏，自动补齐
- 两者不冲突：开机审计会检查当日是否已有审计记录

## 四、审计状态追踪

### 4.1 状态文件

开机审计通过两个文件追踪状态：

| 文件 | 位置 | 内容 |
|:-----|:-----|:-----|
| `audit_boot_summary.json` | `历史数据/` | 最近一次开机审计的摘要（类型/时间/评级） |
| `audit_report_YYYYMMDD.json` | `历史数据/` | 每次审计的完整报告（由run_full_audit.ps1生成） |

### 4.2 判断逻辑

```
读取 audit_boot_summary.json
    ├── 不存在 → 从未审计过，执行首次审计
    ├── 存在 & 日期=今天 → 今日已审计，跳过
    └── 存在 & 日期<今天 → 计算日期间隔，决定审计级别
```

### 4.3 审计日志

所有开机审计行为记录到 `代码文件/监督机制/audit_boot.log`，包含：
- 启动时间、计算机名
- 交易日判断结果
- 审计级别决策过程
- 每个检查项的PASS/WARN/FAIL
- 最终结论

## 五、与Gauge角色协作

### 5.1 开机审计 → Gauge 工作流

```
audit_on_boot.ps1 执行完毕
    │
    ├── PASS (exit 0) → 无异常，Gauge记录状态
    │
    ├── WARN (exit 0, 但有warn) → Gauge下次被召唤时提醒
    │
    └── FAIL (exit 1) → Gauge主动汇报给阿黑
        "开机审计发现X个FAIL需要处理：[列表]"
```

### 5.2 Gauge角色下次被召唤时

```
Gauge被召唤 → 首先检查：
  1. 读取 audit_boot_summary.json
  2. 读取最新 audit_report_YYYYMMDD.json
  3. 汇报自上次召唤以来的审计发现
  4. 追踪上次FAIL是否已修复
```

## 六、边界与限制

### 6.1 不做什么

- **不自动修复**：开机审计只检查，不修改任何文件
- **不阻塞启动**：审计在后台运行，不影响用户操作
- **不消耗大量资源**：Quick模式<5秒，FULL模式<30秒
- **不在非交易日跑完整流水线**：不会因为没有日检记录就在非交易日触发交易分析

### 6.2 依赖

- `is_market_open.ps1` — 交易日判断
- `check_redlines.ps1` — 红线合规检查（Section G）
- `version_supervisor.ps1` — 版本一致性检查（Section G）
- `check_report_style.ps1` — 报告样式检查（Section G）
- `holidays_2026.csv` — 节假日数据

### 6.3 如果依赖脚本不存在

开机审计脚本对每个依赖进行存在性检查，缺失时标记WARN而非FAIL，不阻断审计流程。

> **Gauge注**：开机审计是审计体系的"守门员"——确保审计不会因为一天没开机就被永远跳过。机器可以休假，审计不能。
