## 二、全局纪律（所有API通用）

```
1. 单次请求间隔 ≥ 0.3s（红线硬性规定）
2. 每10次请求后强制休息 2s
3. 财务数据[3][4]每7天拉取一次（禁止每日全量刷新）
4. 批量请求分批执行，每批间休息3-5s
5. 单个股票的数据拉取合并为一次批量请求（不逐个请求）
6. 使用缓存[C]兜底，避免重复请求相同数据
```

## 三、降级触发条件

| 条件 | 动作 | 恢复条件 |
|:-----|:-----|:--------|
| 主源连续3次超时 | 切换备源[B] | 主源恢复响应且稳定5分钟后切回 |
| 主源返回HTTP 429/403 | 立即切换备源[B] | 等待30分钟后重试主源 |
| 备源也失败 | 切换缓存[C] | 下次巡检时重试主+备 |
| 单日请求量触及80%日限额 | 降速至原间隔×2 | 次日重置 |
| IP被封 | 全切缓存[C]，标记告警 | 等待恢复时间后自动重试 |

## 四、财务数据特殊规则

```
财务数据[3][4]每7天拉取一次
  原因：财报数据不会每日变化，高频拉取无意义且易封IP
  例外：财报季(3-4月、8-10月)可缩短为每3天一次
  触发时机：每周一开盘前自动刷新
  检查点：玉夜每周巡检时验证财务数据新鲜度(≤7天)
```

---

## 五、多股票批量拉取规范

```
选股池N只股票的批量拉取顺序：
1. 行情数据[1][2]：一批最多10只，间隔0.5s/只
2. K线数据[2]：一批最多5只，间隔1s/只（量大）
3. 财务数据[3]：仅拉取缓存过期(>7天)的股票
4. 资金数据[9][12]：一批最多5只，间隔1s/只
5. 板块数据[7]：一次性拉取（数据量小）
```

---

## 六、维护规则

- 玉夜每次巡检后更新各源实际延迟和可用率
- 若某源连续3天降级，触发玉夜告警→通知腰子+阿黑
- 新增数据源时同步更新本表
- API变更(限流策略调整)后24小时内更新本表
