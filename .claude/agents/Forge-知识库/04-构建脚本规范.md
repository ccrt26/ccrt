## 一、PowerShell脚本入口规范

### 1.1 完整的脚本骨架

```powershell
<#
.SYNOPSIS
    {一句话描述脚本功能}
.DESCRIPTION
    {详细描述，含上下文和使用场景}
.PARAMETER Param1
    {参数说明}
.PARAMETER Param2
    {参数说明}
.EXAMPLE
    {使用示例}
.NOTES
    版本: v1.0
    数据源: [主源编号] / [备源编号]
    关联白皮书: {白皮书名称} vX.Y
    作者: {铁律量化·工程团队}
#>

[CmdletBinding()]
param(
    [Parameter(Mandatory = $true)]
    [string]$RequiredParam,

    [Parameter(Mandatory = $false)]
    [string]$OptionalParam = "default",

    [switch]$Force,       # 覆盖已有文件
    [switch]$Verbose,     # 详细输出
    [switch]$DryRun       # 试运行（不写文件）
)

# === 强制声明（所有脚本必备） ===
$ErrorActionPreference = "Stop"
$ProgressPreference = "SilentlyContinue"
$OutputEncoding = [System.Text.Encoding]::UTF8

# === 路径初始化 ===
$ScriptRoot = $PSScriptRoot  # 脚本所在目录
if (-not $ScriptRoot) {
    $ScriptRoot = Split-Path -Parent $PSCommandPath
}
$ProjectRoot = Resolve-Path (Join-Path $ScriptRoot "{RELATIVE_PATH_TO_PROJECT_ROOT}")

# === 日志初始化 ===
$LogDir = Join-Path $ProjectRoot "{LOG_DIR}"
if (-not (Test-Path $LogDir)) {
    New-Item -ItemType Directory -Path $LogDir -Force | Out-Null
}
$ScriptName = [System.IO.Path]::GetFileNameWithoutExtension($PSCommandPath)
$LogFile = Join-Path $LogDir ("${ScriptName}_$(Get-Date -Format 'yyyyMM').log")

function Write-Log([string]$Msg, [string]$Level = "INFO") {
    $time = Get-Date -Format "yyyy-MM-dd HH:mm:ss"
    $line = "[$time][$Level] $Msg"
    Write-Host $line
    Add-Content -Path $LogFile -Value $line -Encoding UTF8
}

# === 参数验证 ===
if (-not (Test-Path $RequiredParam -PathType Leaf)) {
    Write-Log "Required file not found: $RequiredParam" -Level "ERROR"
    exit 2  # 数据错误
}

# === 主逻辑 ===
try {
    Write-Log "===== {SCRIPT_NAME} 开始 ====="

    # TODO: {MAIN_LOGIC}

    Write-Log "===== {SCRIPT_NAME} 完成 ====="
    exit 0
}
catch {
    Write-Log "异常: $_" -Level "ERROR"
    Write-Log "堆栈: $($_.ScriptStackTrace)" -Level "ERROR"
    exit 1
}
```

### 1.2 当前项目脚本对照检查

以 `daily_workflow.ps1` 为例，检查已有脚本的合规性：

| 检查项 | daily_workflow.ps1 | version_supervisor.ps1 | pre-commit-check.ps1 |
|:-------|:------------------:|:--------------------:|:-------------------:|
| `.SYNOPSIS` | 有 | 有 | 有 |
| `.DESCRIPTION` | 有 | 有 | 有 |
| `.PARAMETER` | 有（多参数） | 有 | 无（无参数） |
| `.EXAMPLE` | 有 | 无（缺失） | 无（无参数） |
| `.NOTES` | 有 | 有 | 无（缺失） |
| `[CmdletBinding()]` | 无（缺失） | 无（缺失） | 无（缺失） |
| `$ErrorActionPreference = "Stop"` | 无（缺失） | 无（缺失） | 有 |
| `exit 0` | 有 | 无（缺失） | 有 |

**需要补齐的项**（按优先级）：
1. 所有脚本添加 `$ErrorActionPreference = "Stop"`—防止错误被静默吞掉
2. 带参数的脚本添加 `[CmdletBinding()]`—启用 -Verbose/-Debug 通用参数
3. 主脚本添加 `exit` 退出码

### 1.3 Path处理规范

```powershell
# ✅ 正确：使用 Join-Path + PSScriptRoot
$dataFile = Join-Path $PSScriptRoot "..\data\quotes.json"
$dataFile = Join-Path $PSScriptRoot "..\..\data_cache\sectors.json"

# ✅ 正确：Resolve-Path 并处理不存在
if (Test-Path $relativePath) {
    $absPath = Resolve-Path $relativePath
}

# ❌ 错误：硬编码绝对路径
$dataFile = "C:\Users\34269\Documents\Claude\股票分析\data\quotes.json"  # 禁止

# ❌ 错误：手动拼接路径分隔符

```


## 二、Python脚本入口规范

### 2.1 完整的脚本骨架

```python
"""
{SCRIPT_NAME}.py — {一句话描述}

{详细描述，含上下文和使用场景}

数据源: [主源编号] / [备源编号]
关联白皮书: {白皮书名称} vX.Y
版本: v1.0
"""

import argparse
import sys
import logging
from pathlib import Path
from datetime import datetime

# === 日志初始化 ===
def setup_logger(script_name: str, log_dir: Path) -> logging.Logger:
    logger = logging.getLogger(script_name)
    logger.setLevel(logging.DEBUG)
    log_file = log_dir / f"{script_name}_{datetime.now().strftime('%Y%m')}.log"
    fh = logging.FileHandler(log_file, encoding='utf-8')
    fh.setLevel(logging.DEBUG)
    ch = logging.StreamHandler()
    ch.setLevel(logging.INFO)
    formatter = logging.Formatter(
        '[%(asctime)s][%(levelname)s] %(message)s',
        datefmt='%Y-%m-%d %H:%M:%S'
    )
    fh.setFormatter(formatter)
    ch.setFormatter(formatter)
    logger.addHandler(fh)
    logger.addHandler(ch)
    return logger


def main():
    parser = argparse.ArgumentParser(
        description="{SCRIPT_DESCRIPTION}"
    )
    parser.add_argument(
        '-i', '--input',
        required=True,
        help='输入文件路径'
    )
    parser.add_argument(
        '-o', '--output',
        default=None,
        help='输出文件路径（默认：输入文件名_out.json）'
    )
    parser.add_argument(
        '-v', '--verbose',
        action='store_true',
        help='详细调试输出'
    )
    parser.add_argument(
        '-f', '--force',
        action='store_true',
        help='覆盖已有输出文件'
    )
    parser.add_argument(
        '--dry-run',
        action='store_true',
        help='试运行（不写入文件）'
    )
    parser.add_argument(
        '--timeout',
        type=int,
        default=300,
        help='超时秒数（默认300）'
    )

    args = parser.parse_args()

    # === 路径初始化 ===
    script_dir = Path(__file__).resolve().parent
    project_root = script_dir / ".." / ".."  # 根据需要调整
    log_dir = project_root / "{LOG_DIR}"
    log_dir.mkdir(parents=True, exist_ok=True)

    script_name = Path(__file__).stem
    logger = setup_logger(script_name, log_dir)

    if args.verbose:
        logger.setLevel(logging.DEBUG)

    # === 参数验证 ===
    input_path = Path(args.input)
    if not input_path.exists():
        logger.error(f"输入文件不存在: {input_path}")
        sys.exit(2)  # 数据错误

    # === 主逻辑 ===
    try:
        logger.info(f"===== {script_name} 开始 =====")

        # TODO: {MAIN_LOGIC}

        logger.info(f"===== {script_name} 完成 =====")
        sys.exit(0)

    except KeyboardInterrupt:
        logger.warning("用户中断")
        sys.exit(130)
    except Exception as e:
        logger.exception(f"未预期的异常: {e}")
        sys.exit(1)


if __name__ == "__main__":
    main()
```

## 三、统一参数约定

### 3.1 跨语言通用参数

| 参数 | PS形式 | Python形式 | 含义 |
|:-----|:------|:----------|:-----|
| 输入路径 | `-Path <string>` | `-i / --input` | 输入文件或目录路径 |
| 输出路径 | `-Output <string>` | `-o / --output` | 输出文件路径 |
| 详细输出 | `-Verbose` (switch) | `-v / --verbose` | 启用调试级日志 |
| 强制覆盖 | `-Force` (switch) | `-f / --force` | 覆盖已有文件不提示 |
| 试运行 | `-DryRun` (switch) | `--dry-run` | 只读不写 |
| 目标日期 | `-Date <string>` | `--date` | 格式 yyyy-MM-dd |
| 超时 | `-TimeoutSec <int>` | `--timeout` | 超时秒数 |

### 3.2 项目特有参数

| 参数 | 含义 | 出现脚本 | 示例 |
|:-----|:-----|:--------|:-----|
| `-Mode` | 运行模式 | daily_workflow.ps1 | daily / eval / daily_latest |
| `-SkipMarketCheck` | 跳过交易日检测 | daily_workflow.ps1 | switch |

| `-CrossCheck` | 交叉检查模式 | version_supervisor.ps1 | switch |

| `-Uninstall` | 卸载模式 | setup_scheduler.ps1 / register_tasks.ps1 | switch |

## 四、退出码约定

### 4.1 标准退出码

| 退出码 | 含义 | 何时使用 | 流水线行为 |
|:-----:|:-----|:--------|:----------|
| 0 | 成功 | 正常完成 | 进入下一步 |
| 1 | 通用错误/运行时异常 | 未预期的异常 | 根据上下文决定：重试/跳过/中断 |
| 2 | 数据错误 | 输入文件不存在/格式错误/数据缺失 | 检查数据源，不重试 |
| 3 | API错误 | API不可用/超时/返回异常 | 切换备源或标记P1 |
| 4 | 配置错误 | 缺少必要配置/参数无效 | 人工介入 |
| 5 | 红线检查失败 | pre-commit检查不通过 | 阻塞操作 |
| 6 | 交易日跳过 | 非交易日正常跳过 | 不视为错误 |
| 130 | 用户中断 | Ctrl+C | 清理并退出 |

### 4.2 实际使用示例

```powershell
# daily_workflow.ps1 中的退出码使用
if (-not $SkipMarketCheck) {
    $result = & $marketCheckScript -Date $Date -HolidayFile $holidayFile
    if ($LASTEXITCODE -ne 0) {
        Write-Log "$Date is not a trading day, skip" -Level "SKIP"
        exit 0  # 非交易日：视为正常，exit 0
    }
}

# 脚本调用后检查退出码
& $evalScript -ReportDate $reportDateStr
if ($LASTEXITCODE -ne 0) {
    Write-Log "Evaluation script failed (exit: $LASTEXITCODE)" -Level "ERROR"
    # 不退出，继续执行后续步骤
}
```

### 4.3 Python退出码

```python
import sys

# 成功
sys.exit(0)

# 数据错误
sys.exit(2)

# API错误
sys.exit(3)

# 配置错误
sys.exit(4)

# 用户中断
sys.exit(130)
```

## 五、日志输出约定

### 5.1 三层日志模型

| 层级 | PowerShell | Python | 用途 | 目标受众 |
|:---:|:----------|:-------|:-----|:--------|
| UI层 | `Write-Host` | `print()` / `logging.info` | 用户可见的进度信息 | 操作者 |
| 调试层 | `Write-Verbose` | `logging.debug` | 开发者诊断信息 | 开发者 |
| 日志层 | `Write-Log` (自定义) / `Add-Content` | `logging.FileHandler` | 持久化审计记录 | 审计/回溯 |

### 5.2 日志级别使用规范

```powershell
# PowerShell
Write-Log -Level "INFO"  -Msg "评分引擎启动，目标股票数: 50"
Write-Log -Level "WARN"  -Msg "备源API响应慢 (3.2s > 阈值3.0s)"
Write-Log -Level "ERROR" -Msg "主源API不可用: 连接超时"
Write-Log -Level "SKIP"  -Msg "2026-05-24 非交易日，跳过"
Write-Log -Level "DEBUG" -Msg "缓存命中率: 85% (17/20)"

# Python
logger.info("评分引擎启动，目标股票数: 50")
logger.warning("备源API响应慢 (3.2s > 阈值3.0s)")
logger.error("主源API不可用: 连接超时")
logger.debug("缓存命中率: 85% (17/20)")
```

### 5.3 日志格式约定

所有脚本必须使用统一的时间戳格式：
```
[2026-05-23 19:00:01][INFO] 评分引擎启动，目标股票数: 50
[2026-05-23 19:00:05][WARN] 备源API响应慢 (3.2s > 阈值3.0s)
[2026-05-23 19:00:10][ERROR] 主源API不可用: 连接超时
[2026-05-23 19:00:15][SKIP] 2026-05-24 非交易日，跳过
```

日志文件按月份分文件，避免单个文件过大：
```
{script_name}_202605.log
{script_name}_202606.log
```

### 5.4 关键日志事件

每个脚本至少记录以下事件：

```
[INFO]  ===== {SCRIPT_NAME} 开始 =====
[INFO]  参数: -Mode daily -Date 2026-05-23
[INFO]  阶段1/N: {PHASE_NAME}
[INFO]  阶段2/N: {PHASE_NAME}
...
[ERROR] 阶段X/N 失败: {REASON}
[INFO]  耗时: 45.3s
[INFO]  ===== {SCRIPT_NAME} 完成 =====
```

## 六、脚本间调用规范

### 6.1 PowerShell调用PowerShell

```powershell
# ✅ 方式一：& 操作符（推荐）
$script = Join-Path $scriptsDir "build_dynamic_pool.ps1"
& $script -Date $Date
if ($LASTEXITCODE -ne 0) {
    Write-Log "build_dynamic_pool failed (exit: $LASTEXITCODE)" -Level "ERROR"
}

# ✅ 方式二：点号调用（加载函数到当前作用域）
. $script  # 谨慎使用，会污染当前作用域

# ❌ 禁止：Invoke-Expression（安全风险）
Invoke-Expression "$script -Date $Date"  # 禁止

# ❌ 禁止：Start-Process（无法获取输出和退出码）
Start-Process powershell -ArgumentList "-File $script"  # 禁止
```

### 6.2 跨语言调用（PS调用Python）

```powershell
# ✅ 方式一：直接调用（推荐）
python $pythonScript $args 2>&1 | ForEach-Object { Write-Log -Msg $_ }
if ($LASTEXITCODE -ne 0) {
    Write-Log "Python script failed (exit: $LASTEXITCODE)" -Level "ERROR"
}

# ✅ 方式二：指定完整路径
$pythonExe = (Get-Command python -ErrorAction Stop).Source
& $pythonExe $pythonScript --date $Date
```

### 6.3 参数传递规范

```powershell
# 调用方
$params = @{
    Date     = $Date
    Verbose  = $true
    Force    = $true
}
& $script @params  # splatting

# 被调用方
param(
    [string]$Date,
    [switch]$Verbose,
    [switch]$Force
)
```

### 6.4 错误传播

```powershell
# ✅ 正确：检查 $LASTEXITCODE
& $externalTool
if ($LASTEXITCODE -ne 0) {
    throw "External tool failed with exit code $LASTEXITCODE"
}

# ✅ 正确：使用 $ErrorActionPreference = "Stop"
try {
    & $script @params
} catch {
    Write-Log "Script failed: $_" -Level "ERROR"
}

# ❌ 错误：不检查退出码
& $externalTool  # 失败了也继续执行
# ...
```

## 七、临时文件管理

### 7.1 临时文件路径

| 类型 | 路径 | 命名规则 | 生命周期 |
|:-----|:-----|:--------|:--------|
| 原子写入 | 同目录 `.tmp` 后缀 | `{filename}.tmp` | 写入完成后立即rename为正式文件 |
| 中间数据 | `data_cache/tmp/` | `{script}_{timestamp}.json` | 脚本结束时清理 |
| 日志 | `{log_dir}/` | `{script}_YYYYMM.log` | 永久保留 |
| 锁文件 | `{lock_dir}/` | `{task_name}.lock` | 任务结束时删除 |

### 7.2 临时文件清理

```powershell
# === 脚本内清理 ===
$tempFiles = @()

try {
    $tmp = New-TemporaryFile
    $tempFiles += $tmp
    # ... 使用临时文件 ...
}
finally {
    foreach ($f in $tempFiles) {
        Remove-Item $f -ErrorAction SilentlyContinue
    }
}

# === 定期清理脚本（每周运行一次）===
# 清理 data_cache/tmp/ 中超过24小时的临时文件
$tmpDir = "data_cache/tmp"
if (Test-Path $tmpDir) {
    Get-ChildItem $tmpDir -File |
        Where-Object { (Get-Date) - $_.LastWriteTime -gt [TimeSpan]::FromHours(24) } |
        Remove-Item -Force
}
```

### 7.3 原子写入模式（防止写入中断损坏文件）

```powershell
# 所有重要数据的写入必须使用原子模式
$tmpPath = "$targetPath.tmp"
try {
    # 写入临时文件
    $json | Set-Content $tmpPath -Encoding UTF8
    # 原子替换（Windows上Move-Item覆盖是原子的）
    Move-Item $tmpPath $targetPath -Force
} catch {
    Remove-Item $tmpPath -ErrorAction SilentlyContinue
    throw
}
```

## 八、脚本元数据规范

### 8.1 注释帮助块（Comment-Based Help）

所有 .ps1 脚本必须包含最小元数据集：

```powershell
<#
.SYNOPSIS
    {一句话，不超过80字符}
.DESCRIPTION
    {详细描述，可以多段。说明脚本在整体流水线中的位置。}
.PARAMETER Param1
    {参数1的说明，含默认值和有效值范围}
.EXAMPLE
    .\script.ps1 -Mode daily -Date "2026-05-23"
.EXAMPLE
    .\script.ps1 -Mode eval -SkipMarketCheck
.NOTES
    版本: v1.0
    依赖: Python 3.10+ / PSScriptAnalyzer
    数据源: [1]腾讯行情 / [3]东方财富财务
    关联白皮书: 每日荐股分析逻辑白皮书 v2.4
    红线依据: §1.1 数据源1+2架构 / §3.2 API调用间隔>=0.3s
#>
```

### 8.2 检查清单（Forge审查用）

审查任一脚本时，逐项确认：

**PowerShell脚本**：
- [ ] `$ErrorActionPreference = "Stop"` 已声明
- [ ] `$OutputEncoding = [System.Text.Encoding]::UTF8` 已声明
- [ ] 路径使用 `Join-Path` + `$PSScriptRoot`（不硬编码）
- [ ] 文件读写显式指定 `-Encoding UTF8`
- [ ] 所有外部调用检查 `$LASTEXITCODE`
- [ ] `exit N` 明确指定退出码
- [ ] 关键步骤有时间戳日志
- [ ] `<# .SYNOPSIS #>` 帮助块完整

**Python脚本**：
- [ ] `if __name__ == "__main__"` 入口
- [ ] 所有文件操作使用 `encoding='utf-8'`
- [ ] 路径使用 `pathlib.Path`（不硬编码）
- [ ] 异常有 `logger.exception()` 记录
- [ ] `sys.exit(code)` 明确指定退出码
- [ ] `argparse` 参数有 `help` 说明

### 8.3 脚本健康度标记

在脚本文件末尾添加健康度注释（可选，供Forge巡检扫描）：

```powershell
# @HEALTH: OK | 最后审查: 2026-05-23 | 审查人: Forge | 模板合规: 8/8
```

## 九、与项目工具链的集成

### 9.1 version_supervisor.ps1 会检查的项

- 文件名版本号 vs 内部版本声明一致性
- .md ↔ .docx 同步状态
- 版本历史表顺序
- CHANGELOG 版本倒序

Forge需确保：新创建的 .ps1 脚本如有版本号，必须内外一致。

### 9.2 pre-commit-check.ps1 会检查的项

- 版本一致性（如文件名含 _vX.Y）
- 垃圾文件检测
- .md ↔ .docx 同步
- Commit message 格式

Forge需确保：模板生成的脚本不会触发垃圾文件检测（无 .tmp / null / temp 文件进staging）。

### 9.3 check_redlines.ps1 会检查的项

- 数据源编号引用是否正确
- 是否有编造数据嫌疑
- API调用间隔是否符合>=0.3s

Forge需确保：生成的代码中的API调用加了限流延迟。
