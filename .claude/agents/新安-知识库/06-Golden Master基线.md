# Golden Master 基线 — 新安质量工程师

> 版本 v1.0 | 生效日期 2026-05-24
> 用途：引擎变更后的回归基准——5个代表性交易日快照的存储位置和比对方法

---

## 一、Golden Master 概念

Golden Master是评分引擎在5个代表性交易日的完整输出快照。每次引擎变更后，用新引擎重新运行这5天，结果必须与原Golden Master完全一致（评分/排序/否决/相位四项），否则=FAIL。

---

## 二、5个代表性交易日

| 编号 | 日期 | 市场状态 | 选择理由 |
|:----:|:-----|:--------|:--------|
| GM-01 | 待选定 | 牛市上涨日 | 验证上升市场评分逻辑 |
| GM-02 | 待选定 | 熊市下跌日 | 验证下跌市场否决逻辑 |
| GM-03 | 待选定 | 震荡上穿日均线 | 验证均线突破信号 |
| GM-04 | 待选定 | 财报季窗口 | 验证财务数据更新逻辑 |
| GM-05 | 待选定 | 极端波动日(涨跌停>100家) | 验证极端市场边界处理 |

> 具体交易日待评分引擎首次稳定运行后选定。选股池覆盖至少50只股票。

---

## 三、快照格式

每个Golden Master快照包含以下文件：

```
历史数据/golden_master/
├── GM-01_YYYY-MM-DD/
│   ├── input_snapshot.json      # 输入数据快照(行情/财务/K线)
│   ├── scores.json              # 评分输出(每只股票的六维评分)
│   ├── ranking.json             # 排序结果(最终选股排序)
│   ├── veto_log.json            # 否决日志(每只股票的否决检查)
│   ├── phase_labels.json        # 相位标签(板块/题材分类)
│   └── summary.txt              # 摘要(日期/选股数/否决数/通过数)
├── GM-02_YYYY-MM-DD/
│   └── ...
└── README.md                    # 本说明
```

## 四、比对方法

### 4.1 自动比对脚本（新安/红结协作实现）

```python
# compare_golden_master.py — Golden Master比对脚本
"""
执行引擎变更后的Golden Master比对。
用法: python compare_golden_master.py <new_output_dir> <golden_master_dir>

比对内容:
  1. scores.json — 评分值逐项diff (容差: float ±0.01)
  2. ranking.json — 排序位置完全一致
  3. veto_log.json — 否决判定完全一致(无Y/N差异)
  4. phase_labels.json — 相位标签完全一致

输出: PASS(4项一致) 或 FAIL(列出差异项+差异股票+差异值)
"""
```

### 4.2 手动比对步骤

1. 用新引擎重跑GM-01~GM-05的输入数据
2. 对每个GM日：
   - 打开 `scores.json`：逐股票比对评分值（允许浮点±0.01差异）
   - 打开 `ranking.json`：确认排序位置无变化
   - 打开 `veto_log.json`：确认否决判定无变化
   - 打开 `phase_labels.json`：确认板块相位无变化
3. 5个GM日全部PASS → 引擎变更通过
4. 任一GM日任一维度FAIL → 引擎变更不合格，打回红结

## 五、Golden Master更新时机

| 场景 | 动作 |
|:-----|:-----|
| 评分公式变更(权重/因子参数) | **必须更新**所有5个GM快照 |
| 否决阈值变更 | **必须更新**所有5个GM快照 |
| 数据源切换(API A→B) | **必须更新**(可能产生系统性差异) |
| 仅日志/注释修改 | 不更新(无逻辑变更) |
| 新增因子(不影响现有因子) | **必须更新**(评分值变化) |

---

## 六、GM快照生成流程

1. 评分引擎稳定运行≥1个月
2. 新安选定5个代表性交易日
3. 红结运行引擎→输出快照
4. 新安逐项验证快照合理性(评分/排序/否决无逻辑矛盾)
5. 新安+腰子共同签署确认
6. 存档至 `历史数据/golden_master/`
7. 纳入 `version_supervisor.ps1` 检查范围

---

## 七、维护规则

- 新安在每次引擎变更后运行Golden Master比对
- GM快照随评分逻辑重大变更更新
- 存量GM快照保留至少2个版本(变更前+变更后)
- GM比对不通过→FAIL，不得放行至红枫
