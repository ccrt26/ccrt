## 一、分层错误处理

### 1.1 错误级别定义

| 级别 | 含义 | 脚本行为 | 退出码 | 日志级别 |
|:----:|:-----|:---------|:-----:|:-------:|
| FATAL | 致命错误，无法继续执行 | 记录日志 → 清理资源 → 立即退出 | 1 | ERROR |
| ERROR | 严重错误，核心功能受损 | 切换到备源/降级路径后继续 | 0（降级后） | ERROR |
| WARNING | 异常但非致命，可忽略或可恢复 | 记录日志 → 继续执行 | 0 | WARNING |
| INFO | 正常但重要的状态变化 | 记录关键步骤 | 0 | INFO |
| DEBUG | 详细调试信息 | 仅在调试模式输出 | 0 | DEBUG |

### 1.2 级别判断决策树

```
发生异常
  ├── 后续所有操作依赖此结果? 
  │   └── 是 → FATAL（退出）
  │   └── 否 → 继续
  │       ├── 有备选方案（备API/降级逻辑/默认值）?
  │       │   └── 是 → ERROR（切换备选后继续）
  │       │   └── 否 → FATAL（退出）
  │       └── 结果可有可无（如非关键统计数据）?
  │           └── 是 → WARNING（跳过继续）
  └── 预期内的异常（如某只股票数据缺失）?
      └── 是 → WARNING（标记跳过）
```

### 1.3 各层代码示例

**FATAL — 数据源全部不可用**：
```powershell
# 主API + 备API + 缓存 全部失败
if (-not $data -and -not $cacheData) {
    Write-Log -Level "ERROR" -Message "所有数据源均失败，脚本无法继续" -ScriptName $MyInvocation.MyCommand
    exit 1  # FATAL退出
}
```

**ERROR — 主API失败，切换备源**：
```python
try:
    data = fetch_tencent_data(codes)
except DataSourceError:
    logger.error("腾讯API失败，切换新浪备源")
    try:
        data = fetch_sina_data(codes)
    except DataSourceError:
        logger.error("新浪备源也失败，使用缓存兜底")
        data = load_cache(expired_ok=True)
```

**WARNING — 个别数据缺失**：
```powershell
if ($null -eq $stock.pe_ttm) {
    Write-Log -Level "WARNING" -Message "PE数据缺失: $($stock.code)，该股票将跳过PE相关评分" -ScriptName $MyInvocation.MyCommand
    # 继续处理其他股票
    continue
}
```

**INFO — 关键步骤记录**：
```python
logger.info(f"评分引擎启动，输入: {input_path}, 共 {len(df)} 只股票")
logger.info(f"评分完成，有效结果: {valid_count}/{total_count}")
```

## 二、PowerShell日志系统

### 2.1 Write-Log 函数

```powershell
<#
.SYNOPSIS
    统一日志写入函数

.DESCRIPTION
    将日志写入按日滚动的日志文件，同时根据级别输出到控制台。
    ERROR/WARNING → 红色输出到控制台
    INFO → 默认色输出到控制台
    DEBUG → 仅在 $VerbosePreference = "Continue" 时输出
    所有级别都写入日志文件

.PARAMETER Level
    日志级别: ERROR | WARNING | INFO | DEBUG

.PARAMETER Message
    日志消息内容

.PARAMETER ScriptName
    调用脚本名（用 $MyInvocation.MyCommand.Name）

.PARAMETER ExtraData
    附加上下文数据（可选），以JSON格式追加到日志行末尾
#>
function Write-Log {
    param(
        [Parameter(Mandatory=$true)]
        [ValidateSet("ERROR", "WARNING", "INFO", "DEBUG")]
        [string]$Level,

        [Parameter(Mandatory=$true)]
        [string]$Message,

        [Parameter(Mandatory=$true)]
        [string]$ScriptName,

        [Parameter(Mandatory=$false)]
        [hashtable]$ExtraData
    )

    $timestamp = Get-Date -Format "yyyy-MM-dd HH:mm:ss.fff"
    $pid = $PID
    $logLine = "[$timestamp] [PID:$pid] [$Level] [$ScriptName] $Message"

    # 附加上下文数据
    if ($ExtraData) {
        $extraJson = $ExtraData | ConvertTo-Json -Compress
        $logLine += " | context: $extraJson"
    }

    # 确保日志目录存在
    $logDir = Join-Path $PSScriptRoot ".." "logs"
    if (-not (Test-Path $logDir)) {
        New-Item -Path $logDir -ItemType Directory -Force | Out-Null
    }

    # 写入日志文件（按日滚动）
    $logFile = Join-Path $logDir "app_$(Get-Date -Format 'yyyyMMdd').log"
    try {
        Add-Content -Path $logFile -Value $logLine -Encoding UTF8
    } catch {
        # 日志写入失败不终止业务逻辑
        Write-Warning "无法写入日志文件: $logFile"
    }

    # 控制台输出
    switch ($Level) {
        "ERROR"   { Write-Host $logLine -ForegroundColor Red }
        "WARNING" { Write-Host $logLine -ForegroundColor Yellow }
        "INFO"    { Write-Host $logLine }
        "DEBUG"   { Write-Verbose $logLine }
    }
}
```

### 2.2 $MyInvocation 的使用

```powershell
# 获取当前脚本名
$scriptName = $MyInvocation.MyCommand.Name

# 获取当前函数名（在函数内部）

```

## 三、Python日志系统

### 3.1 标准配置模板

```python
"""
日志配置模块 — 项目统一的日志配置

用法:
    from log_config import get_logger, configure_logging
    configure_logging(debug=False)
    logger = get_logger(__name__)
"""

import logging
import sys
from pathlib import Path
from logging.handlers import RotatingFileHandler
from datetime import datetime


def configure_logging(
    debug: bool = False,
    log_dir: str = "logs",
    max_bytes: int = 10 * 1024 * 1024,
    backup_count: int = 5,
) -> None:
    """配置全局日志系统
    
    Args:
        debug: True=DEBUG级别，False=INFO级别
        log_dir: 日志目录
        max_bytes: 单个日志文件最大字节数
        backup_count: 保留的备份文件数
    """
    level = logging.DEBUG if debug else logging.INFO
    
    # 确保日志目录存在
    Path(log_dir).mkdir(parents=True, exist_ok=True)
    
    # 根logger配置
    root_logger = logging.getLogger()
    root_logger.setLevel(level)
    
    # 清除已有handler避免重复
    root_logger.handlers.clear()
    
    # 格式
    formatter = logging.Formatter(
        fmt="[%(asctime)s] [PID:%(process)d] [%(levelname)s] [%(name)s] %(message)s",
        datefmt="%Y-%m-%d %H:%M:%S",
    )
    
    # 控制台handler
    console = logging.StreamHandler(sys.stdout)
    console.setLevel(level)
    console.setFormatter(formatter)
    root_logger.addHandler(console)
    
    # 文件handler（按日滚动）
    log_file = Path(log_dir) / f"app_{datetime.now().strftime('%Y%m%d')}.log"
    file_handler = RotatingFileHandler(
        log_file,
        maxBytes=max_bytes,
        backupCount=backup_count,
        encoding="utf-8",
    )
    file_handler.setLevel(level)
    file_handler.setFormatter(formatter)
    root_logger.addHandler(file_handler)


def get_logger(name: str) -> logging.Logger:
    """获取模块级logger"""
    return logging.getLogger(name)
```

### 3.2 模块使用

```python
import logging

# 每个模块顶部
logger = logging.getLogger(__name__)

# 使用
logger.info("评分引擎启动")
logger.warning("数据不完整: %d条记录缺少PE值", missing_count)
logger.error("评分计算异常: %s", e, exc_info=True)
logger.debug("因子中间值: tech=%.4f, fund=%.4f", tech_score, fund_score)
```

### 3.3 RotatingFileHandler vs TimedRotatingFileHandler

| Handler | 触发条件 | 适用场景 |
|:--------|:---------|:---------|
| RotatingFileHandler | 文件大小 > maxBytes | 所有场景，简单可靠 |
| TimedRotatingFileHandler | 时间到达（如每天午夜） | 需要严格按时间切割 |

项目统一使用 `RotatingFileHandler` + 文件名含日期。这样可以同时按大小切割（单文件不超过10MB）和按日轮转（文件名不同）。

## 四、日志格式约定

### 4.1 标准格式

```
[时间戳] [PID:进程ID] [级别] [脚本/模块名] [消息内容]

示例：
[2026-05-23 15:30:45.123] [PID:28456] [INFO] [stock_data_fetcher.psm1] 主源[1]腾讯API成功，获取500只股票行情
[2026-05-23 15:30:48.456] [PID:28456] [WARNING] [scoring_engine_v2.py] PE数据缺失: 12只股票
[2026-05-23 15:31:00.789] [PID:28456] [ERROR] [gen_daily_html.ps1] 报告生成失败: 模板文件不存在
```

### 4.2 字段说明

| 字段 | 格式 | 说明 |
|:-----|:-----|:-----|
| 时间戳 | `yyyy-MM-dd HH:mm:ss.fff` | 精确到毫秒 |
| PID | `PID:数字` | 进程ID，用于区分并发执行 |
| 级别 | `ERROR/WARNING/INFO/DEBUG` | 必须大写 |
| 脚本名 | 文件名（含扩展名） | PowerShell用.ps1/.psm1，Python用模块名 |
| 消息内容 | 自由文本 | 英文变量名和中文描述混用 |

### 4.3 消息内容写作规范

```powershell
# ✅ 好的日志消息
Write-Log -Level "INFO" -Message "评分完成: 500只股票, 有效结果498只, PE超标排除2只" -ScriptName $scriptName
Write-Log -Level "ERROR" -Message "API调用失败: 腾讯qt.gtimg.cn超时(10s), 尝试次数3/3" -ScriptName $scriptName
Write-Log -Level "WARNING" -Message "缓存过期: stock_quote_cache.json, 年龄7.5分钟, TTL=5分钟" -ScriptName $scriptName

# ❌ 坏的日志消息
Write-Log -Level "INFO" -Message "OK" -ScriptName $scriptName
Write-Log -Level "ERROR" -Message "失败" -ScriptName $scriptName
```

### 4.4 上下文数据记录

```powershell
# 错误日志附加上下文
Write-Log -Level "ERROR" `
    -Message "评分计算异常" `
    -ScriptName $scriptName `
    -ExtraData @{
        Function = "Calculate-TechScore"
        StockCode = $stock.code
        InputValue = $stock.close
        LineNumber = 245
        Exception = $_.Exception.Message
    }
```

## 五、日志文件管理

### 5.1 文件命名和位置

```
项目根目录/
  logs/
    app_20260523.log      ← 当天的日志
    app_20260522.log      ← 昨天的
    app_20260521.log      ← 前天的
    ...
    app_20260423.log      ← 30天前（即将被清理）
```

### 5.2 日志清理脚本

```powershell
function Remove-OldLogs {
    param(
        [string]$LogDir = (Join-Path $PSScriptRoot "logs"),
        [int]$RetentionDays = 30
    )
    
    if (-not (Test-Path $LogDir)) { return }
    
    $cutoff = (Get-Date).AddDays(-$RetentionDays)
    Get-ChildItem -Path $LogDir -Filter "app_*.log" |
        Where-Object { $_.LastWriteTime -lt $cutoff } |
        ForEach-Object {
            Write-Log -Level "INFO" -Message "删除过期日志: $($_.Name)" -ScriptName "日志清理"
            Remove-Item $_.FullName
        }
}
```

### 5.3 日志大小控制

- 单个日志文件 > 10MB → RotatingFileHandler 自动切割（Python）
- PowerShell 通过按日滚动控制（每天一个新文件）
- 保留最近30天日志
- 磁盘空间 < 100MB 时输出警告

## 六、错误追踪

### 6.1 调用栈记录

**PowerShell**：
```powershell
try {
    # 业务逻辑
} catch {
    $callStack = Get-PSCallStack | ForEach-Object { "$($_.Command) at line $($_.ScriptLineNumber)" }
    $stackTrace = ($callStack -join " <- ")
    
    Write-Log -Level "ERROR" `
        -Message "未捕获异常: $($_.Exception.Message)" `
        -ScriptName $scriptName `
        -ExtraData @{
            ExceptionType = $_.Exception.GetType().Name
            StackTrace = $stackTrace
            LineNumber = $_.InvocationInfo.ScriptLineNumber
        }
}
```

**Python**：
```python
import traceback

try:
    # 业务逻辑
except Exception:
    logger.error("未捕获异常", exc_info=True)  # exc_info=True 自动记录调用栈
```

### 6.2 关键操作上下文

```python
# 在处理循环中记录上下文
for idx, stock in df.iterrows():
    try:
        score = calculate_score(stock)
    except Exception:
        logger.error(
            "股票评分失败: code=%s, row_index=%d",
            stock.get("code", "unknown"), idx,
            exc_info=True,
        )
        continue  # 跳过这只股票，不中断整个批次
```

### 6.3 错误聚合报告

在一个批次处理完所有数据后，汇总所有错误：

```python
# 处理过程中收集
errors = []

for stock in stocks:
    try:
        process(stock)
    except Exception as e:
        errors.append({"code": stock["code"], "error": str(e)})
        logger.warning(f"处理异常: {stock['code']} — {e}")
        continue

# 处理完成后汇总
if errors:
    logger.info(f"处理完成，{len(errors)}/{len(stocks)} 条记录异常")
    # 可选：将错误详情写入单独的errors文件
```

## 七、静默失败检测

### 7.1 常见静默失败场景

| 场景 | 表现 | 检测方法 |
|:-----|:-----|:---------|
| 脚本中途退出无日志 | 输出文件未生成 | 检查输出文件是否存在+大小>0 |
| API返回空数据 | 数据库/缓存为空 | 检查数据行数 > 0 |
| 编码错误导致乱码 | 数据内容为乱码但程序不报错 | 抽样检查中文字段 |
| 评分引擎输入为空 | 所有评分=0 | 检查评分分布的std > 0 |
| 缓存过期一直用旧数据 | 数据长期不变 | 检查缓存的LastWriteTime |

### 7.2 防御性检查

```powershell
# 每个脚本的关键输出都必须检查
if (-not (Test-Path $outputPath)) {
    Write-Log -Level "ERROR" -Message "输出文件未生成: $outputPath" -ScriptName $scriptName
    exit 1
}

$outputSize = (Get-Item $outputPath).Length
if ($outputSize -eq 0) {
    Write-Log -Level "ERROR" -Message "输出文件为空: $outputPath" -ScriptName $scriptName
    exit 1
}

$data = Get-Content $outputPath -Raw | ConvertFrom-Json
if ($data.data.Count -eq 0) {
    Write-Log -Level "WARNING" -Message "输出数据为空: 0条记录" -ScriptName $scriptName
}
```

### 7.3 脚本返回值检查模式

```powershell
# 在调用外部脚本后必须检查
$result = & .\get_stock_data.ps1 -Codes $codes
if ($LASTEXITCODE -ne 0) {
    Write-Log -Level "ERROR" -Message "子脚本异常退出: get_stock_data.ps1, 退出码 $LASTEXITCODE" -ScriptName $scriptName
    exit 1
}
```

## 九、异常信息给用户的呈现

### 9.1 用户可见的错误信息

```
# ✅ 好的用户错误信息
[ERROR] 数据获取失败: 腾讯API超时 (已重试3次)
[INFO]  切换新浪备源...
[ERROR] 新浪API也失败: 连接被拒绝
[WARN]  使用本地缓存 (数据更新于 2026-05-23 14:55, 距今35分钟)
[INFO]  报告已生成，但行情数据可能不是最新。文件: output/daily_report.html

# ❌ 坏的用户错误信息
error occurred
Exception: System.Net.WebException: The remote server returned an error: (404) Not Found.
   at System.Net.HttpWebRequest.GetResponse()
   ...20行调用栈...
```

### 9.2 错误信息三段式

1. **发生了什么**：用中文描述错误，避免直接堆栈信息
2. **系统怎么处理了**：降级/重试/跳过（说明自动化应对）
3. **用户需要知道什么**：影响范围（功能受损程度）、时效性（数据是否过期）
