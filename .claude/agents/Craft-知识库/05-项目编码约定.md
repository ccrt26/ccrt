## 一、文件命名约定

### 1.1 PowerShell脚本

| 类型 | 命名格式 | 示例 |
|:-----|:---------|:-----|
| 核心业务脚本 | `Verb-Noun.ps1` 或 `gen_xxx.ps1` | `gen_daily_html.ps1`, `gen_doc_v2.ps1` |
| 模块文件 | `snake_case.psm1` | `stock_data_fetcher.psm1` |
| 工具脚本 | `Verb-Noun.ps1` | `check_redlines.ps1`, `version_supervisor.ps1` |
| 引擎/大型脚本 | `中文名.ps1` | `模拟交易引擎.ps1` |

**注意**：项目历时已久，存在两套命名风格（英文Verb-Noun和中文名）。新增脚本时遵循：
- 纯工具/辅助脚本 → `Verb-Noun.ps1`（英文）
- 核心业务引擎 → 可以用中文名（与项目已有风格一致）

### 1.2 Python脚本

| 类型 | 命名格式 | 示例 |
|:-----|:---------|:-----|
| 核心模块 | `snake_case.py` | `scoring_engine_v2.py` |
| 工具模块 | `snake_case.py` | `md_to_docx.py` |
| 服务模块 | `snake_case.py` | `financial_mcp_server.py` |
| 配置模块 | `config.py` | `config.py` |

### 1.3 其他文件类型

| 类型 | 命名格式 | 示例 |
|:-----|:---------|:-----|
| 配置文件 | `config.json` / `config.py` | — |
| 缓存数据 | `描述_cache.json` | `stock_quote_cache.json` |
| 日志文件 | `app_YYYYMMDD.log` | `app_20260523.log` |
| 输出数据 | `描述_YYYYMMDD.json` | `daily_scores_20260523.json` |
| 报告文件 | `报告名_YYYYMMDD.html` | `每日荐股_20260523.html` |

## 二、变量命名

### 2.1 统一规则

| 类型 | PowerShell | Python |
|:-----|:-----------|:-------|
| 局部变量 | `$camelCase` | `snake_case` |
| 函数/方法 | `Verb-Noun` | `snake_case` |
| 常量 | `$UPPER_SNAKE` | `UPPER_SNAKE` |
| 类名 | `PascalCase` | `PascalCase` |
| 私有成员 | — | `_private_method` |
| 模块级变量 | `$script:xxx` | `_module_var` |

### 2.2 命名示例

```powershell
# PowerShell
$stockPrice = 100.50
$errorCount = 0
$cacheData = @()
$MAX_RETRIES = 3
$API_TIMEOUT_SEC = 10
$script:CACHE_DIR = Join-Path $PSScriptRoot "data"

function Get-StockPrice { ... }
function Test-CacheFreshness { ... }
```

```python
# Python
stock_price = 100.50
error_count = 0
cache_data = []
MAX_RETRIES = 3
API_TIMEOUT_SEC = 10
CACHE_DIR = Path(__file__).parent / "data"

def get_stock_price(codes: list[str]) -> dict: ...
def test_cache_freshness(path: str) -> bool: ...

class StockDataFetcher: ...
```

### 2.3 特殊命名约定

```powershell
# 临时/一次性变量 → 短名有意义即可
$i, $j  # 循环计数器
$k, $v  # 哈希表遍历

# 布尔变量 → Is/Has/Should/Can 前缀
$isCacheValid = $true
$hasError = $false
$shouldRetry = $true

# 集合变量 → 复数或List/Array后缀
$stockList = @()
$errorMessages = @()

# 路径变量 → Path/Dir 后缀
$configPath = "..."
$cacheDir = "..."
```

### 3.2 路径构建

```powershell
# ✅ 基于脚本位置
$configPath = Join-Path $PSScriptRoot "config.json"
$dataDir = Join-Path $PSScriptRoot "data"

# ✅ 跨级别
$rootDir = Join-Path $PSScriptRoot ".." ".."  # 上两级

# ✅ 模块内（.psm1中$PSScriptRoot指向模块文件所在目录）
$moduleDir = $PSScriptRoot

# ❌ 绝对路径 — 永不
$path = "C:\Users\34269\Documents\..."
```

```python
# ✅ pathlib（推荐）
from pathlib import Path
BASE_DIR = Path(__file__).parent
config_path = BASE_DIR / "config.json"
data_dir = BASE_DIR / ".." / "data"
data_dir = data_dir.resolve()  # 规范化

# ✅ os.path（兼容旧代码）
import os
BASE_DIR = os.path.dirname(__file__)
config_path = os.path.join(BASE_DIR, "config.json")
```

### 4.2 读取配置

```powershell
# PowerShell
$configPath = Join-Path $PSScriptRoot "config.json"
$config = Get-Content $configPath -Encoding UTF8 | ConvertFrom-Json

$apiTimeout = $config.api.tencent.timeout_sec
$cacheDir = $config.cache.dir
```

```python
# Python
import json
from pathlib import Path

CONFIG_PATH = Path(__file__).parent / "config.json"

def load_config() -> dict:
    with open(CONFIG_PATH, "r", encoding="utf-8") as f:
        return json.load(f)

config = load_config()
api_timeout = config["api"]["tencent"]["timeout_sec"]
```

### 4.3 配置不散落原则

- 所有可调参数集中在一处（config.json / config.py）
- 修改参数 = 改配置文件，不改业务代码
- 环境变量仅用于运行环境切换（DEBUG/LOG_LEVEL/PORT），不用于业务参数
- API密钥/Token 用环境变量，绝不出现在配置文件中

## 五、JSON数据格式约定

### 5.1 标准JSON结构

```json
{
  "meta": {
    "version": "2.4",
    "generated_at": "2026-05-23 15:30:00",
    "source": "scoring_engine_v2.py",
    "record_count": 500,
    "params": {
      "weights": {"technical": 0.30}
    }
  },
  "data": [
    {
      "code": "sh600519",
      "name": "贵州茅台",
      "close": 1850.50,
      "pe_ttm": 35.2,
      "scores": {
        "technical": 8.5,
        "fundamental": 7.0
      }
    }
  ]
}
```

### 5.2 字段命名规范

- 统一 snake_case（`pe_ttm` 而非 `peTtm` 或 `PETTM`）
- 代码字段用 `code` 而非 `stockCode` 或 `symbol`
- 日期字段：`date` (YYYY-MM-DD), `generated_at` (YYYY-MM-DD HH:MM:SS)
- 百分比用小数（0.05 而非 5），字段名含 `_pct` 或 `_ratio`

### 5.3 数值精度

| 数据类型 | 精度 | 示例 |
|:---------|:----:|:-----|
| 价格 | 2位小数 | 1850.50 |
| 涨跌幅 | 2位小数（百分比） | 2.35 |
| 比率/得分 | 4位小数 | 0.8532 |
| 成交量 | 整数 | 12500000 |
| 市值 | 亿为单位，2位小数 | 18500.50 |

## 六、注释原则

### 6.1 写WHAT vs 写WHY

```powershell
# ❌ 废话注释 — 代码本身已经说了WHAT
# 循环处理每只股票
foreach ($stock in $stockList) { ... }

# ✅ 有用的注释 — WHY
# 使用2.0倍ATR而非项目默认的1.5倍: 科创板波动大，止损过窄会频繁触发误退出
$stopLoss = $entryPrice - 2.0 * $atr
```

### 6.2 必须写注释的情况

1. **复杂算法/公式**：解释计算逻辑
   ```python
   # PE(TTM) = 最新年报EPS - 去年同季EPS + 最新季报EPS
   # 例如：2025年报EPS=10.0, 2024Q1 EPS=2.5, 2025Q1 EPS=3.0
   # TTM_EPS = 10.0 - 2.5 + 3.0 = 10.5
   ttm_eps = annual_eps - same_quarter_last_year_eps + latest_quarter_eps
   ```

2. **魔法数字**：标注来源
   ```powershell
   # 300ms 最小间隔 — 来自红线§1.2 腾讯API频率限制
   Start-Sleep -Milliseconds 300
   ```

3. **临时workaround**：标注原因和计划
   ```python
   # WORKAROUND(2026-05-23): 东财API偶发返回data=null，非超时错误
   # 绕过而非报错。计划在API稳定后移除。关联issue: #NOTION-123
   if data.get("data") is None:
       return []
   ```

4. **非直觉的业务规则**：解释为什么
   ```powershell
   # 涨停阈值9.4%而非10%：考虑四舍五入误差+盘中触及后回落+安全边际
   # 来自模拟交易白皮书v1.4 §6.1.1
   if ($changePct -ge 9.4) { return $false }
   ```

### 6.3 禁止的注释

- 版本号/作者（Git管理）
- 已被注释掉的旧代码（删除它，Git有历史）
- 显而易见的代码行为
- 日期标记（`# 2026-05-23 updated`）——用Git blame
- TODO 无责任人和截止日期 ——要么修，要么建issue

## 七、Git提交前检查清单

### 7.1 自动化检查（pre-commit hook自动运行）

- [ ] 版本一致性检查（`version_supervisor.ps1 -CrossCheck`）
- [ ] 红线合规检查（`check_redlines.ps1`）

### 7.2 人工检查

**代码质量**：
- [ ] 代码至少手动运行过一次，确认不报错
- [ ] 没有遗留的调试输出（`Write-Host "DEBUG:..."` / `print("debug")`）
- [ ] 没有硬编码的绝对路径
- [ ] 所有API调用有 try/catch 或 try/except
- [ ] 关键步骤有INFO级别日志

**文件规范**：
- [ ] 新增文件路径符合项目约定
- [ ] 文件命名符合项目约定
- [ ] 没有遗留的临时文件（.tmp, .bak, test_*.ps1）

**接口影响**：
- [ ] 接口变更已通知Arch
- [ ] 输出格式变更已通知下游模块负责人
- [ ] 新增依赖已通知Dock

**红线合规**：
- [ ] 数据源遵循1+2架构
- [ ] 未编造任何数据或假设API行为
- [ ] PE(TTM)使用公式计算
- [ ] 未删除任何PDF文件

## 八、修改现有代码的注意事项

### 8.1 修改流程

```
1. Read — 完整阅读目标文件，理解全貌
2. Search — 用Grep搜索要修改的函数名，找到所有调用方
3. Analyze — 确认修改的影响范围
4. Modify — 用Edit工具做精确修改
5. Verify — 确认语法无误（至少不报错）
6. Notify — 如有接口变更，通知下游
```

### 8.2 修改前必查

```bash
# 查找函数的所有调用方
grep -r "FunctionName" --include="*.ps1" --include="*.psm1" --include="*.py"

# 查找配置键的所有引用
grep -r "config_key" --include="*.json" --include="*.ps1" --include="*.py"
```

### 8.3 保持一致性

- **缩进风格**：文件用2空格就继续用2空格，用4空格就继续用4空格
- **引号风格**：文件用双引号就继续用双引号，用单引号就继续用单引号
- **变量风格**：哪怕你觉得文件里的命名不够好，也保持一致性
- **混用风险**：一个文件里出现两种风格 = 最大的不一致

### 8.4 改动后的验证

```powershell
# 至少检查PowerShell语法
Get-Command -Syntax .\modified_script.ps1

# 或运行脚本的 --help 模式（如果有）
.\modified_script.ps1 --help

# Python语法检查
python -m py_compile modified_script.py
```

## 九、项目特殊约定

### 9.1 股票代码格式

```
sh600519  — 上海交易所 (sh + 6位数字)
sz000001  — 深圳交易所 (sz + 6位数字)
sh688001  — 科创板 (sh688xxx)
sz300001  — 创业板 (sz300xxx)
bj830001  — 北交所 (bj + 6位数字)

注意：
- 始终小写
- 纯数字代码去掉sh/sz前缀后是6位
- 在API调用中根据API要求使用不同的格式（腾讯用sh600519，新浪用sh600519）
```

### 9.2 路径分隔符

- PowerShell：始终用 `Join-Path`（自动处理 `/` vs `\`）
- Python：始终用 `pathlib` 或 `os.path.join`
- 不要在字符串中硬编码 `\`（Windows）或 `/`（Unix）
- 项目在Windows上运行，但代码应可移植

### 9.3 临时文件

- 临时文件统一放到 `$env:TEMP/铁律量化/` 目录
- 脚本结束时清理临时文件
- 异常退出时在 `finally` 块中清理

### 9.4 进程间通信

- PowerShell → Python：JSON文件传递，命令行参数
- Python → PowerShell：JSON文件传递，退出码
- 不通过标准输入/输出传递复杂结构化数据
