# 08 — 代码分级审核制度 (L0/L1/L2)

> 来源：脚本轻量化+质量保障体系方案 v1.0 | 2026-05-24
> 强制等级：红线级——所有新增/修改代码必须标注等级

---

## 一、三级定义

| 等级 | 范围 | 典型文件 | 审核路径 |
|:----:|:-----|:--------|:--------|
| **L0** | 工具/数据/图表/缓存 | `technical.py`, `cache.ps1`, `kline.ps1` | Craft自查 + Proof常规测试 |
| **L1** | 策略/评分/指标/板块 | `theme.py`, `scores.py`, `sector.py` | Arch复审 + Proof全量测试 + Golden Master diff |
| **L2** | 风控/否决/交易/红线 | `veto.py` | 全工程审核 + **Vega强制二次复核**（逐条对照红线原文） |

---

## 二、标签规则

1. **Arch在设计文档中标注每个模块等级**，Craft不得自行变更
2. 等级标注位置：模块文件头部注释 + Arch设计文档模块清单
3. 等级变更需Arch重新评估+腰子确认（L2变更还需Vega确认）

---

## 三、分级审核流程

```
L0: Craft编码 → 自查清单勾满 → Proof常规测试 → 通过
L1: Craft编码 → 自查清单勾满 → Arch复审 → Proof全量+Golden Master → 通过
L2: Craft编码 → 自查清单勾满 → Arch复审 → Vega逐条红线复核 → Proof全量+Golden Master → 通过
```

---

## 四、需求→代码核对清单模板

> 附于Arch设计文档末尾，Arch+腰子共同勾签后放行至编码环节。

```
### 需求→代码核对清单

| 编号 | 检查项 | 白皮书/红线条款 | Arch勾 | 腰子勾 |
|:----:|:------|:-------------|:-----:|:-----:|
| R1 | 选股规则100%匹配白皮书 | 白皮书§X | ☐ | ☐ |
| R2 | 风控阈值与红线规则一致 | 红线§X | ☐ | ☐ |
| R3 | 指标算法公式与白皮书一致 | 白皮书§X | ☐ | ☐ |
| R4 | 否决条件覆盖全部条款 | 红线§X | ☐ | ☐ |
| R5 | 数据源1+2架构完整 | 红线§1.2 | ☐ | ☐ |
| R6 | PE(TTM)计算使用本地公式 | 红线§1.2 | ☐ | ☐ |
```

---

## 五、单文件行数红线

- 单文件不超过 **500行**
- 超出 → 必须申报Arch拆分评审，评审通过后才可保留/新增
- 评审记录存入 `审计报告/拆分评审/`
- 现有超限文件（`scoring_engine_v2.py` 2359行等）已纳入Phase 2拆分计划，不在此限

---

## 六、L2模块额外要求

1. 每条否决/风控规则必须注释引用红线条款编号（格式：`# 红线§X.X`）
2. Vega复核不是走形式——逐条对照红线原文核验：阈值数值/判断符号/条件逻辑
3. Vega发现偏差 → B1级缺陷，暂停该模块上线，Craft修复后重检
4. 无Vega复核记录的L2变更 → Gauge审计标记FAIL
