# 第一章 评估体系总纲

## 1.1 核心定位

**次日后评估不是简单的「涨跌统计」，而是「评分质量检验 + 规则有效性验证 + 逻辑迭代驱动」三位一体的优化引擎。**

```
N日 20:00                    N+1日 15:00              N+1日 19:00                N+1日 20:00
每日荐股分析                   次日收盘                      次日后评估               新版分析
开盘检查→跳过/执行              数据就绪                    开盘检查→跳过/执行          使用最新白皮书
     │                              │                            │                        │
     ▼                              ▼                            ▼                        ▼
┌─────────────┐           ┌───────────────┐           ┌───────────────┐           ┌─────────────┐
│ 逻辑白皮书   │ ───────→ │ 次日后评估     │ ───────→ │ 归因分析      │ ───────→ │ 新版白皮书   │
│ vX.X 执行   │  驱动     │ 数据采集+比对  │   计算     │ +参数校准建议  │  迭代     │ vX.X+1执行   │
└─────────────┘           └───────────────┘           └───────┬───────┘           └─────────────┘
                                                              │
                                                              ▼
                                                     ┌───────────────┐
                                                     │ 生成评估报告    │
                                                     │ 评估报告_YYYYMMDD│
                                                     │ 自动优化白皮书   │
                                                     │ 更新版本号      │
                                                     └───────────────┘
```

## 1.2 核心指标

| 指标 | 公式 | 目标 | 说明 |
|:----|:----|:----:|:-----|
| **次日胜率** | 盈利次数 / 总推荐次数 | ≥60% | 按次日收盘价计，含滑点 |
| **次日盈亏比** | 总盈利 / 总亏损 | ≥1.5:1 | 含次数权重，反映整体赔率 |
| **组合次日收益** | Σ(各股次日收益率) / 推荐只数 | >0% | 等权组合视角 |
| **超额收益** | 组合次日收益 - 沪深300次日涨跌 | >0% | 跑赢大盘能力 |
| **评分区分度** | ≥70分组胜率 vs <70分组胜率 | 差值≥15% | 高分股确实比低分股表现好 |
| **维度误判率** | 某维度给高分但亏损>3%次数 / 该维度高分总次数 | ≤20% | 见第三章 |
| **否决误杀率** | 被否股次日涨>5% 只数 / 被否总只数 | ≤15% | 否决是否过严 |
| **豁免成功率** | 豁免股盈利比例 | ≥65% | 豁免条件是否有效 |

## 1.3 自动化调度时间线

铁律量化每日工作流分为三个定时任务，由 `daily_workflow.ps1` 统一调度：

### 1.3.1 调度总图

| 时间 | 任务 | 模式 | 开盘检查 | 产出 |
|:----:|:----|:----:|:--------:|:-----|
| **N日 20:00** | 每日荐股分析 | `daily` | ✅ | 每日股票推荐报告 |
| **N+1日 19:00** | 次日后评估 | `eval` | ✅ | 评估报告_YYYYMMDD.docx |
| **N+1日 20:00** | 每日荐股分析（新版） | `daily_latest` | ✅ | 使用优化后白皮书 |

### 1.3.2 各任务详细流程

**Task 1 — N日 20:00（每日荐股分析）**
```
→ 调用 is_market_open.ps1 判断 N 日是否开盘
  ├─ 非交易日 → 跳过本次任务，记录日志
  └─ 交易日 → 执行每日荐股分析逻辑（使用当前版白皮书）
```

**Task 2 — N+1日 19:00（次日后评估）**
```
→ 调用 is_market_open.ps1 判断 N+1 日是否开盘
  ├─ 非交易日 → 跳过本次任务，记录日志（N日推荐无法评估）
  └─ 交易日 → 执行次日后评估流程:
       1. 加载 N 日推荐数据 + N+1 日行情
       2. 模拟交易计算 + 维度归因
       3. 生成评估报告（评估报告_YYYYMMDD.docx）
       4. 执行自动优化：基于评估结论调整白皮书参数
       5. 判断是否需要版本更新，更新 CHANGELOG
```

**Task 3 — N+1日 20:00（新版每日荐股分析）**
```
→ 调用 is_market_open.ps1 判断 N+1 日是否开盘
  ├─ 非交易日 → 跳过
  └─ 交易日 → 使用最新版逻辑白皮书执行每日荐股分析
```

### 1.3.3 关键原则

1. **开盘判断前置**：每个任务启动时先检查目标日是否开盘，不开盘则跳过，不阻塞后续任务
2. **评估→优化→新分析的闭环**：N+1日 19:00 评估完成后立即优化白皮书，1小时后（20:00）新版分析使用优化后的参数
3. **自动化日志**：每次执行记录到 `workflow_records.csv`，运行日志按月保存到 `scripts/workflow_yyyyMM.log`
4. **人工确认点**：次版本升级（v1.0→v1.1）需人工确认后执行，参数微调自动执行

## 1.4 输出文档命名规范

### 1.4.1 评估报告命名

次日后评估生成的报告统一命名为：

```
评估报告_YYYYMMDD.docx
```

其中 `YYYYMMDD` 为**被评估的荐股日期**（N日），而非评估执行日（N+1日）。

| 场景 | N日 | N+1日 | 报告命名 |
|:----|:---:|:-----:|:---------|
| 正常 | 2026-05-21 | 2026-05-22 | 评估报告_20260521.docx |
| 周末跨日 | 2026-05-22(五) | 2026-05-25(一) | 评估报告_20260522.docx |

### 1.4.2 存储位置

```
事后评估\
├── 次日后评估白皮书_v{version}.md      ← 本文档
├── 次日后评估白皮书_v{version}.docx    ← 发布的DOCX版本
├── 次日后评估白皮书_CHANGELOG.md       ← 版本变更记录
├── 评估报告_YYYYMMDD.docx              ← 每日评估报告
├── records.csv                         ← 逐日评估明细
├── summary.csv                         ← 汇总统计
└── issues.csv                          ← 问题跟踪
```

### 1.4.3 评估报告内容结构

每份 `评估报告_YYYYMMDD.docx` 包含：
1. **整体表现**：胜率、盈亏比、组合收益、超额收益
2. **逐股明细**：各推荐标的模拟交易结果
3. **维度回检摘要**：技术/资金/板块/消息四维度预期验证
4. **规则验证**：否决误杀率、豁免成功率、巨量惩罚有效性
5. **参数校准建议**：需调整的参数及建议值
6. **优化状态**：灰度中项、待确认项

# 第二章 次日数据采集与比对

## 2.1 数据获取

| 数据项 | 来源 | 用途 |
|:------|:-----|:------|
| T日推荐股票列表 | T日荐股报告 | 评估对象 |
| T日各推荐股评分明细 | 评分系统输出 | 归因基准 |
| T+1日开盘价 | 腾讯行情[1] | 模拟买入价 |
| T+1日收盘价 | 腾讯行情[1] | 模拟卖出价 |
| T+1日最高价/最低价 | 腾讯行情[1] | ATR/止损触发判断 |
| T+1日成交量/换手率 | 腾讯行情[1] | 量能变化验证 |
| T+1日沪深300涨跌 | 腾讯行情[1] | 大盘环境对照 |
| T+1日板块指数涨跌 | 东方财富[m:90+t:2] | 板块相位验证 |

## 2.2 模拟交易计算

### 2.2.1 买入模拟

| 条件 | 买入价 | 说明 |
|:----|:------|:------|
| 正常开盘 | T+1日 09:30开盘价 × 1.005 | 含0.5%单向滑点 |
| 一字涨停开盘 | 标记"无法成交" | 不计入胜率统计 |
| 开盘跌>3% | 标记"开盘异常" | 独立统计，不计入常规胜率 |

### 2.2.2 卖出模拟

| 优先级 | 触发条件 | 卖出价 | 说明 |
|:-----:|:---------|:------|:------|
| 1 | 持仓期间最低价 ≤ 止损价 | 按触发价卖出 | ATR动态止损 |
| 2 | 盈利>10%后收盘跌破MA5 | 次日开盘价卖出 | 止盈保护 |
| 3 | 大盘当日跌>3% | 当日收盘价卖出 | 系统性风险 |
| 4 | 以上均未触发 | T+1日收盘价卖出 | 默认次日平仓 |

### 2.2.3 止损计算

**止损价 = 买入价 - 2 × ATR(14)**

其中ATR(14)使用T日收盘计算的14日ATR值。

**止损硬上限**：即使ATR计算超过-8%，最大止损仍为-8%。

## 2.3 逐项比对表

对每个推荐标的，逐项比对T日预期 vs T+1日实际：

| 比对项 | T日预期值 | T+1日实际值 | 偏差 | 影响 |
|:------|:---------|:-----------|:----|:-----|
| 收盘价 | T日收盘价 | T+1日收盘价 | ±% | 持仓盈亏 |
| 涨跌幅 | — | T+1日涨跌幅 | — | 核心指标 |
| 成交量/换手率 | T日值 | T+1日值 | 放量/缩量 | 量价判断验证 |
| 板块涨跌 | T日板块相位 | T+1日板块表现 | — | 板块判断验证 |
| 评分预期 | 六维评分 | 次日实际走势 | — | 评分有效性 |
| 催化剂 | 预期催化剂 | 是否落地 | 已落地/未落地/新出现 | 消息面验证 |

# 第三章 评分维度回检

## 3.1 逐维度预期验证

对每个亏损>3%的推荐标的，回检每个评分维度的预期是否成立：

### 3.1.1 技术面回检

| T日评分依据 | T+1日验证 | 判定 |
|:-----------|:---------|:----|
| 均线多头排列 | 均线是否继续多头 | ✅ 预期正确 / ❌ 预期错误 |
| 均线收敛 | 是否向上发散 | ✅ 正确收敛 / ❌ 向下发散 |
| 底部抬高 | 低点是否维持 | ✅ 支撑有效 / ❌ 破位 |
| 量价配合 | 量能是否持续 | ✅ 温和放量 / ❌ 缩量下跌 |
| RSI 40-55 | RSI走向 | ✅ 上行 / ❌ 下行 |
| MACD金叉 | DIF-DEA走势 | ✅ 金叉有效 / ❌ 假金叉 |

### 3.1.2 资金面回检

| T日评分依据 | T+1日验证 | 判定 |
|:-----------|:---------|:----|
| 连续净流入 | 是否继续流入 | ✅ 趋势延续 / ❌ 趋势反转 |
| 量升价平 | 是否突破 | ✅ 放量突破 / ❌ 继续整理 |
| 换手率回升 | 换手是否维持 | ✅ 活跃维持 / ❌ 重新缩量 |

### 3.1.3 板块相位回检

| T日判定 | T+1日板块表现 | 判定 |
|:-------|:-------------|:----|
| 潜伏期 | 板块涨跌 | ✅ 止跌企稳 / ❌ 继续下探 |
| 启动期 | 板块涨跌 | ✅ 温和上涨 / ❌ 启动失败 |
| 主升期 | 板块涨跌 | ✅ 继续上行 / ❌ 见顶回落 |

### 3.1.4 消息面回检

| T日催化剂预期 | T+1日实际 | 判定 |
|:-------------|:---------|:----|
| 明确催化剂即将落地 | 是否落地 | ✅ 落地催化 / ❌ 延迟或落空 |
| 行业催化预期 | 板块消息 | ✅ 有利好 / ❌ 无变化 / ❌ 有利空 |

### 3.1.5 风向标回检（新增）

**概念**：选取每个推荐标的所在行业的龙头股作为"风向标"。如果T+1日龙头股表现正常，但推荐标的大跌，说明问题在个股而非行业；如果龙头股也大跌，说明行业/板块判断出问题。

| 风向标 | T+1日龙头股表现 | 判定 |
|:-------|:--------------|:----|
| 如：推荐中科曙光 | 同行业龙头浪潮信息表现 | 行业问题 vs 个股问题 |

> 风向标选取规则：每个申万一级行业选取市值最大、流动性最好的1只股票作为风向标。

## 3.2 维度误判率

**维度误判率 = 某维度给高分（高于该维度满分60%）且该股票次日亏损>3%的次数 / 该维度给出高分总次数**

### 3.2.1 误判率分级

| 误判率 | 判定 | 操作 |
|:-----:|:----|:-----|
| ≤10% | ✅ 优秀 | 维持该维度权重 |
| 10-20% | ⚠️ 正常 | 关注趋势 |
| 20-30% | 🔴 偏高 | 连续5日超20% → 触发维度重构 |
| >30% | 🚫 失效 | 立即暂停该维度，排查评分逻辑 |

### 3.2.2 误判类型标记

亏损>3%时，必须明确标注一个主要误判维度：

| 误判类型 | 典型场景 | 标记 |
|:---------|:---------|:----|
| 技术面误判 | 均线多头但破位 | TECH_MISJUDGE |
| 资金面误判 | 资金流入但主力出货 | MONEY_MISJUDGE |
| 板块面误判 | 判断潜伏期但板块大跌 | SECTOR_MISJUDGE |
| 消息面误判 | 催化预期落空 | NEWS_MISJUDGE |
| 基本面误判 | 财报指标失真 | FUND_MISJUDGE |
| 风控误判 | 止损不足/跌幅超预期 | RISK_MISJUDGE |

## 3.3 相关系数计算（周更）

每周日计算各维度评分与次日涨跌幅的Spearman相关系数：

```
ρ(维度X) = spearmanr(维度X评分, 次日实际涨跌幅)
```

| 系数范围 | 判定 | 操作 |
|:-------:|:----|:-----|
| ρ > 0.3 | ✅ 有效预测 | 权重可上调 |
| 0.1 ≤ ρ ≤ 0.3 | ⚠️ 弱相关 | 维持当前权重 |
| ρ < 0.1 | 🔴 无预测力 | 重构评分逻辑 |
| ρ < 0（负相关） | 🚫 反向指标 | 立即暂停排查 |


## 3.4 误判子类型分析（新增于v1.2）

> **核心思路**：当前误判标记只到维度级（如 TECH_MISJUDGE），但同一维度内的不同误判原因，命中率差异很大。「均线多头假突破」和「RSI钝化」都是技术面误判，但修复方案完全不同。只有拆到子类型级别，才能精准关闭失效信号、保留有效信号。

### 3.4.1 误判子类型分类体系

亏损>3%时，除标注维度级误判标记外，必须进一步标注子类型：

| 维度级 | 子类型 | 标记 | 典型场景 |
|:-------|:-------|:-----|:---------|
| **技术面** | 均线多头假突破 | TECH_FAKE_BREAK | 均线刚形成多头排列，次日直接破位 |
| | 量价背离 | TECH_DIVERGENCE | 放量但价格不上涨，或缩量上涨 |
| | RSI钝化 | TECH_RSI_BLUNT | RSI在60以上钝化后回落 |
| | MACD假金叉 | TECH_FAKE_GOLDEN | DIF上穿DEA后立即死叉 |
| | 支撑位假突破 | TECH_BREAK_SUPPORT | 跌破关键支撑位后加速下跌 |
| **资金面** | 主力假流入 | MONEY_FAKE_INFLOW | 大单净买为正，但小单净卖出更大 |
| | 尾盘拉升出货 | MONEY_CLOSE_PUMP | 收盘前15分钟拉升，但全天主力净流出 |
| | 缩量反弹 | MONEY_SHRINK_BOUNCE | 反弹时成交量持续萎缩 |
| **板块面** | 潜伏期误判 | SECTOR_EARLY_MISS | 判断板块在潜伏期，实际仍在下跌通道 |
| | 启动期夭折 | SECTOR_ABORT | 板块启动后立即回调，未形成趋势 |
| | 主升期见顶 | SECTOR_TOP | 板块主升末端追入，次日开始回调 |
| **消息面** | 催化延迟 | NEWS_DELAY | 催化剂预期时间未落地 |
| | 催化落空 | NEWS_FAIL | 催化剂确定取消或远低于预期 |
| | 反向消息 | NEWS_ADVERSE | 出现未预见的利空消息 |

### 3.4.2 子类型命中率统计

每个子类型单独统计命中率：

```
子类型命中率 = 该子类型被标记次数 / 该子类型对应的评分信号出现总次数
```

例如：统计过去30日「均线多头」信号出现的总次数，和其中被标记为 TECH_FAKE_BREAK 的次数，计算出该信号的虚假率。

| 子类型 | 信号出现次数 | 误判标记次数 | 命中率 | 判定 |
|:-------|:-----------:|:-----------:|:-----:|:----|
| TECH_FAKE_BREAK | 120 | 12 | 10% | ✅ 正常 |
| TECH_DIVERGENCE | 85 | 22 | 26% | 🔴 偏高 |
| MONEY_FAKE_INFLOW | 65 | 8 | 12% | ⚠️ 正常 |
| SECTOR_EARLY_MISS | 40 | 14 | 35% | 🚫 失效 |

### 3.4.3 信号级别停用/恢复机制

| 命中率 | 判定 | 操作 |
|:-----:|:----|:------|
| ≤10% | ✅ 正常 | 维持信号权重 |
| 10-20% | ⚠️ 观察 | 关注趋势，不操作 |
| 20-30% | 🔴 偏高 | 信号降权50% + 连续5日超20%→暂停该信号 |
| >30% | 🚫 失效 | 立即暂停该信号，从评分逻辑中剔除 |

**恢复机制**：被暂停的信号，如果后续30日内命中率降至≤15%，可自动恢复。恢复后先以50%权重运行10个交易日，稳定后再恢复全权重。

### 3.4.4 自动化频率

- **每日**：统计各子类型当日的误判标记，更新累计命中率
- **每周一**：生成子类型命中率排行榜，输出需要关注的信号列表
- **每月**：回顾被暂停的信号，检查是否满足恢复条件

# 第四章 规则有效性诊断

## 4.1 否决规则验证

### 4.1.1 绝对否决跟踪

对每个被绝对否决（未进推荐池）但实际次日大涨>5%的标的，记录：

| 否决原因 | 股票 | T日评分 | T+1日涨跌幅 | 误杀判定 |
|:---------|:----|:-------:|:-----------:|:--------|
| PE估值泡沫 | — | — | — | 阈值偏严 / 行业PE应调整 |
| 30日涨幅>50% | — | — | — | 牛市应放宽阈值 |
| 中期空头(MA死叉) | — | — | — | 均线参数需调整 |
| 净利润亏损 | — | — | — | 一般不应豁免 |

**绝对否决误杀率 = 被绝对否决但次日涨>5%的只数 / 被绝对否决总只数**
- 目标：≤5%
- 连续3日>5% → 审查相应否决条件的阈值

### 4.1.2 条件否决跟踪

每个被条件否决（评分达标但触发了条件否决条件）的标的，跟踪次日表现：

- 记录：股票、否决条件、豁免所需分、实际得分、次日涨跌幅
- 计算：条件否决平均涨幅 vs 推荐标的平均涨幅
- 差值>3% → 条件阈值过严，需放宽
- 差值<-3% → 阈值合理

### 4.1.3 趋势豁免评估

| 分组 | 胜率 | 说明 |
|:----|:----:|:------|
| 豁免组 | — | 触发趋势豁免条件的推荐 |
| 非豁免组 | — | 正常推荐的标的 |
| **差值** | — | 豁免组 - 非豁免组 |

**判定标准：**
- 豁免组胜率 ≥ 65% → ✅ 豁免条件有效
- 豁免组胜率 < 50% → ❌ 豁免条件失效
- 豁免组连续3天低于非豁免组10%以上 → 暂停趋势豁免功能

## 4.2 巨量惩罚监控

**概念**：量比>12的股票在评分中被封顶处理，防止追高。

每日统计被量比>12过滤后次日仍然大涨的股票：
- 若此类股票频繁涨停 → 封顶阈值可能过严，需上调至15或20
- 判定标准：量比>12封顶的股票中，后续5日跌幅>3%的比例应 ≥ 70%
- 若连续3天该比例 < 70% → 上调封顶阈值

## 4.3 分市场阶段分析

在评估报告中按市场阶段（牛/震荡/熊）拆分统计胜率：

| 市场阶段 | 大盘状态 | 推荐只数 | 胜率 | 盈亏比 | 评分区分度 |
|:-------:|:--------|:-------:|:----:|:-----:|:---------:|
| 牛市 | MA5>MA20>MA60 | — | — | — | — |
| 震荡 | 均线交织 | — | — | — | — |
| 熊市 | MA5<MA20<MA60 | — | — | — | — |

**用途**：识别评分体系在不同市场环境下的表现差异，为白皮书第七章「市场情绪自适应」提供数据支撑。

## 4.4 对照组评估（新增于v1.2）

> **核心问题**：当前评估只验证「推荐了的股票」表现，但缺少关键对照——「没推荐的股票」是不是真的更差？如果否决池的胜率和推荐池差不多，说明否决规则在误杀；如果推荐池的胜率和全市场随机选股差不多，说明评分体系没有区分度。

### 4.4.1 三组对照结构

每日评估同时计算三个组的表现：

| 分组 | 定义 | 期望胜率 | 说明 |
|:----|:-----|:--------:|:------|
| **推荐池** | 评分通过 + 无否决 + 被选中推荐的标的 | ≥60% | 我们的目标 |
| **被否决池** | 评分达标但触发否决条件被剔除的标的 | ≤40% | 否决应该选出更差的 |
| **全市场基准** | 当日所有可交易A股的平均涨跌幅（等权） | ≈50% | 随机水平 |

### 4.4.2 关键判定指标

```
否决有效度 = 推荐池胜率 - 被否决池胜率（目标 ≥ 20%）
评分区分度 = 推荐池胜率 - 全市场胜率（目标 ≥ 10%）
否决误杀率 = 被否决池中次日涨>5%的比例（目标 ≤ 15%）
```

| 指标 | 公式 | 目标 | 预警值 |
|:----|:----|:----:|:------:|
| 否决有效度 | 推荐胜率 - 否决池胜率 | ≥20% | <10%连续5日 |
| 评分区分度 | 推荐胜率 - 全市场胜率 | ≥10% | <5%连续5日 |
| 否决误杀率 | 否决池涨>5%占比 | ≤15% | >15%连续3日 |

### 4.4.3 诊断规则

**否决规则过严**（否决有效度<10%）：
- 被否决池胜率接近推荐池 → 部分否决条件无效，在误杀好股
- 操作：逐条审查否决条件，暂停区分度最低的1-2条

**评分体系失效**（评分区分度<5%）：
- 推荐池表现接近随机水平 → 评分维度没有预测力
- 操作：全面审查六维评分的相关系数，触发维度重构

**否决池跑赢推荐池**（否决有效度为负值）：
- 被否掉的股票比推荐的表现更好 → 否决条件完全反向
- 操作：立即暂停所有否决条件，逐一回测后恢复

### 4.4.4 数据存储

在 `summary.csv` 中新增字段：

| 字段 | 说明 |
|:-----|:------|
| recommended_win_rate | 推荐池胜率 |
| vetoed_win_rate | 被否决池胜率 |
| market_win_rate | 全市场基准胜率（沪深300替代） |
| veto_effectiveness | 否决有效度（推荐-否决） |
| score_distinction | 评分区分度（推荐-市场） |

## 5.3 版本升级决策树

### 5.3.1 参数微调（不升版本号）

可自动执行，无需人工确认的条件：
- 单个阈值调整幅度 ≤ 10%
- 仅涉及数值变更，不改变评分逻辑结构
- 调整依据来自连续5日以上的评估数据

**示例**：PE否决阈值从80上调至85、ATR止损倍数从2.0调整为2.2

### 5.3.2 次版本升级（v1.0 → v1.1）

需生成修订草案，AI提出建议，人工确认后执行：
- 新增或删除评分子项
- 维度权重调整（单个维度±5%以上）
- 否决条件增删
- 市场阶段参数整体切换

**触发条件**：
- 某维度误判率超20%连续5日
- 评分区分度（高分vs低分胜率差）<10%连续5日
- 整体胜率<50%连续一周

### 5.3.3 主版本升级（v1.x → v2.0）

必须人工审核，全面重构：
- 评分框架结构性调整（维度增减/权重重组）
- 股票池体系规则变更
- 新增/废除核心机制（如否决制重构）
- 市场自适应逻辑重新设计

**触发条件**：
- 月度胜率<45%
- 多维度同时失效（≥2个维度误判率>20%）
- 市场结构发生根本性变化（如T+0、涨跌幅限制变化）

## 5.4 灰度测试规则

对评估发现的问题，新规则上线前需经过灰度测试：

| 阶段 | 持续时间 | 操作 | 切换条件 |
|:----|:-------:|:----|:---------|
| 并行运行 | 5个交易日 | 新旧规则同时评分，旧规则产出推荐，新规则记录但不执行 | — |
| 数据对比 | 第6日 | 对比新旧规则在5日内的推荐胜率 | 新规则胜率≥旧规则+5% |
| 正式切换 | 对比通过次日 | 旧规则下线，新规则上线 | 人工确认 |
| 跟踪确认 | 切换后10个交易日 | 监控新规则胜率 | 胜率无明显下降 |

## 5.5 自动化回测引擎（新增于v1.2）

> **核心问题**：每次参数修改都是基于「当前数据」做的判断，但改完的参数真的是最优吗？自动化回测引擎允许我们用历史数据模拟「如果当时用了新参数，结果会怎样」——让每次参数修改都经过历史验证。

### 5.5.1 回测架构

```
┌───────────────────────────────────────────────────────────────┐
│                     回测请求                                   │
│  "如果PE阈值从80调到100，过去30日会怎样？"                     │
└───────────────────────────┬───────────────────────────────────┘
                            │
                            ▼
┌───────────────────────────────────────────────────────────────┐
│  Step 1 — 加载历史数据                                        │
│  ├─ records.csv 中最近30/60/90日的推荐记录                     │
│  └─ 对应的评分明细、否决记录、次日行情                          │
└───────────────────────────┬───────────────────────────────────┘
                            │
                            ▼
┌───────────────────────────────────────────────────────────────┐
│  Step 2 — 模拟新参数                                          │
│  ├─ 使用新参数重新计算评分（对历史数据重新打分）                │
│  ├─ 使用新参数重新执行否决规则                                 │
│  └─ 使用新参数重新生成推荐列表                                 │
└───────────────────────────┬───────────────────────────────────┘
                            │
                            ▼
┌───────────────────────────────────────────────────────────────┐
│  Step 3 — 对比结果                                            │
│  ├─ 旧参数推荐池  vs  新参数推荐池                             │
│  ├─ 胜率、盈亏比、最大回撤对比                                 │
│  └─ 新参数胜率 ≥ 旧参数胜率 + 3% → 建议采纳                    │
└───────────────────────────┬───────────────────────────────────┘
                            │
                            ▼
┌───────────────────────────────────────────────────────────────┐
│  Step 4 — 输出回测报告                                        │
│  ├─ 新旧参数各项指标对比表                                    │
│  ├─ 逐日对比收益曲线（可选）                                  │
│  └─ 建议：采纳 / 不采纳 / 需更多数据                          │
└───────────────────────────────────────────────────────────────┘
```

### 5.5.2 可回测的参数列表

并非所有参数都适合回测，只有「评分计算规则」类的参数可回测，「数据源选择」类参数不可回测。

| 参数 | 回测方法 | 历史数据需求 |
|:-----|:---------|:-----------|
| PE否决阈值（科技80/消费50/金融15） | 调整阈值后重新筛选否决池，计算否决有效度 | 各行业PE值历史记录 |
| 涨幅否决阈值（牛市80%/震荡50%/熊市30%） | 调整阈值后重新筛选否决池，计算误杀率 | 评分+涨幅历史 |
| ATR止损倍数（牛2.5/震荡2.0/熊1.5） | 调整倍数后重新模拟止损触发 | ATR历史值 |
| 量比封顶阈值（当前12） | 调高后重新计算封顶股票的后续表现 | 量比+5日涨跌幅 |
| 均线收敛间距（当前<1%） | 调整间距后重新判断收敛信号准确率 | 均线数据+后续方向 |
| 连续流入天数（当前3日/5日） | 调整天数后重新计算资金面评分胜率 | 资金流向数据 |
| 子类型信号权重（当前均为100%） | 调整权重后重新计算综合评分的区分度 | 各子类型信号触发记录 |

### 5.5.3 回测触发条件

回测分为「主动触发」和「自动触发」两种：

**主动触发**（人工发起）：
- 准备修改某个参数前，先回测3个候选值，选最优
- 参数修改灰度通过后，回测确认是否真的优于旧参数

**自动触发**（系统在以下条件满足时后台运行回测）：
- 某维度误判率超20%连续3日 → 自动回测该维度各子信号的权重调整方案
- 否决有效度<10%连续3日 → 自动回测各否决条件的阈值调整方案
- 子类型命中率>30% → 自动回测剔除该信号后的评分效果
- 每月1日 → 全参数回测扫描（对所有可调参数执行一轮回测，找出当月最优组合）

### 5.5.4 回测记录与版本关联

每次回测生成一条记录，存储在 `backtest_log.csv`：

| 字段 | 说明 |
|:-----|:------|
| bt_id | 回测编号 |
| bt_date | 回测执行日期 |
| parameter | 回测参数名称 |
| old_value | 当前值 |
| candidate_values | 候选值列表（可多个） |
| best_value | 回测出的最优值 |
| data_range | 历史数据范围（如30日/60日/90日） |
| new_win_rate | 最优值回测胜率 |
| old_win_rate | 当前值回测胜率 |
| improvement | 提升幅度 |
| status | 待确认/已采纳/已拒绝 |
| adopted_date | 采纳日期 |

**核心原则**：每次正式参数修改前，必须有对应的回测记录证明新参数更优。没有回测数据的参数变更不被允许。

# 第七章 优化决策流程

## 7.1 触发条件

| 触发条件 | 判定标准 | 响应动作 |
|:---------|:--------|:---------|
| 胜率警告 | 连续2周胜率<40% | 暂停策略，全面排查 |
| 回撤警告 | 单周组合收益<-10% | 暂停策略，全面排查 |
| 维度失效 | 某维度误判率>20%连续3天 | 触发维度重构流程 |
| 豁免失效 | 豁免组连续3天低于非豁免组10% | 暂停豁免功能 |
| 否决过严 | 否决误杀率>15%连续3天 | 放宽相应阈值 |
| 否决有效度低 | 有效期<10%连续5日 | 逐条审查否决条件，暂停区分度最低的1-2条 |
| 评分区分度低 | 区分度<5%连续5日 | 全面审查六维评分相关系数，触发维度重构 |
| 参数漂移 | 相关系数<0.1 | 该维度权重下调 |
| 子类型命中率偏高 | 某子类型命中率>20%连续5日 | 信号降权50%；>30%立即暂停 |
| 子类型命中率失效 | 某子类型命中率>30% | 立即暂停该信号，从评分逻辑中剔除 |
| 月度体检 | 月度胜率<50% | 全面审视，季度大迭代 |
| 季度体检 | 每季度末 | 全面复盘+主版本评估 |
| **全参数回测扫描** | **每月1日** | **对所有可调参数执行一轮自动化回测，生成当月最优参数建议** |
| **否决池跑赢推荐池** | **否决有效度为负值** | **立即暂停所有否决条件，逐一回测后恢复** |

## 7.2 「假设-验证-切换」流程

**Step 1 — 假设**：基于评估数据提出具体假设
- 数据来源：维度误判率、相关系数、否决误杀率
- 示例："假设PE否决阈值对于科技股过严，导致误杀率>5%"

**Step 2 — 回测**：用历史数据验证假设
- 回测范围：至少10个交易日的历史记录
- 判定标准：新阈值能降低误杀率至少50%且不提高亏损率
- 示例："将PE阈值从80上调至100，回测过去10日误杀率降低60%"

**Step 3 — 灰度**：新旧规则并行1周对比
- 详见5.4节灰度测试规则
- 判定标准：新规则胜率≥旧规则+5%

**Step 4 — 切换**：胜率提升≥5%且盈亏比不降 → 正式切换
- 更新逻辑白皮书参数附表
- 更新CHANGELOG

**Step 5 — 跟踪**：切换后跟踪2周确认效果
- 核心指标：胜率、盈亏比、维度误判率
- 异常回滚：新规则胜率低于旧规则 → 回退参数+重新分析

## 7.3 问题跟踪闭环

所有发现的问题录入 `issues.csv`，按以下状态流转：

```
发现 → 记录 → 分析 → 方案 → 灰度 → 修复 → 验证 → 关闭
                                                        │
                                                        ▼
                                                  回到「发现」（若验证不通过）
```

| 状态 | 说明 | 责任人 |
|:----|:------|:------|
| 待确认 | 问题已记录，待人工确认 | AI发现→人工确认 |
| 灰度中 | 修复方案正在并行测试 | AI执行 |
| 已修复 | 灰度通过，正式切换 | AI执行 |
| 已关闭 | 验证通过，问题解决 | 人工确认 |
