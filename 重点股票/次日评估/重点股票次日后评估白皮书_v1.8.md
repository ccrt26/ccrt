# 一、评估体系概述

## 1.1 目的与范围

**目的：** 对重点股票分析框架进行系统性复盘，评估六维评分模型、各子指标信号、阈值设定的有效性，持续改进分析逻辑。**核心问题不是"这只股票预测对了吗"，而是"我们的分析方法有效吗"。**

**核心问题：**
1. 六维评分框架是否有效？哪些维度有真正的预测能力？
2. 每个子指标（MA排列、MACD、RSI、ROE等）的信号准确率如何？
3. 评分阈值（优秀/良好/一般/差）是否合理？能否区分好坏？
4. 分析框架是否自洽？评分与结论是否一致？
5. 随着时间推移，我们的分析是否在进步？

**范围：**
- 评估对象：分析框架的各个维度、指标、阈值
- 评估频率：每个交易日盘后执行（累积数据）
- 评估数量：全部在库重点股票每次分析的数据点

## 1.2 评估流程

```
日报Markdown解析(§3.7) → 提取信号→JSON → 采集当日行情 → 读取历史评估数据 → 
各维度相关性分析 → 各指标信号胜率计算 → 日报专项评估(§2.5) →
阈值有效性检验 → 趋势分析 → 生成逻辑诊断报告 → 更新知识积累 → 产出优化建议
↓
**前置检查：评分方向校准（§1.3）**
↓
**微循环（每次）：元评估数据采集 + 自动信号发现**
↓（每20次触发）
**中循环：评估系统自检 + 信号组合发现(§7.8) + 实验提案(§7.9) + 失效归因(§7.6) + 知识遗忘(§7.7.1)**
↓（每40次触发）
**大循环：知识蒸馏(§7.7.2) + 反刍验证(§7.7.3) + 外部知识融合**
↓（月度触发）
**月度全量：三级学术/独立研究/卖方搜索 + 方法论对比**
```

1. **日报解析**：从各股票日报Markdown提取结构化信号数据，按§3.7规范写入 `评估数据_YYYYMMDD.json`（v1.8新增）
2. **前置检查**：评分方向校准 — 综合评分与多窗口收益的Spearman ρ方向检查（§1.3）
3. **采集数据**：当日行情 + 历史评估数据（跨期累积）
4. **维度有效性分析**：每个评分维度与T+1/T+5收益的相关性（日报以T+1为主窗口，§2.1.5）
5. **指标有效性分析**：每个子指标的信号准确率（T+1为主，T+5待日报补充后启用）
6. **日报专项评估**：情景应对准确率/核心矛盾验证率/风控判断准确率（§2.5，v1.8新增）
7. **阈值有效性分析**：评分分段的区分度
8. **趋势分析**：随时间的准确率变化
9. **生成逻辑诊断报告**
10. **更新知识积累文件**
11. **产出优化建议**（如需触发）
12. **中循环触发**（每20次）— 评估系统自检(权重/信号/阈值) + 条件规则学习(§7.8) + 实验提案检查(§7.9) + 失效归因(§7.6) + 知识遗忘(§7.7.1)
13. **大循环触发**（每40次）— 知识蒸馏(§7.7.2) + 反刍验证(§7.7.3) + 外部知识融合
14. **月度全量触发**（每月）— 三级学术/独立研究/卖方搜索、方法论对比改进

## 1.3 评分方向校准

> **背景**：首次后评估实战(v1.4)发现综合评分与次日收益的Spearman ρ = -0.436，即评分越高的股票次日反而表现越差。这迫使后评估体系本身在每次评估前先验证评分的"方向"是否正确。

### 1.3.1 校准流程

每次后评估正式开始前，必须先执行评分方向校准：

1. 计算综合评分与**各窗口收益**（T+1/T+3/T+5/T+10）的 Spearman ρ
2. 以 T+5 窗口为主要判定基准（中期框架以中期窗口为核心）

| ρ方向 | T+5判定 | 动作 |
|:-----:|:------:|:-----|
| ρ > 0 | 正向 | 正常评估，结论可信度维持原档 |
| ρ ≈ 0 (|ρ|<0.05) | 无效 | 标记"评分无方向性"，本次各维度有效性结论降一档置信度 |
| ρ < 0 | 反向 | 标记"评分方向异常"，本次所有维度有效性结论降一档置信度；所有"有效"信号标记为"需谨慎解释" |

### 1.3.2 方向异常升级机制

| 条件 | 动作 |
|:-----|:-----|
| 单次 ρ < 0 | 降置信度一档，评估报告加"评分方向异常"标注 |
| 连续2次 ρ < 0 | 降置信度两档，触发§6.6双白皮书联动（审查每日荐股评分权重） |
| 连续3次 ρ < 0 | 触发"评分体系方向审查"——全面审视综合评分公式、各维度权重、评分算法，生成系统性优化方案 |

### 1.3.3 校准记录

每次校准结果写入评估报告的"评分方向校准"章节，记录：
- 各窗口 Spearman ρ 值
- 方向判定（正向/无效/反向）
- 置信度调整情况
- 连续反向计数

# 二、评估维度

## 2.1 维度有效性 (30分)

核心问题：**六维评分框架的每个维度是否真的有预测能力？**

### 2.1.1 相关性分析 (15分)

> **v1.5 变更**：Pearson r → Spearman ρ（秩相关系数）。理由：股票收益非正态分布、评分也未必正态，Spearman ρ 对异常值和分布假设更稳健。

对每个维度，分别计算评分与各窗口收益的 **Spearman 秩相关系数 ρ**：

| 窗口 | 含义 | 说明 |
|:---:|:-----|:-----|
| T+1 | 次日收益 | 短期反应 |
| T+3 | 3日累计收益 | 短期趋势 |
| T+5 | 5日累计收益 | 中期趋势（主窗口） |
| T+10 | 10日累计收益 | 中期确认 |

以 **T+5 为主窗口**判定，T+1/T+3/T+10 为辅助参考：

| ρ值范围 (T+5) | 判断 | 得分 |
|:------------:|:----|:----:|
| ρ ≥ 0.3 | 强相关，维度有效 | 15分 |
| 0.15 ≤ ρ < 0.3 | 弱相关，维度有参考价值 | 8分 |
| 0 ≤ ρ < 0.15 | 几乎不相关，需审视 | 3分 |
| ρ < 0 | 负相关，维度反向指引 | 0分 |

**输出格式：** 每次评估报告维度相关性汇总表，含各窗口ρ值：

```
维度,ρ(T+1),ρ(T+3),ρ(T+5),ρ(T+10),主窗口判定,得分
技术面,0.08,0.15,0.22,0.18,弱相关(参考),8
基本面,-0.05,0.02,0.10,0.12,几乎不相关,3
...
```

### 2.1.2 区分度分析 (15分)

对每个维度，将样本按评分分为**高分组(≥60)**和**低分组(<40)**，比较两组各窗口平均收益：

| 窗口 | 高分-低分收益差 | 判断 | 得分 |
|:---:|:--------------:|:----|:----:|
| T+5 | 差异 ≥ 1% | 有效区分 | 15分 |
| T+5 | 0.5% ≤ 差异 < 1% | 部分区分 | 8分 |
| T+5 | 差异 < 0.5% | 无法区分 | 3分 |
| T+5 | 高分收益 < 低分收益 | 反向区分 | 0分 |

辅助窗口（T+1/T+3/T+10）的区分度作为参考列示，不单独计分。

**输出格式：**

```
维度,高分收益(T+5),低分收益(T+5),差异(T+5),T+1差异,T+3差异,T+10差异,判定,得分
技术面,1.8%,0.5%,1.3%,0.4%,0.9%,1.1%,有效区分,15
...
```

### 2.1.3 维度有效性跟踪

每次评估后更新维度有效性跟踪表：

```
维度,ρ(T+1),ρ(T+3),ρ(T+5),ρ(T+10),区分度(T+5),样本数,有效性评级
技术面,0.08,0.15,0.25,0.18,1.2%,30,有效
基本面,-0.05,0.02,0.10,0.12,0.5%,30,参考
...

综合评级：有效(ρ_T+5≥0.2) / 参考(ρ_T+5≥0.1) / 无效(ρ_T+5<0.1)
```

### 2.1.4 IC/ICIR 评估 (新增)

> **v1.5 新增**：在 Spearman ρ 单次评估基础上，引入时间序列 IC/ICIR 框架，评估维度预测能力的**稳定性**。

**定义：**
- **Rank IC** = Spearman_corr(维度评分, 未来收益) — 即 §2.1.1 的 Spearman ρ
- **ICIR** = mean(Rank IC) / std(Rank IC) — 信息系数的信息比率，衡量预测稳定性
- 计算窗口：滚动最近 20 次评估的 IC 序列

| ICIR 范围 | 判断 | 含义 |
|:---------|:----|:-----|
| ICIR ≥ 1.0 | 优秀 | 维度预测能力稳定可靠 |
| 0.5 ≤ ICIR < 1.0 | 可接受 | 有一定预测能力但波动较大 |
| 0.2 ≤ ICIR < 0.5 | 边缘 | 预测能力不稳定，需监控 |
| ICIR < 0.2 | 不可靠 | 该维度不具备稳定的预测能力 |

**输出格式：** 每次评估后更新 IC/ICIR 跟踪表：

```
维度,mean(IC),std(IC),ICIR,滚动周期,判定
技术面,0.18,0.12,1.50,20期,优秀
基本面,0.08,0.10,0.80,20期,可接受
资金面,0.05,0.15,0.33,20期,边缘
...
```

> **注意**：IC/ICIR 需要至少 20 次评估的滚动数据才能计算。初期仅计算单次 Rank IC，待累积足够数据后再启用 ICIR 判定。

### 2.1.5 日报评估的双窗口框架

> **v1.8 新增**：日报4段式格式当前仅覆盖T+1"明日情景应对"，而白皮书以T+5为主窗口。本节定义日报评估的双窗口规则。

**问题**：后评估白皮书§2.1.1-§2.1.4以T+5为主窗口（权重40%），但日报第四章仅输出T+1的"明日情景应对"——T+3/T+5/T+10预判数据缺失，导致后评估主窗口无法计算Spearman ρ。

**解决方案——双窗口并行：**

| 窗口 | 数据来源 | 用途 | 启用条件 |
|:---:|:--------|:-----|:--------|
| **T+1（日报主窗口）** | 日报第四章"明日情景应对" | 日常评估：情景准确率、方向判断 | 立即启用 |

**期望收益分析（T+5窗口为主）：**

信号的有效性不仅看胜率，还要看盈亏比：

```
E[r] = 胜率 × 平均正收益 + (1-胜率) × 平均负收益
```

信号判定矩阵（T+5窗口）：

| 胜率 | E[r] | 判定 |
|:---:|:----:|:----:|
| ≥ 60% | > 0 | **有效** — 高胜率+正期望 |

| < 50% | > 0 | **有潜力** — 低胜率但盈亏比优秀（trend-following特征） |
| < 50% | ≤ 0 | **无效** — 胜率期望双差 |

**收益分布指标（T+5窗口）：**
- **偏度(skewness)**：正偏度表示多为正收益且尾部向上，负偏度表示多为负收益或有极端亏损
- **最大回撤(MaxDD)**：信号发出后T+5窗口内的最大峰值到谷值回撤

**输出格式：**

## 2.3 阈值有效性 (20分)

核心问题：**评分分段（优秀≥80 / 良好60-79 / 一般40-59 / 差<40）是否合理？**

### 2.3.1 分段收益分析

> **v1.5 变更**：从单一"次日"扩展为多窗口，以T+5为主窗口判定。

| 评分段 | 样本数 | T+1平均收益 | T+5平均收益 | T+10平均收益 | T+5正收益比例 | 判断 |
|:-----:|:-----:|:----------:|:----------:|:-----------:|:------------:|:----|
| ≥ 80 (优秀) | N | X% | X% | X% | Y% | 是否真优秀 |
| 60-79 (良好) | N | X% | X% | X% | Y% | 是否真良好 |
| 40-59 (一般) | N | X% | X% | X% | Y% | 是否真一般 |
| < 40 (差) | N | X% | X% | X% | Y% | 是否真差 |

**理想状态：** 评分越高，各窗口平均收益和正收益比例越高。呈现单调递减趋势。

### 2.3.2 最优阈值建议

> **v1.5 变更**：样本门槛从≥20上调至≥50，并引入交叉验证；阈值期望下调。

**触发条件：** 当累积数据≥50个样本后，自动寻找最优分段阈值。

**方法：**
1. 将数据按评分排序
2. 以10分步长搜索所有可能的分段点组合
3. 对每个组合：将数据按时间顺序分为5折，4折训练（找最优阈值）、1折验证（计算区分度）
4. 选取5折交叉验证中平均区分度最大的分段方案
5. 输出建议调整的阈值

**评分规则（基于T+5窗口，≥50样本+交叉验证后）：**

| 条件 | 得分 |
|:-----|:----:|
| 优秀段收益 > 差段收益 ≥ 1% | 20分 |
| 优秀段收益 > 差段收益 ≥ 0.5% | 12分 |

## 3.2 相关性分析

> **v1.5 变更**：Pearson r → Spearman ρ；新增零假设随机baseline。

```python
import numpy as np
from scipy.stats import spearmanr

# 对每个维度，分窗口计算Spearman秩相关系数
for each 维度:
    scores = [stock.Scores.维度 for stock in all_stocks]
    for window in [1, 3, 5, 10]:
        returns = [stock[f"T+{window}收益"] for stock in all_stocks]
        rho, p_value = spearmanr(scores, returns)
        
        # 零假设随机baseline：打乱评分后重算Spearman ρ
        shuffled_scores = np.random.permutation(scores)
        rho_baseline, _ = spearmanr(shuffled_scores, returns)
        rho_excess = rho - rho_baseline  # 实际ρ超出随机baseline的部分
    
    # 以 T+5 为主窗口判定
    if rho_T5 >= 0.3: 有效
    elif rho_T5 >= 0.15: 参考
    else: 需审视

# 报告格式：维度 | ρ(T+5) | ρ_baseline | ρ_excess | p值 | 判定
```

**零假设baseline说明：** 每次相关性分析后，打乱评分随机重算Spearman ρ作为baseline（重复1000次取均值）。报告"实际ρ vs 随机baseline ρ"的差值（ρ_excess）。若ρ_excess < 0，说明该维度的预测力甚至不如随机——这是比ρ绝对值更有力的判断依据。

## 3.6 样本外验证

> **v1.5 新增**：防止过拟合，确保信号发现和参数估计的泛化能力。

### 3.6.1 数据划分

将累积评估数据按时间顺序分为三段：

| 段 | 比例 | 用途 | 操作限制 |
|:--|:----:|:-----|:--------|
| **Training** | 60% | 信号发现、参数估计、相关性分析 | 可自由探索 |
| **Validation** | 20% | 阈值调优、信号筛选 | 仅做选择和校准 |
| **Test** | 20% | 最终评估、报告输出 | **严禁任何优化操作** |

### 3.6.2 执行规则

```
1. 所有新信号发现和维度权重探索 → 仅在 Training 集合
2. 信号筛选和阈值调优 → 在 Training+Validation 上交叉验证
3. 最终有效性结论（胜率、ICIR、阈值区分度） → 仅在 Test 集合
4. 任何在 Test 集合上表现不佳的信号不得调整参数后重新报告
```

### 3.6.3 违规检测

中循环（§7.3）将检查是否存在Test集合的数据泄漏：
- 信号发现参数是否使用了Test数据
- 阈值调优是否在Test上反复验证
- 违规将标记为"样本外验证违规"，对应结论降两档置信度

## 6.4 优化逻辑的权衡设计

自优化机制的设计需要平衡三个内在矛盾：

### 6.4.1 快速反应 vs 避免过拟合

单日涨跌受市场情绪波动影响大，不能因为某个信号一天表现差就急于调整。

**分层门槛策略：**

| 信号加权胜率<45% | 样本≥20才触发 | 约一个月数据量，筛掉日间噪音后再建议调权重 |
| 维度ρ<0.1 | 样本≥30才触发 | 约一个半月数据量，确认该维度已失效而非偶发 |
| 优秀段≤差段 | 任何样本量立即触发 | 框架级问题，不设样本门槛，当日即警示 |

直觉：P0只是"提个醒"，P1才建议"改权重"——门槛高低对应动作的严重程度。

### 6.4.2 自动化 vs 人工把控

优化流程设计为"建议→确认→执行"三段式，不让系统自行修改分析逻辑。

**原因：**
1. **后评估是质检员，不是厂长**——发现问题是它的职责，要不要改、怎么改应由人来判断。自动调权重可能陷入自我强化的循环（越调越偏但系统自己不知道）。
2. **你不知道你不知道的**——某个维度连续3期表现差可能不是权重问题，而是整个市场风格切换（如从价值驱动转向资金驱动）。这需要人的判断。

### 6.4.3 短期波动 vs 长期趋势

不关注单日胜率，而是关注**累积胜率的变化趋势**。

- 单日数据意义有限：一个信号今天30%明天70%，不能说明任何问题
- 累积胜率匀速下降才是真警报：如从60%逐期下降到45%，说明该信号正在失效
- 连续下降检测：跑赢大盘准确率连续5期下降才触发P0（约一周多，能看出方向性变化但又不至于等太久）

## 6.5 已知局限与改进方向

### 6.5.1 缺乏市场环境分类

当前系统计算维度有效性时，不分市场环境。

**问题：** 牛市里技术面可能很准，熊市里资金面可能更有效。系统目前会说"技术面ρ=0.3比资金面ρ=0.1好"，但不会区分"在上涨市场中技术面优于资金面，在下跌市场中反过来"。

**计划改进方向：** 在积累2-3个月足够数据后，引入市场状态分类（上涨/震荡/下跌），分场景计算维度有效性。这需要至少30-50个交易日的样本才能分得开。

**v1.4进展：** 首次月度外部调研发现了两条可借鉴的方法论——Stratapro的动态权重切换（按大盘状态调整评估维度权重）和华泰的路径优选模型（按场景拆分为追高/抄底/追空/逃顶四条路径）。两项方法均建议在数据积累≥20日后进入回测验证阶段。

**v1.5进展：** 新增市场环境信号S19-S22（§2.2.2），为市场环境分类提供数据基础。当S19/S20/S21的样本各≥15次后，可启动分市场环境的相关性分析和信号胜率计算。

### 6.5.2 相关性的滞后性

Spearman ρ 衡量的是秩相关性，但股市中的关系不一定是单调的（如：评分在60-80区间有效，超过80后反而无效）。

**长期方向：** 样本量充足后，可引入非线性分析方法（如分位数回归），更精细地刻画评分与收益的关系。也可使用信息系数(IC)的衰减曲线分析不同评分区间的预测力差异。

### 6.5.3 Spearman=-0.436 发现及其影响 (v1.5新增)

> **发现背景**：v1.4首次后评估实战中，综合评分与次日收益的Spearman ρ = -0.436，即综合评分越高的股票T+1表现反而越差。

**对后评估体系的影响：**
1. **方向检验前置**：每次评估前必须先检查评分与多窗口收益的Spearman ρ方向（§1.3），防止在"评分反向"状态下误读维度有效性结论
2. **多窗口必要性**：单窗口（T+1）的反向不代表T+5/T+10也反向——评分可能在超短期失效但在中期有效，必须多窗口交叉验证
3. **Pearson→Spearman转换**：Pearson r对极端值敏感，Spearman ρ在评分体系方向不稳定的场景下更稳健
4. **期望收益校验**：单看胜率可能被方向性偏差误导——需结合期望收益E[r]做综合判定

**已知解释假说（待验证）：**
- 假说A：评分体系侧重基本面（ROE/PE），而短期T+1走势由情绪/资金驱动，两者背道而驰
- 假说B：高分股前期已充分上涨（追高效应），T+1面临获利回吐压力
- 假说C：样本量不足(N<20)，ρ=-0.436可能不具统计显著性

**后续验证计划：** 当累积评估≥10次后，重新计算各窗口Spearman ρ，结合ICIR评估评分体系的长期稳定性。

## 6.7 优化建议生命周期管理

> **v1.5 新增**：防止优化建议无限累积、避免冲突、确保优先级合理。

### 6.7.1 建议优先级自动排序

每条优化建议计算综合优先级分数：

```
PriorityScore = ExpectedImprovement × (1 - ImplementationDifficulty)
```

其中：
- **ExpectedImprovement**：预估该建议采纳后对评估指标（如胜率、ICIR）的改善幅度（0~1）
- **ImplementationDifficulty**：实现难度（0~1，0=极易/1=极难）

排序规则：PriorityScore 高的优先执行。同等分数时，P0/P1/P2 标签优先。

### 6.7.2 过期建议自动归档

| 条件 | 动作 |
|:-----|:-----|
| 建议创建后10次评估周期内未被处理 | 自动标记为"已过期"，移入 `逻辑积累/归档/` |
| 关联维度已被删除或重构 | 相关建议自动标记为"已失效"并归档 |
| 建议被明确拒绝 | 标记为"已拒绝"，保留6个月备查后归档 |

归档前警告：在自动归档前1个评估周期发出提醒。

### 6.7.3 冲突建议检测

当两条建议存在逻辑冲突时自动标记：

| 冲突类型 | 示例 | 处理规则 |
|:--------|:-----|:--------|
| 方向冲突 | 建议A：提高技术面权重 / 建议B：降低技术面权重 | 标记为"待裁决"，暂停自动排序，等待人工判断 |
| 依赖冲突 | 建议A依赖建议B生效，但B已被拒绝 | 标记建议A为"依赖失效" |
| 资源冲突 | 两条建议要求修改同一评分公式的不同方向 | 合并为一条"综合调整建议" |

**检测时机：** 每次新增优化建议后自动运行冲突检测，结果写入建议的 `conflicts` 字段。

## 6.8 与重点股票跟踪分析逻辑白皮书的联动

> **v1.7 新增**：后评估发现的维度有效性/信号胜率/预判准确率/板块相位/催化剂幅度/评分分布/条件规则/亏损归因等结论，自动反馈到《重点股票跟踪分析逻辑白皮书》对应章节。v1.6 的 §6.6 仅覆盖了到每日荐股白皮书的联动，本节点对重点股票分析逻辑白皮书建立完整的 8 条桥接机制，形成"深度分析→后评估→分析逻辑优化→分析质量提升"的闭环。

### 6.8.1 联动总览

| 桥接# | 后评估数据源 | → | 分析逻辑白皮书目标章节 | 反馈内容 |
|:------|:-----------|:-:|:---------------------|:-----|
| **B1** | 维度 Spearman ρ_T+5 (§1) | → | §3.1 六维评分权重 | 权重调整建议 |
| **B2** | 信号 ICIR/胜率 (§2) | → | §1.1-1.5 各维度信号定义 | 信号阈值/参数校准 |
| **B3** | 三周期预判一致率 (§2) | → | §2.1-2.4 预判体系 | 预判权重再分配 |
| **B4** | 板块信号 S25-S30 胜率 | → | §1.4.1 板块相位条件 | 相位量化阈值校准 |
| **B5** | 催化剂落地实际幅度 | → | §1.3.1 催化剂分级 | 影响幅度再校准 |
| **B6** | 综合评分 vs 实际收益分布 | → | §3.1.1 评分阈值 | 评级区间优化 |
| **B7** | 条件规则 (§7.8) | → | §6.4 信号冲突裁决树 | 裁决规则验证/增强 |
| **B8** | 亏损归因 (§7.6) | → | §6.5 "不做"清单 | 禁止条款增补/放宽 |

### 6.8.2 桥接触发条件

#### B1：六维权重校准（后评估 §1 维度有效性 → 分析逻辑 §3.1）

| 触发条件 | 动作 | 优先级 |
|:---------|:-----|:------|
| 某维度 Spearman ρ_T+5 连续 2 次 < 0.1 | 建议该维度降权 20-30%，附 ρ 序列 + ICIR 证据 | P1 |
| 某维度 ρ_T+5 连续 3 次 < 0 | 建议该维度权重降至 ≤5% 或拆解为子维度重新评估 | P0 |
| 某维度 ρ_T+5 > 0.3 且当前权重 < 15% | 建议提高该维度权重 +5~10% | P2 |
| 所有维度 ρ_T+5 均 < 0.1 | 触发全面权重审查（整个 §3.1 重新评估） | P0 |

**安全边界（流金 设定）**：单次调整幅度 ≤ 原值 ±30%。同维度两次调整间隔 ≥ 20 个交易日。权重之和必须保持 100%，调整时从其他维度按比例增减。

#### B2：信号阈值/参数校准（后评估 §2 信号胜率 → 分析逻辑 §1.1-1.5）

| 触发条件 | 动作 | 优先级 |
|:---------|:-----|:------|
| 某信号 ICIR 连续 2 次评估下降 > 30% 且 §7.6 归因排除"环境依赖" | 审查该信号在分析逻辑中的参数/阈值设定 | P1 |
| 某信号全市场环境下 ICIR 均 < 0.2 | 建议从组合确认规则中降权或移除 | P1 |
| §7.2.2 新发现信号连续 2 次 T+5 胜率 ≥ 60% 且样本 ≥ 20 | 建议纳入分析逻辑对应维度作为辅助信号 | P2 |
| 技术指标参数（ADX 窗口/MACD 参数/RSI 阈值）后评估显示 A 股优化值偏离当前设定 | 生成参数优化建议，标注当前值 vs 建议值 vs 证据 | P2 |

**B2 典型场景**：
- ADX(14)>25 阈值——后评估发现 A 股实际最优阈值可能是 20 或 30
- RSI 超买 70/超卖 30——是否适应 A 股高波动特征
- 布林带 (20,2)——标准参数是否适用 A 股短线节奏
- MACD (10,20,8)——A 股快参数是否捕捉到足够信号

#### B3：三周期预判体系校准（后评估 §2 预判准确率 → 分析逻辑 §2.1-2.4）

| 触发条件 | 动作 | 优先级 |
|:---------|:-----|:------|
| 短期预判方向一致率（T+1/T+5）连续 3 次 < 55% | 审查 §2.1 短期预判权重分配 | P1 |
| 中期预判方向一致率（T+10）连续 3 次 < 55% | 审查 §2.2 中期预判权重分配 | P1 |
| Wyckoff 阶段判断正确率（§2.3 战略判断 vs T+20 实际走势）连续 3 次 < 50% | 审查 §1.1.2 Wyckoff 量化条件（吸筹/拉升/派发/下跌四阶段的判定参数） | P1 |
| 分市场环境的一致率差异 > 20%（如牛市 80% vs 熊市 45%） | 建议引入市场环境修正系数，不同环境下使用不同的预判权重 | P2 |

**山猫 特别说明**：三周期预判准确率必须分市场环境统计。牛市中短期预判天然偏乐观，熊市中偏悲观——不区分环境的"一致率"数据会误导权重调整方向。

#### B4：板块相位条件校准（后评估板块信号 → 分析逻辑 §1.4.1）

| 触发条件 | 动作 | 优先级 |
|:---------|:-----|:------|
| 板块启动期信号（S25-S27）加权胜率连续 2 次 < 50% | 审查 §1.4.1 启动期量化触发条件（"放量突破 20 日均线""龙头股涨幅 > 5%"）是否过于宽松或滞后 | P1 |
| 板块高潮期信号（S28-S30）加权胜率连续 2 次 < 50% | 审查高潮期触发条件（"4 周涨幅 > 15%""换手率 > 80% 分位"）是否存在滞后 | P1 |
| 板块退潮期信号的提前预警能力（是否能在板块实际下跌前 ≥ 3 日发出信号） | 若持续 < 3 日提前量，重新校准退潮期触发条件 | P2 |

#### B5：催化剂影响幅度校准（后评估消息面信号 → 分析逻辑 §1.3.1）

| 触发条件 | 动作 | 优先级 |
|:---------|:-----|:------|
| 同级别催化剂（如 S 级）实际 T+5/T+10 涨跌幅中位数偏离预期幅度 > 50% | 校准该级别的影响幅度预期值 | P1 |
| 小盘股催化剂实际影响 vs 大盘股比值偏离当前调整系数（×1.5/×2.0）> 30% | 校准 §1.3.1 小盘股调整系数 | P2 |
| 某级别催化剂连续 5 次落地后实际方向与预期方向一致率 < 60% | 审查该级别催化剂的定义标准——可能级别划分本身有问题 | P1 |

#### B6：评分阈值校准（后评估评分分布 → 分析逻辑 §3.1.1）

| 触发条件 | 动作 | 优先级 |
|:---------|:-----|:------|
| 相邻评级区间（如 ≥80 vs 65-79）的 T+5 平均收益差异不显著（Welch's t-test p > 0.05） | 建议合并或调整区间边界值 | P1 |
| 所有评级区间的 T+5 收益单调性不成立（高评级收益 < 低评级收益） | 触发全面阈值重校准 | P0 |
| 某评级区间样本量 < 10 且已累积 ≥ 60 个总样本 | 该区间阈值不可靠，建议暂不使用该区间的操作建议 | P2 |

**青山 的样本量要求**：B6 的 t-test 需要每组至少 15 个独立样本才执行。总样本量 < 50 时，仅输出描述性统计，不做推断性检验。

#### B7：信号冲突裁决树验证（后评估 §7.8 条件规则 → 分析逻辑 §6.4）

| 触发条件 | 动作 | 优先级 |
|:---------|:-----|:------|
| §7.8 发现的确认组合规则（状态="确认"） | 建议将规则写入 §6.4 裁决树作为新的裁决分支 | P2 |
| 某条现有裁决规则在历史数据中的正确率 < 50%（回溯验证） | 标记该裁决规则为"需复审" | P1 |
| 后评估发现裁决树未覆盖的常见冲突场景（出现频率 > 10%） | 建议新增裁决分支 | P1 |

#### B8："不做"清单增补（后评估亏损归因 → 分析逻辑 §6.5）

| 触发条件 | 动作 | 优先级 |
|:---------|:-----|:------|
| 后评估发现某类场景的亏损占比 > 30% 且该场景不在当前"不做"清单中 | 建议新增禁止条款 | P0 |
| 某条现有禁止条款所涉场景的亏损占比 < 5%（连续 40 次评估） | 建议降低该条款级别（绝对禁止→有条件禁止）或移除 | P2 |
| 某禁止条款被触发频率 > 20% 且触发后胜率仅 48-52%（接近随机） | 该条款可能过于宽泛，建议细化触发条件 | P2 |

# 七、自我进化机制

> **核心理念：** 后评估系统本身也需要不断进化。如果评估方法停滞不前，它就无法持续有效地指导分析框架的改进。
> **四层能力增长模型：** 微循环（每次）→ 中循环（每20次）→ 大循环（每40次）→ 月度全量（每月）。从"量的积累"到"质的理解"——从"这个信号好不好"到"这个信号在什么条件下好、为什么好、什么时候会变坏"。

## 7.1 四层能力增长模型

```
微循环（每次评估）
  → 数据采集 + 多窗口评估 + 元评估 + 自动信号发现
      ↓（每20次触发）
中循环（每20次）
  → 评估系统自检 + 信号组合发现(§7.8) + 实验提案检查(§7.9)
  → 失效归因(§7.6) + 知识遗忘(§7.7.1)
      ↓（每40次触发）
大循环（每40次）
  → 外部知识融合 + 知识蒸馏(§7.7.2) + 反刍验证(§7.7.3)
      ↓（月度触发）
月度全量（每月）
  → 学术搜索(ArXiv/SSRN) + 独立研究 + 卖方报告 → 对比当前系统 → 生成融合建议 → 更新方法论
```

| 层级 | 周期 | 做什么 | 产出物 | 新增能力(v1.6) |
|:----|:----|:-------|:-------|:------|
| 微循环 | 每次评估 | 评分方向校准、记录评估系统自身表现、扫描发现新信号 | 方向校准记录、元评估跟踪CSV、候选信号列表 | —（基础层） |
| 中循环 | 每20次评估 | 评估系统自检（权重/信号/阈值）+ 信号组合发现 + 实验提案检查 + 失效归因 + 知识遗忘 | 评估系统自检报告、组合规则库、实验提案、归因记录 | 失效归因(§7.6)、知识遗忘(§7.7.1)、条件规则学习(§7.8)、主动实验提案(§7.9) |
| 大循环 | 每40次评估 | 全量知识蒸馏 + 反刍验证 + 外部知识融合 | 稳健知识库、反刍验证报告、外部知识调研日志 | 知识蒸馏(§7.7.2)、反刍验证(§7.7.3) |
| 月度全量 | 每月 | 三级学术/独立研究/卖方搜索、方法论对比融合 | 方法论改进建议、融合建议 | —（延续v1.5大循环） |

**边界约定：** 四个层级都只产出"建议"，不做自动修改。元评估不自循环（不评估"元评估做得好不好"）——那会无限嵌套。

**实施时序：**
- **近期实施（立即启用）：** 失效归因(§7.6) + 知识代谢(§7.7)。仅需现有累积数据即可运行，无需额外数据积累。
- **中期实施（数据≥60日后启用）：** 条件规则学习(§7.8) + 主动实验提案(§7.9)。需要足够的样本量支撑组合规则发现和实验效果评估，避免小样本过拟合。

## 7.2 微循环：每日元评估与信号发现

在每日评估流程末尾自动执行。

### 7.2.1 元评估数据采集

每次评估后，记录以下元数据到 `逻辑积累\元评估\评估系统有效性跟踪.csv`：

- 本次评估日期
- 累积样本总数
- 四个维度各自得分（维度有效性/指标有效性/阈值有效性/框架一致性）
- 综合评分
- 当日优化建议数量
- 置信度标记（样本<20标记为"低置信度评估"）
- **v1.5新增：** 评分方向校准结果（各窗口Spearman ρ、方向判定、置信度调整）
- **v1.5新增：** 优化建议采纳率（本期被采纳的建议数/本期建议总数）
- **v1.5新增：** 建议采纳后对应指标的改善幅度（如"技术面ρ_T+5从0.12→0.22"）
- **v1.5新增：** 评估结论与实际结果的偏差（如判定"技术面有效ρ=0.3"，但后续10期实际ρ=0.08，记录为"误报"）
- **v1.5新增：** 误报率（"有效/参考"判定中实际ρ<0.1的比例）

**目的：** 长期跟踪评估系统自身的表现——哪些评估维度有区分度、评估分数是否稳定、评估系统是否在进步、建议采纳后是否真有改善。

### 7.2.2 自动信号发现

> **v1.5 变更**：样本门槛上调、新增多重检验校正。

每次评估后，扫描累积数据中 `Signals` 字段的**所有取值组合**，计算每个信号值的胜率（以T+5窗口为主）：

```
对每个 Signals 字段（如 Bollinger_Position）:
  对字段的每个取值（如 "中轨上方"、"中轨下方"、"触及上轨"、"触及下轨"）:
    如果出现次数 ≥ 8:
      计算该取值的多窗口胜率（T+1/T+5/T+10）
      如果 T+5 胜率 ≥ 60% 且当前跟踪列表未包含:
        加入候选信号列表
      如果该值在当前跟踪列表中但加权胜率 < 40% 且样本 ≥ 20:
        加入淘汰候选列表
```

**多重检验校正（v1.5新增）：**

当同时检验 N 个候选信号时，必须进行多重检验校正，防止"数据挖掘偏差"：

1. **Bonferroni校正**：将显著性水平调整为 α/N（如检验20个信号，α=0.05/20=0.0025）
   - 候选信号的 p 值必须 < α/N 才被视为统计显著
2. **Benjamini-Hochberg (BH) 校正**：控制 False Discovery Rate (FDR) 在 5%
   - 将所有 p 值排序，找到最大的 k 满足 p_k ≤ (k/N) × 0.05
   - 排名 1~k 的信号视为显著
3. **双重过滤**：仅同时通过 Bonferroni 和 BH 校正的信号进入候选列表
4. **偏度/期望收益附加条件**：通过统计显著性检验的信号还需满足 E[r] > 0（T+5窗口），否则标记为"显著但负期望"

**目的：** 自动发现"我们没意识到但实际有效的信号"，以及识别"我们已经不跟踪但一直在浪费注意力的信号"，同时通过多重检验校正避免过度发现虚假信号。

## 7.3 中循环：评估系统自检

> **v1.5 变更**：触发周期从每5次调整为每20次评估。

每20次评估后触发，通过 `run_meta_evaluation.ps1` 执行。

### 7.3.1 评估维度权重优化

当前四个评估维度权重为 **维度有效性30/指标有效性30/阈值有效性20/框架一致性20**。

**检查逻辑：** 分析每个维度在历次评估中的**得分方差**。
- 如果某个维度每次都得满分（如阈值有效性总是20/20），说明它没有区分度——要么阈值设定太宽松，要么该维度权重应降低
- 如果某个维度得分波动大且波动方向与后续分析改进效果相关，说明该维度有信息量——权重应提高或维持

**触发条件：** 累积评估 ≥ 20次后开始分析，输出权重调整建议。

### 7.3.2 评估阈值校验

当前评估系统的评分标准（如维度有效性中 ρ_T+5≥0.3=15分）的合理性检验。

**检查逻辑：** 当累积样本足够多（≥50个样本点）时，检查 ρ 值的实际分布：
- 如果大多数 ρ 值都在 0.3 以上，说明阈值太容易达到，应提高
- 如果大多数 ρ 值都在 0.1 以下，说明阈值太严格，应降低
- 输出建议调整或确认当前阈值合理

### 7.3.3 信号列表动态管理

**淘汰机制：** 对跟踪信号列表中加权胜率长期在40%-60%区间徘徊且样本≥30的信号，建议从跟踪列表移除（该信号不具备预测价值）。

**新增机制：** 从候选信号列表中选取加权胜率≥60%且样本≥20的信号，通过Bonferroni+BH多重检验校正后，建议加入跟踪列表。

**输出：** 信号列表增删建议，待人工确认后执行。

## 7.6 失效归因 — 信号表现下降时的根因诊断（第一层·近期实施）

> **定位：** 当信号或维度表现下降时，不直接建议调权重，先跑归因诊断。从"信号变差了"到"信号为什么变差、在什么条件下变差"。

### 7.6.1 三维归因框架

| 归因维度 | 诊断方法 | 数据来源 |
|:-----|:-----|:-----|
| **市场环境变化** | 对比该信号在牛/熊/震荡市中的分场景加权胜率。若仅某环境下胜率下降而其他环境正常 → "环境依赖型失效" | 山猫市场状态分类（S19-S21信号数据） |
| **因子拥挤** | 对比该信号被触发频率的历史变化。若触发频率上升 + 胜率下降 → "拥挤型失效" | 流金拥挤度监控（换手率分位/成交量分位/HHI指数） |
| **结构性失效** | 排除环境+拥挤后胜率仍持续下降 → "结构性失效"。检查底层逻辑（制度变化/市场结构变化/行业政策） | 外部知识调研 + 制度追踪（大循环月度融合结果） |

### 7.6.2 归因决策树

```
信号表现下降(连续2次评估加权胜率 < baseline)
  → Step 1: 分市场环境检查胜率
    → 仅在特定环境下下降 → "环境依赖" → 不调权重，等环境回归后复检
    → 全环境下都下降 → Step 2
  → Step 2: 检查拥挤度
    → 触发频率上升 + 拥挤指标超标(换手率分位>80% 或 成交量分位>80%) → "拥挤型" → 建议降权(保留观察，定期复检)
    → 拥挤度正常 → Step 3
  → Step 3: 结构审查
    → 检查是否有制度/规则变化 → "结构性失效" → 建议移出跟踪列表
    → 无明显结构变化 → 标记"原因不明"，置信度降级，持续观察
```

### 7.6.3 归因记录

每次归因诊断结果输出到 `逻辑积累\失效归因\归因记录.csv`：

```
日期,信号ID,信号名称,baseline胜率,当前加权胜率,胜率变化,分环境判定,拥挤度判定,归因结果,处理建议,下次复检日期,状态
20260601,S01,MA多头排列,62%,48%,-14%,全环境下降,换手率分位85%触发,拥挤型失效,建议降权至原权重60%,20260615,待确认
```

**归因触发条件：**
- 信号加权胜率连续2次评估 < baseline（baseline = 该信号历史累积加权胜率）
- 维度 Spearman ρ_T+5 连续2次 < 0.1
- 手动触发：任何信号或维度被怀疑失效时

## 7.7 知识代谢机制 — 让旧知识过期、提炼稳健知识（第三层·近期实施）

> **核心理念：** 旧知识不过期会挤占新知识的关注力。不是删除旧知识，是降级。同时，经过多环境验证的稳健知识应得到保护。

### 7.7.1 遗忘曲线 — 定期清理低效信号

**触发周期：** 每20次评估（约1个月）自动执行一次。

**执行逻辑：**

```
对跟踪信号列表中的所有信号：
  if 最近60个交易日无显著表现(ICIR < 0.2):
    置信度降一级（高 → 中 → 低 → 候选观察）
    写入遗忘日志，标注降级原因
  if 最近60个交易日 ICIR < 0:
    建议从跟踪列表移至候选观察列表
    保留信号定义和历史数据，但停止在日常评估中计分
```

**保护机制：** 标记为"稳健知识"的信号（§7.7.2）不参与遗忘曲线降级处理。新发现信号（跟踪<40个交易日）也不参与遗忘，给予充分观察期。

**遗忘日志输出：** `逻辑积累\知识代谢\遗忘日志.csv`
```
日期,信号ID,信号名称,近60日ICIR,原置信度,新置信度,操作,原因
```

### 7.7.2 知识蒸馏 — 提炼稳健知识

**触发周期：** 每40次评估（大循环）执行一次。

**执行逻辑：**

```
对跟踪信号列表中的每个信号：
  if 该信号在 ≥ 3 种市场环境中都表现出正 ICIR 且 ICIR标准差 < 0.3:
    提炼为"稳健知识"
    标记为"高置信度、不易过期"
    写入 逻辑积累\知识蒸馏\稳健知识库.json
```

**稳健知识条目结构：**

```json
{
  "knowledge_id": "RK-001",
  "signal_id": "S01",
  "signal_description": "MA多头排列",
  "applicable_environments": ["牛市", "震荡市", "熊市"],
  "ICIR_mean": 0.85,
  "ICIR_range": [0.62, 1.12],
  "ICIR_std": 0.18,
  "last_validated": "2026-06-15",
  "robustness_grade": "A",
  "protected_from_decay": true
}
```

**稳健等级标准：**

| 等级 | 条件 | 含义 |
|:----:|:-----|:-----|
| **A** | ICIR≥0.8, 适用环境≥3, std<0.2 | 高度稳健，核心知识 |
| **B** | ICIR≥0.5, 适用环境≥2, std<0.3 | 较为稳健，可信依赖 |
| **C** | ICIR≥0.3, 适用环境≥2, std<0.3 | 基本稳健，参考使用 |

稳健知识不参与遗忘曲线（§7.7.1）的降级处理——已验证的核心规律应得到保护。

### 7.7.3 反刍验证 — 定期重新验证所有"有效"信号

**触发周期：** 每40次评估（大循环）触发一次全量回溯。

**执行逻辑：**

```
对跟踪列表中所有标记为"有效"的信号：
  用最近20期数据独立计算ICIR
  对比历史ICIR（信号首次被标记为"有效"时的ICIR值）：
    差异 < 20% → 确认有效，维持状态
    差异 20%-50% → 标记"需关注"，写入观察列表
    差异 > 50% → 触发失效归因分析（§7.6）
```

**反刍验证报告输出：** `逻辑积累\知识代谢\反刍验证报告_YYYYMMDD.md`
```

|:------|:--------|:--------|:-------|:-----|:--------|
| S01 | 0.85 | 0.78 | -8.2% | 确认有效 | 维持 |
```

## 7.8 条件规则学习 — 发现信号组合的增强效应（第二层·中期实施）

> **定位：** 当数据积累≥60日后启用。从"单信号好不好"升级为"信号A在信号B同时出现时好不好"。
> **触发周期：** 中循环（每20次评估）中执行。

### 7.8.1 信号对联合胜率

对高胜率信号（ICIR > 0.5），枚举所有其他信号作为条件：

```
for 信号A (ICIR > 0.5 且 样本 ≥ 20):
  for 信号B (除A外的所有信号，样本 ≥ 15):
    计算 P(A有效 | B有效) vs P(A有效)
    其中"有效"定义为该信号的加权胜率 ≥ 55%
    若条件概率提升 > 15%:
      记录为候选组合规则
```

### 7.8.2 组合规则模板

发现的规则写入 `逻辑积累\条件规则\组合规则库.json`：

```json
  "primary_signal": "S01",
  "condition_signal": "S27",
  "primary_alone_win_rate": 0.58,
  "combined_win_rate": 0.72,
```

| 约束 | 值 | 理由 |
|:-----|:---|:-----|

| 组合样本量 ≥ 15 | ≥15 | 确保统计可信度，低于15的组合不记录 |
| 不做全排列搜索 | — | 仅对 ICIR>0.5 的信号枚举条件，避免多重检验陷阱 |
| 提升幅度阈值 | ≥15% | 提升不足15%的组合不记录，减少噪音 |

### 7.8.4 组合规则的验证与升级

组合规则的状态流转：

```
候选（新发现） → 2次验证通过（连续2次中循环检查均满足条件概率提升>10%）→ 确认 → 写入稳健知识库
候选 → 验证失败（后续检查条件概率提升<5%） → 废弃
```

已确认的组合规则可被每日荐股分析框架引用，作为"增强信号"使用。

## 7.9 主动实验提案 — 自动生成灰度测试方案（第四层·中期实施）

> **定位：** 当同一优化建议反复出现时，不等人工确认，自动生成可灰度测试的实验方案。对接青山策略优化提案框架的灰度测试流程。
> **触发周期：** 中循环（每20次评估）中检查。

### 7.9.1 触发条件

同一优化建议（相同目标+相同方向）连续3次评估出现 → 自动生成实验方案。

**判定"同一建议"的规则：**
- target（目标白皮书/章节）相同
- 修改方向相同（如均为"降低技术面权重"或"提高资金面权重"）
- 方向幅度方向一致（均为降低或均为提高，不含具体幅度）

### 7.9.2 实验提案模板

```json
{
  "experiment_id": "EXP-20260615-001",
  "trigger": "技术面权重建议降低(连续3次后评估出现: 20260601/20260605/20260610)",
  "trigger_evidence": {
    "occurrence_count": 3,
    "first_date": "2026-06-01",
    "latest_date": "2026-06-10",
    "avg_priority_score": 0.72
  },
  "hypothesis": "降低技术面维度权重从25%→15%将提高综合评分与T+5收益的Spearman ρ",
  "design": {
    "target": "重点股票跟踪分析逻辑白皮书 §3.1.1 技术面评分权重",
    "change": "技术面权重 25% → 15%",
    "duration": "5个交易日",
    "metrics": ["Spearman ρ(T+5)", "评分区分度(高分组vs低分组T+5收益差)"],
    "success_criterion": "Spearman ρ(T+5) 提升≥0.05 且 区分度不下降",
    "safety_criterion": "若ρ下降>0.03或区分度转为负值，立即终止实验"
  },
  "rollback": "实验结束后自动恢复原权重配置",
  "output_channel": "青山知识库05-策略优化提案框架——灰度测试入口",
  "status": "提案_待确认",
  "created_date": "2026-06-15"
}
```

### 7.9.3 对接青山灰度测试

实验提案输出到青山策略优化提案框架的灰度测试流程（青山知识库05-策略优化提案框架），由青山评估可行性后执行。流程：

```
后评估中循环检测到连续3次相同建议
  ↓
自动生成实验提案JSON（§7.9.2模板）
  ↓
输出到 逻辑积累\实验提案\
  ↓
青山评估：样本量是否充足？变量是否可控？回测是否能验证？
  ↓
[通过] → 青山执行灰度测试（小权重/短周期）
  ↓
实验结果回传给后评估系统 → 写入元评估跟踪表 → 形成闭环
```

### 7.9.4 安全边界

| 约束 | 值 | 理由 |
|:-----|:---|:-----|
| 权重变动上限 | 不超过原值±50% | 避免单次实验造成评分体系大幅波动 |
| 一次只测一个变量 | 1个 | 多变量同时变动无法归因效果 |
| 实验周期上限 | 10个交易日 | 防止"实验状态"长期运行脱离跟踪 |
| 自动终止条件 | ρ下降>0.03或区分度转负 | 实验不能以破坏评分体系为代价 |
| 实验重叠禁止 | 同一目标上一次实验结束后≥5个交易日才能开始新实验 | 防止实验效果叠加混淆归因 |

### 7.9.5 实验提案管理

所有实验提案存储在 `逻辑积累\实验提案\` 目录下，状态流转：

```
提案（待确认） → 青山评估中 → 灰度测试中 → 实验完成 → 结果已回传
                 ↓                    ↓
               青山拒绝          自动终止(触发安全边界)
```

实验完成后，结果必须回写到元评估跟踪表（§7.2.1），标记该优化建议是否经过实验验证、实验结论是什么。

# 十、版本管理 — 通用红线规则

> ⛔ **红线**：所有分析白皮书（重点股票次日后评估、重点股票跟踪分析逻辑、每日荐股分析逻辑、次日后评估）只要有内容更新，必须执行本版本管理流程。不允许无版本号的直接修改。

## 10.1 适用范围

本规则适用于以下所有分析白皮书：

| 白皮书 | 存储路径 |
|:-------|:---------|
| 重点股票次日后评估白皮书 | 重点股票\次日评估\ |
| 重点股票跟踪分析逻辑白皮书 | 重点股票\分析逻辑\ |
| 每日荐股分析逻辑白皮书 | 每日荐股\分析逻辑\ |
| 次日后评估白皮书 | 每日荐股\事后评估\ |

## 10.2 版本号规则

格式 `v<主版本>.<次版本>`：

| 变更类型 | 版本号变化 | 举例 |
|:---------|:----------|:------|
| 主版本：评估维度重构、核心方法论变更 | v1 → v2 | 从"逐股预测准确率"重构为"分析逻辑有效性" |
| 次版本：新增/删除章节、调整阈值权重、信号列表管理 | v1.2 → v1.3 | 新增自我进化机制章节、新增版本管理章节 |

不设 patch 级别，对白皮书文档粒度够用。

## 10.3 版本载体

| 载体 | 位置 | 用途 |
|:-----|:-----|:------|
| 文档头 | `> 当前版本: vX.Y \| 最后更新: YYYY-MM-DD` | 一眼看到当前版本 |
| 版本历史表 | 本文档开头版本历史表格 | 快速回顾，保留最近 10 条 |
| CHANGELOG.md | 同目录独立文件 | 完整永久记录，每条含文件变更清单 |

## 10.4 变更流程

```
AI或人发现需要改 → 记录到改进日志.md（含证据） → 人工确认 →
[确认采纳] → 升版本号 + 更新日期 → 修改文档正文 →
更新版本历史表 → 更新CHANGELOG.md → 生成新版DOCX
```

## 10.5 归档策略

- 每个版本独立文件：`重点股票次日后评估白皮书_vX.Y.md` + `.docx`
- 旧版本保留不删（v1.1 因命名错乱已删除，属特例），历史可追溯
- CHANGELOG.md 是权威变更记录，文档内版本历史表是快速索引

## 10.6 修改权限

- **人**：任何时候可发起、审批、执行版本变更
- **AI**：只能**提议**变更（写入改进日志），经人确认后才能执行版本修改
