# 一、评估体系概述

## 1.1 目的与范围

**目的：** 对重点股票分析框架进行系统性复盘，评估六维评分模型、各子指标信号、阈值设定的有效性，持续改进分析逻辑。**核心问题不是"这只股票预测对了吗"，而是"我们的分析方法有效吗"。**

**核心问题：**
1. 六维评分框架是否有效？哪些维度有真正的预测能力？
2. 每个子指标（MA排列、MACD、RSI、ROE等）的信号准确率如何？
3. 评分阈值（优秀/良好/一般/差）是否合理？能否区分好坏？
4. 分析框架是否自洽？评分与结论是否一致？
5. 随着时间推移，我们的分析是否在进步？

**范围：**
- 评估对象：分析框架的各个维度、指标、阈值
- 评估频率：每个交易日盘后执行（累积数据）
- 评估数量：全部在库重点股票每次分析的数据点

## 1.2 评估流程

```
采集当日行情 → 读取历史评估数据 → 各维度相关性分析 → 各指标信号胜率计算 → 
阈值有效性检验 → 趋势分析 → 生成逻辑诊断报告 → 更新知识积累 → 产出优化建议
↓
**微循环（每次）：元评估数据采集 + 自动信号发现**
↓（每5次）
**中循环：评估系统自检（权重优化/信号管理/阈值校验）**
↓（每月）
**大循环：外部知识融合（Web搜索 + 方法论对比）**
```

1. **采集数据**：当日行情 + 历史评估数据（跨期累积）
2. **维度有效性分析**：每个评分维度与次日收益的相关性
3. **指标有效性分析**：每个子指标的信号准确率
4. **阈值有效性分析**：评分分段的区分度
5. **趋势分析**：随时间的准确率变化
6. **生成逻辑诊断报告**
7. **更新知识积累文件**
8. **产出优化建议**（如需触发）
9. **微循环：元评估数据采集** — 记录评估系统自身表现，写入元评估跟踪表
10. **微循环：自动信号发现** — 扫描累积数据，发现未跟踪的有效信号
11. **中循环触发**（每5次）— 评估维度权重优化、信号列表增删管理、阈值校验
12. **大循环触发**（每月）— 外部知识融合、方法论对比改进

# 二、评估维度

## 2.1 维度有效性 (30分)

核心问题：**六维评分框架的每个维度是否真的有预测能力？**

### 2.1.1 相关性分析 (15分)

对每个维度，计算评分与次日涨跌幅的**Pearson相关系数r**：

| r值范围 | 判断 | 得分 |
|:-------:|:----|:----:|
| r ≥ 0.3 | 强相关，维度有效 | 15分 |
| 0.15 ≤ r < 0.3 | 弱相关，维度有参考价值 | 8分 |
| 0 ≤ r < 0.15 | 几乎不相关，需审视 | 3分 |
| r < 0 | 负相关，维度反向指引 | 0分 |

### 2.1.2 区分度分析 (15分)

对每个维度，将样本按评分分为**高分组(≥60)**和**低分组(<40)**，比较两组次日平均收益：

| 高分-低分收益差 | 判断 | 得分 |
|:--------------:|:----|:----:|
| 差异 ≥ 1% | 有效区分 | 15分 |
| 0.5% ≤ 差异 < 1% | 部分区分 | 8分 |
| 差异 < 0.5% | 无法区分 | 3分 |
| 高分收益 < 低分收益 | 反向区分 | 0分 |

### 2.1.3 维度有效性跟踪

每次评估后更新维度有效性跟踪表：

```

技术面,0.25,1.2%,30,有效
基本面,0.18,0.8%,30,参考
...

综合评级：有效(≥0.2) / 参考(≥0.1) / 无效(<0.1)
```

## 2.3 阈值有效性 (20分)

核心问题：**评分分段（优秀≥80 / 良好60-79 / 一般40-59 / 差<40）是否合理？**

### 2.3.1 分段收益分析

| 评分段 | 样本数 | 次日平均收益 | 正收益比例 | 判断 |
|:-----:|:-----:|:----------:|:---------:|:----|
| ≥ 80 (优秀) | N | X% | Y% | 是否真优秀 |
| 60-79 (良好) | N | X% | Y% | 是否真良好 |
| 40-59 (一般) | N | X% | Y% | 是否真一般 |
| < 40 (差) | N | X% | Y% | 是否真差 |

**理想状态：** 评分越高，次日平均收益和正收益比例越高

### 2.3.2 最优阈值建议

当累积数据≥20个样本后，自动寻找最优分段阈值：
- 最大化各分段的收益差异
- 保证每个分段有足够样本
- 输出建议调整的阈值

**评分规则：**
- 优秀段收益 > 差段收益 ≥ 2% → 20分
- 优秀段收益 > 差段收益 ≥ 1% → 12分
- 优秀段收益 > 差段收益 ≥ 0% → 5分
- 优秀段收益 ≤ 差段收益 → 0分（阈值完全无效）

## 2.4 框架一致性 (20分)

核心问题：**分析框架内部是否自洽、稳定？**

### 2.4.1 评分-结论一致性 (8分)

检查综合评分文字评级与预判方向的一致性：
- 高分（≥70）应搭配"看多"或"偏多"预判
- 低分（<40）应搭配"看空"预判
- 统计不一致比例

### 2.4.2 置信度校准 (6分)

三周期预判的置信度与实际准确率是否匹配：
- "高置信度"预判的实际准确率 ≥ 70%
- "中置信度"预判的实际准确率 ≥ 50%
- 持续校准置信度表述

### 2.4.3 多期稳定性 (6分)

同一分析框架在不同日期的表现稳定性：
- 各维度评分的标准差
- 准确率的逐期波动
- 极端值出现频率

# 六、自优化机制

## 6.1 触发条件

| 条件 | 阈值 | 建议动作 |
|:----|:----|:---------|
| 某信号胜率 < 45% 且样本 ≥ 10 | 45% | 调整该信号的评分权重 |
| 某维度相关系数 r < 0.1 且样本 ≥ 15 | 0.1 | 审视该维度评分逻辑 |
| 优秀段收益 ≤ 差段收益 | 0 | 全面审视阈值设定 |
| 准确率连续 3 期下降 | 负趋势 | 方法论整体审视 |
| 累积评估 ≥ 5 次 | 5次 | 触发首次全面优化分析 |

## 6.2 优化执行流程

```
触发条件
  ↓
读取逻辑积累数据
  ↓
生成优化建议（含具体修改方案）
  ↓
人工确认 → 采纳/拒绝/修改
  ↓
[采纳] 更新重点股票跟踪分析逻辑白皮书（新版本）
  ↓
记录改进日志
  ↓
更新后评估白皮书版本
```

## 6.3 效果跟踪

每次优化执行后，持续跟踪：
- 优化前的准确率基线
- 优化后的准确率变化
- 效果评估（改善/无变化/恶化）

## 6.4 优化逻辑的权衡设计

自优化机制的设计需要平衡三个内在矛盾：

### 6.4.1 快速反应 vs 避免过拟合

单日涨跌受市场情绪波动影响大，不能因为某个信号一天表现差就急于调整。

**分层门槛策略：**

| 信号胜率<45% | 样本≥10才触发 | 约两周数据量，筛掉日间噪音后再建议调权重 |
| 维度r<0.1 | 样本≥15才触发 | 约三周数据量，确认该维度已失效而非偶发 |
| 优秀段≤差段 | 任何样本量立即触发 | 框架级问题，不设样本门槛，当日即警示 |

直觉：P0只是"提个醒"，P1才建议"改权重"——门槛高低对应动作的严重程度。

### 6.4.2 自动化 vs 人工把控

优化流程设计为"建议→确认→执行"三段式，不让系统自行修改分析逻辑。

**原因：**
1. **后评估是质检员，不是厂长**——发现问题是它的职责，要不要改、怎么改应由人来判断。自动调权重可能陷入自我强化的循环（越调越偏但系统自己不知道）。
2. **你不知道你不知道的**——某个维度连续3期表现差可能不是权重问题，而是整个市场风格切换（如从价值驱动转向资金驱动）。这需要人的判断。

### 6.4.3 短期波动 vs 长期趋势

不关注单日胜率，而是关注**累积胜率的变化趋势**。

- 单日数据意义有限：一个信号今天30%明天70%，不能说明任何问题
- 累积胜率匀速下降才是真警报：如从60%逐期下降到45%，说明该信号正在失效
- 连续下降检测：准确率连续3期下降才触发P0（约一周，能看出方向性变化但又不至于等太久）

## 6.5 已知局限与改进方向

### 6.5.1 缺乏市场环境分类

当前系统计算维度有效性时，不分市场环境。

**问题：** 牛市里技术面可能很准，熊市里资金面可能更有效。系统目前会说"技术面r=0.3比资金面r=0.1好"，但不会区分"在上涨市场中技术面优于资金面，在下跌市场中反过来"。

**计划改进方向：** 在积累2-3个月足够数据后，引入市场状态分类（上涨/震荡/下跌），分场景计算维度有效性。这需要至少30-50个交易日的样本才能分得开。

### 6.5.2 相关性的滞后性

Pearson相关系数衡量的是线性相关性，但股市中的关系不一定是线性的（如：评分在60-80区间有效，超过80后反而无效）。

**长期方向：** 样本量充足后，可引入非线性分析方法（如分位数回归），更精细地刻画评分与收益的关系。

# 七、自我进化机制

> **核心理念：** 后评估系统本身也需要不断进化。如果评估方法停滞不前，它就无法持续有效地指导分析框架的改进。
> **三条回路架构：** 微循环（每日）→ 中循环（每5次评估）→ 大循环（月度/20次评估）

## 7.1 三条进化回路

```
微循环（每日）
  评估 → 采集元评估数据 → 自动发现新信号 → 记录
      ↓（每5次触发）
中循环（每5次）
  读取元评估数据 → 分析权重合理性 → 管理信号列表 → 自检报告
      ↓（每20次或月度触发）
大循环（月度）
  Web搜索新方法 → 对比当前系统 → 生成融合建议 → 更新方法论
```

| 回路 | 周期 | 做什么 | 产出物 |
|:----|:----|:-------|:-------|
| 微循环 | 每次评估 | 记录评估系统自身表现、扫描发现新信号 | 元评估跟踪CSV、候选信号列表 |
| 中循环 | 每5次评估 | 检查评估维度权重是否合理、信号列表是否需增删 | 评估系统自检报告、权重建议 |
| 大循环 | 每月 | 搜索业界新方法、对比融合 | 外部知识调研日志、方法论改进建议 |

**边界约定：** 三条回路都只产出"建议"，不做自动修改。元评估不自循环（不评估"元评估做得好不好"）——那会无限嵌套。

## 7.2 微循环：每日元评估与信号发现

在每日评估流程末尾自动执行。

### 7.2.1 元评估数据采集

每次评估后，记录以下元数据到 `逻辑积累\元评估\评估系统有效性跟踪.csv`：

- 本次评估日期
- 累积样本总数
- 四个维度各自得分（维度有效性/指标有效性/阈值有效性/框架一致性）
- 综合评分
- 当日优化建议数量
- 置信度标记（样本<20标记为"低置信度评估"）

**目的：** 长期跟踪评估系统自身的表现——哪些评估维度有区分度、评估分数是否稳定、评估系统是否在进步。

### 7.2.2 自动信号发现

每次评估后，扫描累积数据中 `Signals` 字段的**所有取值组合**，计算每个信号值的胜率：

```
对每个 Signals 字段（如 Bollinger_Position）:
  对字段的每个取值（如 "中轨上方"、"中轨下方"、"触及上轨"、"触及下轨"）:
    如果出现次数 ≥ 3:
      计算该取值的胜率（次日正收益比例）
      如果胜率 ≥ 60% 且当前跟踪列表未包含:
        加入候选信号列表
      如果该值在当前跟踪列表中但胜率 < 40% 且样本 ≥ 10:
        加入淘汰候选列表
```

**目的：** 自动发现"我们没意识到但实际有效的信号"，以及识别"我们已经不跟踪但一直在浪费注意力的信号"。

## 7.3 中循环：评估系统自检

每5次评估后触发，通过 `run_meta_evaluation.ps1` 执行。

### 7.3.1 评估维度权重优化

当前四个评估维度权重为 **维度有效性30/指标有效性30/阈值有效性20/框架一致性20**。

**检查逻辑：** 分析每个维度在历次评估中的**得分方差**。
- 如果某个维度每次都得满分（如阈值有效性总是20/20），说明它没有区分度——要么阈值设定太宽松，要么该维度权重应降低
- 如果某个维度得分波动大且波动方向与后续分析改进效果相关，说明该维度有信息量——权重应提高或维持

**触发条件：** 累积评估 ≥ 5次后开始分析，输出权重调整建议。

### 7.3.2 评估阈值校验

当前评估系统的评分标准（如维度有效性中 r≥0.3=15分）的合理性检验。

**检查逻辑：** 当累积样本足够多（≥50个样本点）时，检查 r 值的实际分布：
- 如果大多数 r 值都在 0.3 以上，说明阈值太容易达到，应提高
- 如果大多数 r 值都在 0.1 以下，说明阈值太严格，应降低
- 输出建议调整或确认当前阈值合理

### 7.3.3 信号列表动态管理

**淘汰机制：** 对跟踪信号列表中胜率长期在40%-60%区间徘徊且样本≥20的信号，建议从跟踪列表移除（该信号不具备预测价值）。

**新增机制：** 从候选信号列表中选取胜率≥60%且样本≥10的信号，建议加入跟踪列表。

**输出：** 信号列表增删建议，待人工确认后执行。

## 7.4 大循环：月度外部知识融合

### 7.4.1 搜索策略

每月初，通过以下关键词搜索业界新方法：

```
中文搜索：
- 量化交易 因子有效性 评估方法
- A股 多因子模型 因子衰减 研究
- 技术指标 统计显著性 检验方法

英文搜索：
- quantitative analysis signal evaluation methodology
- factor decay research A-share market
- technical indicator statistical significance testing
```

### 7.4.2 融合流程

```
搜索 → 阅读 → 对比当前系统 → 生成融合建议 → 记录到外部知识调研日志
```

每种发现记录包含：
- **核心发现**：该方法解决了什么问题
- **与当前系统的差异**：我们当前用的是什么方法，业界用什么方法
- **采纳建议**：建议尝试 / 建议跟踪 / 暂不采纳

### 7.4.3 调度方式

通过定时任务每月1日触发，prompt 指定为"执行月度量化方法调研"。

## 7.5 自我进化记录

所有自我进化的相关记录存储在 `逻辑积累\元评估\` 和 `逻辑积累\信号发现\` 目录下：

| 文件 | 用途 |
|:-----|:-----|
| 逻辑积累\元评估\评估系统有效性跟踪.csv | 每次评估后记录系统自身表现 |

# 十、版本管理 — 通用红线规则

> ⛔ **红线**：所有分析白皮书（重点股票次日后评估、重点股票跟踪分析逻辑、每日荐股分析逻辑、次日后评估）只要有内容更新，必须执行本版本管理流程。不允许无版本号的直接修改。

## 10.1 适用范围

本规则适用于以下所有分析白皮书：

| 白皮书 | 存储路径 |
|:-------|:---------|
| 重点股票次日后评估白皮书 | 重点股票\次日评估\ |
| 重点股票跟踪分析逻辑白皮书 | 重点股票\分析逻辑\ |
| 每日荐股分析逻辑白皮书 | 每日荐股\分析逻辑\ |
| 次日后评估白皮书 | 每日荐股\事后评估\ |

## 10.2 版本号规则

格式 `v<主版本>.<次版本>`：

| 变更类型 | 版本号变化 | 举例 |
|:---------|:----------|:------|
| 主版本：评估维度重构、核心方法论变更 | v1 → v2 | 从"逐股预测准确率"重构为"分析逻辑有效性" |
| 次版本：新增/删除章节、调整阈值权重、信号列表管理 | v1.2 → v1.3 | 新增自我进化机制章节、新增版本管理章节 |

不设 patch 级别，对白皮书文档粒度够用。

## 10.3 版本载体

| 载体 | 位置 | 用途 |
|:-----|:-----|:------|
| 文档头 | `> 当前版本: vX.Y \| 最后更新: YYYY-MM-DD` | 一眼看到当前版本 |
| 版本历史表 | 本文档开头版本历史表格 | 快速回顾，保留最近 10 条 |
| CHANGELOG.md | 同目录独立文件 | 完整永久记录，每条含文件变更清单 |

## 10.4 变更流程

```
AI或人发现需要改 → 记录到改进日志.md（含证据） → 人工确认 →
[确认采纳] → 升版本号 + 更新日期 → 修改文档正文 →
更新版本历史表 → 更新CHANGELOG.md → 生成新版DOCX
```

## 10.5 归档策略

- 每个版本独立文件：`重点股票次日后评估白皮书_vX.Y.md` + `.docx`
- 旧版本保留不删（v1.1 因命名错乱已删除，属特例），历史可追溯
- CHANGELOG.md 是权威变更记录，文档内版本历史表是快速索引

## 10.6 修改权限

- **人**：任何时候可发起、审批、执行版本变更
- **AI**：只能**提议**变更（写入改进日志），经人确认后才能执行版本修改
