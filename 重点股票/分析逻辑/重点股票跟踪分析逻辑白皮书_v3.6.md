## 核心设计原则

1. **深度分析是地图，日报是当天路况**
   - 深度分析负责：中期判断、核心逻辑、估值框架、安全边际、关键价位、风险边界
   - 日报负责：每天检查今日数据有没有让原判断增强、减弱、失效

2. **baseline → delta → trigger 三层模型**
   - baseline：引用深度分析official baseline（不重算）
   - delta：每日增量数据（价格/量能/资金/融资/板块/公告）
   - trigger：触发检查决定action_change

3. **数据驱动，不堆砌指标**
   - 每个数据必须回答：这对明日操作意味着什么
   - 不允许"数据不可获取"掩盖已有数据

4. **口径唯一**
   - 所有支撑/压力/止损/仓位上限优先引用深度baseline
   - 修正必须说明原因并标记action_change
   - 同一报告不允许两个仓位口径或两个止损口径

# 第一章 baseline → delta → trigger 三层模型

## 1.1 模型总览

```
深度分析（baseline）          日报（delta + trigger）
┌──────────────────┐         ┌──────────────────────┐
│ 核心逻辑          │         │ 今日价格/量能          │
│ 估值判断          │ ─引用→  │ 四档资金结构           │
│ 证据等级          │         │ 融资融券变化           │
│ 关键价位(S/R)     │         │ 板块相位变化           │
│ 风险边界          │         │ 消息面事件跟踪         │
│ 仓位上限          │         │ 信号胜率验证           │
└──────────────────┘         └──────────────────────┘
                                      ↓
                             ┌──────────────────────┐
                             │ trigger 触发检查       │
                             │ → upgrade             │
                             │ → unchanged           │
                             │ → downgrade           │
                             │ → stop_watch          │
                             │ → reanalysis_required │
                             └──────────────────────┘
```

## 1.2 baseline 块

日报不做深度分析。以下内容直接从深度分析引用：

| 引用内容 | 来源 | 日报用法 |
|:-----|:-----|:-----|
| 核心逻辑 | 深度分析§结论 | P0决策卡一句话结论+§0基线段 |
| 估值判断 | 深度分析§估值 | §3基本面段（仅在有新财报时更新） |
| 证据等级 | 深度分析§基本面 | L1/L2/L3标注 |
| 关键价位 S1/S2/S3/R1/R2/R3 | 深度分析§6.1 | P0决策卡+§2.3关键价位+§5情景应对 |
| 风险边界 | 深度分析§风控 | §7风险段 |
| 仓位上限 | 深度分析§6.3 | P0决策卡当前仓位上限 |

**修正规则**：如需修正baseline（如市场结构变化导致支撑位失效），必须：
1. 标注 `override_reason`
2. 输出 `action_change`
3. 说明修正有效期
4. 修正不覆盖baseline原文，仅日报本次生效

**日报 baseline_id 权威源规则**（第1阶段生效）：

1. 日报引用 baseline 时，`baseline_id` 的**唯一权威源**是 `00_项目地基/02_权威注册表/baseline_registry.json`
2. 深度分析正文标题、深度分析附录中的旧 ID、历史日报中的 ID 均**不得**作为日报 baseline_id 的引用源
3. 日报生成前必须执行：`python3 scripts/resolve_current_baseline.py --code <代码> --name <名称> --date <日期> --json`
4. registry 与日报不一致时，日报生成**不得提交**
5. registry 中返回多条有效基线时，日报生成**不得提交**

## 1.3 delta 块

每日增量数据，只写变化的：

| 数据类 | 频率 | 日报段 | 规则 |
|:-----|:-----|:-----|:-----|
| 价格/量能/K线 | 日频 | §1+§2.1 | 近4日对比 |
| 四档资金 | T+1延迟 | §2.2 | 必须输出超大单/大单/中小单/结构判断 |
| 融资融券 | T+1延迟 | §2.2 | ⛔禁止写不可获取 |
| 北向大盘 | 日频 | §1.1 | 区分日频/季度 |
| 板块相位 | 日频 | §1.1 | 五阶段标签 |
| 消息事件 | 日频 | §2.3 | T+1/T+3/T+5跟踪 |
| 信号胜率 | 每周更新 | §2.4 | 样本数+胜率+影响 |

## 1.4 trigger 块

触发条件决定 action_change：

| 触发条件 | 结果 | 优先级 |
|:-----|:-----|:----:|
| >=2独立维度正向确认 | upgrade | P1 |
| delta与baseline一致 | unchanged | P1 |
| >=1关键维度恶化 | downgrade | P1 |
| baseline被部分否定但不反转 | stop_watch | P0 |
| 10条重评条件任一触发 | reanalysis_required | P0 |

**reanalysis_required 10条触发条件**：
1. 收盘跌破核心支撑
2. 放量跌破MA20
3. 主力连续3日流出+四档共振
4. 融资连续下降+破位
5. 公告与baseline假设相反
6. 板块转入衰退
7. 连续2日downgrade
8. 数据完整度不足影响判断
9. 单日涨跌幅>±7%
10. 质押/解禁/大宗触发红灯

# 第二章 P0 明日决策卡

## 2.1 格式

必须放在报告最前面，markdown表格，九字段+一句话结论：

| 项目 | 输出要求 |
|:-----|:-----|
| 明日主动作 | 观望/试探/加仓/减仓/清仓/暂停观察 |
| 当前仓位上限 | 如 0% |
| 条件触发后仓位 | 如"缩量回踩MA20企稳后允许试探3%" |
| 关键买点 | 价位+确认条件 |
| 禁止动作 | 至少2条 |
| 新仓止损 | 针对明日新建仓 |
| 已持仓止损 | 引用深度S3，无持仓写"无持仓" |
| 置信度 | 高(>70%)/中(50-70%)/低(<50%) |
| action_change | upgrade/unchanged/downgrade/stop_watch/reanalysis_required |
| 一句话结论 | ≤40字 |

## 2.2 规则

- 仓位上限0%与触发后试探3%必须拆开写
- 置信度标注数据完整度和信号胜率影响
- 禁止动作至少2条，可含"数据缺失不买"

# 第三章 四档资金结构

## 3.1 格式（日报§2.2 必须输出）

| 指标 | 数值 | 方向 | 说明什么 | 操作影响 |
|:-----|:-----|:----:|:-----|:-----|
| 超大单净额 | x万 | 流入/流出 | 机构大资金态度 | 加/减置信度 |
| 大单净额 | x万 | 流入/流出 | 主力/游资态度 | 判断是否共振 |
| 中小单净额 | x万 | 流入/流出 | 散户承接/撤退 | 判断筹码结构 |
| 主力合计 | x万 | 流入/流出 | 总体资金方向 | 决定是否可试探 |
| 结构判断 | 共识/分歧/... | — | 谁在买谁在卖 | 影响仓位 |

## 3.2 判断规则

- 超大单流出+大单流出+小单流入 → 大资金撤，散户接，**禁止抄底**
- 超大单流入+大单流入+缩量企稳 → 资金认可，**允许小仓位试探**
- 超大单流出+大单流入 → 资金分歧，**降低置信度**
- 主力净流出但跌幅缩小 → 抛压释放，**等待次日确认**

# 第四章 大盘与板块相位

## 4.1 板块相位五阶段（引用白皮书v3.3 §1.4.1）

| 相位 | 量化触发条件（>=2项） | 操作 |
|:-----|:------------|:-----|
| 见底期 | 距52周高点回撤>30% + 4周未创新低 + 周线MACD金叉 | 开始关注 |
| 启动期 | 放量突破MA20 + 龙头率先上涨 + 5日涨幅>3% | 可建仓 |
| 主升期 | 沿MA5/MA10周线上涨 + 板块内>5%涨幅>=3只 + RSI 50-75 | 加仓/持仓 |
| 高潮期 | 4周涨幅>15% + 换手率>80%分位 + 周线上影线>实体×1.5 | 分批减仓 |
| 退潮期 | 跌破MA20周线 + 前期领涨股跌>8% + 5日均量<20日均量×0.7 | 清仓回避 |

## 4.2 行业资金对操作的影响

- 行业资金流入+个股流入+启动期 → 仓位上限可上调10%
- 行业资金流出+个股流出+退潮期 → 仓位上限=0%
- 行业流入+个股流出 → 个股弱于板块，降低置信度
- 行业流出+个股流入 → 警惕板块拖累，仓位上限降5%
- 行业连续3日流出 → 不论个股，禁止新开仓

# 第九章 U-1 ~ U-4 闸门

## 9.1 U-1：数据源覆盖

检查日报是否使用并披露：baseline、深度分析结论、K线、成交量、换手率、四档资金、融资融券、北向、质押、解禁、股东人数、财务指标、事件、信号胜率（14项）。

## 9.2 U-2：核心字段完整性

检查：P0决策卡九字段齐全、action_change∈五枚举、仓位上限与触发后仓位分开、止损/加仓/减仓口径清楚、T+5展望存在、数据完整度表存在、machine_fields存在。

## 9.3 U-3：数据使用质量

检查：四档资金不能只写"主力净流入"、信号胜率<50%不增强买入、样本<20标注low_sample、风控灯映射到仓位折扣、风险不只罗列必须给操作影响、大盘/板块只影响仓位不替代个股触发。

## 9.4 U-4：不可获取约束

检查：本地已有数据不写不可获取、写不可获取必须说明原因、缺失超阈值→降级WARN/BLOCK、融资本地存在时禁止写不可获取、北向缺失时说明是否使用替代字段。

# 第十一章 数值权威规则（第2阶段生效）

## 11.1 数值权威源总则

所有日报引用的数值字段，其权威源由以下文件统一管理：

| 文件 | 作用 |
|:-----|:------|
| `00_项目地基/01_数据契约/numeric_authority_contract.md` | 数值权威契约（字段→权威源映射规则） |
| `00_项目地基/02_权威注册表/numeric_field_registry.json` | 字段注册表（字段名/类型/单位/来源） |
| `00_项目地基/04_一致性闸门/numeric_field_mapping.json` | 字段映射表（sidecar路径→权威源字段） |

## 11.2 板块相位权威规则

- ⛔ 日报不得自行判断板块相位替代 data_scored

# 第十二章 日期新鲜度与降级路径权威规则（第3阶段生效）

## 12.1 数据类别新鲜度标准

| 数据类别 | 权威源 | 新鲜度要求 | 缺失处理 |
|:---------|:-------|:-----------|:---------|
| K 线行情 | `kline_cache/{code}.json` | T+0 必须存在 trade_date 记录 | ⛔ BLOCK |
| 四档资金 | `fund_flow_cache/{code}.json` | T+0 必须匹配 trade_date | ⛔ BLOCK |
| 融资融券 | `margin_detail/{code}.json` | T+1 允许，超 T+2 需声明 | ⛔ BLOCK / ⚠️ WARN |
| 板块相位 | `data_scored.json`（三桶） | 引用最新评分数据 | ⛔ BLOCK / ⚠️ WARN |
| Baseline | `baseline_registry.json` | baseline_date ≤ trade_date ≤ valid_until | ⛔ BLOCK |
| Eval_hooks | sidecar 内嵌 | t1 ≥ next_trade_date, t5 > trade_date | ⛔ BLOCK |

## 12.2 降级声明规则

降级声明必须在 sidecar `degraded_items` 中声明，包含：数据类别、应有日期、实际最新日期、延迟天数、是否影响决策。

| 延迟范围 | 已声明降级 | 未声明降级 |
|:---------|:----------:|:----------:|
| T+1（融资） | ✅ PASS | ⚠️ WARN（未声明延迟但不影响） |
| 超 T+2 | ⚠️ WARN | ⛔ BLOCK |

## 12.3 日报生成前必须执行的命令

```bash
python3 scripts/check_freshness_degradation.py --all --date <日期>
```

全池 10/10 通过（允许 WARN）后方可提交日报生成。

## 12.4 补充规则

- ⛔ 禁止通过修改历史日报适配闸门
- ⛔ 禁止通过修改缓存数据适配闸门
- ⛔ 禁止用口头说明替代降级声明

# 第十三章 MD/sidecar 一致性权威规则（第4阶段生效）

## 13.1 一致性原则

日报 MD 正文与 JSON sidecar 必须同源一致。sidecar 是机器可读事实载体，MD 是展示载体，两者描述的是同一份报告。

## 13.2 必须一致的字段

| 类别 | 字段 | 容差 |
|:-----|:-----|:----:|
| 报告身份 | stock_code, stock_name, trade_date | 精确 |
| Baseline | baseline_id | 精确 |
| P0 决策卡 | t1_action, position_cap, stop_loss, confidence, forbidden_actions | 动作方向兼容，价格±0.01 |
| 行情 | close, change_pct, volume_wan_shou | close±0.001, change±0.05%, volume±1万手 |
| 四档资金 | super_large/large/medium/small/main_force_net | 金额±1万元 |
| 板块相位 | sector_phase | 精确 |
| 风控灯 | risk_light.overall | 精确 |
| eval_hooks | t1_verify, t5_verify 日期 | 日期一致 |
| sidecar 内部镜像 | machine_fields 与顶层字段 | 精确 |

## 13.3 禁止事项

- ⛔ 禁止修改历史日报来适配闸门
- ⛔ 禁止修改 sidecar 掩盖 MD 错误
- ⛔ 禁止用 MD 作为数值权威源（MD 值是展示层，数值以 sidecar 和权威数据源为准）

## 13.4 日报生成后必须执行的命令

```bash
python3 scripts/check_md_sidecar_consistency.py --all --date <日期>
```

出现 BLOCK 不得归档。

# 第十四章 报告权威继承规则（第5阶段生效）

## 14.1 权威层级

| 层级 | 来源 | 可用作 |
|:----:|:-----|:-------|
| L1 | 权威注册表 / 基础数据源 | baseline_id、行情数值、资金、融资、板块相位 |
| L2 | 日报 JSON sidecar | 日报内镜像一致性 |
| L3 | 日报 MD | 展示层，数值以 L1/L2 为准 |
| L4 | 深度分析正文 | 分析假设、逻辑背景、研究脉络 |
| L5 | 系统附录 / 旧日报 | 历史记录，禁止作为当前权威源 |

## 14.2 深度分析能做和不能做的事

**可以做：** 分析假设、逻辑背景、策略推演、定性判断参考。
**不能做：** baseline_id、行情数值、资金、日期新鲜度、风控数字的权威源。

## 14.3 禁止事项

- ⛔ 禁止用 `deep_*` 格式 baseline_id
- ⛔ 禁止用深度分析正文覆盖 baseline/数值权威
- ⛔ 禁止用系统附录反向决定日报事实字段
- ⛔ 禁止用旧日报作为当前报告生成依据

## 14.4 日报生成前/后必须运行的命令

```bash
# 生成后：报告权威继承检查
python3 scripts/check_report_authority_lineage.py --all --date <日期>
python3 scripts/check_baseline_authority.py --all --date <日期>
python3 scripts/check_numeric_source_consistency.py --all --date <日期>
python3 scripts/check_freshness_degradation.py --all --date <日期>
python3 scripts/check_md_sidecar_consistency.py --all --date <日期>
```
