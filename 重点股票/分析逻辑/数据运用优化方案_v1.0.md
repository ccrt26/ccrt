# 数据运用优化方案 v1.0

> **版本**: v1.0（定稿） | **日期**: 2026-05-30
> **制定**: 腰子（综合）+ 山猫（宏观/行业）+ 信鸽（事件）+ 玉夜（数据监理）+ 流金（风控）+ 青山（策略/因子）
> **触发**: 玉夜全数据审计（2026-05-30），发现管线数据利用率~22%，后评估统计累积基本为零
> **核心原则**: 用已有数据，不拉新数据。本次优化不增加任何新API或数据源，100%基于现有管线已落盘数据
> **涉及体系**: 重点股票深度分析 + 重点股票日报 + 每日荐股评分引擎 + 三套后评估

## 二、优化目标

### 2.1 管线数据利用率

| 维度 | 当前 | 三个月目标 | 一年目标 |
|:-----|:----:|:------:|:------:|
| 管线13类数据加权利用率 | ~22% | **≥70%** | ≥80% |
| Tushare新数据6类利用率 | 0% | **≥65%** | ≥75% |
| 每份深度分析报告引用数据源种类 | ~6类 | **≥12/19类** | ≥15/19类 |

### 2.2 后评估数据累积

| 指标 | 当前 | 三个月目标 | 启用门槛 |
|:-----|:----:|:------:|:-----|
| records.csv | 9条 | ≥60条 | — |
| summary.csv | 空 | 每日滚动更新 | — |
| Spearman ρ(T+1) | null | 首次非null | n≥30 |
| 深度后评估次数 | 1次 | ≥8次 | A层启用≥3次 |
| 单次IC记录 | 0次 | ≥4次 | 每次记录 |
| 信号S01-S33胜率表 | 无 | 首次统计 | 每信号≥5次触发 |

### 2.3 为什么不是100%

针对每个数据类的天花板逐项论证（详见§三），汇总为五类原因：

| 原因类别 | 涉及数据 | 说明 |
|:--------|:------|:-----|
| 数据源客观限制 | 北向[8]/业绩预告/大宗交易 | 日频政策限制或非每日都有 |
| 字段冗余 | 财务季报[3] | 100+字段中~30个是同一指标不同公式，~20个q_前缀是子集 |
| 使用频率天然低于采集频率 | 周线/月线/分红/宏观 | 月频数据按月算=100%，按日算=40-50% |
| 分析框架不需要全覆盖 | 成分股/大宗/月线/研报 | 部分场景无信息增量 |
| 设计冗余（1+2备源） | 新浪行情[1B]/腾讯K线[2B] | 备源存在=价值，主源正常时不激活 |

### 8.4 问题分级与闭环

审计发现的问题分三类，各有独立闭环路径：

| | A类：报告缺陷 | B类：模板/流程缺陷 | C类：执行延期 |
|:--|:-----|:-----|:-----|
| **发现方** | 玉夜(U检查) | 玉夜(周报模式识别) | 旧影(C检查) |
| **触发条件** | 单份报告U-1~U-4 FAIL | 连续2次同类型A类FAIL | 任一批次动作未按时完成 |
| **通知对象** | 直接通知腰子 | 上报阿黑 | 上报阿黑 |
| **责任人** | 腰子（补全报告） | 腰子+情墨（修复模板） | 按§五"负责"列 |
| **补全时限** | ≤2项→2h，≥3项→当天 | 下次报告产出前 | 阿黑与责任人协商DDL |
| **验证方** | 玉夜（单份复核） | 旧影（模板验证） | 旧影（逐项复核） |
| **关闭条件** | 玉夜PASS | 旧影PASS | 旧影PASS |
| **升级条件** | 超时未补→B类 | 连续2次→联合审查 | 连续2次→联合审查 |
| **极限升级** | — | 连续3次→L3请示用户 | 连续3次→L3请示用户 |
| **历史记录** | 不单独记录 | 旧影写入审计历史DB | 旧影写入审计历史DB |

**闭环流程图**：

```
┌─────────────────────────────────────────────────────┐
│                   A类：报告缺陷                        │
│  玉夜FAIL → 通知腰子 → 腰子补全 → 玉夜复核 → 关闭     │
│  超时未补 → 升级B类 ↗                                │
├─────────────────────────────────────────────────────┤
│                B/C类：模板/流程/延期                   │
│  玉夜/旧影FAIL → 上报阿黑 → 阿黑分派责任人             │
│      → 责任人修复 → 通知阿黑 → 旧影复核               │
│      → PASS → 关闭 + 写入审计历史DB                  │
│      → FAIL → 打回责任人（附新根因）                  │
│      → 连续2次FAIL → 联合审查（腰子+情墨+责任人）      │
│      → 连续3次FAIL → L3升级（请示用户）               │
└─────────────────────────────────────────────────────┘
```

### 8.5 审计记录规范

**玉夜**：U检查结果嵌入数据运用周报。周报和月计分卡归档至 `重点股票/深度分析/后评估报告/` 目录。

```
- 修复: [改动内容]
- 经验: [对未来排计划/写模板的参考]
```
