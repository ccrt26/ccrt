## 0. 核心原则

### 0.1 分析深度铁律

> ⛔ **本文件定义的不仅是报告结构，更是分析深度。** 只填表不分析 = 不合格。

每章必须产出：
- **表格**（数据展示）
- **发现段落**（≥3条关键发现，每条≤80字，从数据中提炼洞察）
- **判断结论**（一句话总结该维度的多空方向）

### 0.2 腰子全团强制咨询（不可跳过）

```
用户提问 → 腰子激活
  ↓
① 山猫 宏观/政策/情绪/事件风险 ≤200字
  ↓
② 玉夜 数据可用性/1+2合规/降级路径 ≤150字
  ↓
③ 流金 风险评估/红线边界/止损约束 ≤150字
  ↓
④ 青山 策略维度/因子信号/后评估规律 ≤150字
  ↓
⑤ 腰子 综合以上四角色全部意见 → 输出最终分析结论
```

### 0.3 数据铁律

- PE(TTM) = 统一口径§1.3公式：Price[1] / TTM_EPS[3]
- TTM_EPS = 最新年报EPS - 去年同季EPS + 最新季报EPS
- 财务数据主源: fina_indicator[tushare](100+字段) → [3]东财
- K线数据主源: kline_cache/{code}.json → data_full.json
- 资金流主源: moneyflow[tushare] → [9]东财
- 两融主源: margin_detail[tushare] → [12]东财
- 北向数据: hk_hold[tushare] → [8]东财
- 独有数据(无备源,标注"仅供参考"): pledge/share_float/holder_number/fina_mainbz/block_trade/repurchase
- 数据缺失时说"数据不可获取"，标注checked_sources + unavailable_reason + next_owner
- 所有数字标注数据源编号

### 0.8 人读版优先铁律（v1.5 新增）

> ⛔ **深度分析报告首先是给用户看的，其次才是给系统检查的。**

报告必须帮助用户理解：
1. 这家公司为什么值得关注；
2. 行业、政策、事件背景是什么；
3. 当前数据说明了什么；
4. 哪些指标支持判断；
5. 哪些风险可能推翻判断；
6. 后续日报应该重点盯什么；
7. 用户接下来该如何观察和决策。

**禁止**：
- 只翻译baseline JSON
- 只罗列signals、risk_flags、score_history
- 只有表格，没有解释
- 只有数据，没有结论
- 只有结论，没有原因
- 为了过release_gate牺牲报告可读性

**每章必须保留**：
- 数据表格
- 关键发现
- 人话解释
- 判断结论
- 对用户决策的意义

### 0.9 数据增强层规则（v1.5 新增）

> ⛔ **新版数据能力必须嵌入报告，但不能替代正文分析。**

**数据增强层包括**：
- official baseline（baseline_id + baseline_date + valid_until）
- score_history（评分历史沉淀）
- signals（触发信号列表）
- signal_evaluator胜率（每个信号的历史胜率+样本数）
- risk_flags（质押/解禁/股东人数/大宗交易/业绩预告/分红/两融/北向）
- decision_impact（scoring/position/downgrade/stop_loss/confidence五维）
- counter_evidence（≥4条反证条件）
- release_gate G8（基线联动检查结果）
- delta_vs_baseline（日报交接字段）

**使用规则**：
1. 正文先讲业务、行业、财务、技术、风险逻辑，再用数据增强层验证
2. signals必须解释"这个信号历史上准不准"，不能只列signal_id
3. risk_flags必须解释"这个风险对仓位、止损、降级有什么影响"，不能只列字段
4. baseline_id放在报告首页和数据附录中，用于日报引用
5. G8只证明结构化联动合格，不代表分析质量合格
6. 数据不可用必须写checked_sources、unavailable_reason、next_owner
7. 数据增强层集中放在报告末尾的【数据附录】，正文中只在相关章节简要引用
