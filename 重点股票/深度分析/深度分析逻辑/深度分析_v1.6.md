## 0. 核心定位

### 0.1 一句话原则

> 周报定逻辑，日报验状态，后评估改参数。

深度分析周报不是单纯给用户阅读的长篇结论报告，而是金融团队的“周度逻辑校准与日报指导书”。它必须同时服务三类对象：

| 层级 | 标签 | 服务对象 | 核心问题 |
|:-----|:-----|:---------|:---------|
| 金融团队作业层 | 【A层】 | 金融团队、日报维护者 | 本周逻辑、参数、证据和下周指令是什么 |
| 后评估基准层 | 【B层】 | 后评估、参数优化、知识进化 | 判断对错后如何修正字段、阈值、权重和证据等级 |
| 用户摘要层 | 【C层】 | 用户、模拟交易观察者 | 下周可看什么、不可做什么、触发后状态如何变化 |

### 0.2 v1.5 继承关系

v1.6 继承 v1.5 的以下原则：

1. 人读版优先，不允许只有表格没有解释。
2. 数据增强层必须嵌入报告，但不能替代正文分析。
3. PE(TTM) 使用项目统一公式，禁止用静态 PE 替代。
4. 自动评分、signals、risk_flags 只能辅助解释，不能替代人工金融判断。
5. baseline_id、valid_until、日报承接字段必须保留。
6. 报告必须有反证条件、风险边界和后评估入口。

v1.6 新增的优先级高于 v1.5。若两者冲突，按 v1.6 执行。

### 0.3 本版不做的事

1. 不修改生产代码。
2. 不修改日报正式入口。
3. 不修改数据库 Schema。
4. 不直接把东睦股份单次样稿结论写成永久规则。
5. 不让后评估自动改角色知识库、参数库或评分权重。
6. 不用执行模型替代腰子、山猫、信鸽、玉夜、流金、青山、旧影签字。

## 2. 证据等级

v1.6 使用 L1/L2a/L2b/L3 四级证据。不得继续使用旧版宽泛 L2 口径。

| 等级 | 定义 | 使用口径 | 后评估口径 |
|:-----|:-----|:---------|:-----------|
| L1 | 已公告、财报、披露的硬事实 | 可直接支撑核心假设 | 若被证伪，必须重评核心逻辑 |
| L2a | 有明确预期窗口的推进事项 | 可支撑假设，但必须标注有效期 | 未如期兑现视为假设部分失败 |
| L2b | 有方向但无时间表的战略叙事 | 只能作为背景或观察项 | 未兑现不直接视作失败，但要评估是否继续保留 |
| L3 | 推测、概念、无法落地叙事 | 不得作为单独核心假设 | 进入反例库或删除 |

强制规则：

1. 技术修复不得把 L2b 或技术假设升级成 L1 基本面事实。
2. 产能扩张不得直接等同于订单增长。
3. 事件进入核心假设前必须说明证据等级、来源、有效期和反证条件。
4. L2a 必须有明确窗口；没有窗口的一律降为 L2b。

## 3. 结论强度规则

深度分析周报必须区分“短线状态”和“中期逻辑”。

| 情况 | 允许结论 | 禁止结论 |
|:-----|:---------|:---------|
| 价格站上均线、技术位修复 | 短线状态修复、交易状态改善 | 中期逻辑强化、基本面强化 |
| 资金结构改善但口径冲突 | 资金结构出现改善迹象，口径待复核 | 主力共识流入、机构明确加仓 |
| 无新增公告、订单、财报 | 中期逻辑未证伪 | 中期逻辑进一步强化 |
| L2a 催化在窗口内推进 | 催化仍在观察窗口 | 催化已落地 |
| L2b 叙事长期无进展 | 保留为背景或降权 | 继续作为核心支撑 |

标准句式：

```text
短线状态明显修复，中期逻辑未证伪；是否强化仍待 L1/L2a 事实验证。
```

禁止用语：

1. “中期逻辑进一步强化”，除非新增 L1 或强 L2a 事实。
2. “资金面确认”，除非多口径一致且来源可追溯。
3. “谨慎乐观”“持续关注”，除非后面给出触发条件。
4. C 层直接写“买入、加仓、减仓、止损、持有”。C 层统一写“模拟观察、维持跟踪、等待确认、降级观察、移出跟踪、观察失效线”。

## 4. A/B/C 三层结构

### 4.1 A 层：金融团队作业层

A 层是周报主体，必须承载最多数据和最完整逻辑。

| 章节 | 必填 | 输出要求 |
|:-----|:----:|:---------|
| A0 本周版本与样本说明 | 是 | 报告周期、数据截止、数据源、缺失项、限制项 |
| A1 一句话工作结论 | 是 | 当前状态、短线变化、中期逻辑、不得越界的结论 |
| A2 周度核心假设表 | 是 | 假设、证据等级、当前状态、下周验证、反证条件、有效期 |
| A3 本周变化归因 | 是 | 增强项、削弱项、待验证项；每项说明来源和限制 |
| A4 下周日报指令清单 | 是 | 价格、量能、事件、财务、行业、风控指令 |
| A5 状态机与触发规则 | 是 | A/B/C/D/E/M 状态、切换条件、恢复路径 |
| A6 参数快照 | 是 | 技术位、估值、资金、风控、事件窗口、参数版本 |
| A7 风险边界 | 是 | 否决项、降级项、反证项、数据缺口 |

### 4.2 B 层：后评估基准层

B 层不服务用户阅读，服务下周复盘。

| 章节 | 必填 | 输出要求 |
|:-----|:----:|:---------|
| B1 后评估问题 | 是 | 下周必须回答的 5 到 8 个问题 |
| B2 数据使用记录 | 是 | 本周新增、继续使用、限制使用、禁用的数据 |
| B3 可量化复盘指标 | 是 | 本期值、上期值、变化、限制 |
| B4 参数修正入口 | 是 | 阈值是否过紧/过松，是否需要修正 |
| B5 字段价值评估 | 是 | 保留、降权、删除、新增建议 |
| B6 知识更新候选 | 条件必填 | 只生成候选，不自动入库 |

### 4.3 C 层：用户摘要层

C 层只给用户看，必须短、清楚、可执行。

| 字段 | 要求 |
|:-----|:-----|
| 一句话结论 | 当前状态 + 下周核心观察，不超过 120 字 |
| 下周可做 | 不超过 5 条，必须有触发条件 |
| 下周不做 | 不超过 3 条，必须写清动作边界 |
| 触发后变化 | 用 A/B/C/D/E/M 状态表达 |
| 风险边界 | 不超过 3 条，不堆技术细节 |

C 层不是交易指令。正式文字不得写成直接投资建议。

## 5. 状态机

主状态为 A/B/C/D，E 是 B 的子状态，M 是宏观覆写层。

```text
A 继续跟踪 <-> B 等待确认 <-> C 降级观察 -> D 移出/否决
                  |
                  E 试探跟踪（B 的子状态）

M 宏观覆写层位于个股状态之上，只临时覆写动作和展示，不直接改个股基础状态。
```

| 状态 | 含义 | 进入最小举证 | 退出最小举证 |
|:-----|:-----|:-------------|:-------------|
| A 继续跟踪 | 中期逻辑未证伪，仍具备跟踪价值，短线状态健康 | 至少 1 条 L1 或强 L2a 支撑核心假设，且无硬风控触发 | 出现核心分歧到 B，风险升高到 C，L1 反证到 D |
| B 等待确认 | 中期逻辑未坏，但短期信号分歧 | 2 类普通信号分歧，或 1 类核心信号分歧 | 分歧消失回 A，风险扩大到 C，满足条件进入 E |
| E 试探跟踪 | B 状态下的模拟观察子状态 | 标的已在 B，风险可控，触发试探条件 | 成功回 A，失败回 B，恶化到 C |
| C 降级观察 | 风险明显升高 | 1 条降级项，或 2 类风险信号共同恶化 | 修复后回 B，反证出现到 D |
| D 移出/否决 | 中期逻辑或风险边界被破坏 | 1 条 L1 级反证或硬风控失效 | mini 深度分析 + 1 条 L1 新事实 + 全团咨询，只能回 B |
| M 宏观覆写 | 宏观或市场环境临时压过个股状态 | 山猫提出，腰子 + 山猫双签 | 宏观稳定后解除，必要时逐个重评 |

## 6. 日报指令

周报必须向未来一周日报下发指令清单。日报不重写深度逻辑，只回答：

> 今天是否触发了周报设定的状态变化？

### 6.1 指令最小模板

| 指令类型 | 必填核心项 | 可选扩展项 |
|:---------|:-----------|:-----------|
| 价格指令 | 支撑/压力位、触发后状态、确认规则 | 分时异动、波动率、缺口 |
| 量能指令 | 放量/缩量口径、比较窗口、触发后动作 | 换手率、成交额、量价背离 |
| 事件指令 | 事件类型、证据等级、触发后增强/削弱 | 落地窗口、预期偏差、信鸽标签 |
| 财务指令 | 核心反证项、最新数据窗口、触发后状态 | 同业对比、环比修复阈值 |
| 行业指令 | 下游或竞品变化、证据等级、影响方向 | 政策窗口、库存、排产 |
| 风控指令 | 降级/否决项、硬风控位、人工复核要求 | 风险暴露估算、恢复条件 |

### 6.2 日报输出模板

```text
日期: YYYY-MM-DD
股票: {code} {name}
周报方法论版本: 深度分析_v1.6
周报参数版本: {parameter_version}
昨日/当前状态: A/B/C/D/E/M

【状态检查】
□ 价格指令: 未触发/触发/待确认
□ 量能指令: 未触发/触发/待确认
□ 事件指令: 未触发/触发/待确认
□ 风控指令: 未触发/触发/待确认
□ M层检查: 正常/需覆写

【当日结论】
今日状态: 维持/回A/转B/转C/转D/触发M
触发指令: D-__
证据来源: __
是否需要人工复核: 是/否

【后评估记录】
是否进入B层后评估: 是/否
需要记录的问题: __
```

### 6.3 Shadow 执行

在正式改日报模板前，日报可以先运行 Shadow 指令执行栏。Shadow 运行不改变日报正式结构，但必须记录指令是否被执行。

| 字段 | 要求 |
|:-----|:-----|
| 周报指令编号 | 对应 A4 指令 |
| 今日是否触发 | 未触发/触发/待确认 |
| 触发证据 | 价格、量能、事件、财务、行业或风控 |
| 状态变化 | A/B/C/D/E/M 是否变化 |
| 未执行原因 | 数据缺失、未到窗口、人工复核中、指令不清 |
| 是否进入后评估 | 是/否 |

## 7. 数据进入层级

### 7.1 A 层数据

只有“确定下次更新能取到或能解释限制”的数据才能进入 A 层。

| 数据 | A 层使用口径 |
|:-----|:-------------|
| K线与均线 | 按需补齐标的、指数和高度相关标的；不足 250 天时必须标注限制 |
| daily_basic | PE/PB/换手/市值可进参数快照；分位必须标注窗口长度 |
| moneyflow 四档资金 | 可写结构变化；若与 main_force_net 冲突，只能写口径待复核 |
| 融资融券 | 可写融资余额、5 日变化、杠杆风险 |
| 质押 | 进入否决项或风险边界 |
| 解禁 | 进入降级项或风险边界 |
| 财务扩展字段 | 进入核心假设和参数快照 |
| events_db | 最近 15 天事件强制读取 |
| SectorPhaseMap / 指数 K线 | 进入 M 层检查 |
| 产品级营收 | 只能 A 层占位；信鸽从年报/半年报 PDF 提取并标注页码后才可填数 |

### 7.2 B 层数据

| 数据 | B 层使用口径 |
|:-----|:-------------|
| 评分历史 | 样本不足时只记录，不影响状态机 |
| 股东户数 | 季频数据，优先进 B 层复盘筹码变化 |
| 财务同比 | 用于验证中期逻辑，不强行做周度判断 |
| 参数快照版本 | 必须记录 |
| 指令执行率 | 必须记录 |
| 字段价值评估 | 必须记录 |
| signal_winrate | 来源链路未校验前仅 B 层参考，不支撑 A 层上调 |

### 7.3 C 层数据

C 层不展示复杂数据，只展示结论边界：

1. 一句话结论。
2. 下周可做 3 到 5 条。
3. 下周不做 1 到 3 条。
4. 触发后状态变化。
5. 风险边界。

## 9. B 层后评估

后评估不是评价报告文笔，而是回答：

1. 哪些假设被验证、部分验证、未验证或证伪。
2. 日报是否忠实执行周报指令。
3. 哪些参数阈值过紧或过松。
4. 哪些字段真的有用，哪些字段应降权或删除。
5. 哪些证据等级被高估。
6. 哪些结论强度写过头。
7. 是否存在策略环境变化。
8. 是否需要产生知识更新候选。

### 9.1 归因分类

| 类型 | 含义 |
|:-----|:-----|
| 数据问题 | 缺失、延迟、口径错误、缓存断层 |
| 参数问题 | 阈值过紧、过松、窗口不合适 |
| 权重问题 | 某类因素被高估或低估 |
| 证据等级问题 | 把预期当事实，或把技术修复当基本面强化 |
| 分析逻辑问题 | 因果链条不成立 |
| 展示问题 | C 层不能指导用户下一步观察 |
| 执行问题 | 日报未执行周报指令 |
| 策略环境变化 | 因子有效性、市场风格或流动性环境变化 |

### 9.2 量化指标

| 指标 | 公式 | 初始阈值 | 处理 |
|:-----|:-----|:---------|:-----|
| 指令执行率 | 已执行指令数 / 总指令数 | < 80% | 分析未执行原因 |
| 阈值偏差率 | abs(实际触发值 - 预设阈值) / abs(预设阈值) | >= 10% | 复核参数 |
| L2a 未兑现率 | 未兑现 L2a 数 / 总 L2a 数 | >= 30% | 重审 L2a 标准 |
| 字段命中率 | 被复盘引用字段数 / 周报展示字段数 | < 50% | 降权或移出字段 |
| C 层返工率 | 需人工重写摘要数 / 摘要总数 | > 30% | 修摘要模板 |
| 状态切换准确率 | 正确切换次数 / 触发切换次数 | < 70% | 重审状态机 |

### 9.3 知识更新候选

B 层后评估可以生成 KnowledgeUpdateCandidate，但不得自动改知识库。

```text
候选ID:
来源报告:
触发问题:
归因类型:
涉及角色:
建议进入: 角色核心知识库 / 场景适配器 / 反例库 / 参数库 / 暂不入库
证据:
是否跨样本:
是否需要腰子终审:
是否需要旧影审计:
```

进入核心知识库的最低门槛：

1. 同类问题连续出现 3 次以上，且跨至少 2 个标的或 2 个周期。
2. 单次造成重大风险误判，并被角色复盘确认为规则缺陷。
3. 后评估量化指标连续 2 个周期触发修正规则。
4. 腰子判定为通用金融口径，而非单票样本经验。

## 12. 东睦样稿映射

东睦股份 20260610 手工样稿是 v1.6 的首个验证样例，但不是永久模板。执行时吸收以下经验：

1. “短线状态明显修复，中期逻辑未证伪”是标准结论强度样例。
2. K线补齐后可用 MA250，但不能因为 MA250 站上就写基本面强化。
3. moneyflow 四档资金与 main_force_net 冲突时，不能放入 A 层增强项。
4. PE/PB 1.5 年临时分位必须写临时限制。
5. 产品级营收必须等待信鸽从年报 PDF 提取，不能用地区级数据替代。
6. C 层必须写“可做/不做/触发后变化/风险边界”，不写交易指令。
7. 下周 B 层后评估必须回看日报指令执行率、状态切换准确率、字段价值和参数阈值。

## 13. 版本收口结论

自本文件生效后：

1. 新增深度分析周报按 `深度分析_v1.6` 执行。
2. `深度分析_v1.5.md` 保留为历史版本。
3. 旧报告后评估按其报告头版本执行；若报告头为 `v1.5 + 新G1/G2口径`，按 v1.6 差距复查。
4. 东睦股份闭环下一步不是继续大改框架，而是跑完整链路：周报定参数 -> 日报执行 -> 下周 B 层后评估 -> 修正阈值和字段。
5. 若下周后评估证明 v1.6 某些字段无效，先进入 B 层参数/字段修正，不直接重构框架。
