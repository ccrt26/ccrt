## 0. 核心原则

### 0.1 与日报后评估的关系：互补而非替代

> ⛔ 深度分析后评估与日报后评估（重点股票次日后评估白皮书 v1.8）是**两套独立但协同**的评估体系。

| 维度 | 日报后评估 | 深度分析后评估 |
|:-----|:---------|:------------|
| 评估对象 | 每日4段式日报 | 每周九章深度分析报告 |
| 频率 | 每日盘后 | 每周五 + 月度 + 季度 |
| 主窗口 | T+1 / T+5 | T+20 / T+60 |
| 信号覆盖 | 33信号（日常技术面+资金面为主） | 33信号 + 11项深度分析特有维度 |
| 核心问题 | "今天的判断对吗？" | "这周的分析框架有效吗？" |
| 数据来源 | 日报Markdown + 独立API拉取 | 深度分析报告版本锁定读取 + 完整财务管线 |

**协同规则：**
- 两套后评估在大循环（季度）层面合并——共享条件规则库、失效模式库、知识蒸馏结果
- 日报后评估发现的技术面/资金面信号问题 → 可触发深度分析方法论审查
- 深度分析后评估发现的估值/Wyckoff/催化剂问题 → 不反馈日报（日报不涉及这些维度）

### 0.2 版本感知前置读取（最高优先级）

> ⛔ **后评估不假设所有报告按最新方法论编写。** 每次评估必须先读取目标报告 → 提取方法论版本 → 用对应版本的标准检验。

```
后评估启动
  ↓
① 读取目标深度分析报告，提取报告头中的 方法论版本 字段
   例如：> 方法论版本: 深度分析.md v1.1
  ↓
② 若报告中无版本声明 → 按报告日期反查深度分析.md的版本历史表
   v1.0 = 2026-05-26当日 / v1.1 = 2026-05-26起
  ↓
③ 读取对应版本的方法论，提取该版本的：
   - 强制章节清单
   - 自检清单（v1.0=12条, v1.1=15条）
   - 评分权重规则
   - 数据铁律版本
  ↓
④ 用该版本的标准执行后评估
  ↓
⑤ 若当前方法论版本 > 报告版本 → 额外输出"跨版本差距报告"
```

**跨版本差距报告**：列出报告版本缺失的检验项（因当时未要求），标注"非错误，方法论演进差异"。这为方法论升级效果提供天然的 A/B 对照数据。

### 0.3 深度分析报告的强制版本声明

> ⛔ 每份深度分析报告头**必须**包含方法论版本声明。缺少此行 → 后评估标记 `[MISS]`，按日期推断版本，降一档置信度。

```markdown
# [代码] [名称] — 深度分析报告

> **日期**: YYYY年M月D日 | **方法论版本**: 深度分析.md vX.X
> **分析团队**: 腰子 + 山猫 + 玉夜 + 流金 + 青山
```

此声明是后评估自动读取版本号的唯一锚点。深度分析.md 每次升级时，报告模板同步更新此行。

### 0.4 多时间尺度铁律

> ⛔ 深度分析后评估**不可仅用T+5单窗口**。深度分析的中长期判断（估值、Wyckoff、市场阶段、行业周期）天然需要更长验证窗口。

| 窗口 | 验证内容 | 评估类型 | 频率 |
|:---:|:--------|:--------|:----:|
| T+5 | 短期方向、催化剂即时反应、止损位触及 | 快层 | 每周 |
| T+10 | 短期趋势确认、资金面持续性 | 快层 | 每周 |
| T+20 | Wyckoff阶段、情景概率、五红旗前瞻、评分方向 | 中层 | 每周（滚动） |
| T+40 | Wyckoff阶段转换、市场阶段判断 | 慢层 | 月度 |
| T+60 | 行业判断、公司类型判定、幻觉防范效果 | 慢层 | 月度 |
| T+120 | 估值预测误差（vs实际EPS） | 季度 | 季度 |

### 0.5 数据铁律

- 所有数字标注数据源编号（[2][3][7][8][9][10][11][12]→[5]）
- 降级数据标注 `[C]` 和过期时间
- AI推断数据标注 `[INFER]`，降一档置信度
- 缺失数据标注 `[MISS]`，不参与当次计算
- ⛔ 禁止编造任何数字

## 一、评估体系概述

### 1.1 目的与范围

**目的**：对深度分析报告进行系统性后评估，检验九章分析方法论的有效性，驱动分析框架的持续自我优化。

**核心问题**：
1. 深度分析的六维评分在T+20窗口是否有预测力？
2. 估值三情景（乐观/中性/悲观）与实际EPS的偏差有多大？
3. 市场阶段判断、Wyckoff周期定位、行业判断的准确率如何？
4. 催化剂识别和影响评估是否准确？
5. AI幻觉防范机制是否有效拦截了异常数据？
6. 五红旗、情景概率、止损位等风控判断是否经得起时间检验？
7. 深度分析方法论的每次版本升级是否真正提升了分析质量？

**范围**：
- 评估对象：深度分析报告的九章全部判断
- 评估频率：每周五 + 月度 + 季度（见§1.2）
- 评估数据：全部重点股票的深度分析报告

### 1.2 评估频率与时机

| 评估类型 | 频率 | 触发时机 | 验证窗口 | 输出 |
|:--------|:----:|:--------|:--------|:-----|
| **快层评估** | 每周五 | 深度分析完成后立即执行 | T+5, T+10 | 快报（≤500字） |
| **中层评估** | 每周五 | 对前2-4周的报告滚动验证 | T+20 | 嵌入月度报告 |
| **慢层评估** | 每月末 | 当月最后一次深度分析时 | T+40, T+60 | 月度综合报告 |
| **季度全量** | 每季度末 | 3/6/9/12月最后一周 | T+120 | 季度全量报告 |

**设计理由**：
- 每周五深度分析产生新报告 → 同时也是上周报告的T+5验证点 → **零额外调度成本**
- 中层T+20与Wyckoff阶段转换、催化剂落地的验证周期天然匹配
- 慢层T+60与财报季、估值验证周期匹配
- 快/中/慢三层形成"评估→反馈→优化"的连续循环

### 1.3 评估流程

```
深度分析报告生成（每周五）
  ↓
① 版本感知前置读取（§0.2）
   提取方法论版本 → 加载对应版本的检验标准
  ↓
② 报告结构化解析
   从深度分析报告Markdown提取结构化数据 → 写入 评估数据_深度分析_YYYYMMDD.json
  ↓
③ 评分方向校准（§2.2）
   综合评分 vs T+5/T+10/T+20收益的Spearman ρ方向检查
  ↓
④ A层评估（§2.3-§2.7）
   维度有效性/信号有效性/阈值有效性/框架一致性（复用日报框架，主窗口改T+20）
  ↓
⑤ B层评估（§2.8）
   11项深度分析特有维度：催化剂/市场阶段/行业/幻觉防范/数据源/情景概率/五红旗/止损/估值/Wyckoff/类型判定
  ↓
⑥ 跨版本差距分析（若当前方法论版本 > 报告版本）
  ↓
⑦ 生成后评估报告（快报/月度/季度，按§6规范）
  ↓
⑧ 更新知识积累（§5）
  ↓
⑨ 触发学习循环（§5.1-§5.4）
  ↓
⑩ 生成优化建议（若触及§5.5触发条件）
```

### 2.2 评分方向校准（前置，不计分）

> ⛔ **每次后评估正式分析前强制执行**。方法复用日报后评估§1.3，主窗口改为T+20。

1. 计算综合评分与各窗口收益（T+5/T+10/T+20/T+40）的 Spearman ρ
2. 以 **T+20** 为主判定窗口（深度分析的中期框架以中期窗口为核心）

| ρ方向(T+20) | 判定 | 动作 |
|:----------:|:----:|:-----|
| ρ > 0 | 正向 | 正常评估，结论置信度维持原档 |
| \|ρ\| < 0.05 | 无效 | 标记"评分无方向性"，本次各维度有效性结论降一档置信度 |
| ρ < 0 | 反向 | 标记"评分方向异常"，所有维度有效性结论降一档置信度；所有"有效"信号标记为"需谨慎解释" |

**方向异常升级机制**：

| 条件 | 动作 |
|:-----|:-----|
| 单次 ρ < 0 | 降置信度一档，评估报告加"评分方向异常"标注 |
| 连续2次 ρ < 0 | 降置信度两档，触发深度分析.md 六维权重审查 |
| 连续3次 ρ < 0 | 触发"评分体系方向审查"——全面审视综合评分公式、各维度权重、评分算法 |

### 2.3 A层：维度有效性（15分）

> 复用日报后评估§2.1方法论，主窗口从T+5改为T+20，权重从20分降为15分（B层分担了5分）。

#### 2.3.1 相关性分析（8分）

对六维评分的每个维度，计算评分与T+20收益的 Spearman ρ：

| ρ值范围 (T+20) | 判断 | 得分 |
|:-------------:|:----|:----:|
| ρ ≥ 0.3 | 强相关，维度有效 | 8分 |
| 0.15 ≤ ρ < 0.3 | 弱相关，维度有参考价值 | 4分 |
| 0 ≤ ρ < 0.15 | 几乎不相关，需审视 | 1分 |
| ρ < 0 | 负相关，维度反向指引 | 0分 |

辅助窗口（T+5/T+10/T+40）的ρ值作为参考列示，不单独计分。

#### 2.3.2 区分度分析（7分）

将样本按评分分为高分组（≥60）和低分组（<40），比较两组T+20平均收益：

| 高分-低分收益差 (T+20) | 判断 | 得分 |
|:--------------------:|:----|:----:|
| 差异 ≥ 3% | 有效区分 | 7分 |
| 1.5% ≤ 差异 < 3% | 部分区分 | 4分 |
| 0% ≤ 差异 < 1.5% | 无法区分 | 1分 |
| 高分收益 < 低分收益 | 反向区分 | 0分 |

> **阈值上调说明**：T+20窗口的收益波动天然大于T+5，区分度阈值从日报的1%/0.5%/0%上调至3%/1.5%/0%。

#### 2.3.3 IC/ICIR评估

计算维度评分的Rank IC序列（滚动最近8次深度分析评估），评估预测稳定性：

| ICIR 范围 | 判断 |
|:---------|:----|
| ICIR ≥ 1.0 | 优秀——维度预测能力稳定可靠 |
| 0.5 ≤ ICIR < 1.0 | 可接受——有一定预测能力但波动较大 |
| 0.2 ≤ ICIR < 0.5 | 边缘——预测能力不稳定，需监控 |
| ICIR < 0.2 | 不可靠——该维度不具备稳定的预测能力 |

> **启用条件**：需累积≥8次深度分析评估（约2个月）。初期仅计算单次Rank IC。

### 2.4 A层：信号有效性（20分）

#### 2.4.1 信号胜率与期望收益

每个信号发出后，统计各窗口的表现。深度分析加权方案：

| 窗口 | 权重 | 理由 |
|:---:|:----:|:-----|
| T+5 | 20% | 短期反应，噪音较大 |
| T+10 | 30% | 短期趋势确认 |
| T+20 | 50% | 中期趋势，核心窗口 |

**期望收益分析（T+20窗口为主）**：

```
E[r] = 胜率 × 平均正收益 + (1-胜率) × 平均负收益
```

信号判定矩阵（T+20窗口）：

| 胜率 | E[r] | 判定 |
|:---:|:----:|:----:|
| ≥ 60% | > 0 | **有效** — 高胜率+正期望 |
| ≥ 60% | ≤ 0 | **需审视** — 虽胜率高但赚少赔多 |
| < 50% | > 0 | **有潜力** — 低胜率但盈亏比优秀 |
| < 50% | ≤ 0 | **无效** — 胜率期望双差 |

### 2.5 A层：阈值有效性（10分）

> 复用日报后评估§2.3方法论，主窗口改为T+20。

核心问题：深度分析的评分分段（优秀≥80/良好60-79/一般40-59/差<40）在T+20窗口是否有区分度？

| 评分段 | T+20平均收益 | T+20正收益比例 | 判断 |

#### B6：情景概率校准（6分） — 流金

> **数据来源**：深度分析报告§六.2持仓风险情景表
> **验证窗口**：T+20
> **启用条件**：立即启用

深度分析§六.2输出4情景（最优/基准/偏弱/最差）的概率分布。后评估计算概率校准质量：

**Brier Score（概率校准的核心指标）**：

```
Brier Score = (1/N) × Σ(预测概率_k - 实际结果_k)²

其中实际结果_k：若实际落在该情景=1，否则=0
Brier Score越低越好：0=完美校准，0.25=完全无效（随机猜测四分类）
```

**得分规则**：

| Brier Score | 判断 | 得分 |
|:----------|:----|:----:|
| < 0.15 | 概率校准优秀 | 6分 |
| 0.15-0.22 | 概率校准一般 | 3分 |
| ≥ 0.22 | 概率校准差 | 1分 |

> **特别说明（流金）**：单次深度分析只有4个情景1个实际结果，Brier Score需要累积≥5次评估才有统计意义。初期先收集数据，≥5次后启用正式评分。

> **数据来源**：深度分析报告§六.4五红旗表
> **验证窗口**：T+20
> **启用条件**：立即启用

核心问题：红旗多的标的在T+20是否确实表现更差？

**验证方法**：
```
对每次深度分析：
  红旗数 = 🔴数量（🟡计0.5）
  计算 Spearman ρ(红旗数, T+20回撤幅度)
  
  ρ > 0 → 红旗多=回撤大，五红旗有前瞻预测力
  ρ ≈ 0 → 五红旗无预测力
  ρ < 0 → 红旗多反而回撤小，五红旗反向
```

**得分规则**：

| ρ(红旗数, T+20回撤) | 判断 | 得分 |
|:------------------:|:----|:----:|
| ρ ≥ 0.3 | 五红旗前瞻有效 | 5分 |
| 0.1 ≤ ρ < 0.3 | 有参考价值 | 3分 |
| ρ < 0.1 | 预测力不足 | 1分 |

> **最低样本**：需累积≥8次深度分析评估（含红旗数和T+20回撤数据）。初期仅记录不评分。

#### B9：估值预测误差（6分） — 青山

```
MAPE = |预测EPS - 实际EPS| / |实际EPS| × 100%

对三情景分别计算MAPE：
  - 乐观情景MAPE
  - 中性情景MAPE

```

**得分规则**（以中性情景MAPE为主）：

| 中性MAPE | 判断 | 得分 |

| 10-25% | 盈利预测可接受 | 3分 |
| ≥ 25% | 盈利预测偏差大 | 1分 |

**系统性偏差检测**（累积≥5次后启用）：
```
若乐观MAPE持续 < 悲观MAPE → 分析偏乐观，建议中性情景上修
若悲观MAPE持续 < 乐观MAPE → 分析偏悲观，建议中性情景下修
```

### 4.3 Spearman ρ与IC计算

```python
import numpy as np
from scipy.stats import spearmanr

# 对每个维度，分窗口计算Spearman秩相关系数
for each 维度 in [基本面, 技术面, 资金面, 行业面, 估值, 风控]:
    scores = [评估数据[stock].scores[维度] for stock in all_stocks]
    for window in [5, 10, 20, 40]:
        returns = [评估数据[stock][f"T+{window}收益"] for stock in all_stocks]
        rho, p_value = spearmanr(scores, returns)
        
        # 零假设随机baseline（1000次打乱取均值）
        baseline_rhos = []
        for _ in range(1000):
            shuffled = np.random.permutation(scores)
            rho_b, _ = spearmanr(shuffled, returns)
            baseline_rhos.append(rho_b)
        rho_baseline = np.mean(baseline_rhos)
        rho_excess = rho - rho_baseline

    # 以 T+20 为主窗口判定
    if rho_T20 >= 0.3: 判定 = "有效"
    elif rho_T20 >= 0.15: 判定 = "参考"
    else: 判定 = "需审视"
```

### 5.2 失效归因

> **触发**：中循环（每8次深度分析评估，约2个月）

当某信号或维度的有效性持续下降时，归因到以下四类：

| 失效类型 | 特征 | 应对 |
|:--------|:----|:----|
| **环境依赖** | 分市场状态后某状态有效、某状态无效 | 标记"条件有效"，写入条件规则库(§5.3) |
| **因子拥挤** | 有效性逐步下降，伴随该因子被广泛讨论 | 降权，关注反向指标 |
| **数据源退化** | 某数据源的误差增大导致下游评分失真 | 触发数据源审查（玉夜） |
| **方法论错配** | 指标本身逻辑有问题（如成长股用PE否决） | 方法论修正提案 |

**归因模板**：
```markdown
### 失效归因：[维度/信号名称] — [日期]
- **表现**：ρ从X降至Y，连续Z次下降
- **归因**：[环境依赖/因子拥挤/数据源退化/方法论错配]
- **证据**：[分市场状态数据/因子关注度/数据源可用率/逻辑链分析]
- **建议**：[具体措施]
```

### 5.4 知识代谢机制

> 复用日报后评估v1.8的认知科学隐喻（遗忘曲线/知识蒸馏/反刍验证）。

#### 5.4.1 知识遗忘（中循环）

每次中循环检查所有条件规则和信号有效性数据：
- 最近4个月内未被新数据验证的规则 → 标记为"休眠"
- 连续2次中循环（约4个月）保持休眠 → 降权至原权重的50%
- 连续3次中循环（约6个月）保持休眠 → 移入"历史规则库"（不删除，备查）

#### 5.4.2 知识蒸馏（大循环）

每16次深度分析评估（约4个月），将分散的信号有效性数据蒸馏为精简规则：

```
输入：原始信号评估数据（~44个信号 × 多次评估）
  ↓
聚类：相似信号的合并（如S01+S03+S10→"技术面多头组合"）
  ↓
筛选：仅保留ICIR≥0.5的信号组合
  ↓
输出：蒸馏后的核心规则（≤15条）
```

#### 5.4.3 反刍验证（大循环）

每16次评估，选取2-3个被标记为"有效"超过8次的关键信号，用**全部历史数据**重新验证：

- 反刍后ICIR与原始ICIR偏差>30% → 标记"早期样本偏差"，降置信度
- 反刍后胜率下降>10% → 标记"信号退化中"
- 反刍后验证通过 → 标记"反刍验证通过"，置信度升级

| 条件 | 阈值 | 建议动作 |

### 5.6 深度分析特有学习机制

#### 5.6.1 催化剂效果映射库

累积≥20条催化剂记录后，建立"催化剂类别→T+20影响幅度"映射：

| 催化剂类别 | 样本数 | 中位影响幅度 | 方向正确率 | 备注 |
|:---------|:----:|:---------:|:--------:|:----|
| 并购重组 | N | ±X% | Y% | — |
| 大额订单 | N | ±X% | Y% | — |
| 政策利好 | N | ±X% | Y% | — |
| 新产品发布 | N | ±X% | Y% | — |

此库直接反馈到深度分析.md §一.4的催化剂预期影响估计。

#### 5.6.2 估值偏差模式识别

累积≥10次三情景EPS预测后，分析系统性偏差：

```
若 mean(乐观预测EPS - 实际EPS) > 0 且 p<0.05
  → 分析体系偏乐观，建议中性EPS ×0.9 校准

若 mean(悲观预测EPS - 实际EPS) < 0 且 p<0.05
  → 分析体系偏悲观，悲观情景过于保守
```

#### 5.6.3 失败案例深度解剖

触发条件：某次深度分析的综合评分方向与T+20实际走势**完全相反**（评分≥70但T+20跑输大盘>5%；或评分<40但T+20跑赢大盘>5%）。

解剖流程：
```
失败案例触发
  ↓
山猫 审查：宏观/市场阶段判断是否误判？
  ↓
玉夜 审查：当时的财务数据是否存在未被识别的质量问题？
  ↓
流金 审查：五红旗是否漏标关键风险？情景概率是否严重失准？
  ↓
青山 审查：估值方法是否错配？因子信号是否给出了矛盾提示？
  ↓
腰子 综合：失败根因 + 方法论改进建议
  ↓
写入 失败案例库/（独立于常规后评估的深度解剖记录）
```

### 7.1 数据共享

|:--------|:--------|:------------|:--------|

| 财务数据 | ✅ 基础指标 | ✅ 多期+单季拆解 | 共享财务数据管线 |

### 7.2 循环同步

| 循环 | 日报 | 深度分析 | 同步方式 |
|:-----|:----|:--------|:--------|
| 微循环 | 每日 | 每周 | 独立执行，不交互 |
| 中循环 | ~每月 | ~每2月 | 深度分析触发时拉取日报中循环最新结果 |
| 大循环 | ~每2月 | ~每4月 | **联合执行**——两套后评估合并知识蒸馏+反刍验证 |
| 季度全量 | 每月 | 每季度 | **联合执行**——共享外部知识融合结果 |

### 7.3 联合升级规则

当日报后评估和深度分析后评估同时指向同一问题时（如"技术面维度ρ持续<0"），升级为**联合审查**，优先级提升一级。

## 八、版本管理

### 8.1 本文档版本规则

遵循项目统一版本规范：
- **主版本号**（X）：评估体系重大重构（如新增评估层、变更核心方法论）
- **次版本号**（Y）：维度新增/删除/权重调整、触发条件变更
- **修订号**（Z）：阈值微调、文字修正、示例更新

### 8.2 版本变更流程

```
后评估发现 → 触发优化条件(§5.5) → 腰子审核 → 
全团确认(山猫→玉夜→流金→青山) → 更新本文档新版本 → 记录CHANGELOG
```

### 8.3 与深度分析.md的版本联动

| 深度分析.md 升级 | 本文档响应 |
|:----------------|:--------|
| 新增章节/检验项 | 对应新增B层评估维度 |
| 修改评分权重 | 更新§2.3维度有效性权重 |
| 修改估值方法 | 更新B9/B11评估方法 |
| 新增信号类型 | 新增SXX补充信号 |
| 修改自检清单 | 更新版本差异检验项清单 |

### 8.4 归档策略

- 旧版本保留不删，存放于 `后评估逻辑/归档/`
- 每次版本升级时，上一版本移入归档目录
- 评估数据JSON永久保留（不可逆的历史记录）
