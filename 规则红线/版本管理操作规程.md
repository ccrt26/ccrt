# 版本管理操作规程

> 版本: v1.0 | 日期: 2026-05-24 | 来源: 从规则红线v1.13 §5.4拆出
> 关联: [分析的规则红线--Claude_v1.14.md §5.4](分析的规则红线--Claude_v1.14.md)

本文档是规则红线§5.4（全分析白皮书版本管理要求）的配套操作规程，包含模板、流程、载体定义等操作性细节。

---

## 1. CHANGELOG 条目格式模板

每个版本条目按以下结构组织，变更类型采用 Keep a Changelog 六类标记：

```markdown
## [vX.Y.Z] - YYYY-MM-DD

### 负责人
- 修改：<人名>（<角色>）
- 审批：<人名>（仅 MAJOR/MINOR）
- 依据：<来源说明>

### Added
- 新增内容 1 — 说明

### Changed
- 修改内容 1 — 说明前后对比

### Deprecated
- 即将废弃的功能

### Removed
- 已移除的内容

### Fixed
- 修复的问题

### Security
- 安全修复（如有）
```

## 2. 版本发布流程

```
Phase 1: 提案
  发现修改需求 → 记录到改进日志.md（含证据/原因/修改方案）
  → AI 向人提交修订提案

Phase 2: 确认
  人审查提案 → 决定：采纳 / 修改后采纳 / 拒绝
  → 如采纳，确定版本层级（MAJOR / MINOR / PATCH）

Phase 3: 执行
  升版本号 + 更新文档头日期 → 修改文档正文
  → 更新版本历史表 → 按模板更新 CHANGELOG.md
  → 重新生成 .docx → 更新文档版本索引
  → 运行 version_supervisor.ps1 验证一致性
  → git commit（message 标注版本号）→ git tag 标注
```

---

## 3. 版本载体

| 载体 | 位置 | 用途 | 保留期限 |
|:-----|:-----|:------|:---------|
| 文档头 | 第 1-3 行 | 当前版本和更新日期 | 随文档更新 |
| 版本历史表 | 文档开头表格 | 快速回顾，保留最近 10 条 | 保留所有 |
| CHANGELOG.md | 同目录独立文件 | 永久记录，含责任人+文件清单 | 永久 |
| git tag | git tag | 发布标记，便于回溯 | 永久 |
| 文档版本索引.md | 规则红线\ | 全局版本概览 | 随索引更新 |

---

## 4. 归档策略

- 每个版本独立文件：`白皮书名称_vX.Y.Z.md` + `.docx`
- 旧版本保留不删，历史可追溯
- 已发布文件的版本号禁止修改（应发布新版本）
